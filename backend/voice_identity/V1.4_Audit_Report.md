## 3. 生命周期状态机 (V1.4 完整)

```
creating ──→ processing ──→ ready ──→ active ──→ disabled
   │            │             │          │           │
   └────────────┴─────────────┴──────────┴───────────┴──→ deleted (终态)
```

转移表 (`_TRANSITIONS`):
- creating → {processing, ready, disabled, deleted}
- processing → {ready, disabled, deleted}
- ready → {active, disabled, deleted, creating, processing}
- active → {ready, disabled, deleted}
- disabled → {ready, deleted, creating}
- deleted → {} (终态)

状态枚举: creating / processing / ready / active / disabled / deleted (6 态)
注: status 为 TEXT 列, 增 'processing' 无需 DB 迁移。

## 5. Cache 协议 (V1.5 实现, Manager duck-typed 调用)

Manager 经 Cache 间接访问引擎, 永不直接调用 GPT-SoVITS/Qwen3:

| 生命周期阶段 | Cache 方法 | 语义 |
|-------------|-----------|------|
| PROCESSING | `cache.prepare(voice_id, reference_audio)` | 准备 embedding/engine cache |
| ACTIVE | `cache.load(voice_id)` | 加载缓存到内存 |
| DISABLED | `cache.unload(voice_id)` | 卸载缓存 (保留磁盘) |
| DELETED(硬) | `cache.remove(voice_id)` | 清理缓存 (磁盘+内存) |

cache=None 时所有缓存操作静默跳过 (debug 日志), Manager 仍可独立运行。

- ✅ delete: 软删 (status=deleted, cache 保留) / 硬删 (级联, cache remove)

- ✅ 完整生命周期: CREATED→PROCESSING→READY→ACTIVE→DISABLED→DELETED
- ✅ AST: Manager 无引擎/TTS 直接依赖

## 8. 修复: list_voice 优先级 (V1.3 回修)

V1.3 `list_voice(discoverable_only=True)` 会忽略 status 参数, 导致 `get_active_voices` 误返回 ready+active。
V1.4 修复: **status 显式给定 → 按 status 精确筛选**, 优先于 discoverable_only。已回归测试验证。
