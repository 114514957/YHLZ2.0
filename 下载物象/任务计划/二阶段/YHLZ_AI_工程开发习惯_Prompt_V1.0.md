# YHLZ AI 工程开发习惯（Agent 工程师 × Prompt 工程师）


## 一、总原则

稳定开发 / 增量迭代 / 可测试 / 可维护 / 可扩展，完成完整工程闭环：

```
需求分析 → 架构设计 → 开发实现 → 自动测试 → 验收评估 → 生成报告 → 下一阶段规划
```


## 二、开发前（动手前的纪律）

1. 先读后写: 写任何代码前，先摸清项目结构、既有模块风格、依赖清单 (package/requirements)、已有测试框架与命令
2. 遵循现有约定: 命名、目录组织、单例模式、RLock、中文注释、分层调用——新代码必须与老代码同构 (如 YHLZ 中 Personality 与 Vision 系列模块的架构一致性)
3. 不破坏既有模块: 只新增、只增量接入；严禁跨层调用 (Service → Manager → Adapter)
4. 配置驱动: 阈值/开关/路径全部进 config，用 `模块名_*` 前缀隔离，不写死
5. 列计划再动手: 多步骤任务先建 todo 清单，逐项推进，实时更新状态


## 三、开发中（代码习惯）

1. 接口先行: 先定义 Schema / ABC 接口，再写实现；保证可替换、可 Mock、可扩展
2. 安全默认: 权限默认拒绝、真实能力默认关闭、Mock 优先、测试模式环境变量隔离
3. 异常隔离: 每个模块内部捕获异常转错误码/日志，不让异常穿透破坏主流程
4. 数据独立: 模块数据独立存储，绝不污染其他模块 (如行动记录绝不写入 Agent Memory)
5. 完整可观测: 日志覆盖 start/success/fail/cancel/exception 全事件 + 指标统计 (成功率/延迟/拒绝数等)
6. 边界防御: 白名单枚举、长度/数值边界校验、频控/节流、超时与取消机制


## 四、测试习惯（核心信仰: 无测试不交付）

1. 先写测试后验证: 功能实现后立即配套单元测试，覆盖正常/边界/异常三分支
2. 环境隔离: 环境变量修改 try/finally 成对恢复；测试数据用 Mock/临时目录，不留残留
3. 分层测试: 单测 (模块级) → 专项套件 (模块全量) → 集成/冒烟 (TestClient 端到端) → 全量回归 (验证不破坏其他模块)
4. 验收标准量化: 如 `专项 120+ / 全量回归 Failed=0 / 冒烟 N 场景全过`
5. 跑测试看证据: 不凭感觉，每次改动后实际运行命令，确认 Failed=0


## 五、Prompt 工程习惯

1. 规范即契约: 为下一阶段写开发 Prompt 时，固定模板: 版本→依据→当前能力盘点→本阶段任务 (目标/原则/P0/P1/验收标准)→工程规范 (目录/约束/依赖)→验收输出
2. 验收标准先行: 任务开始前就明确"什么叫完成" (Failed=0 + 冒烟全过 + 清单全勾选)
3. 明确边界: 写清"必须做 / 禁止做" (如 Vision Action 禁止自动控制电脑)，防止 AI 越界
4. 渐进式提示: 复杂任务拆 P0 (核心) → P1 (接入) → P2 (扩展)，每阶段可独立验收
5. 可复现: 测试命令、环境变量、目录路径全部写进 Prompt，任何工程师都能复现验证


## 六、交付习惯

1. 验收报告: 版本信息 / 执行总结 / 代码修改记录 / 测试数据 / 架构影响 / 问题复盘 / 下一阶段规划
2. 问题复盘必写: 现象→原因→解决方案→预防措施（四段式）
3. 收尾清理: 删除临时文件、确认无测试残留 db、检查 lint/语法
4. 总结给用户: 完成内容 / 测试数据 / 架构图 / 使用方法 / 下一阶段建议


## 七、工程闭环实例 (YHLZ 已验证)

- Personality Engine V3.4: 专项 137 + Vision 663 + Agent 131 Failed=0
- Vision Action V1.0: 专项 151 + Personality 137 + Vision 663 (2 skip) + Agent 131 Failed=0, 冒烟 16/16
