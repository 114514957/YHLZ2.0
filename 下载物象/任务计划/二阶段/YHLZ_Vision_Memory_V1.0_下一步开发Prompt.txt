================================================ 二、本阶段开发判断
================================================

当前系统已经具备：

- 输入： Voice + Vision (基础帧)
- 感知： Vision Perception (文字 + 对象)
- 理解： Vision Understanding (场景语义 + 视觉问答)
- 思考： Agent Core
- 基础记忆： Memory Interface (文本记忆)

当前 YHLZ 每次理解屏幕后立即丢弃结果 —— 不能记住"上次看到了什么"、
不能积累用户视觉偏好、不能基于历史画面回答"刚才屏幕上是什么"。

Understanding 阶段严守"只理解不记忆"的边界, 已完成并验收通过。

下一步必须进入：

视觉理解 → 视觉记忆

为什么做 Vision Memory, 不做其他：
- 架构顺序: 感知 → 理解 → 记忆 → 行动, 记忆是让理解产生长期价值的关键
- 用户价值: "刚才那个窗口写的什么?" / "上次看到的界面是什么样" 需要视觉记忆
- 避免跳级: 未记忆就做自主行动会导致行为无据可依

================================================ 三、本版本目标
================================================

版本：

YHLZ Vision Memory V1.0

目标：

建立 Vision Memory Layer

```
UnderstandingResult / PerceptionResult
    ↓
Vision Memory Engine
    ↓
Persistent Vision Memory (持久化视觉记忆)
```

输出：

- 视觉记忆持久化 (SQLite, 复用 Agent Memory 模式)
- 视觉记忆检索 (按时间 / 关键词 / 场景类型)
- 视觉记忆管理 (增删改查 / 清理策略)

================================================ 四、本版本不包含
================================================

禁止（明确边界）：

1. Agent 自主视觉行动（自动看屏幕后主动执行, 未来）
2. 视觉人格化（视觉记忆参与人格决策, 未来）
3. 视觉偏好自动学习（从记忆自动推断偏好并改变行为, 未来）
4. 自动电脑控制（一切外部操作, 未来）
5. 视频流实时记忆（本版本仅单帧 / 快照记忆）

本版本只建设：

- 视觉记忆存储引擎 + 数据结构
- 记忆检索 / 管理接口
- Agent 视觉记忆工具
- 与 Understanding / Perception 的可选自动归档通道

    ↓

- 禁止跨层调用: Adapter/Store 不调 Service
- 全部配置进 config.py (vision_memory_* 前缀)

================================================ 六、开发任务
================================================

P0 必须完成：

1. Vision Memory Schema

   VisionMemoryEntry 字段:
   - id / timestamp / created_at
   - memory_type      (scene / text / object / qa / combined)
   - source           (describe / qa / ocr / detection / combined)
   - scene_type       (场景类型)
   - content          (记忆内容: 描述文本)
   - summary          (简短摘要)
   - keywords         (关键词列表, 供检索)
   - subjects         (主体列表, 复用 UnderstandingSubject 结构或平铺 dict)
   - confidence / metadata / processed 标志

2. Vision Memory Store Interface

   VisionMemoryStore 接口:
   - add(entry) -> id
   - get(memory_id) -> entry
   - update(memory_id, **fields) -> bool
   - delete(memory_id) -> bool
   - list_all(limit, offset) -> entries
   - search(keywords, scene_type, time_range, limit) -> entries
   - count() -> int
   - clear() -> int
   - close()

3. SQLite Store

   - 数据库: backend/data/vision_memories.db (配置可改)
   - 表: vision_memories
   - 字段与 schema 对应 (JSON 列存 subjects / keywords / metadata)
   - 线程安全 (SQLite 连接池或每操作连接 + WAL)
   - 懒加载 / 启动不阻塞

4. Memory Store (内存实现)

   - 测试用, 与 SQLite 实现同一接口
   - 环形 / 容量上限可配

5. Vision Memory Manager

   - Store 注册表 + 路由
   - 默认注册: 内存优先 (测试) / SQLite (生产)
   - 单例 get_manager / reset_manager

6. Vision Memory Service

   - 统一入口: 增删改查 / 检索 / 统计
   - 权限校验 (vision_memory_enabled 默认 False)
   - 日志记录 (add / delete / search)
   - 可选: remember_from_result(result) 自动归档 UnderstandingResult / PerceptionResult
   - 单例 get_service / reset_service

7. 权限控制

   - vision_memory_enabled 默认 False
   - allow_save 策略 (仅记忆结构化结果, 不保存原始图片)
   - 禁止未经授权保存图片

P1 建议完成：

8. Agent 工具: remember_scene (记住当前屏幕) / recall_scene (回忆最近的视觉记忆)

9. 配置管理: vision_memory_* 配置项 (enabled / db_path / max_entries / test_mode / tool_timeout)

10. API 端点: /vision-memory/status / add / list / search / get / delete / clear / logs

11. 性能指标: 操作耗时记录 + 统计 (add/search 平均耗时)
