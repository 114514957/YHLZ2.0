# 三、当前系统缺失能力


目前 YHLZ 已经：

能看 (Vision) → 能提取信息 (Perception) → 能理解画面 (Understanding) → 能记住 (Memory) → 能思考 (Agent) → 有声音 (Voice)


但是仍然不能：

- 拥有稳定的人格 (性格/语气/习惯/价值观)
- 在对话中保持一致的自我形象
- 根据用户偏好调整互动风格
- 人格化地回应 (幽默/温柔/严谨/简洁)
- 记忆与人格结合 (长期行为模式)


因此进入：

Vision Memory → Personality Engine

# 四、本阶段开发判断


## 为什么开发 Personality Engine

### 1. 架构顺序正确

完整进化链路：

感知 → 理解 → 记忆 → 思考 → 人格 → 行动

人格是让记忆产生个性化价值的引擎, 是"有人格"目标的直接实现。


### 2. 用户体验需求

没有人格：

AI 每次回应都是"通用助手腔调", 用户感到冷漠、不真实。


拥有人格：

- 一致的自我形象 (我是谁)
- 稳定的互动风格 (怎么说话)
- 可配置的个性特征 (幽默/温柔/严谨/简洁/热情)
- 与记忆结合的长期行为模式


### 3. 避免架构跳跃

本阶段不进入：

- 自动行动 (Vision Action)
- 自主控制电脑
- 视觉人格决策 (基于画面直接改变人格)


先建立稳定人格层, 作为未来所有输出的基座。

# 五、本版本目标


版本：YHLZ Personality Engine V3.4


目标：

建立人格引擎层 (Personality Engine), 让 YHLZ 拥有可配置、可持久化、可进化的稳定人格。


整体架构：

```
PersonalityProfile (人格档案)
    ↓
Personality Engine (人格引擎)
    ↓
Personality Style (输出风格)
    ↓
Prompt 增强 (注入对话上下文)
```


核心价值：

- 人格可配置 (用户可自定义)
- 人格可持久化 (SQLite)
- 人格可评估 (人格一致性打分)
- 人格可进化 (随记忆积累调整)


---


# 六、核心能力目标


## 1. Personality Profile (人格档案)

包含：

- 人格 ID / 名称 / 描述
- 核心特征 (性格维度: 友好度 / 幽默感 / 严谨度 / 简洁度 / 热情度)
- 说话风格 (语气 / 用词 / 句式)
- 互动偏好 (称呼用户 / 回应长度 / 表情使用)
- 行为准则 (该做什么 / 不该做什么)
- 创建时间 / 更新时间 / 活跃状态


## 2. Personality Engine (人格引擎)

- 人格加载 (默认人格 / 用户自定义人格)
- 人格切换 (运行时动态切换)
- 人格管理 (创建 / 更新 / 删除 / 列表)
- 人格评估 (一致性打分: 当前回应是否符合人格)


## 3. Personality Style (输出风格)

- 基于人格生成对话风格指令
- 注入 Agent / LLM 对话上下文
- 支持多人格并存 (按场景切换)


## 4. Personality Persistence (人格持久化)

- SQLite 存储 (personality_profiles 表)
- 与 Agent Memory 模式一致
- Mock 与真实双实现
