================================================ 二、本阶段开发判断
================================================

当前系统已经具备：

- 输入： Voice + Vision (基础帧) + Vision Perception (结构化感知)
- 思考： Agent Core
- 基础记忆： Memory Interface

当前 Vision Perception V1.0 已能产出结构化感知数据 (文字 + 对象),
但 YHLZ 还不能"理解"画面含义 —— 不能回答"屏幕上发生了什么"、
不能做场景描述、不能基于视觉内容推理。

Perception 阶段严守"只提取不理解"的边界, 已完成并验收通过。

下一步必须进入：

视觉感知 → 视觉理解

为什么做 Vision Understanding, 不做其他：
- 架构顺序: 感知 → 理解 → 记忆 → 行动, 理解是感知的下游必需环节
- Agent 需要: 视觉问答 / 场景描述 / 视觉上下文, 才能参与多模态对话
- 避免跳级: 未理解就做视觉记忆 / 自主行动会导致架构耦合

================================================ 三、本版本目标
================================================

版本：

YHLZ Vision Understanding V1.0

目标：

建立 Vision Understanding Layer

```
Structured Perception Result / VisionFrame
    ↓
Understanding Engine
    ↓
Semantic Result (机器可读的视觉语义数据)
```

输出：

- 场景描述 (Scene Description)
- 视觉问答 (Visual QA)
- 结构化语义 (Structured Semantics: 场景类型 / 主体 / 行为 / 环境)

================================================ 四、本版本不包含
================================================

禁止（明确边界）：

1. Vision Memory（视觉记忆持久化, 下一版本）
2. Agent 自主视觉行动（自动看屏幕后主动执行, 未来）
3. 视觉人格化（视觉输入参与人格决策, 未来）
4. 自动电脑控制（一切外部操作, 未来）
5. 视频流实时理解（本版本仅单帧 / 快照）

本版本只建设：

- 理解接口 + 结构化语义结果
- VLM (Vision Language Model) Adapter 接口与 Mock 实现
- 场景分析基础 (单帧)
- Agent 视觉问答工具

- 禁止跨层调用: Adapter 不调 Service
- 全部配置进 config.py (understanding_* 前缀)

================================================ 六、开发任务
================================================

P0 必须完成：

1. Understanding Schema

   UnderstandingResult 字段:
   - id / source / timestamp / success
   - scene_type       (场景类型: 如 desktop / document / image / unknown)
   - description      (场景描述文本)
   - subjects         (主体列表: name / category / position / confidence)
   - summary          (简短摘要)
   - metadata / processing_time / status / error

2. Understanding Interface

   VLMAdapter 接口:
   - name / is_available()
   - understand(image, prompt, options) -> UnderstandingResult
   - 支持未来: Qwen-VL / GPT-4V / 其他 VLM

3. Mock Provider

   - MockVLMProvider: 不加载模型, 返回可配置的合成理解结果
   - 支持错误模式 (provider 失败 / 超时 / 空图)

4. Understanding Manager

   - 注册表 + 路由 (与 PerceptionManager 同模式)
   - 单例 get_manager / reset_manager

5. Understanding Service

   - 统一入口, 权限校验 + 日志 + 路由
   - 输入: VisionFrame / numpy image / PerceptionResult(可选)
   - 输出: UnderstandingResult
   - 单例 get_service / reset_service

6. 权限控制

   - understanding_enabled 默认 False (默认拒绝)
   - 与视觉 / 感知权限组合校验
   - 禁止未经授权保存图片

P1 建议完成：

7. Agent 工具: describe_scene (屏幕场景描述) / answer_visual (视觉问答)

8. 配置管理: understanding_* 配置项 (enabled / provider / timeout / test_mode)

9. API 端点: /understanding/status / describe / qa / logs

10. 性能指标: latency_ms 记录 + stats (沿用 PerceptionLogger 模式)

================================================ 七、开发要求
================================================

必须：

- 中文注释 / 类型注解 / 异常处理 / 线程安全 (RLock)
- 日志全生命周期 (start / success / fail)
- Mock 与真实双模式 (测试默认 Mock, YHLZ_RUN_REAL_TESTS=true 切换真实)

禁止：

- 禁止在 Understanding 中直接调用 LLM 文本接口做视觉理解 (必须经 VLM Adapter)
- 禁止修改 Agent Core / Voice / Vision Foundation / Perception 既有接口
- 禁止跨层调用
- 禁止绑定单一 VLM 实现
- 禁止未经授权保存图片
- 禁止临时方案进入主架构
