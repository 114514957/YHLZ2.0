## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"感知-记忆深度集成"

V6.3 打通了**安全管道**（感知 → 验证 → 候选 → 批准 → 记忆），但：
- 反思检查只是占位回调（未深度评估）
- 感知统计不持久化（重启丢失）
- 感知结果未反哺情绪/成长（多模态闭环未闭合）

V6.4 三主线：
1. **感知-反思深度集成**：候选入批准前经 ReflectionEngine 深度评估（模式/矛盾/价值）
2. **感知统计持久化**：快照扩展感知域（V6.0 快照体系）
3. **感知-成长闭环**：感知事件自动 track（multimodal 事件）+ 感知情绪联动

### 为什么不做（V6.4 明确不包含）

- 不做具身化（虚拟形象/动作）→ V7.x
- 不做自主行动（行动仍经 Permission + 用户确认）
- 不做音频感知（V7.x）
- 不做黑盒训练 / LLM 视觉理解

## 3. 本版本目标

**V6.4 Perception-Memory Deep Integration**

1. **感知-反思深度集成** `perception/memory_gate/reflection_evaluator.py`
   - 候选 → ReflectionEngine.reflect → 模式/矛盾/价值评估 → 批准建议
   - 反思结果参与批准评分（可解释）
2. **感知统计持久化**（快照扩展 `perception_stats` 域）
   - 事件数/验证数/批准数/拒绝数/OCR 次数/检测次数
   - 旧快照兼容（无感知域 → 跳过）
3. **感知-成长闭环**（rhythm 联动）
   - 感知批准 → 自动 track multimodal_perception 事件
   - 感知成功 → 情绪联动（creative_done 类似）
4. **多目标模板检测**（detection 增强）
   - 同模板多实例匹配（非极大值抑制 NMS 规则版）

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 反思评估器

```
backend/embodied/companion/perception/memory_gate/
└── reflection_evaluator.py
```

- 输入：候选 + ReflectionEngine
- 输出：{reflection_score, patterns, contradictions, value_hint, reason}
- 评分入批准流程（approval_rule 增加 reflection 维度或加权）

### 快照扩展

- SNAPSHOT_DOMAINS + `perception_stats`
- collect_states: 感知统计（从 PerceptionService.stats()）
- 恢复：重建统计（只读指标，无副作用）
- 旧快照兼容测试（无感知域不报错）

### 成长闭环

- memory_gate 批准成功后回调（track multimodal + 情绪联动）
- 拒绝也记录（verification_rejected 语义）
