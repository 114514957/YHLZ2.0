## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"具身伙伴集成"

V8.0 完成最高治理后，YHLZ 已有完整能力栈但缺三块落地：
1. **HIL 全部 Mock**（模型端点无真实调用，config 已有 api_key）
2. **形象无推送**（Presence 状态机就绪，无外部消费接口）
3. **感知不调度**（视觉/语音任务未走 HIL 路由）

V8.1 三主线：
1. **HIL 真实模型接入**：OpenAI/Claude/Gemini/本地 真实 Adapter
   （Mock ↔ Real 双模式，失败降级 Mock）
2. **形象推送接口**：Presence 状态 → 推送事件（WebSocket 预留，
   状态快照 + 事件序列）
3. **感知-调度联动**：视觉任务 → HIL 路由（本地实时/云端增强）

### 为什么不做（V8.1 明确不包含）

- 不做 3D 渲染引擎（状态驱动，GPU 不做）
- 不做自动应用成长（growth_auto_apply 保持 false）
- 不做云端成为核心（身份/记忆/安全永远本地）
- 不做多智能体协作调度（V9 Constitution 深化）

## 3. 本版本目标

**V8.1 Embodied Partner Integration**

1. **HIL 真实模型接入** `hybrid/cloud/adapters/`
   - CloudAdapter 接口 + 真实 Adapter（openai/claude/gemini/local）
   - ModelEndpoint.handler 注入（现有接口不变）
   - 真实调用失败 → 降级 Mock（不崩溃）
2. **形象推送接口** `embodied_presence/`
   - Presence 事件序列（状态变化 → 事件）
   - 推送接口预留（WebSocket 通道可注册）
3. **感知-调度联动**
   - VisionService 任务入口 → HIL.route（本地/云端）
   - 权限模型不变（screen/camera 默认 false）
4. **演化建议持久化**：constitution_state 快照域

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### HIL 真实接入

```
backend/embodied/companion/hybrid/cloud/adapters/
├── base.py                (CloudAdapter 接口)
├── openai_adapter.py      (OpenAI 真实)
├── claude_adapter.py      (Claude 真实)
├── gemini_adapter.py      (Gemini 真实)
├── local_adapter.py       (本地模型)
└── mock_adapter.py        (Mock 默认)
```

- 测试默认 Mock（YHLZ_RUN_REAL_TESTS=true 切真实）
- 真实调用失败 → 降级 Mock（结构化错误帧）

### 形象推送

```
backend/embodied/companion/embodied_presence/presence_stream.py
```

- 状态变化 → 事件序列（可回放）
- 推送通道注册（WebSocket 预留接口）

### 感知联动

- VisionService 任务 → HIL route → 执行
- 权限模型不变

## 6. 开发要求

### 必须

- 真实 Adapter 与 Mock 同一接口（行为一致）
- 真实调用失败降级 Mock（不崩溃）
- 形象推送事件可回放（可审计）
- 感知联动不改变权限模型
- 配置驱动（`companion_hybrid_*` / `companion_presence_*` 前缀）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V8.0 及以前 API
- 禁止自动应用成长（growth_auto_apply 恒 false 语义）
- 禁止云端结果直接改变身份（宪法验证铁律保持）
- 禁止跨层调用 / 静默吞异常 / 黑盒 / 临时方案
