## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"自主成长成熟化"

V6.5 打通了**认知反思与受控成长**（理解经验 → 建议 → 评估 → 受控应用）。
但三个缺口：
1. **反思不联动情绪**（Reflection → Meaning → Growth Value → Emotion 未接）
2. **成长闭环靠人工触发**（反思/建议/评估未自动化）
3. **成长趋势不入报告**（成长历史无趋势分析）

V6.6 三主线：
1. **反思-情绪集成**：反思结果经 Meaning → Growth Value → 情绪调整（不直接）
2. **成长闭环自动化**：节律触发反思 → 建议 → 评估（自动生成，应用仍人工/审批）
3. **成长趋势报告**：建议/评估/应用趋势入 growth_report

### 为什么不做（V6.6 明确不包含）

- 不做具身化（虚拟形象/动作）→ V7.x
- 不做 LLM（纯规则保持）
- 不做自动应用（应用永远需人工/审批，growth_auto_apply 保持 false）
- 不做多智能体成长协作（V6.7/V7）

## 3. 本版本目标

**V6.6 Autonomous Growth Maturation**

1. **反思-情绪集成** `companion/reflection/reflection_emotion.py`
   - 反思 → Meaning → Growth Value → Emotion Adjustment（不直接）
   - 正面反思（有效策略）→ 温和积极；负面反思（问题模式）→ 有限调整
2. **成长闭环自动化** `companion/growth/growth_cycle.py`
   - 节律触发：每日/事件驱动自动反思 → 建议生成 → 评估（应用仍需审批）
   - 自动行为全部审计
3. **成长趋势**（growth_report 扩展）
   - 建议/评估/应用趋势（按天/周）
4. **快照增强**：growth_state 域补充趋势统计

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 反思-情绪集成

```
backend/embodied/companion/reflection/
└── reflection_emotion.py
```

- 规则：反思报告 → Meaning（成功模式→积极；问题模式→中性/有限）→ 情绪调整（creative_done/relationship_up 级别，不剧烈）
- 情绪调整经 EmotionEngine（不直接写状态）
- 禁止：负面反思大幅压低情绪（有限幅）

### 成长闭环

```
backend/embodied/companion/growth/
└── growth_cycle.py
```

- 触发器：距上次反思 ≥ N 天 或 经历数增长 ≥ M
- 流程：track(experience) → 自动反思 → 建议 → 评估 → 待审批列表
- 应用永远需人工（growth_auto_apply=false 硬保持）
- 自动行为审计（reuse GrowthAudit）

### 成长趋势

- growth_report 增加 growth_trend（建议数/评估通过率/应用数 按天）
- GrowthTrend 复用（V6.1 已有按桶统计）

## 6. 开发要求

### 必须

- 反思-情绪集成必须经 Meaning（禁止反思直接改情绪）
- 成长闭环自动化不改变"应用需审批"铁律
- 自动行为全部审计
- 配置驱动（`companion_growth_*` / `companion_reflection_*`）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V6.5 及以前 API
- 禁止自动应用成长（growth_auto_apply 恒 false 语义）
- 禁止反思直接修改情绪/人格
- 禁止跨层调用 / 静默吞异常 / 黑盒 / 临时方案
