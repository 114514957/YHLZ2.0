## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"互动表达 + 视觉感知"

V6.1.1 建立了**可计算的情绪状态**，但情绪还没有"出口"——它不修饰任何表达。
同时视觉只有**采集层**（V1.0 Foundation：屏幕/摄像头/Mock），没有**理解层**。

V6.2 双主线：
1. **互动表达**：情绪状态修饰回应风格（仅建议不强制，核心人格不可变）
2. **视觉感知**：从"能看到"到"能理解"（OCR + 基础目标检测，独立子系统）

### 为什么不做（V6.2 明确不包含）

- 不做具身化（虚拟形象/动作）→ V7.x
- 不做 LLM 情绪理解 / 视觉 VLM 深度理解（保持纯规则 + 规则 OCR）
- 不做真实设备强制控制（权限默认拒绝）
- 不做黑盒训练

## 3. 本版本目标

**V6.2 Interaction Expression & Vision Perception**

1. **互动表达层** `companion/expression/`
   - 情绪 → 表达建议映射（情绪高 → 建议热情措辞；情绪低 → 建议耐心）
   - 表达建议 ≠ 强制输出（仅建议，核心人格/对话风格不可变）
   - 表达审计（每次建议记录原因）
2. **视觉感知 V1.0** `backend/vision_perception/`（独立子系统）
   - OCR（Tesseract/规则 Mock 双模式）
   - 基础目标检测（模板匹配/规则 Mock 双模式）
   - 权限（默认拒绝）+ 日志 + 审计
3. **情绪趋势入成长报告**（V6.1.1 growth_report 增加情绪维度）

## 4. 架构设计要求

### 互动表达层

```
backend/embodied/companion/expression/
├── expression_rules.py    # 情绪 → 表达建议规则表 (可解释)
├── expression_engine.py   # 表达引擎 (建议生成 + 审计)
└── expression_audit.py    # 表达审计
```

- 规则：positivity ≥ 0.7 → 热情措辞建议；≤ 0.3 → 耐心措辞建议；中间 → 中性
- 建议含 reason（情绪值 + 规则依据）
- 表达建议不写入对话输出（由 GUI/上层决定），仅提供建议接口

### 视觉感知子系统

```
backend/vision_perception/
├── __init__.py
├── perception_schema.py   # 感知数据模型 (OCRResult/DetectionResult)
├── perception_interface.py# 感知适配器接口
├── perception_manager.py  # 管理器 (注册/路由/单例)
├── perception_service.py  # 服务 (权限 + 采集 + 日志编排)
├── adapters/
│   ├── ocr_mock.py        # OCR Mock 适配器
│   ├── ocr_tesseract.py   # Tesseract 适配器 (真实, skipIf 无环境)
│   ├── detection_mock.py  # 检测 Mock 适配器
│   └── detection_template.py # 模板匹配适配器
├── permission.py           # 权限 (默认拒绝)
├── logger.py               # 感知日志
└── tests/                  # 测试目录
```

- 配置 `perception_*` 前缀（config.py）
- Mock 优先：OCR/检测 Mock 行为与真实一致
- 权限默认拒绝：`perception_enabled=false` / `ocr_enabled=false` / `detection_enabled=false`

### 成长报告扩展

growth_report 增加 `emotion_trend`（情绪均值/趋势，来自 emotion history）

## 6. 开发要求

### 必须

- 分层铁律（Interface → Service → Manager → Adapter）
- 配置驱动（`perception_*` / `companion_expression_*`），禁止魔法数字
- 权限默认拒绝，显式开启才采集
- Mock 与真实实现同一接口（行为一致）
- 表达建议只建议不强制（核心人格不可变）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V6.1.1 及以前 API
- 禁止表达层修改人格/情绪（只读情绪 + 建议）
- 禁止跨层调用 / 静默吞异常 / 黑盒 / 临时方案
- 禁止在感知层直接调用 LLM
