## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"自主成长治理"

V6.6 打通了反思-情绪联动与成长闭环自动化，但三个缺口：
1. **趋势无时间对比**（growth_score 静态分档，无近期 vs 早期趋势判断）
2. **审批模式未学习**（用户批准/拒绝模式未反馈到建议排序）
3. **闭环是单体的**（无多智能体成长协作准备，无策略多样性）

V6.7 三主线：
1. **趋势双窗口对比**：近期窗口 vs 早期窗口 → 加速/减速真实判定
2. **成长策略偏好学习**：用户审批记录 → 策略偏好 → 建议排序（只排序不越权）
3. **多智能体成长协作接口**（V7 具身化前最后准备，只建接口）

### 为什么不做（V6.7 明确不包含）

- 不做具身化（虚拟形象/动作）→ V7.x
- 不做 LLM（纯规则保持）
- 不做自动应用（应用永远需人工/审批，growth_auto_apply 保持 false）
- 不做身份/核心价值自动调整（永远人工 + 身份守护）

## 3. 本版本目标

**V6.7 Autonomous Growth Governance**

1. **趋势双窗口对比** `growth_trend_analysis` 扩展
   - 近期（近半窗口）vs 早期（前半窗口）指标对比
   - 输出 trend: accelerating/decelerating/stable（基于对比，非静态分档）
2. **成长策略偏好学习** `growth/growth_preference.py`
   - 用户审批记录（approve/reject）→ 策略类型偏好分
   - 建议排序（偏好分 + 评估分加权），不改变审批流程
3. **多智能体成长协作接口**（Reserved 接口）
   - 成长策略注册表（策略源可替换）
   - 不实现协作调度
4. **快照增强**：preference_state 域

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 趋势双窗口对比

- 复用 GrowthTrendAnalysis，新增对比段（不破坏 V6.6 API）
- 输入增加 events（带时间戳的成长事件）或 recent/earlier 统计

### 策略偏好学习

```
backend/embodied/companion/growth/growth_preference.py
```

- 输入：审批记录（proposal.type + decision）
- 输出：偏好分（每类型 0~1）+ 排序建议（只读）
- 禁止：偏好分改变评估结果/跳过审批

### 多智能体协作接口

```
backend/embodied/companion/growth/growth_registry.py
```

- 策略源注册表（注册/查询/替换）
- 状态：Reserved（只建接口，不实现调度）

## 6. 开发要求

### 必须

- 偏好学习只排序，不越权（审批流程不变）
- 趋势对比纯规则（无黑盒）
- 自动行为全部审计
- 配置驱动（`companion_growth_*` 前缀）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V6.6 及以前 API
- 禁止自动应用成长（growth_auto_apply 恒 false 语义）
- 禁止偏好分直接修改评估结果
- 禁止跨层调用 / 静默吞异常 / 黑盒 / 临时方案
