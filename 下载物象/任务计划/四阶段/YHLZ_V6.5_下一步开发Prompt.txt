## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"互动理解 + 自适应表达"

V6.4 打通了**感知-记忆认知闭环**（感知 → 验证 → 反思 → 批准 → 经验）。
但两个缺口：
1. **一致性/模式判断是关键词包含**（简单规则），没有语义相似度
2. **表达层与感知/情绪分离**（表达建议不感知感知结果）

V6.5 三主线：
1. **语义理解增强**：纯规则 TF 相似度（反思一致性/模式匹配升级）
2. **自适应表达融合**：情绪 + 感知批准 → 表达建议融合
3. **感知-行动预览**：感知帧 → 行动建议（经 Permission，不自动执行）

### 为什么不做（V6.5 明确不包含）

- 不做具身化（虚拟形象/动作）→ V7.x
- 不做 LLM 语义理解（纯规则 TF，铁律保持）
- 不做自主行动（行动建议需 Permission + 用户确认）
- 不做音频感知（V7.x）

## 3. 本版本目标

**V6.5 Interaction Understanding & Adaptive Expression**

1. **语义相似度引擎** `companion/semantics/`
   - `tokenizer.py`：中文分词（规则：字/词/短语）
   - `similarity.py`：TF 余弦相似度（纯规则）
   - `semantic_matcher.py`：语义匹配（一致性/模式/重复判断升级）
2. **自适应表达融合** `companion/expression/`
   - `expression_fusion.py`：情绪 + 感知结果 + 任务上下文 → 融合表达建议
   - 感知批准 → 表达建议（"我看到任务清单了" 风格）
3. **感知-行动预览** `companion/perception/action_preview.py`
   - 感知帧 → 行动建议（经 Permission + action_allowed 检查）
   - 预览 ≠ 执行（禁止自动行动）
4. **成长报告感知趋势**（multimodal 事件趋势入报告）

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 语义理解层

```
backend/embodied/companion/semantics/
├── tokenizer.py        # 中文规则分词
├── similarity.py       # TF 余弦相似度
└── semantic_matcher.py # 语义匹配器
```

- 纯规则（禁止 NN/LLM）
- tokenizer：按长度/常见词拆分（可解释）
- similarity：TF 向量 + 余弦（0~1）
- 集成：reflection_rules 一致性/模式用语义相似度替代包含匹配

### 表达融合

```
backend/embodied/companion/expression/
└── expression_fusion.py
```

- 输入：情绪状态 + 感知批准事件 + 任务结果
- 规则：感知批准 → 表达含感知参考（"我注意到..."）；情绪高 → 热情叠加
- 输出：{style, tone, content_hint, reason, confidence}

### 行动预览

```
backend/embodied/companion/perception/
└── action_preview.py
```

- 感知帧 → 行动建议（路由 target + action_allowed 检查）
- 建议含：目标/理由/风险/需确认标记
- 禁止：自动执行（返回 preview 供上层/用户确认）

## 6. 开发要求

### 必须

- 语义纯规则（TF 余弦，可解释，禁 NN/LLM）
- 表达融合不修改人格/情绪（只读融合）
- 行动预览不自动执行（Preview ≠ Action）
- 配置驱动（`companion_semantics_*` / `companion_expression_*` /
  `perception_*`），禁止魔法数字
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V6.4 及以前 API
- 禁止语义层依赖 LLM/NN
- 禁止行动预览绕过 Permission
- 禁止跨层调用 / 静默吞异常 / 临时方案
