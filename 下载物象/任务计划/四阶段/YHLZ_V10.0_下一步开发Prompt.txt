## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"认知综合"

V9.5 打通了元认知反馈，但认知还是会话级的：
1. **元认知无持久化**（监控/记忆/审计内存驻留）
2. **错误模式不学习**（重复错误只统计，不生成预防策略）
3. **评价为关键词级**（无深度推理分析）
4. **元认知与成长分离**（策略优化未进入成长闭环）

V10.0 四主线：
1. **元认知持久化**：cognition_state 快照域（监控/记忆/审计可恢复）
2. **错误模式学习**：重复错误 → 预防策略建议（经宪法）
3. **评价语义化**：深度推理分析（依据链/矛盾检测增强）
4. **元认知-成长联动**：验证过的策略优化 → 成长建议（经审批）

### 为什么不做（V10.0 明确不包含）

- 不做 LLM 核心（纯规则保持）
- 不做自动应用成长（growth_auto_apply 保持 false）
- 不做云端成为核心（身份/记忆/安全永远本地）
- 不做无约束自主（元认知永远受宪法/防谵妄约束）

## 6. 开发要求

### 必须

- 错误学习只出建议不越权（经宪法）
- 元认知-成长联动经审批（不自动应用）
- 评价语义化可解释（依据链）
- 配置驱动（`companion_meta_cognition_*` 前缀）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V9.5 及以前 API
- 禁止自动应用成长（growth_auto_apply 恒 false 语义）
- 禁止云端结果直接改变身份（宪法验证铁律保持）
- 禁止跨层调用 / 静默吞异常 / 黑盒 / 临时方案
