## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"具身伙伴层"

V6.8 打通了智能调度（知道任务该在哪里算），但 YHLZ 仍无"身体"：
1. **无虚拟形象表达**（表情/动作/姿态无法承载情绪与人格）
2. **HIL 未接真实模型**（全部 Mock，无真实云端推理）
3. **HIL 未接感知任务**（摄像头实时分析/语音情绪理解未走调度）

V7.0 三主线：
1. **虚拟形象表达层**：表情/动作状态机 → 情绪/人格 → 形象状态
   （不依赖 GPU 渲染，状态驱动 + WebSocket 推流）
2. **HIL 接真实模型**：真实 Adapter 注入（OpenAI/Claude/Gemini/
   本地模型），Mock ↔ Real 双模式
3. **感知-调度联动**：视觉/语音任务自动走 HIL 路由（摄像头→本地，
   情绪理解→混合）

### 为什么不做（V7.0 明确不包含）

- 不做 3D 渲染引擎（LLM 不做，GPU 渲染不做）
- 不做自动应用成长（growth_auto_apply 保持 false）
- 不做云端成为核心（身份/记忆/安全永远本地）
- 不做多智能体协作调度（V8 Constitution Engine 前）

## 3. 本版本目标

**V7.0 Embodied AI Partner**

1. **虚拟形象表达层** `companion/embodied_presence/`

3. **感知-调度联动**
   - 视觉任务 → HIL 路由（本地实时/云端增强）
   - 语音情绪任务 → HIL 路由（混合）

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 虚拟形象表达层

```
backend/embodied/companion/embodied_presence/
├── presence_state.py      (形象状态: 表情/姿态/强度)
├── presence_mapper.py     (情绪/人格 → 形象状态映射)
├── presence_engine.py     (状态机 + 快照 + 推送接口)
└── presence_audit.py      (形象状态审计)
```

- 纯规则状态机（可解释）
- 情绪经 EmotionEngine 状态 → 映射（不直接改情绪）
- 人格维度参与映射（热情→微笑强度等）

### HIL 真实模型接入

```
backend/embodied/companion/hybrid/cloud/adapters/
├── base.py                (CloudAdapter 接口)
├── openai_adapter.py      (OpenAI 真实)
├── claude_adapter.py      (Claude 真实)
├── gemini_adapter.py      (Gemini 真实)
├── local_adapter.py       (本地模型)
└── mock_adapter.py        (Mock 默认)
```

- ModelEndpoint.handler 注入 Adapter（现有接口不变）
- 真实调用失败 → 降级 Mock（不崩溃）

### 感知-调度联动

- VisionService/PerceptionService 任务入口 → HIL.route → 执行
- 权限模型不变（screen/camera 默认 false）

## 6. 开发要求

### 必须

- 形象表达经状态机（禁止直接改情绪/人格）
- HIL 真实接入双模式（Mock 默认，测试隔离）
- 身份稳定（形象 ≠ 身份，形象可换身份不变）
- 配置驱动（`companion_presence_*` / `companion_hybrid_*` 前缀）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V6.8 及以前 API
- 禁止自动应用成长（growth_auto_apply 恒 false 语义）
- 禁止云端结果直接改变身份/记忆（验证铁律保持）
- 禁止跨层调用 / 静默吞异常 / 黑盒 / 临时方案
