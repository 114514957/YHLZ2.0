## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"认知综合"

V8.5 打通了受治理的创造流程，但创造还是规则级的：
1. **知识图无语义**（概念仅字符串匹配，无相似度/语义关系）
2. **组合逻辑静态**（4 类固定，不随创造记忆反馈学习）
3. **验证为字段级**（不验证假设的合理性/矛盾）
4. **创造与成长分离**（验证过的假设未进入成长闭环）

V9.0 四主线：
1. **知识图语义化**：概念相似度（字符/类别/共现）→ 语义关系
2. **组合逻辑学习**：创造记忆反馈（success/failure）→ 组合偏好
3. **深度验证**：假设矛盾检测（与知识图冲突）+ 反事实检查
4. **创造-成长联动**：验证过的假设 → 成长建议（经审批）

### 为什么不做（V9.0 明确不包含）

- 不做 LLM 核心（纯规则保持）
- 不做自动应用成长（growth_auto_apply 保持 false）
- 不做云端成为核心（身份/记忆/安全永远本地）
- 不做 3D 渲染（表达保持状态机）

## 3. 本版本目标

**V9.0 Cognitive Synthesis**

1. **知识图语义化** `creative_intelligence/semantics.py`
   - 概念相似度（字符重叠/类别/共现关系）
   - 语义关系发现（相似概念合并/关联推荐）
2. **组合逻辑学习** `creative_intelligence/fusion_learning.py`
   - 创造记忆反馈（success/failure）→ 组合逻辑偏好分
   - 组合建议排序（只影响推荐，不越权）
3. **深度验证** `creative_intelligence/deep_validation.py`
   - 假设-知识冲突检测（与知识图矛盾）
   - 反事实检查（假设推翻会怎样）
4. **创造-成长联动**
   - 验证过的假设 → 成长建议（经 growth_cycle 审批）

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 知识图语义化

```
backend/embodied/companion/creative_intelligence/semantics.py
```

- 相似度: 字符重叠率 / 类别相同 / 共同邻居
- 语义关系: 相似概念 → 合并建议 / 关联推荐

### 组合逻辑学习

```
backend/embodied/companion/creative_intelligence/fusion_learning.py
```

- 输入: 创造记忆 (success/failure + fusion_logic)
- 输出: 逻辑偏好分 (每逻辑 0~1) + 推荐排序
- 禁止: 偏好分改变验证结果

### 深度验证

```
backend/embodied/companion/creative_intelligence/deep_validation.py
```

- 假设-知识冲突: 假设关键词 vs 知识图已知关系
- 反事实: 假设为假时的影响评估

### 创造-成长联动

- 验证通过假设 → growth_cycle 建议（经审批铁律）
- 配置开关 (companion_meta_creative_growth_link)

## 6. 开发要求

### 必须

- 语义化纯规则（可解释）
- 组合学习只排序不越权（验证结果不变）
- 深度验证可解释（冲突/反事实 reason）
- 创造-成长联动经审批（不自动应用）
- 配置驱动（`companion_meta_creative_*` 前缀）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 版本断言批量更新用 Python 脚本

### 禁止

- 禁止破坏 V8.5 及以前 API
- 禁止自动应用成长（growth_auto_apply 恒 false 语义）
- 禁止云端结果直接改变身份（宪法验证铁律保持）
- 禁止跨层调用 / 静默吞异常 / 黑盒 / 临时方案
