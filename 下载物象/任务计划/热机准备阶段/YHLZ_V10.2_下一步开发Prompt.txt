## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"Cognitive Optimization"

V10 规划第三阶段目标。热机运行中的认知质量风险：

1. **错误模式不学习**：重复错误只被元认知统计（V9.5），未生成预防策略
2. **策略无评价**：成长/反思产生的策略没有效果评估，无法迭代改进
3. **风险无预警**：错误/失败只在发生后记录，没有前置预测
4. **稳定化后缺闭环**：记忆清理（V10.1）之后，认知质量需要主动优化

热机闭环：健康指标 Cognitive 维度**发现问题**（错误率/修正率）→ 本阶段**解决问题**（错误模式学习/策略评价/风险预测）→ 指标验证效果 → 数据采集持续。

### 为什么不做（V10.2 明确不包含）

- 不做多模态统一（V10.5 Multimodal Experience Layer）
- 不做 LLM 核心（纯规则保持，规则可解释）
- 不做自动应用（策略应用永远需审批）
- 不做记忆清理（V10.1 已完成）

## 3. 本版本目标

**V10.2 Cognitive Optimization（认知优化）**

1. **错误模式学习**：重复错误（≥阈值）→ 预防策略建议（经宪法）
2. **策略评价**：历史策略效果评估（命中率/改善率 → 建议保留/调整/淘汰）
3. **风险预测**：错误/失败前置预警（模式匹配 → 风险提示，不阻断）

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 热机冻结约束

- **既有 API 签名不改**（只允许新增字段/新 API 独立命名）
- 新模块 `companion/cognitive_optimization/`（独立命名）
- 纯增量：在 meta_cognition（V9.5）之上做认知治理，不替换既有引擎

### 认知优化流程

```
Error Input (重复错误)
    ↓
Error Learning   (模式统计 ≥阈值 → 预防策略建议)
    ↓
Strategy Review  (历史策略 → 效果评价 → 建议)
    ↓
Risk Prediction  (当前模式 → 风险预警)
    ↓
Constitution Check (建议经宪法, 不自动应用)
    ↓
Audit + Health Metrics (可追踪 + Cognitive 维度联动)
```

### 关键设计

1. **错误模式学习**：`learn(records)` → 按错误类型/触发聚合，重复 ≥ 阈值 → 预防策略建议 `{pattern, occurrences, suggestion, risk_level}`；建议经宪法，不自动应用
2. **策略评价**：`evaluate_strategies(records)` → 策略命中率/改善率 → 建议保留/调整/淘汰（只建议）
3. **风险预测**：`predict(record)` → 与已知错误模式匹配 → `{risk, level, matched_pattern, reason}`；只预警不阻断
4. **健康指标联动**：`WarmRuntimeHealth` Cognitive 维度加 `optimization` 统计（错误模式数/策略建议数/风险预警数，只读聚合）

## 6. 开发要求

### 必须

- 错误学习/策略建议/风险预警全部可解释（rule/reason，阈值进 config）
- 建议只输出不应用（热机"禁止未验证写入"语义 + Constitution Check）
- 审计全程记录（来源/原因/修改内容/验证结果，热机可追踪铁律）
- 配置驱动（`companion_cognitive_opt_*` 前缀）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 生成式测试纪律（setattr + 闭包默认参数 + 工厂内赋 __name__）
- 版本断言批量更新用 Python 脚本（如涉及）

### 禁止

- 禁止破坏 V9.5 及以前 API（热机冻结）
- 禁止自动应用策略/预防建议（必须显式审批）
- 禁止风险预警阻断执行（只提示不干预）
- 禁止静默吞异常（必须日志）
- 禁止跨层调用（Adapter 不调 Service 等）
- 禁止修改最高原则/核心身份/权限（热机五禁令）
- 禁止未验证写入核心记忆
