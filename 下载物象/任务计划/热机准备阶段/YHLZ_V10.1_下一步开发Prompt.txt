## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"Memory Stabilization"

V10 规划将记忆稳定化列为**热机最高优先级**（Phase1 Prompt §Memory Stabilization Layer）。热机运行中的实际风险：

1. **记忆膨胀**：长期运行下记忆条目持续增长，内存与检索成本上升
2. **重复信息**：同一事实/经验反复写入，污染检索结果（健康指标 Memory 维度可观测）
3. **错误积累**：低价值/错误记录占用存储，稀释有效记忆
4. **无价值数据**：未确认/已过期经验长期驻留（V5.8 教训：经验仅供参考，只有 CONFIRMED 进长期参考）

热机闭环：健康指标**发现问题**（重复率/污染率升高）→ 本阶段**解决问题**（压缩/淘汰/评估/冲突检测）→ 指标验证效果 → 数据采集持续。

### 为什么不做（V10.1 明确不包含）

- 不做认知综合（元认知持久化/错误学习等，V10.2 Cognitive Optimization 再做）
- 不做多模态统一（V10.5 Multimodal Experience Layer）
- 不做自动清理（淘汰必须可审计可解释，禁止静默删除）
- 不做 LLM 核心（纯规则保持，规则可解释）

## 3. 本版本目标

**V10.1 Memory Stabilization（记忆稳定化）**

1. **记忆压缩**：重复信息合并（同触发词/同内容去重 → 合并计数/引用）
2. **记忆淘汰**：无价值数据清理（低价值 + 超龄 + 未确认 → 淘汰候选 + 审计）
3. **权重评估**：重要度动态调整（频率/确认状态/被引用 → 动态权重）
4. **冲突检测**：矛盾记忆标记（同主题正反结论 → 冲突标记 + 治理上报）

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 热机冻结约束

- **既有 API 签名不改**（只允许新增字段/新 API 独立命名）
- 新模块 `companion/memory_stabilization/`（独立命名，与 V6.3 memory 网关区分）
- 纯增量：不替换既有 MemoryIndex/MemoryConsolidation，而是新引擎在既有索引之上做治理

### 记忆稳定化流程（Phase1 Prompt 定义）

```
Memory Input
    ↓
Evaluation    (价值评估: 频率/确认/引用)
    ↓
Classification (保留/压缩/淘汰候选/冲突)
    ↓
Storage       (经既有 memory 网关)
    ↓
Maintenance   (审计 + 健康指标联动)
```

### 关键设计

1. **压缩**：`compress(records)` → 按 trigger 分组，同语义合并，输出 `{kept, merged, merged_from}`
2. **淘汰**：`prune(records)` → 只出**候选**（proposal），执行必须显式调用；每笔记录审计
3. **权重评估**：`evaluate(record, context)` → 动态重要度（frequency/confirmed/referenced 加权），可解释 rule/reason
4. **冲突检测**：`detect_conflicts(records)` → 同主题相反结论标记，经宪法上报不自动删
5. **健康指标联动**：稳定化统计接入 `WarmRuntimeHealth` Memory 维度（只读聚合，不破坏冻结）

## 5. 开发任务

### P0（必须）

1. `memory_stabilization/` 模块（压缩/淘汰/权重/冲突四能力，≥400 测试）
2. `MemoryStabilizationError` 分层异常（不跨层）
3. 审计：淘汰/合并/冲突全部记录（可回放）
4. Service API：`companion_memory_stabilize`（压缩+评估+冲突报告）/
   `companion_memory_prune_candidates`（淘汰候选, 不执行）/
   `companion_memory_prune_execute`（显式执行淘汰, 带审计）
5. 配置驱动：`companion_memory_stabilize_*` 前缀（禁重复定义同名配置）

### P1（尽力）

6. 冲突上报 Constitution（不自动解决）
7. 稳定化统计接入健康指标（Memory 维度加 stabilize 统计）

## 6. 开发要求

### 必须

- 压缩/淘汰/冲突全部可解释（rule/reason，禁止魔法数字进业务代码，阈值进 config）
- 淘汰默认只出候选，执行必须显式（热机"禁止未验证写入"语义）
- 审计全程记录（来源/原因/修改内容/验证结果，热机可追踪铁律）
- 配置驱动（`companion_memory_stabilize_*` 前缀）
- 中文 docstring / 类型注解 / RLock / 完整日志 / 测试 CRLF
- 生成式测试纪律（setattr + 闭包默认参数 + 工厂内赋 __name__）
- 版本断言批量更新用 Python 脚本（如涉及）

### 禁止

- 禁止破坏 V9.5 及以前 API（热机冻结）
- 禁止自动删除记忆（淘汰必须显式执行 + 审计）
- 禁止静默吞异常（必须日志）
- 禁止跨层调用（Adapter 不调 Service 等）
- 禁止修改最高原则/核心身份/权限（热机五禁令）
- 禁止未验证写入核心记忆
