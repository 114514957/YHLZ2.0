二、本阶段开发判断

为什么做 Companion Perception & Strategy Integration:
- V5.0~V5.1 建立了内部多 Agent 协同架构 (路由/委派/统计)
- 但专业 Agent 目前是"只读快照"式能力 (observe/report/overview)
- 现实 AI 伙伴需要: 感知→策略的闭环集成,
  专业 Agent 之间传递信息 (感知结果 → 策略建议 → 规划输入)

V5.2 增强方向:
- 感知集成: perception_agent 输出环境状态 → 供其他 Agent 复用 (信息管道)
- 策略集成: experience_agent 输出策略建议 → 供 planning/long_horizon 使用
- Agent 间数据管道: 前序 Agent 结果作为后序 Agent 输入 (顺序依赖, 可解释)
- 感知-策略闭环: 观察环境 → 识别风险/机会 → 生成策略建议 → 规划执行

为什么不做 (本阶段边界):
- 不做跨进程分布式多 Agent (内部单进程)
- 不做 Agent 间自由对话/协商 (确定性管道 + 规则依赖)
- 不做强化学习 / 神经网络 / 黑盒优化
- 不改 Agent Brain / Vision Interface / Memory Interface
- 不控制真实设备 / 机器人 / 自动驾驶
- 不做自我目标生成

五、架构设计要求

分层: Interface → Service → Manager → Storage/Adapter (保持)

增强模块 (companion 包内):
- 新增 companion/pipeline.py: Agent 间数据管道 (前序输出 → 后序输入,
  顺序依赖, 可解释)
- companion/delegate.py 增强: 管道感知委派 (支持依赖顺序执行)
- companion/__init__.py 增强: 感知-策略闭环 (perception → experience →
  planning 管道)

配置项 (全部 backend/config.py, companion_* 前缀, COMPANION_* 环境变量):
- companion_pipeline_enabled (默认 True)
- companion_pipeline_strict (默认 False, 严格模式: 管道输入缺失 → 报错)

数据模型增强:
- CompanionResponse 增加: pipeline (管道执行明细) / pipeline_stages
- PipelineStage: {stage, input_from, output_to, source, target}

API (Service 层新增, 保持 V5.1 兼容):
- companion_pipeline(request)  管道分析 (Agent 依赖顺序, 不执行)
- companion_handle() 增强: 管道感知委派 (返回结构向后兼容)

六、开发任务

P0:
1. Agent 数据管道: 前序 Agent 结果 → 后序 Agent 输入 (顺序依赖)
2. 感知-策略闭环: perception → experience → planning 管道 (端到端)
3. 管道分析: companion_pipeline() (依赖图/执行顺序, 可解释)
4. 管道执行: 带依赖的委派 (前序完成后才执行后序)
5. 单元测试 (新增 >=100 用例, 目标专项 >= 1614)

P1:
6. 管道严格模式: 输入缺失 → 错误标记 (可配置)
7. 管道缓存: 同输入短时窗口复用 (可选, 阈值可配)
8. 闭环统计: 感知-策略-规划全链路耗时/成功率 (扩展 CompanionStats)

七、开发要求

必须:
- 先读后写 / 接口先行 / 配置驱动 / 向后兼容
- 中文注释 (模块/类/函数 docstring) / 类型注解 / 完整日志
- RLock 线程安全 (管道场景注意共享状态)
- 单例 + reset (get_service/reset_service)
- Mock 优先 / 默认测试模式
- 异常分层隔离 (Service 捕获返回结构化错误)
- 无测试不交付 (每功能配单元测试)

禁止:
- 硬编码 (魔法数字/路径/阈值全进 config)
- 跨层调用 (Adapter 不调 Service)
- 临时方案进入主架构
- 静默吞异常
- 破坏 V5.1 既有 API (只新增不修改)
