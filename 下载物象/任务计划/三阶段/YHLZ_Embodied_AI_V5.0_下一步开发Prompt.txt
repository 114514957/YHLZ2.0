二、本阶段开发判断

为什么做 Internal Multi-Agent System:
- V4.0~V4.7 已建立完整单体智能 (感知→推理→经验→策略→规划→长期任务)
- 但所有能力集中在单一 EmbodiedService, 职责耦合
- 现实 AI 伙伴需要分工协作: 每个领域由专业子系统处理,
  但保持一个统一人格 / 一个核心意识 / 一个决策中心

V5.0 引入:
- Main Companion Agent (主伙伴 Agent): 统一人格 / 统一决策中心 / 统一入口
- Specialist Agents (专业 Agent): 按能力域分工 (感知/推理/经验/规划/执行)
- 内部消息路由: 主 Agent 分派任务 → 专业 Agent 处理 → 结果汇总返回

例如:
- 用户问"帮我整理房间" → 主 Agent 理解意图
  → 分派 Long Horizon Agent (任务拆解)
  → 分派 Cross-Goal Agent (子规划)
  → 分派 Strategy Agent (策略选择)
  → 汇总为完整执行方案返回

为什么不做 (本阶段边界):
- 不做跨进程分布式多 Agent (内部多 Agent 在同一进程)
- 不做 Agent 间自由对话/协商 (确定性路由 + 规则分派)
- 不做强化学习 / 神经网络 / 黑盒优化
- 不改 Agent Brain / Vision Interface / Memory Interface
- 不控制真实设备 / 机器人 / 自动驾驶
- 不做自我目标生成

五、架构设计要求

分层: Interface → Service → Manager → Storage/Adapter (保持)

新增模块建议:
- backend/embodied/companion/  (自适应伙伴架构, 新建包)
  - main_agent.py      Main Companion Agent (统一入口/统一人格/决策中心)
  - specialist.py      Specialist Agent 注册中心 (能力域分派)
  - router.py          内部消息路由 (任务 → 专业 Agent, 确定性规则)
  - delegate.py        任务委派与结果汇总 (可解释)
  - __init__.py        门面类 (Service 唯一接入点)

专业 Agent 能力域 (建议, 对接既有模块):
- perception_agent:    感知 (World Model / Observe / Scene)
- reasoning_agent:     推理 (Causal / Prediction / Events)
- experience_agent:    经验 (Policy Table / Strategy Selection)
- planning_agent:      规划 (Cross Goal Planner / Budget)
- long_horizon_agent:  长期任务 (Long Horizon Planner / Milestone)
- governance_agent:    治理 (Strategy Governance / Health)

配置项 (全部 backend/config.py, companion_* 前缀, COMPANION_* 环境变量):
- companion_enabled (默认 False, 权限默认拒绝)
- companion_agent_timeout (默认 10.0)
- companion_route_rule_version (默认 "v1", 路由规则版本)

数据模型:
- CompanionResponse: {request_id, intent, assigned_agents, results,
  aggregated, explainable_reason, mode: rule_based}

API (Service 层新增, 保持 V4.7 兼容):
- companion_handle(request)    主入口: 意图 → 分派 → 汇总
- companion_agents()           专业 Agent 清单 (能力域/状态)
- companion_route(request)     路由分析 (任务 → 专业 Agent)
- companion_dry_run(request)   预演 (不执行, 复用 dry_run 风格)
