二、本阶段开发判断

为什么做 Companion Self-Correction & Learning:
- V5.0~V5.3 建立了完整闭环 (感知-策略-规划-执行-反馈)
- 但反馈仅输出"建议", 未形成"自我修正" (执行失败 → 调整策略 → 再执行)
- 且未沉淀"学习" (失败模式统计 → 经验规则 → 下次避免)
- 现实 AI 伙伴需要: 自我修正 (失败后可解释地调整) + 学习 (从结果沉淀规则)

V5.4 增强方向:
- 自我修正: 执行失败 → 规则驱动调整 (重试/换策略/换目标) → 再执行 (上限内)
- 失败学习: 失败模式统计 (原因/动作/场景) → 更新失败规则表 (可解释)
- 成功学习: 成功模式统计 → 更新成功配方规则 (可解释)
- 修正审计: 每次修正记录 (原因/调整/结果)

为什么不做 (本阶段边界):
- 不做跨进程分布式多 Agent (内部单进程)
- 不做 Agent 间自由对话/协商 (确定性规则 + 修正策略)
- 不做强化学习 / 神经网络 / 黑盒优化 (学习为规则统计)
- 不改 Agent Brain / Vision Interface / Memory Interface
- 不控制真实设备 / 机器人 / 自动驾驶
- 不做自我目标生成

三、本版本目标

YHLZ Embodied AI V5.4
Companion Self-Correction & Learning
伙伴自我修正与学习层

核心目标:

四、本版本不包含 (明确边界)

- 禁止神经网络训练 / 梯度更新 / 黑盒优化 (学习 = 规则统计)
- 禁止自主修改策略内容 (修正只调整执行方式, 内容修改仍来自经验规则)
- 禁止绕过 Permission Layer (执行必须经 Permission)
- 禁止写入 Agent Memory
- 禁止真实设备控制
- 禁止修改 Agent Brain / Vision Interface / Memory Interface
- 禁止自我目标生成
- 禁止跨子系统调用 (只改 Embodied 模块)
- 禁止分布式多进程 Agent (内部单进程)

五、架构设计要求

分层: Interface → Service → Manager → Storage/Adapter (保持)

增强模块 (companion 包内):
- 新增 companion/correction.py: 自我修正器 (失败 → 规则调整 → 再执行,
  上限可配, 可解释)
- 新增 companion/learning.py: 学习器 (失败/成功模式统计 → 规则表, 可解释)
- companion/executor.py 增强: 修正循环 (executor → correction → retry)

配置项 (全部 backend/config.py, companion_* 前缀, COMPANION_* 环境变量):
- companion_correction_max_attempts (默认 3, 修正重试上限)
- companion_learning_enabled (默认 True, 学习开关)
- companion_correction_strict (默认 False, 严格模式: 无法修正 → 报错)

数据模型增强:
- CompanionResponse 增加: correction (修正明细) / learning (学习结果)
- CorrectionRecord: {attempt, reason, adjustment, result}
- LearningRule: {pattern, action, count, last_seen, reason}

API (Service 层新增, 保持 V5.3 兼容):
- companion_correct(request)  自我修正入口 (执行失败 → 调整 → 再执行)
- companion_learning()        学习结果 (失败/成功模式规则表)
- companion_handle() 增强: 修正闭环 (返回结构向后兼容)
