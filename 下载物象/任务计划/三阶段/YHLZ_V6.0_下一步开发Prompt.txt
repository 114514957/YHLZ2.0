## 2. 本阶段开发判断（为什么做这个，不做那个）

### 为什么做"长期成长闭环"

V5.7~V5.9 已经证明：伙伴能够**积累经验 → 验证 → 反思 → 发现机会 → 提出方案**。
但所有关键状态（经历/关系/人格/反思/创造）都是**内存态**，重启即丢失。
没有连续性的伙伴无法形成"长期成长"——这是 V6 的核心主题。

### 为什么不做（V6.0 明确不包含）

- 不做具身化（虚拟形象/视觉/声音/动作）→ V7.x
- 不做情感表示（Emotion Representation）→ V6.1 或 V6.2
- 不做 LLM 驱动创造（保持纯规则可解释）→ 铁律
- 不做自由协商 / 黑盒优化 / 神经网络训练 → 铁律

## 3. 本版本目标

**V6.0 Long-term Growth Companion（长期成长闭环）**

1. **全量持久化**：经历 / 验证状态 / 关系 / 人格调整 / 反思报告 / 创造方案统一 JSONL 持久化与恢复
2. **长期经验组织**：经验分层（活跃/归档）、低价值回收、高价值长期保存、跨会话连续
3. **成长报告**：长期成长轨迹（经验增长曲线 / 反思频次 / 创造转化率 / 关系演化）
4. **连续身份验证**：重启后身份/人格/关系/记忆完整恢复，且核心人格不可变

## 4. 架构设计要求

### 分层铁律（保持）

```
Interface → Service → Manager → Storage / Adapter
```

### 持久化设计

```
backend/embodied/companion/persistence/
├── storage.py          # 统一 JSONL 存储 (原子写 + 校验 + 恢复)
├── snapshot.py         # 全量快照 (version + state + checksum)
├── restore.py          # 恢复 (校验版本兼容 + 降级策略)
└── persistence_audit.py# 持久化审计
```

- 所有子系统状态经 `persistence/storage.py` 统一读写（禁止各模块自写文件）
- 路径配置 `companion_persistence_path`（默认空=不持久化，显式配置开启）
- 保存格式 JSONL + 每条含 `schema_version`
- 恢复时版本不兼容 → 跳过并记录（不崩溃）

### 长期经验组织

```
backend/embodied/companion/experience/
└── experience_lifecycle.py   # 经验生命周期: 活跃 → 冷数据 → 归档 → 回收
```

- 活跃经验：近期 + 高价值（参与创造/反思）
- 冷数据：超期低访问（不参与，但可查）
- 归档：高价值但低频（压缩保留）
- 回收：低价值超期（删除, 记录审计）

### 成长报告

```
backend/embodied/companion/growth/
├── growth_tracker.py     # 成长指标采集 (经验/反思/创造/关系/验证)
├── growth_report.py      # 长期成长报告生成
└── growth_trend.py       # 趋势分析 (按天/周/月)
```

### 配置（全部进 config.py，companion_persistence_* / companion_growth_* 前缀）

- `companion_persistence_enabled` / `companion_persistence_path`
- `companion_persistence_snapshot_max` / `companion_persistence_schema_version`
- `companion_experience_archive_days` / `companion_experience_recycle_value`
- `companion_growth_window_days` / `companion_growth_enabled`

## 6. 开发要求

### 必须

- 全部配置进 config.py（环境变量 + 默认值），禁止魔法数字
- 持久化默认关闭（`companion_persistence_enabled=false`），显式开启
- 恢复失败不崩溃（跳过 + 日志 + 审计）
- 新模块带 `companion_*` 前缀 property 命名（禁止与 API 方法同名）
- 中文 docstring / 类型注解 / RLock / 完整日志
- Mock 优先：持久化用临时目录测试，无真实路径依赖
- 版本断言批量更新用 Python 脚本（UTF-8，禁止 PowerShell 写中文文件）
- 测试文件 CRLF 行尾

### 禁止

- 禁止破坏 V5.9 及以前 API（向后兼容测试必须全绿）
- 禁止跨层调用（Adapter 不调 Service）
- 禁止静默吞异常（必须日志）
- 禁止修改核心人格 / 自主改变目标 / 自主执行高风险行为
- 禁止 NN 训练 / 黑盒 / 临时方案进主架构

- **持久化**：保存 → 新实例加载 → 经历/验证/关系/人格/反思/方案完整恢复

- 新增 ≥250 用例（专项 ≥3038）
