二、本阶段开发判断

为什么做 Cross-Goal Strategic Planning:
- V4.5 已让 AI 能"管理策略体系" (单策略维度的治理与进化)
- 但策略选择仍是"单目标独立决策": 每个 goal 独立调度最佳策略
- 现实任务是多目标/多步/资源受限: 需要跨目标统筹

例如:
- 同一场景同时多个 pick 目标 → 批量规划优于逐个执行
- 一次扫描 (scan) 可为多个后续目标提供共享信息 → 前置一次扫描更优
- 多个策略共享同一资源 (动作数上限 / 步骤预算) → 需按优先级分配

V4.6 让 AI 从"管理策略体系"进入"跨目标战略规划":
- 多目标分组与排序 (目标间依赖/共享资源识别)
- 跨目标策略复用 (一次决策惠及多目标)
- 步骤预算分配 (max_steps 跨目标统筹, 可解释优先级)

为什么不做 (本阶段边界):
- 不做端到端自动执行编排 (仍是规则 + 统计 + 阈值)
- 不做强化学习 / 神经网络 / 黑盒优化 (保持纯规则可解释)
- 不改 Agent Brain / Vision Interface / Memory Interface
- 不控制真实设备 / 机器人 / 自动驾驶

- 禁止绕过 Permission Layer
- 禁止写入 Agent Memory
- 禁止真实设备控制
- 禁止修改 Agent Brain / Vision Interface / Memory Interface
- 禁止自我目标生成 (目标仍由外部提供)
- 禁止跨子系统调用 (只改 Embodied 模块)

五、架构设计要求

分层: Interface → Service → Manager → Storage/Adapter (保持)
治理动作只影响: 策略表 → 审计日志 → 体系快照
新增模块建议:
- backend/embodied/planning/  (跨目标规划层, 新建包)
  - cross_goal.py    跨目标规划器 (分组/排序/预算分配)
  - dependency.py    目标依赖与共享资源分析
  - budget.py        步骤预算分配 (可解释优先级)
  - __init__.py      门面类 (Service 唯一接入点)
- backend/embodied/governance/ 保持 V4.5 不变 (只读扩展)

配置项 (全部 backend/config.py, embodied_* 前缀, EMBODIED_* 环境变量):
- embodied_planning_enabled (默认 False, 权限默认拒绝)
- embodied_planning_max_budget / embodied_planning_min_shared_gain 等

数据模型:
- CrossGoalPlan: {plan_id, goals, groups, shared_steps, budget_allocation,
  explainable_reason, mode: rule_based}

API (Service 层新增, 保持 V4.5 兼容):
- cross_goal_plan(goals, budget)     跨目标规划主入口
- cross_goal_groups()                目标分组分析
- cross_goal_budget()                预算分配
- cross_goal_dry_run()               预演 (复用 V4.5 dry_run 风格)

六、开发任务

P0:
1. 目标分组分析: 同场景/同目标类型/共享动作序列 → 可合并组
2. 共享步骤识别: 多个目标可复用的前置步骤 (如 scan) → 一次执行
3. 预算分配: 跨目标 max_steps 统筹, 按策略质量/优先级排序 (可解释)
4. cross_goal_plan() 主入口 + 输出可解释规划
5. 单元测试 (新增 >=60 用例, 目标专项 >= 1138)

P1:

七、开发要求

必须:
- 先读后写 / 接口先行 / 配置驱动 / 向后兼容
- 中文注释 (模块/类/函数 docstring) / 类型注解 / 完整日志
- RLock 线程安全 / 单例 + reset (get_service/reset_service)
- Mock 与真实双模式 / 默认测试模式
- 异常分层隔离 (Service 捕获返回结构化错误)
- 无测试不交付 (每功能配单元测试)

禁止:
- 硬编码 (魔法数字/路径/阈值全进 config)
- 跨层调用 (Adapter 不调 Service)
- 临时方案进入主架构
- 静默吞异常
- 破坏 V4.5 既有 API (只新增不修改)
