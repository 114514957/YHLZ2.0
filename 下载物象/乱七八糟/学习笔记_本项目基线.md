========================================================================
YHLZ 2.0 本项目现状基线（清理后2026-07-31记录）
=======================================================================
定位: 桌面AI语音助手"元亨" - 云端大脑+本地轻量感官
技术栈: Python + FastAPI后端(端口8000) + Flask WebUI(端口5000)
        + PyQt5桌宠 + Live2D + VTS + Edge-TTS
核心: LLM(DeepSeek/通义千问API) + ASR(Qwen3-ASR-1.7B/SenseVoice/
      Whisper) + TTS(Edge-TTS在线) + VAD(Silero) + 五维能力模块

==========================================================
一、后端架构 (backend/)
==========================================================
backend/main.py 主入口 (FastAPI):
- lifespan启动: 模块管理模式, 按需加载ASR, 注册GPU资源管理器(错峰运行)
- CompressedWebSocket: zlib压缩, 512字节阈值, 压缩统计
- 音频播放线程 _audio_player_loop: 累积2秒音频->sd.play()播放,
  每0.1秒计算口型数值->sync_manager.record_event('mouth_sync')
  (基于音频RMS计算mouth_open, 但无音频则复位0)
- API: /chat(SSE流式) /transcribe /synthesize /synthesize/stream
  /interrupt /clear-history /tools(智能工具) /personality(性格)
  /memory(记忆库+誓约+情景+关联) /sandbox(白名单) /live2d /modules
- /chat 流程: 智能工具决策(smart_tool_manager) -> 上下文 ->
  LLM流式 -> 文本队列 -> TTS流式合成 -> audio_buffer -> 播放线程
- TTS生产者: 累积>=12字符或6字符+标点才合成(降低延迟)

config.py: .env配置, API_PROVIDER(deepseek/dashscope), ASR模型选择,
  FP16/KV缓存/错峰运行开关, 上下文8000tokens

引擎模块:
- asr_engine.py / asr_engine_qwen.py: 多引擎
- tts_engine.py: Edge-TTS (stream_synthesize_text流式)
- llm_engine.py: DeepSeek/通义API (generate_stream/generate_stream_with_image)
- vad_engine.py: Silero VAD
- audio_buffer.py: 音频缓冲+口型计算(calculate_mouth_open)
- echo_cancellation.py / noise_suppression.py: 回声消除/降噪
- gpu_manager.py: GPU显存管理+错峰调度
- conversation_manager.py: 连续对话(ASR+LLM+TTS+VAD管线)
- context_manager.py: 上下文+性格+记忆
- memory.py / memory_v2.py: 记忆库(分类/重要性/关联/誓约/情景)
- cognitive_engine.py: 认知引擎
- vision_engine.py: 屏幕/摄像头捕获+VL模型分析
- vts_client.py: VTS(虚拟主播软件)客户端, AUTH_TOKEN_FILE
- voice_clone_engine.py: 声音克隆
- sync_manager.py: 多模态同步(口型事件记录)
- tools.py / sandbox.py / smart_tool_manager.py: 工具+沙盒
- plugin_manager.py / plugin_sdk.py: 插件系统(plugins/目录4类插件)
- batch_processor.py / bilibili_client.py: 批处理/B站客户端
- personality.py: 性格设定

==========================================================
二、桌宠/虚拟形象
==========================================================
- avatar_main.py: Windows API分层窗口(透明+拖拽+缩放+托盘)

  (端口18765), 口型同步(音频RMS->Live2D参数)
- desktop_avatar.py: 另一版PyQt桌宠+Live2DRenderer

- live2d_desktop_avatar.py: QWebEngineView加载HTML查看器版

- gui_main.py / gui_simple.py / main_gui.py / gui_floating_ball.py:
  GUI聊天界面/悬浮球
- desktop_avatar/ (Node.js版桌宠: main.js/pet.html/preload.js)

==========================================================
四、当前已知可优化点(对比NEKO/NachoBot之前自我审视)
==========================================================
1. 口型同步: 基于0.1秒音频chunk的RMS, 相对粗糙
   - 无LIPSYNC参数保护(表情/动作会覆盖口型)
   - 无差分淡出/参数基线快照
2. TTS: 仅Edge-TTS单引擎, 无多服务商抽象/回退/情绪音色映射
3. 说话: 无"首段音频就绪即开口"的零等待流式(有累积2秒策略)
4. 主动陪伴: 有screen_monitor插件, 但无活动状态机/话题源权重/防复读
5. 记忆: 有关联/誓约/情景, 无事实抽取/反思综合/遗忘衰减
6. 无情绪引擎(外显表情+内隐用户情绪追踪)
7. 桌宠与后端通过HTTP/WS通信, 无版本化协议边界/心跳PING/PONG
8. 插件系统已有, 但无SDK生态/角色卡导出
