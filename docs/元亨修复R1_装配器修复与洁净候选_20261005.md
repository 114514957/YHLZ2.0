# 元亨修复 R1：训练装配器修复与洁净数据候选

日期：2026-10-05 晚。接 Codex《人格偏移复核与修复建议》R1 节点「修装配器角色映射、保留对话问题和承接；筛重复/故事/旧边界 → 洁净数据候选、逐条改动清单」。**本文件未训练、未替换 v8 训练包、未改生产。**

## 1. 根因（代码级）

`tools/finetune_assemble.py::_to_messages`（修复前）：

```python
if role == "元亨": who = "assistant"
elif role in USER_ROLES:  # ("老爹","陌生人","朋友","群友")
    who = "user"
else:
    continue  # ← 利贞等在场角色被整句丢弃
```

- 素材 `docs/素材/对话样本.md` 共 1993 个场景块，**1954 块含利贞**（利贞发言 3232 人次，占全部发言约 32%）。
- 被丢的通常是利贞的**提问**，于是「元亨答1 →（利贞问2被丢）→ 元亨答2」在导出后变成**相邻 assistant**；场景开头若为利贞问，则导出以 assistant 开头。
- 另：`_block_turns` 只保留说话人、丢弃「问/答」标记；未知角色直接跳过。

**实测（v8 全量 4047 条）：相邻 assistant 1180 条、以 assistant 开头 1222 条（其中多数由丢问造成）、利贞 user 上下文仅 238 条。**

## 2. 修复内容（tools/finetune_assemble.py）

1. **保留在场角色**：未列名角色（含利贞）一律转为 `user` 并带 `角色：` 前缀；仅 元亨→assistant、老爹→user（无前缀）。不再丢弃任何有内容的发言。
2. **同角色相邻合并**：相邻 user 与相邻 assistant 都在同一消息内合并（消除相邻 assistant 结构缺陷；真实连续双元亨发言合并为一条）。
3. **`--repair-repeats`**：修复同一消息内相邻重复段（≥20 字，循环 4 次），本批修复 **1 处**（即已知的第 20 行 164 字复读）。
4. **`quality_gates` 统计门禁**：装配完成后输出 `adjacent_assistant / leading_assistant / lizhen_user_turns / repeat_repairs`，杜绝"JSON 合法=格式合格"。
