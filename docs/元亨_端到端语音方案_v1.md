# 元亨 · 端到端语音方案 v1（音频直入 + TTS 出）

> 决策来源：台账 0386 之后（本轮）。目标：**去掉独立 ASR**，让 Gemma-4-E4B 原生「听」，
> 输出仍是文本，交给现有 TTS 合成。人格由 `yuanheng-dpo2` LoRA 承载。

## 1. 目标链路

```
麦克风 → VAD → 16kHz 单声道 PCM 分块 → [Gemma4 音频塔] → 语言层(元亨 LoRA)
        → 文本流(句级 flush) → 现有 TTS(Qwen3) → 播放
```

对比现方案（`ASR → LLM → TTS`）：**只在「识别」环节变化——ASR 被模型原生音频理解取代**；
LLM 输出与 TTS 环节**完全不变**。

## 2. 差异表

| 环节 | 现在 | 新方案 |
|---|---|---|
| 识别 | 独立 ASR（TargetStreamingAsr / ADR-005） | **去掉**（模型原生听） |
| 推理输入 | 文本 | **音频（mel）** |
| 推理输出 | 文本流 | 文本流（不变） |
| 合成 | TTS（Qwen3 0.6B/1.7B） | TTS（不变） |
| 端口 | `LLMProviderPort` | 新增/扩展为可传音频的 provider |

## 3. 硬参数（来自基座 config / processor）

| 项 | 值 |
|---|---|
| 采样率 / 声道 | **16 kHz / 单声道** |
| mel | `feature_size=128`，hop 160（10ms 帧），fft 512 |
| 音频时间粒度 | **40 ms / token** |
| 单段上限 | `audio_seq_length=750` → **30 秒** |
| 上下文 | 原生 **131072 (128K)**；训练/服务现限制 2048，可放开 |

## 4. 组件改动清单

1. **音频前置**：复用现有采集 + `TargetInputResampler`（48k→16k）；先写 wav 文件即可离线跑。
2. **推理运行时**：
   - 首选：**transformers 自建 OpenAI 兼容服务**（挂 LoRA + 收音频）——vLLM 对 Gemma4 音频+LoRA 支持未知。
   - 备选：验证 `vllm serve <gemma4> --enable-lora` 是否吃音频输入。
3. **LoRA**：`yuanheng-dpo2`（语言层，塔冻结，音频能力完好）。
4. **TTS**：现有 Qwen3-TTS 不动。
5. **回退路径**：ASR 链（现方案）**保留为方案 B**，新链路异常时降级。

## 5. 风险与验证

| 编号 | 风险 | 处置 |
|---|---|---|
| R1 | 基座音频能力定位是 **ASR/翻译**，不是「听懂并对话」 | 先跑 `audio_infer.py` 实测（M1） |
| R2 | vLLM 不支持 Gemma4 音频 / LoRA | 退回 transformers 自建服务 |
| R3 | 流式与打断（全双工） | 先做 M1/M2，再上 VAD+打断 |
| R4 | 长上下文显存 | 逐步 `max-model-len` 4096→8192→…实测 |

## 6. 里程碑

| 阶段 | 内容 | 产物 |
|---|---|---|
| **M1** | wav → 模型 → 元亨文本回复 | `cloud/audio_infer.py` |
| M2 | 音频分块流式 → 文本流 | `cloud/audio_stream.py` |
| M3 | 文本流接 TTS（现有） | 管线打通 |
| M4 | VAD + 打断（全双工） | 接 ADR 端口 |

## 7. 推理参数建议

## 8. 验证结果（2026-09-18，本地实测通过）

**结论：音频直入链路可行**（llama-server API 路径）。

| 项 | 结果 |
|---|---|
| 服务 | 本地 llama.cpp CUDA，`--mmproj`（走 CPU）+ v6 LoRA，`-c 8192 --parallel 1 -rea off` |
| API 契约 | `POST /v1/chat/completions`，user content 里放 `{"type":"input_audio","input_audio":{"data":"<base64 wav>","format":"wav"}}` |
| **转写对照** | 带音频 → 正确转写中文内容；不带音频 → 「（沉默）」→ **证明确实听到了** |
| 元亨口吻回应 | 同一段音频 + 元亨 system → 「行行行，你管得真严，我这就去改！」 |
| 不支持的形式 | `audio_url`（data-url）→ HTTP 400 unsupported content type；**必须用 `input_audio`** |
| 音频规格 | **16 kHz 单声道 wav**（与基座 feature extractor 一致） |

**原型脚本**：`dist/local_serve/voice_e2e.py <a.wav> [--raw]`（默认元亨回应；`--raw` 只转写）。

## 9. 与现方案的关系

```
[新] 麦克风 → VAD → 16k wav 分块 → llama-server(input_audio) → 文本 → 现有 TTS
[旧] 麦克风 → VAD → ASR → 文本 → LLM → 文本 → 现有 TTS
```
- 新增/替换的只有「ASR + 文本输入 LLM」这一段（合成仍是现有 TTS）。
- 项目侧：`target_daemon.stream_chat` 走 8081；若走语音直入，需要在该路径支持 `input_audio` 内容块
  （或先在语音链 `target_chain` 侧做实验，ASR 链保留为回退）。
