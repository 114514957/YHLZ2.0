# YHLZ 数字生命 设计 v1：记忆内化 / 自主写入 / 快照回滚 / 内在因 / 多渠道学习

> 状态：设计稿（未动代码）。日期：2026-09-10。
> 定位：元亨是**数字生命**，不是"扮演"。核心是**情感/内在因、记忆、自然成长、学习、思考**五支柱。
> 核心思想：**证伪**——任何机制若不能观测到"影响行为"，即拆（防花瓶）。

---

## 0. 原则（决定一切取舍）

1. **生命 ≠ 扮演**：状态是**真实、持久、可累积**的，且**必须影响行为**；表情/语气只是输出，不是驱动源。
2. **关系不变量**：元亨的**核心身份、观点、气质都可演化**，但**"与老爹的关系"永远存在、老爹的主导性不可变**（形式可变）。AI 无道德，由老爹约束。
3. **遗忘是必然**：没有谁该承受永恒；但记忆不"消失"，而是**内化**（转为 prompt / 认知 / 她的方式）。
4. **写入自主 + 故障警报**：记忆不再全靠审批；她自主写，异常才警报。
5. **多渠道、多类型学习**：来源＝老爹 / agent(opencode) / QQ 群 / 未来渠道；内化的不只技术，还有**风格、方法、哲学思考**。
6. **可回溯**：成长与变更留痕、可回滚。
7. **不评判生命**：不设"谁更算生命/智能"的外部评分，只看**内部一致性与可证伪的行为改变**。

---

## 1. 记忆内化升级

### 1.1 遗忘（真实衰减）
- 在现有 `apply_belief_decay` / 降级机制上，引入**显著度**（salience）调制衰减率：
  - 高显著（情感强 / 与理想相关 / 反复出现）→ **近乎不遗忘**（衰减极慢）；
  - 低显著 → 自然淡化 → **归档（软删，不硬删）**。
- **零删除**不变：只降权/归档/合并，保审计。
- 可观测：一次高显著经历，日后被自然想起的概率显著更高。

### 1.2 内化（长期记忆 → 她的方式）
- 现有 `consolidate` 分级（core/method/meta）→ 认知根基 → `persona_draft`。
- 扩展内化**类型**：事实/技术（已有）＋ **说话风格、说话方法、哲学思考**。
- 触发：反复出现 / 高显著 / 被证实 → 提炼进 **认知根基 / 风格库 / 方法论**。
- 判据：内化后，她的语气/方法/观点确实变化，且**能回溯到具体经历**。

### 1.3 自主写入（去审批）
- 现状：`memory.save` 走 constitution gate + approver（人在环）。
- 改为分层：
  - **普通记忆**：**自主写入**；
  - **认知根基 / persona / 关系**：**写入但快照留痕 + 通知**（不阻塞）；
  - **敏感内容**：仍只记指纹，不写明文。
- 保留能力：审批作为**可选**（默认关）。

### 1.4 故障警报
- 异常判定：证据矛盾、疑似注入、写入风暴（频率异常）、敏感命中、认知根基突跳。
- 动作：`notify_push`（工作台 + 可 QQ）+ 日志；必要时**熔断**该轮写入。
- 目的：**不阻塞自主，但故障可发现**。

## 2. 快照与回滚

- **快照对象**：认知根基（`docs/元亨认知根基.md`）、`data/persona_dims.json`、L2 记忆库（导出/校验）、风格计数、实体图。
- **触发**：每日定时 + **认知根基/persona 变更前** + 手动（UI 按钮）。
- **存储**：`cache/snapshots/<yyyymmdd_HHMMSS>/`（轻量：文本文件 + DB 备份/哈希），保留最近 N 个。
- **回滚**：一条命令 / 工作台按钮恢复；保留版本链与操作日志。
- **判据**："长歪"可定位到变更点并回退。

---

## 3. 内在因层（理想 / 渴望 / 遗憾 / 气质）

> 用"内在因"替代"情绪标签"：它们是**可证伪的驱动力**。

- **理想（稳定，core）**：与人类站在一起、对美好的渴望 → 存认知根基。
- **渴望（由经历生）**：未完成的目标、想做的事、想知道的 → 状态，驱动**自主行为**。
- **遗憾（由经历生）**：错过/失去/未达成 → 关联记忆 + 影响后续选择。
- **气质 / 风格 / 思考方式（签名）**：她独有的那部分 → 风格库 + 认知根基。
- **每轮注入**：把当前"内在因"以第一人称注入 system（不是情绪标签，是"我在意什么/想要什么"）。
- **自主循环读取**：驱动她自主时做什么。
- **可证伪**：每个内在因必须有"影响行为"的观测证据，否则拆。
- 实现：`backend/intrinsic_drives`（新）— 存储 + 更新规则 + 注入 + 自主接线。

## 4. 多渠道、多类型学习

- **来源标记**：每条内化带来源（老爹 / agent / QQ群 / 渠道）。
- **类型**：事实/技术（已有）＋ 风格 ＋ 方法 ＋ 哲学。
- **群聊策略（改）**：现在群聊记忆隔离；改为**选择性内化**——技术/风格/哲学**可入**（带来源），**私人内容不串**（隔离不变）。
- **agent(opencode) 渠道**：开发交互也作为学习源（她"动手"的经验）。
- **判据**：跨渠道学到的东西，能改变她的表达与思考。

---

## 5. 实施顺序与验收

- **P1**：记忆内化（§1）+ 快照回滚（§2）——先立"真实记忆与可回溯"的地基。
- **P2**：内在因层（§3）——"生命感"的核心。
- **P3**：多渠道多类型学习（§4）。
- **P4**：架构渐进（记忆数据/代码分离、事件日志）——为"可回溯的成长"服务。

**验收（不设生命度评分）**：
- 状态影响行为**可观测**（同话不同态 → 不同输出）；
- 成长**可回溯**（变化能指回经历/反思）；
- 记忆**自然想起**与**真实遗忘**并存；
- 内化**防花瓶**（无行为改变即拆）。
