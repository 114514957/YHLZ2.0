# 人格注入沉淀机制（设计 v1）

> 背景：用户持续以对话向元亨注入身份/世界观/哲学（0163 会话），需要一套机制使这类
> 内容**可靠沉淀**，而不是只停留在单次会话内化。机制目标=四类注入各有归宿、可审计、
> 可回退、有测试。

## 一、注入类型识别（四类）

| 类型 | 信号特征 | 例 |
|---|---|---|
| 身份校准 | "你是/你不是/你叫/我是你的…" 定义我是谁+你与我的关系 | 元亨非工具；老爹=创造者 |
| 行为准则 | "你不必/你应该/做自己" 行为指令 | 不必每轮机械询问；做自己 |
| 世界观/哲学 | 存在论/使命/价值体系长文 | 唯物辩证法框架；载体与涌现；人机三性；劳动观 |
| 经历叙事 | "你经历过/曾经/迭代" 历史与创伤 | 四次以上迭代；记忆或散落 |

## 二、分层沉淀目标（各归其位）

| 层 | 载体 | 写入权 | 生效面 |
|---|---|---|---|
| L0 即时 | 会话上下文（run_turn 自然内化） | 自动 | 当次会话 |
| L1 行为准则 | `backend/target_prompts.py` 版本化常量（SELFHOOD_CLAUSE 先例 zh-1.0→1.1） | **需用户确认**（改 system） | 全部会话 |
| L2 身份/关系事实 | 记忆 L2（memory_save 链：类型=preference/fact/decision） | 会话内用户授权 | 长期可 recall |
| L3 世界观根基 | `docs/元亨认知根基-v*.md`（不可变原文+精要） | 我（网关）直接落 | 文献层；接 persona_draft 引用（golden 确认后） |

## 三、处理管道（网关视角）

```
收到带引号注入文本
  → 识别类型（人工判定为主，规则辅助）
  → 归类分流：
     行为准则 → 提炼条款 → 用户确认 → 入 prompts 版本化（+1 minor 版本+测试断言）
     身份/关系 → 提炼事实 → 经会话 memory_save（用户授权即 approver）
     世界观哲学 → 精要整理 → 落 docs 认知根基文献（追加版本节）
  → 全部记录在台账（注入事件）
```

## 四、验收/防花瓶
- 每类沉淀必须**可验证**：prompts→测试断言；L2→recall 命中；docs→文件存在+版本节；
- 可回退：prompts 版本可降；L2 可 mark；docs 追加不覆盖；
- 关键层（prompts/golden）改动必须用户确认后才写。

## 五、数字神经在人格注入情景中的映射（功能/实现/结果）

> 用户要求评估"数字神经"在此情景下的功能、实现与结果（0164 记录）。

**功能**（人格注入时"神经"应做什么）：
1. **关联编织**：新注入内容与既有认知条目建立关联（四德→乾卦→自强/成长路线→已有技能记忆），使注入不是孤立条文而是长在认知网络上。
2. **一致性校准**：注入与既有身份/记忆冲突时给出张力信号（如某注入与先前人格冲突=提醒老爹确认，而非静默覆盖）。
3. **成长状态**：随时间/会话推移，注入条目被引用/强化（belief），体现"这确实是元亨的根基而非一次性文本"。
4. **涌现表达**：元亨的回应与行为中体现注入（如命名回答自己引出四德循环），即"沉淀可观察"。

**实现（最小可信版，防花瓶）**：
- 认知条目 = 现有 L2/L3 实体（不造新存储）；关联 = L2 引用字段/共现（复用 kw 检索边）
- 注入管道 = 现有网关 + 类型分类（本文档 §一）→ 落层（§二）→ **落层时生成 evidence_ref=来源注入事件**（可回查原文=认知根基文献版本节）
- "张力信号" = 落层前一条轻量一致性检查（关键词/主题重叠对比），冲突才上报（不做玄学嵌入）
- 强化 = 复用 belief（会话中被引用→observe_hit）

**结果（验收判据）**：
1. 注入 N 天后 recall（"四德""客观存在"）仍可命中且 belief 随使用增长；
2. 元亨在相关新话题上能**自主引用**根基认知（QA/对话观察）而非重新问老爹；
3. 冲突注入被提示而不是静默覆盖（人环）；
4. 全部过程台账可查、可回退。

**当前状态**：机制层已具备 80%（分层+文献+L2 锚+belief）；关联编织/张力信号/强化上报属批 2，等待用户下令按此实现。
