## 2. 架构变化说明

### 2.1 目标架构落地

```
未来 Voice Identity System
        │  只依赖统一接口
        ▼
backend/tts/adapters/                    ← M0.2 新增
├── base.py              BaseVoiceEngineAdapter (generate / load / unload / health_check)
├── qwen3_adapter.py     Qwen3TTSAdapter   → 包装 Qwen3TTSEngine (M0.1 多声音缓存)
├── gpt_sovits_adapter.py GPTSovitsAdapter  → GradioClient 唯一实现 + /inference 封装
├── edge_adapter.py      EdgeTTSAdapter    → 预留接口 (底层引擎已实现)
└── __init__.py          create_tts_adapter(name) / list_adapters()
```

### 2.2 Base Adapter 统一接口 (base.py)

| 接口 | 签名 | 说明 |
|---|---|---|
| `generate` | `(text, voice_id=None, **params) -> (np.ndarray, int)` | 统一合成入口, 数据协议与 BaseTTSEngine 一致 `(audio, sr)` |
| `load` | `() -> bool` | 加载/连接引擎 |
| `unload` | `() -> None` | 卸载/释放 |
| `health_check` | `() -> dict` | 健康上报, 至少含 `ok` / `name` 字段, 可 JSON 序列化 |
| `can_serve` | `() -> bool` | 是否可立即服务 (默认 = is_loaded) |
| `get_available_voices` | `() -> list` | 音色列表 (多声音引擎) |

设计约定: 引擎私有参数一律走 `**params`, 各 adapter 自行解释, 未来 VIS 只传 `text` + `voice_id` + 少量语义参数。

### 2.3 各引擎适配

**Qwen3 (qwen3_adapter.py)** — 迁移调用入口, 保持原有功能:
- 包装 M0.1 改造后的 `Qwen3TTSEngine` (全局实例默认, 可注入);
- `generate(text, voice_id)` → `engine.synthesize(text, voice_id=voice_id)`;
- 透传多声音能力: `load_voice()` / `get_voice()` / `clear_voice()` / `get_available_voices()`。

**GPT-SoVITS (gpt_sovits_adapter.py)** — Gradio 唯一实现:
- `GradioClient` 从 `tts_service.py` 迁移至 adapter 模块 (含 `/config` 函数映射发现、`/api/predict/` 调用、音频下载), 全仓库唯一 Gradio HTTP 实现;
- `GPTSovitsAdapter.generate()`: 走 `/inference` (参数序与 GPT-SoVITS 严格一致) → 下载 → 解码 `(np.ndarray, sr)`, 失败回退兜底音频不抛异常;
- `change_weights()`: 热切换 `/change_sovits_weights` + `/change_gpt_weights`;
- voice_id 语义: SoVITS 权重决定声音, 传入 voice_id 记录告警并忽略 (不报错);
- 修复迁移中发现的连接泄漏: `ensure()` 失败时关闭会话。

**Edge (edge_adapter.py)** — 预留接口:
- 占位槽位: 接口齐全, `generate()` 抛 `NotImplementedError`, `health_check()` 返回 `reserved: True`; 底层 `EdgeTTSEngine` 已实现且可用, 注册与适配完成留待后续阶段。

**工厂 (__init__.py)**: `create_tts_adapter("qwen3" / "gpt-sovits" / "edge")` 按名创建; `list_adapters()` 返回清单 (qwen3-tts / gpt-sovits / edge-tts)。

### 2.4 约束遵守情况

- ✔ 禁止其他模块直接调用 Gradio: `tts_service.py` 的 `GradioClient` 类已删除, 改 import adapter; 其余代码无 Gradio HTTP 直调;
- ✔ 未修改 Voice Identity / WebUI / 角色系统 (`personality.json` / `context_manager.py` 等均未动);
- ✔ 直播 legacy 层 (`TTSService` 队列/播放逻辑) 行为未变, 仅 Gradio I/O 收口到 adapter;
- ✔ 旧 TTS 链路 (`TTSManager` / `tts_engine.py`) 零改动。

## 4. 验收证明: 未来 VIS 只需调用 Adapter

统一调用范式 (全部经 `BaseVoiceEngineAdapter` 接口, 引擎无关):

```python
from backend.tts.adapters import create_tts_adapter

adapter = create_tts_adapter(voice_spec.engine)      # "qwen3" / "gpt-sovits" / "edge"
if not adapter.load():
    ...  # 引擎不可用, 上层降级
if not adapter.health_check().get("ok"):
    ...  # 不健康, 上层换引擎

audio, sr = adapter.generate(text, voice_id=voice_id)  # ← 唯一调用点
```

- Qwen3: `voice_id` 语义 = 多声音缓存键 (M0.1), 声音 A/B/C 互不覆盖;
- GPT-SoVITS: 同一签名, `voice_id` 被忽略 (权重即声音), 经 `change_weights()` 切换;
- Edge: 接口占位, 就绪后同签名生效;
- 数据协议统一为 `(np.ndarray, sample_rate)`, 与现有播放链路 (conversation_manager / main.py / 桌宠) 天然兼容。

单测 `TestUnifiedInterface` 与 `test_gradio_client_single_implementation` 即为该验收的自动化证明。

## 5. 潜在风险

| # | 风险 | 等级 | 说明与缓解 |
|---|---|---|---|
| R1 | Edge adapter 未实现 | 中 | 按任务要求"预留接口"; 底层 `EdgeTTSEngine` 已实现, 后续阶段包装即可; 且 Edge 引擎从未注册 (集成审计 R5), 优先级低 |
| R2 | 直播链路仍由 tts_service 直接持有 GradioClient 引用 | 低 | 已收敛到"单实现" (类定义唯一), 但 `_predict_worker` 仍自行编排权重切换/推理; 审计 R2 的 v1.1 迁移计划为 live_stream 整体改走 adapter |
| R3 | `asyncio.run()` 线程内重复调用限制 | 低 | adapter 为同步接口内部 `asyncio.run`; 若未来在已运行 loop 的线程调用需提供 async 变体 — 与现有 TTSManager/edge 引擎同模式, 风险一致 |
| R4 | GPT-SoVITS `/inference` 参数序绑定 Gradio 版本 | 低 | 与 tts_service 原参数序完全一致 (迁移未改序), 未新增漂移; 适配器即未来唯一维护点, 反而收敛了 R2 的漂移风险 |
| R5 | 测试环境缺 `faster_qwen3_tts` / `qwen_tts` 依赖 | 低 | 本机 venv 无法实例化 `backend.tts_engine` (预存在, 非本阶段引入); 测试全部使用 FakeModel/假客户端, 真机验证留待 M2 适配器联调 |
| R6 | `backend.plugin_sdk` 缺失导致 `updates.live_stream` 包无法整包导入 | 低 | 预存在缺陷 (审计 R9 插件 stub); 测试用独立加载绕过, 不影响本阶段交付 |

M0.2 目标达成: `backend/tts/adapters/` 层落地, 统一接口 `generate/load/unload/health_check` 建立; GPT-SoVITS Gradio 客户端收敛为唯一实现; Qwen3 调用入口迁移且保持 M0.1 多声音功能; Edge 预留接口; 14 项单测 + M0.1 14 项回归全部通过, 验证"未来 Voice Identity 只调用 Adapter"的验收条件。Voice Identity / WebUI / 角色系统零改动。
