- 范围映射 R4；语音冻结；不引重运行时。

## 2. 缺口（R4 要补）

1. **复盘检查点仅内存**：`_last_reviewed` 等重启即从 0 重算 → 节拍漂移/重复或漏复盘。
2. **窗口截断**：`review_once` 只喂 `history[-16:]`；文字轮**无稳定 ID/序号**（仅链式 `history_digest`）。
3. **无复盘 job 队列**：L1 `pending` 管摘要、`MemoryReviewQueue` 管候选，**复盘窗口本身无持久队列/租约**。
4. **非幂等**：`evidence_ref=review:<time.time()>`；重复提交可能重复效果。

## 3. 设计（复用现有机制，不新建同职责存储）

### 3.1 持久检查点（复用 L1 JSON）
- 把 `_last_reviewed`/`_turn_count` 的**已提交水位**写入 L1 JSON（复用现有 `_save_l1`/`_load_l1` 原子写），内存计数降级为缓存。
- 重启后**从已提交水位**续跑；`_summary_pending` 同机制。

### 3.2 稳定消息序号（复用 L1 turns）
- 给 L1 `turns` 每轮加 `seq`（单调递增）+ `msg_id`（`chan+seq` 指纹）；语音轮已有 `voice_id` 对齐。
- 复盘窗口 = `(start_seq, end_seq]` 冻结；截止位置在 job 建立时固定，新消息另建窗口。

### 3.3 复盘 job 队列（复用 MemoryReviewQueue 模式）
- **不新建第三套**：在**同一记忆库**按 `memory_candidates` 的模式新增 `review_jobs` 表（或扩展 candidate 表带 `job_kind`）。字段：
  `job_id, channel, principal_id, session_id, start_seq, end_seq, source_ids, snapshot_hash, state(pending|leased|extracting|adjudicating|committing|done|retry_wait|needs_review), attempts, next_retry_at, last_error_code, lease_owner, lease_epoch, lease_until, result_ref, pipeline_version, idempotency_key, created_at/updated_at/committed_at`。
- 幂等键 = `sha256(channel|principal|session|start_seq|end_seq|pipeline_version)`（**不用纯内容前缀**）。
- 状态流：`pending → leased → extracting → adjudicating → committing → done`；可恢复错误 → `retry_wait`；不可恢复 → `needs_review`。

### 3.4 事务与锁（沿用现有正确做法）
- 模型提炼/裁决**在写事务外**（现有 `adjudicate_async` 已如此，不跨 await 持写锁）。
- 最后**一个短事务**提交：L2 变更 + FTS + 来源关联 + `job=done` + 检查点水位；不同载体时用提交日志/效果键恢复，**不声称跨库原子**。
- 租约：每 owner/session 至多一个有效 lease；`lease_epoch` 递增，旧 worker 返回也不能提交（与 T3 同语义）。

### 3.5 语义规则（复用）
- 偏好改口：新记录 `supersedes_id`，旧记录保留；**当前检索过滤失效版本**。
- 任务状态以**任务载体**为准（记忆只记"用户声称完成"）。
- 群转述**不得升级**为主人事实（保留 `speaker`/`visibility`）。
- L3 认知仍**待审批**，不自动改人格/权限。

## 4. 验收（沿用 R4 目标）
- 24 场景 ×3（明确纠错/时间转变/说话者隔离/长积压≥200条/中途崩溃/空结果与错误/并发与取消/存储权限变化）。
- 机械不变量 100%：来源覆盖、隔离、事务原子、幂等、水位正确；任何跨人泄漏/错误覆盖/丢来源=阻断。
- 崩溃点：提炼后/裁决中/写入前/提交后 ack 前分别终止，重启无重复效果、无水位跳跃。
