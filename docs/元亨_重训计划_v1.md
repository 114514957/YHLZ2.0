# 元亨 · QAT 重训计划 v1（可执行）

> 决策来源：用户选 **A（重训）**，且**保留多模态不裁塔**。
> 目的：① 让 LoRA 与部署基座**同源**（QAT）；② 修掉首训暴露的三个问题。

## 1. 为什么是 QAT（同源链）

| 角色 | 仓库 | 大小 |
|---|---|---|
| **训练基座** | `google/gemma-4-E4B-it-qat-q4_0-unquantized` | 14.82 GB（bf16 可训） |
| **部署基座** | `google/gemma-4-E4B-it-qat-q4_0-gguf` → `gemma-4-E4B_q4_0-it.gguf` | 4.80 GB |
| 多模态 | 同仓库 `gemma-4-E4B-it-mmproj.gguf` | 0.92 GB |
| 备选(vLLM) | `google/gemma-4-E4B-it-qat-w4a16-ct` | 10.75 GB |

**关键**：首训用的是 `google/gemma-4-E4B-it`（非 QAT），与 QAT-Q4 部署基座**权重不同**，LoRA 挂不上 → 必须重训到 QAT 基座。

## 2. 首训暴露的三个问题 → v4 数据对策

| # | 问题 | 现状 | v4 对策 |
|---|---|---|---|
| 1 | **利贞出不了声**（模型只会扮元亨，偶发 `利贞：` 前缀泄漏） | 装配格式把元亨=assistant、其余=user | **改多 persona**：给利贞做 `你是利贞——…` 的 system prompt，把「利贞答」的样本训成利贞=assistant；推理时**切 system prompt 即切人格** |
| 2 | **边界话术薄**（`骂他做什么？` 能挡但单薄） | 边界样本仅 ~10 条 | 边界/拒绝样本补到 **30–40 条**（含诱导、越权、冒充、隐私） |
| 3 | **偏长 / 冒 Markdown** | SFT 长、DPO 治好了 | 数据保持 ≤32 字；**推理侧强制 `-rea off`**（Gemma4 thinking 会输出 `<|channel>thought`） |

## 3. 数据 v4（在现有 1214 条基础上）

1. **新增「利贞 persona」子集**：把对话/故事里**利贞回答**的轮次抽出，配 `利贞 system prompt` 生成独立样本（目标 **150–250 条**）。
2. **边界子集扩充** 到 30–40 条。
3. **元亨子集不变**（1214 条里的大部分）。
4. 命名沿用 `sft_persona_v4_train.jsonl` / `_val.jsonl`（现装配器加 `--tag v4`）。
5. 比例仍控：memory 20%、golden 5–10%。

> 工具现成：`gen_supplement.py`（生成）、`finetune_assemble.py --tag v4`（装配）、`audit_dialogue.py`（闸门）。

## 4. 训练配置（沿用已验证值）

| 项 | SFT | DPO |
|---|---|---|
| 基座 | QAT 未量化（bf16） | 同上 + SFT adapter |
| 精度 | **bf16（`--no-4bit`）** | bf16 |
| LoRA | r16 / α32 / dropout0.05 | 继承 |
| `target_modules` | **regex 限定语言层** `model\.language_model\..*\.(q|k|v|o|gate|up|down)_proj`（Gemma4 塔是 `ClippableLinear`，PEFT 不支持，必须绕开） | 同 |
| 序列 / batch | 2048 / 4 × GA4 | 2048 / 1 × GA8 |
| epoch / lr | 3 / 2e-4 | 1 / **1e-5** |
| ⚠️ DPO β | — | **0.05（v2 最佳；0.1 会过度缩短导致断句）** |
| 偏好对 | — | 400（chosen=数据答案, rejected=基座生成） |

## 5. 执行（云上，已是脚本）

```bash
# 0) 上传 bundle；设 token
export HF_TOKEN=...
# 1) 一条命令跑完（含镜像/依赖/下基座/SFT/DPO/导出）
cd finetune_bundle/cloud && bash run_qat.sh
```
**已知 5 坑脚本里都修好了**：hf-mirror、ClippableLinear、`warmup_ratio→warmup_steps`、trl1.x 对话格式、bf16（不用 bitsandbytes）。

## 6. 时间与成本（A800 80G）

| 阶段 | 预计 |
|---|---|
| 下 QAT 基座 14.8G（镜像） | 5–10 min |
| SFT（~1200 条 ×3ep） | **~5–8 min** |
| DPO 构对 400 | ~35 min |
| DPO 训练 | ~4 min |
| **合计** | **~50–60 min**（按 ¥5–8/h ≈ **¥5–10**） |

## 7. 验收标准

1. `audit_dialogue.py` 全绿（v4 数据）
2. SFT eval_loss 与首训同量级（2.8 上下）
3. **20 条评测**：短句、无 Markdown、口癖准
4. **利贞 persona 测试**：切 system prompt 后能稳定以利贞口吻回答（首训做不到 → 这是 v4 的核心验收）
