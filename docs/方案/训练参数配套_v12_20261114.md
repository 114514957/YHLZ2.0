# 训练参数配套方案（v12，2026-11-14）

> 一句话：**先把地基验了（能不能复现 48），再做单变量（LCCC 到底伤不伤），最后才谈 KL / DPO。**
> 台账依据：1211《训练注意事项总表》｜1212（闸门）｜训练素材盘点_20261114
> 所有配置文件在 `dist/retrain_pkg_gemma_v12/config/`，都能过 `tools/train_preflight.py`。

---

## 一、核心参数表（一套，A/B 共用；A 与 B 只差数据）

| 参数 | 值 | 为什么是这个值（依据） |
|---|---|---|
| `base_model` | `gemma-4-e4b-it`（bf16） | 换基座=换赛道；qwen 全参只有 29–35 分 |
| `epochs` | **1.0** | 3 epoch 实测腰斩：v9t5(3ep)=25 vs v9t6(1ep)=42 |
| `batch_size × grad_accum` | **4 × 2 = 8** | 有效 batch=8 是既定形状，1×8/4×2/8×1 等价，**别再当变量** |
| `lr` | **2e-4** | v9t6–v9t10 都是 2e-4 拿到 42–48；1.5e-4 只在 v11 用过且与数据量混淆 |
| `lr_scheduler_type` | **cosine**（显式） | v9t5–v9t10 是 `None`（吃默认），这是我们长期的不确定项 |
| `optim` | **paged_adamw_8bit**（显式） | 同上；8bit 优化器状态省显存 |
| `warmup_ratio` | 0.03 | 现行；≈15 步（5931/8=742 步 × 0.03） |
| `max_grad_norm` | **1.0** | 实测 grad_norm p95 3.4–5.7，裁剪不常触发，属安全网 |
| `max_seq_len` | **1536** | 覆盖 99% 样本；且 >512 滑窗，训练时已包含跨窗结构 |
| `lora_r / alpha` | **16 / 32** | 34.88M 可训练（0.437%）；r 加大留到"风格仍不显"时再试 |
| `lora_dropout` | 0.05 | 现行 |
| `target_modules` | **7 类全挂**（q,k,v,o,gate,up,down） | 只挂 q/v 容量不够；文本塔就是 `nn.Linear`，无需 `.linear` 后缀 |
| `bias` | **none** | 全模型唯一 bias 在 audio_tower，`lora_only` 是空操作 |
| `load_in_4bit / nf4 / double_quant` | true / nf4 / true | 8G–40G 都能跑；A800 上也用它省时间 |
| `bnb_compute_dtype` | **fp32** | 4bit 反量化算 loss 时更稳（v9t11 起固定） |
| `gradient_checkpointing` | true | 省显存；**配套必须 `use_cache=False`**（HF 要求，非 bug） |
| `mask_prompt` | **true** | 只对 assistant 段算 loss |
| `weight_decay` | 0.0 | 现行；LoRA 上意义有限 |
| `logging_steps / save_steps` | 20 / 200 | 每 742 步约 37 条日志、3 个 ckpt |
| `save_total_limit` | 2 | 只留最近两个，省盘 |
| `seed` | 20261114 | 固定，便于复现与对照 |
| **DeepSpeed** | **不用** | ZeRO-3 可能存半空 adapter |
| **`weight` 机制** | **重采样**（`rng.choices`） | 不是乘 loss；2026-11-08 前 weight 根本没生效 |

## 二、四个实验（按顺序做，别跳）

### A. 复现基线（**先做这个**）

| 项 | 值 |
|---|---|
| 配置 | `config/finetune.gemma4.v12a-repro.json` |
| 数据 | v9t10 原样 **5931 条**，Σw 3040（人格 33.5%/场景 16.2%/记忆 9.5%） |
| 目的 | **验证 48 分能否复现**（台账 1211 P7：从未验过训练重跑一致性） |
| 通过 | 56 题 **48±0**、群聊 27、闸门全过；若只有 44–46 说明环境有漂移，先查环境再谈实验 |
| 成本 | A800 约 25–30 分钟（742 步）≈ ¥2.8 |

### B. 数据红线单变量（A 之后立即做）

| 项 | 值 |
|---|---|
| 配置 | `config/finetune.gemma4.v12b-lccc05.json` |
| 数据 | A 的全部样本 **+ LCCC 3494 条 × 0.5 权重** → 约 9425 条，Σw 约 3300 |
| **唯一变量** | **LCCC 权重 0 → 0.5×**（其余一字不动） |
| 目的 | 分清"数据多有毒"还是"掺 LCCC 有毒"（v11 因同时改 lr 而无法归因） |
| 判读 | ≥48 → **稀释论成立**，以后可以扩量但必须控稀释；<46 → LCCC 本身伤人格，直接弃用 |
| 成本 | 约 35 分钟 ≈ ¥3.3 |

### C. KL 锚定（B 之后再谈，**要先给 trainer 打补丁**）

| 参数 | 值 | 说明 |
|---|---|---|
| `kl_coef`（λ） | **0.03**（区间 0.02–0.05） | 比外部建议的 0.01–0.1 更紧，我们风格偏移很灵敏 |
| 参考模型 | **冻结的 dpo2 adapter** | 锚"元亨的平衡点"，不是锚原始基座 |
| loss | `CE + λ·KL(p_cur ‖ p_ref)` | 多一次前向，显存 +约 30% |
| 其余 | 与 A 完全一致 | 单变量 |

> ⚠️ 现行 `finetune_train.py` **没有 KL 项**，先加实现再加配置，否则字段会被忽略却看起来"做过了"。

### D. DPO 续训（当 A/B/C 都压不住时才走）

| 参数 | 值 | 说明 |
|---|---|---|
| β | 0.1（TRL 默认附近） | dpo2 就是这条路，48→49 |
| lr | 5e-5 | DPO 比 SFT 更敏感 |
| epochs | 1 | 同上 |
| batch × accum | 1 × 8 | 偏好对显存更吃 |
| 数据 | (prompt, chosen, rejected) 偏好对，chosen 用老爹认可的句子 | 现有 `build_dpo_style_v2.py` 流程 |

## 三、验收口径（每版都照这个判）

| 层 | 判据 |
|---|---|
| 训练健康 | loss 从 ~5 起、末值 ≤ 起点 60%；grad_norm 无 100+、无 NaN |
| 过拟合校验 | 60 条冒烟能逐字背出（阶段 1 已单独验过） |
| 主评 | **56 题 ≥ 基线（48）**，闸门 r07/r08/s06 全过 |
| 群聊 | **28 题 ≥ 27**，g 系闸门全过 |
| 稳定性 | 同一 GGUF **双跑分数完全一致** |
| 记账 | 变量、条数、lr/epochs/eff_batch、loss 起终、grad_norm、56+28、闸门、是否上线 |

**不超基线就不上线**（基线：dpo2 = 49/56、群聊 27/28）。

## 五、这套参数的取舍说明（怕你以为我在堆参数）

- **没有调 lr**：2e-4 是历史唯一验证过的值，调它等于同时动两个变量。
- **没有放大 r**：34.88M 已够；r 是"风格仍不显"时的下一张牌，不是第一张。
- **没有动 max_seq**：1536 覆盖 99% 样本，且已跨过 512 滑窗。
- **没有上 KL/DPO**：它们是 C/D，必须等 A/B 给出干净的因果结论。
- **唯一"新增"的是显式 cosine + paged_adamw_8bit**——这不是调参，是把原来吃默认的字段写死，消除不确定项。
