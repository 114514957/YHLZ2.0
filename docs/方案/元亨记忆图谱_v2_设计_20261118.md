## 一、MaiBot 的设计（外部参考）

MaiBot（麦麦）把长期记忆做成独立子系统 **A_Memorix**（v2.0），核心不是“一个向量库”，而是：

- **双路检索**：向量 + 图谱关系联合召回，`search/time/hybrid/episode/aggregate` 五种模式；
- **写入**：段落与关系**联合写入**，`external_id` 幂等去重，Episode pending 队列；
- **Episode / 人物画像**：按 source 重建事件、自动快照人物画像；
- **维护**：关系 reinforce/protect/restore/freeze/recycle_bin，删除可恢复，运维审计；
- **LoCoMo 风格**：长期、可维护、可管理，而不是只追召回率。

更早的 **LPMM** 模块基于 **HippoRAG 2**：LLM 抽实体 + RDF 关系 → OpenIE JSON（段落/实体/三元组）
→ Faiss 段落/关系向量 → 检索时向量召回 + LLM 过滤关系 + Personalized PageRank 扩散 + 返回证据段落。
规划里还有“遗忘/压缩/保护阈值/LRU 剪枝”。

## 二、元亨旧图的问题（实测，不是印象）

`cache/entity_graph.db`：**632 实体 / 752 关系**，头部是：

- 计划表 → 到点 → `09:30+daily`（35 次）
- 老爹 → 需要配合 → 跑工具（22 次）
- 元亨/老爹 → 尝试更新计划 → 失败（25 次）
- 实体含“你/我/计划表/跑工具”等代词与过程词

根因：
1. 没有段落节点，关系脱离上下文，无法回溯证据；
2. 没有 evidence / confidence / 时间，无法判断“现在还成立吗”；
3. 抽取输入是 `用户话 + 元亨回答`，把助手的过程动作也抽成事实；
4. `_local_llm` 用 `llm_endpoint()` 的 **云端 base_url**（DeepSeek），云端不可达时静默抽空；
5. `memory_graph.py` 只是把 L2 摘要按关键词/2-gram 连线做**可视化**，不是抽取图。

## 三、v2 结构

新库 `cache/kg/kg_v2.db`（与旧库物理隔离）：

```
docs(id, hash, text, source, ts)                 # 段落，哈希幂等
entities(id, name, type, hits, confidence, ...)   # 实体（名字/别名归一）
relations(id, src, rel, dst, evidence, doc_id,    # 关系：带证据、置信度、时间
          confidence, hits, first_seen, last_seen)
mentions(doc_id, entity_id)                       # 段落↔实体
```

**抽取**（LLM，本机 8081，`YHLZ_KG_LLM_BASE` 可改）：
- 只抽**跨轮仍成立**的事实；身份/归属/喜好/职责/项目状态优先；
- 每条必须给 `evidence`（原文连续片段）→ **归一化子串校验**，编造直接丢；
- 代词/泛指/过程词/文件名/环境变量名过滤；过程动词（挖出/修正/完成/发现/误判…）不入关系；
- 输出兼容 JSON 数组 / 逐行对象 / `{"triples":[]}` 三种格式；
- 置信度 <0.35 丢弃；同段落幂等，同关系累计 hits。

**检索**：实体名/别名在 query 中命中 → 取该实体 1-hop 关系（`confidence × hits × 新鲜度`）→ 拼“已知事实”提示块；无命中返回空，不硬塞。

**回滚**：
- 代码：`YHLZ_KG_V2=0` 回到旧 `entity_graph + associations`（旧库原样，不迁移）；
- 抽取：`YHLZ_KG_LLM=0` 关闭 LLM 抽取；
- 版本：tag `yhlz-v1.3.14-pre-kg-20261118`（开工点）+ 旧库备份 `cache/entity_graph.db.bak-20261118`。

   `semantic_docs()` 段落余弦；`retrieve()` 返回 `facts + docs`；`context_for` 在无实体命中且模型已热时用段落片段兜底。

2. **Episode / 人物画像**：`episodes`（按 source + 6h 间隔聚合，摘录式摘要）、`profiles`（按实体聚合关系+证据）；

   单值关系（喜欢/住在/是/负责/属于…）出现新值时旧关系标 `superseded`（不删除）；`facts_for` 默认只取 active。
4. **遗忘维护**：`decay()` 归档久未命中低置信关系、`restore()/forget()/protect()/purge_archived()`、`maintenance()` 统计。

   `--batch` 批量模式因小模型易漏 evidence/变慢，不作为主路径。
