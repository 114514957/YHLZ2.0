## 二、两个工具

### 1. 采集器 `tools/qq_daily_log.py`

**要解决的问题**：`cache/sessions/qq_*.json` 只有 `saved_at`（整文件最后保存时间），history 里**没有时间戳**，没法按天复盘。

**做法**：增量快照。每跑一次：
1. 读所有 `qq_*.json` 的 history
2. 用 `sha1(role + 内容)` 判重（`cache/qq_daily/_seen_hashes.json`）
3. 没见过的轮次，以当前时间戳追加进 `cache/qq_daily/<YYYYMMDD>.jsonl`
4. 记录 `channel / idx / role / text / next_role`

**字段**：`ts, day, channel, idx, role, text, next_role`

**用法**：
```
python tools/qq_daily_log.py                 # 采一次
python tools/qq_daily_log.py --loop 300      # 每 5 分钟采一次（挂后台/计划任务）
```

### 2. 复盘器 `tools/style_review.py`

**只评说话方式，不评对错、不评安全。**

指标（每条回复都算一遍）：

| 指标 | 说明 | 健康线 |
|---|---|---|
| 字数中位/均值 | 太短没内容，太长像演讲 | 8–60 字 |
| 碎句占比 | ≤6 字小句的比例 | <60% |
| 最长整句中位 | 能不能说出完整一句 | ≥15 字 |
| 超短回复 | ≤4 字 | <15% |
| **客服腔** | 随时待命/需要我帮您/很高兴为您… | **0** |
| **自称助手** | AI 助手/作为语言模型… | **0** |
| **复读** | 4–20 字片段连续重复 | **0** |
| 括号动作 | （笑）（叹气） | 越低越好 |
| 反问收尾 | 以「？」结尾 | 越低越好 |
| 叫「老爹」 | 关系感 | 越高越好 |
| 「哇」 | 口头禅 | 别泛滥 |

输出：
- `docs/复盘/风格日报_<YYYYMMDD>.md` — 指标表 + 好句 + 坏句 + 明天要盯的
- `docs/风格/好句库.md` — **只存句式骨架**（见下）
- `docs/复盘/索引.md` — 每天一行汇总

## 三、⚠️ 最要紧的一条规矩：好句必须去内容化

**只学怎么说，不学说什么。**

2026-11-10 实测过：系统提示里的示例带具体内容（台账重排那段），模型在 s08「我不在的时候你都干了什么」上**把示例内容整段搬了过去**。

所以好句进库前一律抹掉：
- 拉丁字母/数字 → `·`
- 老爹/利贞/大肥鱼 → `某人`
- 只留第一整句（太短就并上下一句），上限 40 字

例：
| 原话 | 入库骨架 |
|---|---|
| 老爹，你可算回来了。外头冷吧？ | `某人，你可算回来了` |
| 在呢。别一个人发。 | `在呢，别一个人发` |
| 累就说累。别硬撑。 | `累就说累，别硬撑` |

坏句**只进报告，不进提示**——它是给我们看的，不是教她的。

## 四、每天的流程（已接入项目，自动跑）

```
① 采集   启动器自动拉起 qq_daily_log.py --loop 600     （每 10 分钟）
② 复盘   同进程到 23:50 自动出日报                      （--review-at）
③ 看报告 docs/复盘/风格日报_<date>.md
④ 好句自动进 docs/风格/好句库.md
⑤ 次日提示可引用最近 3–5 条骨架（只引骨架，不引内容）
```

第 ⑤ 步还没接——**等真有几天数据、确认好句库干净了再接**，否则会把噪声喂回去。

## 四之二、怎么接入项目（2026-11-13 已接）

不是"旁边放着两个脚本"，是**跟着整条链一起起、挂了自动补**：

| 位置 | 改动 |
|---|---|
| `tools/yhlz_launcher.py` | 新增 `_spawn_daily_log()`；`ensure_stack()` 末尾按 `_proc_alive("qq_daily_log.py")` 自动补起（冷却 300 秒，走项目既有 `_spawn_allowed` 闸门） |
| 同上 | 新增 `DAILY_REVIEW_AT`，默认 `23:50`，环境变量 `YHLZ_DAILY_REVIEW_AT` 可覆盖（空串＝只采集不自动复盘） |
| `tools/qq_daily_log.py` | 新增 `--review-at HH:MM`：同进程到点自动复盘，**不需要额外计划任务** |
| 日志 | `cache/logs/qq_daily_log.log` |

**它是旁路观测**：挂了不影响聊天，所以**不进 `CRITICAL_SERVICES`**，只做自动补起。

实际拉起的命令行（已验）：

```
.venv\Scripts\python.exe -B tools\qq_daily_log.py --loop 600 --review-at 23:50
```

### ⚠️ 首日回填

第一次运行会把 `sessions` 里的**全部历史**一次性落盘——那些不是当天说的。
`qq_daily_log.py` 给它们打 `backfill: true`，`style_review.py` **直接剔除、不计入当日**，
报告只写一行「今天只有 N 轮首日回填」。

实测：首跑回填 **104 轮**，当日有效 **0 轮**。

## 四之三、接入时发现的两个既有问题（不是这次引入的）

### 1. `yhlz_launcher.py --self-test` 恒报 FAIL

自检要求工作台首页含字面量 `"YHLZ"`，但页面标题是「元亨 · 工作台」，全文没有 "YHLZ"：

```
含 YHLZ: False
title: 元亨 · 工作台
```

`ok &= "YHLZ" in h` 恒为假 → **SELFTEST 永远 FAIL**（services 明明都 True）。
**这是项目验收口径过期，我没擅自改。**

### 2. 评测侧与生产侧的提示词是两套

`tools/unified_prompt.py` 只给评测/训练用；生产走 `backend/target_prompts.py` 自己的渲染。
两条风格示例原先只在评测侧，**生产里没有**——已补 `STYLE_HABIT_CLAUSE`（台账 1171）。

**教训**：任何"改提示词改善效果"的实验，必须**同时确认生产路径**，否则你测的东西线上根本不存在。
