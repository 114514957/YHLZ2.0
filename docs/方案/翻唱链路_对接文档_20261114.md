# 翻唱链路 · 对接文档

> 2026-11-14 · 利贞交接版
> 读者：接手翻唱的人（或另一个 agent）。**照着这份能跑、能查、能改**，不用再问原作者。
> 本文所有数字都是**实测**，不是估算；标「待定」的说明还没定。

---

## 一、这条链是干什么的

输入一首歌（`m4a/mp3/wav/flac`）+ 选一个音色，输出**老爹自己声音的翻唱成品**（wav）。

一句话流程：

```
原曲 → ①规范化 → ②人声/伴奏分离 → ②.5电平归一 → ②.6干声预处理 → ③主唱/和声拆分
     → ④换声(Seed-VC) → ⑤柔化 → ⑥三轨混回 → ⑦归档
```

---

## 二、三个入口（任选）

### 1. 工作台 UI（老爹日常用这个）
`http://127.0.0.1:8321/` → 「翻唱」页 → 拖歌 / 选音色 → 开始翻唱。

### 2. HTTP API
```http
POST /sing          {"target": "C:\\...\\歌.m4a", "voice": "bright"}
GET  /sing/status    # {status, step, log, result, started, finished, sep, error}
POST /sing/upload?name=歌.m4a   # body=二进制；返回 {ok, path}
POST /sing/stop     # 停
```

### 3. 命令行（调试/批量用）
```bash
.venv\Scripts\python.exe -u tools\cover_produce.py <音源> \
    --voice bright --presets e --out-dir cache\sing\produce_<ts>
# 只做分离（不换声），排查分离问题用：
    --dry-run
# 跳过干声预处理（默认做）：
    --no-prep
```

## 三、各阶段：工具、耗时、失败会怎样

| 阶段 | 工具 | 实测耗时（202 秒的歌） | 失败后果 |
|---|---|---|---|
| **S1 规范化** | ffmpeg（imageio_ffmpeg 自带）→ 44.1k/立体声/`input.wav` | **0.5 秒** | 整单失败 |
| **S2 人声/伴奏** | `tools/svc_kim_split.py` → MSST `kim.ckpt`（Mel-Band-RoFormer） | **43 秒** | 整单失败 |
| **S2.5 电平归一** | `tools/svc_stage_level.py`，每轨压到 **-3 dBFS**（只降不升） | **0.6 秒** | 记错误、**继续** |
| **S2.6 干声预处理** | `tools/svc_prep_vocal.py` = 高通70Hz + **dereverb.ckpt 去混响** + 轻参考谱减 | **约 75 秒**（去混响 55 + 谱减 20） | 记错误、**退回未处理干声继续** |
| **S3 主唱/和声拆分** | `tools/svc_mdx_karaoke.py` → audio-separator + `UVR_MDXNET_KARA_2.onnx` | **83–85 秒**（冷启动可达 **232 秒**） | 整单失败（**不做静默降级**） |
| **S4–S6 换声+柔化+混音** | `tools/cover_rebuild.py` → Seed-VC + 柔化(`--preset e`) + `tools/wsl_mix3.py` | **164 秒** | 整单失败 |
| **S7 归档** | 写 `说明.txt`，拷成品到 `音频素材\翻唱产出\<时间戳>_<歌名>\` | 秒级 | 记错误 |

**端到端实测：202 秒的歌 ≈ 6.3 分钟**（旧版 9.9 分钟）。
⚠️ 界面文案写着「约 6–7 分钟」，**是准的**；但 S3 冷启动会多 2 分钟。

## 五、流式进度（这块踩过坑，照抄别改）

`console_server` 调 `cover_produce.py` 的方式**必须是这三件同时成立**，否则页面上跑的时候永远显示「还没有任务」：

1. **父进程**：`Popen`（不是 `subprocess.run(capture_output=True)`）+ 循环读 `job_dir/release.log` 的尾巴
2. **子进程不缓冲**：命令行带 `-u`，环境 `PYTHONUNBUFFERED=1`
3. **子进程逐阶段输出**：`cover_produce.py` 里 `_say(stage, ...)` 每个阶段结束 `print(..., flush=True)`

少任何一条都会是空的（我在这上面白改了三轮）。日志形如：
```
{"stage": "S1", "ok": true, "elapsed_s": 0.5}
{"stage": "S2", "ok": true, "elapsed_s": 43.4}
```

## 六、关键参数（想调音色/平衡改这里）

| 参数 | 位置 | 默认 | 作用 |
|---|---|---|---|
| `--voice` | API/CLI | `bright` | 音色（对应 Seed-VC 参考音色） |
| `--presets` / `--preset` | CLI | `e` | 柔化预设（`e` = 验收版） |
| `--lead-gain` / `--backing-gain` / `--bgm-gain` | `cover_rebuild.py` → `wsl_mix3.py` | 1.0 / 0.8 / 0.7 | 三轨混音比例 |
| `--peak` | `wsl_mix3.py` | 0.99 | 末级归一目标（**默认归一，不是只限幅**） |
| `--gate both` | `cover_rebuild.py` | — | 人声门控（防器乐段硬唱） |
| `--floor` | `svc_gate.py` | 0.0 | 掩码为 0 处的残余增益 |
| `--alpha/--floor/--hp` | `svc_vocal_clean.py` | 0.6/0.20/70 | 参考谱减力度/保留底/高通 |

## 七、干声质量：链路已做与待定

**已做（2026-11-13/14 新增）**
1. **电平**：分离输出会顶到 0 dBFS 甚至 **+0.8 dB（已削波）** → S2.5 统一压到 **-3 dBFS**；
   混音末级改成**归一到 0.99**（否则整体小 3 dB）。
2. **去混响**：`dereverb.ckpt`（871 MB，仓库自带）。**分离模型只管"人声/伴奏"，不管"直达声/混响"**，
   混响会让换声后又糊又散。尾巴能量比 0.733 → 0.674（约 -8%，客观改善但不夸张）。
3. **参考谱减**：用伴奏当参考压"与伴奏相干"的成分——实测只压 2–4%，**听感贡献有限**，别指望它。

**精修环（`tools/svc_vocal_polish.py`，已写好，档位待定）**
- 去电音味：log 幅度做时间向+频率向轻度平滑（倒谱 lifter 思路）
- 去不自然：自适应压 2.5–4.5 kHz 刺耳区 + 2:1 轻压缩 + 断句 5 ms 淡化
- 提饱和：tanh 软饱和（drive）
- 三档实测（都 -3.0 dB、0 削波）：

| 档 | 去电音/去刺/压缩/驱动 | crest |
|---|---|---|
| 轻 | 0.4 / 0.35 / 0.20 / 1.3 | 5.14→3.86 |
| 中 | 0.6 / 0.50 / 0.35 / 1.6 | →3.49 |
| 重 | 0.85 / 0.70 / 0.50 / 2.2 | →2.99 |

**⚠️ 待定**：老爹还没选档；选定后作为 **S2.7** 接进 `cover_produce.py`（在 S2.6 之后、S3 之前）。

## 八、已知问题（别重复排查）

| # | 现象 | 真相 | 处置 |
|---|---|---|---|
| 1 | 干声听着沙哑/毛刺 | **源文件自己就削波**（赤蛮奇：**1569 个样本**，峰值 0 dB）。分离救不回来 | S1 前报削波比例；修复会改音色，需老爹同意 |
| 2 | 页面显示「还没有任务」 | 老代码 `capture_output=True` + 块缓冲 + 只在最后打印 | 见 §5，三件缺一不可 |
| 3 | S3 有时 85 秒有时 232 秒 | 模型冷/热差异 | 正常，别当故障 |
| 4 | 成品比预期小 3 dB | 上游归一了、末级只限不归 | 已修：末级默认归一 |
| 5 | 门控把人声切没 | **改 hop 时必须同步改上采样的 step**（写死 256/22050 会把掩码压成一半） | 已修，见 `svc_gate.py` 注释 |
| 6 | GPU 抢用 | S2 会开 **gpu_window**（临时停 llama），窗口内聊天会等 | 设计如此；`backend/gpu_window.py` |

## 九、验收怎么验（照这个顺序）

1. **分离**：`cover_produce.py <歌> --dry-run`，看 `stems/` 四轨都在、`release.log` 有 S1/S2/S2.5/S2.6/S3 五行
2. **电平**：`python experiments\stem_quality2.py <作业目录名>` → 每轨峰值 ≤ -3 dB、**削波 0**
3. **相关性**：lead vs backing 应 **< 0.3**（赤蛮奇实测 0.065–0.123）
4. **整单**：`POST /sing`，看 `/sing/status` 的 `step` 是否逐阶段推进、`result` 有成品路径
5. **成品**：`python experiments\accept_new_chain.py` → 峰值 ≈ **-0.7~-0.1 dB**、**削波 0**

## 十、环境与依赖

- Python：主 venv `.venv`；分离另有 `venv-gsv5`（audio-separator 专用），**别混用**
- 模型权重：`cache/msst/pretrain/{kim,karaoke,dereverb}.ckpt`（871 MB / 1.6 GB / 871 MB）；
  `cache/msst/UVR_MDXNET_KARA_2.onnx`（50 MB）
- MSST 推理入口：`cache/msst/inference.py`（`--model_type mel_band_roformer --config_path ... --start_check_point ...`）
- ffmpeg：`imageio_ffmpeg` 自带的那个
- 显存：8 GB 卡够用；S2 会主动让 llama 让出显存（gpu_window）

## 十二、还没做的（想往上抬再看）

- **歌词/ASR 对齐门控**：有歌词→强制对齐，或在干声上跑 ASR；只在有字区间保留。
  这能解决"该不该留"（挡住有音高的乐器泄漏），但解决不了"留下的部分混着伴奏"。
- **二次分离**：对干声再跑一遍不同模型取交集（现有 kim/karaoke/dereverb 三套权重）。
- **S3 提速**：老爹明确「不要，保证质量」，所以维持现状。
