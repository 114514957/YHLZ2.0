# Gemma-4 风格微调：诊断 → 修复 → 正式训练（可执行版）

> 2026-11-14 · 利贞整理
> 起因：外部给了一份《Gemma4 无效训练陷阱》建议。我**逐条核对**了我们这台机器和这个 checkpoint，
> 结论是：**三条不成立、一条待验、一条不适用；真正该照做的是它提的"冒烟测试"，而我们从来没做过。**
> 下面每条都标明「证据」和「要不要做」。

## 〇、先把结论说清楚

1. **15000 条足够学一种说话风格** —— 这点同意，我们自己的数据也印证：6909 条的 v9t10 拿到 48/56，
   而 **15,148 条的 v11 只有 44/56**。**不是数据不够，是"堆更多"反而更差。**
2. **"死记硬背都背不下来"这个判断，我们没有验证过** —— 我们**从来没做过小样本过拟合测试**。
   这是整份建议里唯一必须补的一环（§二）。
3. 建议里三条"Gemma4 专属陷阱"，**在我们这个 checkpoint 上不成立**（§一，附源码/权重头证据）。
4. 我们的问题不在训练通路（loss 一直在正常下降、adapter 能被 llama.cpp 加载并明显改变说话方式），
   而在**策略**：越训越偏离 dpo2 那个平衡点（§三）。

## 一、五条"陷阱"逐条核对（有证据，不是观点）

### ① `use_cache=False` 会毁掉 Gemma4 注意力 —— **不成立（且有标准做法冲突）**

| 项 | 结果 |
|---|---|
| 查 `modeling_gemma4.py` 里 `use_cache` 的分支 | **只有 2 处**，都是标准的 `past_key_values` 处理：`if use_cache and past_key_values is None` / `if not (is_first_iteration or not use_cache)` |
| 有没有"损坏路径" | **没有任何针对 Gemma4 的特殊分支** |
| 业内标准做法 | 开梯度检查点时**必须** `use_cache=False`（否则 HF 会直接警告，且 KV cache 与 checkpoint 冲突） |

**处置**：不改。若仍想证伪，用 §二.3 的前向对比脚本（同输入 `use_cache=True/False` 比 logits），**一次就能定论**。

### ② LoRA 挂不上语言模型主干（`Gemma4ClippableLinear`） —— **不成立**

| 项 | 证据 |
|---|---|
| `ClippableLinear` 出现在哪些类附近 | `Gemma4AudioFeedForward`、`Gemma4AudioLightConv1d`、`Gemma4VisionMLP` —— **全是音频/视觉塔** |
| 文本 MLP 用什么 | `Gemma4TextMLP` 里的线性层 = **`nn.Linear`**（源码实证） |
| 我们的可训练参数 | **34,881,536**（0.4373%） |

建议说"健康的 E4B 文本 LoRA 应约 595 万（0.14%）"——那是**只训 q/v** 的量级。
我们训了 **q,k,v,o + gate,up,down 共 7 类**，34.9M 是合理值。**不是挂错，是挂得比它多。**

> 备注：这条我 2026-11-10 就查过一次（台账 1126），当时结论也是"文本塔就是 nn.Linear"。
> 今天用源码复核一致。

### ③ `lm_head` 有预训练 bias，不训就崩 —— **这个 checkpoint 上不成立**

读 `model.safetensors` 头（2130 个张量，全量静态扫描）：

```
带 .bias 的张量：只有 1 个 → model.audio_tower.output_proj.bias（音频塔的）
lm_head 相关张量：无 → 输出层与 embed_tokens 绑定（tied）
embed_tokens：model.language_model.embed_tokens.weight
```

- **没有 lm_head，更没有 lm_head.bias**，所以「不训 bias 会破坏校准」在这里无从谈起。
- `bias="lora_only"` 在这个模型上等于**空操作**（目标层本身没有 bias），加了也只是噪音。

**处置**：不加。真要加正则，方向应该是 §三.2 的 KL 锚定，不是动 bias。

### ④ 梯度累积 / DeepSpeed 保存"半空 adapter" —— **我们不适用**

- 所有训练配置：`deepspeed` **全为空**（没用）。
- `grad_accum` 取 1/2/8 都用过；v9t11 起我们对齐了"权重按 resampling 生效"，**每步都实际更新**。
- 我们的 loss 曲线正常（5.33 → 1.58），**从未出现 100/300 这种爆值**。

**处置**：无需处理。

### ⑤ "正常 E4B 的 loss 基线 13–15" —— **不能拿来当尺子**

我们实测：v11 训练 **5.3327 → 1.5830**（1649 步，降 70.32%）；v9t10 也是 5 左右起步。
loss 绝对值随**分词器、标签掩码、序列长度、数据难度**变化，跨项目比较毫无意义。
**判据只能用"同一条数据在训练前后的下降"和"下游评测分数"，不能用别人的绝对数。**

## 二、唯一必须补的一环：冒烟测试（证明"能背下来"）

我们从没做过小样本过拟合。这是验"训练通路是否健康"最便宜的一招，**成本约 10 分钟 GPU**。

### 2.1 做法（用我们现成的包和 trainer，不重写）

```bash
# 1) 从现有训练集抽 60 条，单独成一个包
python - <<'PY'
import io, json, random
src = r"YH\dist\retrain_pkg_gemma_v11\sft_persona_v11_train.jsonl"
rows = [json.loads(x) for x in io.open(src, encoding="utf-8") if x.strip()]
random.Random(20261114).shuffle(rows)
pick = rows[:60]
io.open(r"YH\dist\smoke60.jsonl", "w", encoding="utf-8").write(
    "\n".join(json.dumps(r, ensure_ascii=False) for r in pick))
print("写出", len(pick), "条")
PY

# 2) 复用 v9t11 的 trainer（已修过 weight/截断/掩码那些坑），只换数据与超参
python dist\retrain_pkg_gemma_v9t11\finetune_train.py \
  --config <改好的 smoke 配置> --base <基座> --resume-from <可选：dpo2>
```

**smoke 配置关键值**（照抄，别用建议里的 13–15 当判据）：

| 项 | 值 | 理由 |
|---|---|---|
| 样本数 | **60** | 够过拟合，跑得快 |
| epochs | **6**（≈ 60×6/8 ≈ 45 步） | 要能背下来 |
| lr | **1e-4** | 过拟合用，别用它训正式 |
| batch / grad_accum | 8 / 1 | 与正式训练同形状，避免累积误差混进来 |
| max_seq_len | 1536 | 与正式一致 |
| 目标模块 | 同正式（7 类含 MLP） | 验的就是这条通路 |

### 2.2 判据（我们自己的口径，不是外部的）

| 观察 | 通过 | 不通过 |
|---|---|---|
| **训练 loss** | 从 ~5 附近**持续下降**，最后显著低于起步（≤ 起步的 60%） | 纹丝不动 / 上下乱跳 / 出现 100+ |
| **过拟合校验**（拿这 60 条原样推理） | 输出**逐字贴近**训练目标（背下来了） | 仍泛泛而谈 → 通路或掩码有问题 |
| **对照组**（基座直接推理） | 明显不同 | 与训练后一样 → adapter 没生效 |

### 2.3 顺手用同一套数据验 `use_cache`（一次定论）

```python
# 同一条输入，use_cache=True / False 各跑一次前向，比 logits
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
m = AutoModelForCausalLM.from_pretrained(BASE, torch_dtype=torch.bfloat16, device_map="auto")
tok = AutoTokenizer.from_pretrained(BASE)
ids = tok("今天有点累，你陪我坐会儿。", return_tensors="pt").to(m.device)
outs = {}
for uc in (True, False):
    with torch.no_grad():
        outs[uc] = m(**ids, use_cache=uc).logits.float()
d = (outs[True] - outs[False]).abs().max().item()
print("max|Δlogits| =", d)   # ≈0 → 建议①在本模型不成立
```

## 三、正式训练：按我们的教训来（不是照抄建议）

### 3.1 数据：**不是越多越好，是"配比 + 权重"**

| 我们试过的 | 结果 | 结论 |
|---|---|---|
| v10u 8850 条（权重化） | **48/56** | 当时最好 |
| v11 **15,148 条**（口述故事 3.5×、LCCC 0.15×） | **44/56，r07 破闸** | **堆更多反而更差**，且冲掉"记住家里事"（r04 记忆分层答错） |
| dpo2（在 v9t10 上做风格 DPO） | **49/56** | 目前最高 |

**建议里的"混 20–40% 通用指令"** —— 方向对，但**别用外部通用语料**：v11 里 LCCC 占 7.3% Σw
已经稀释了人格；通用指令混多了会让她更"助手"。更安全的是**混我们自己的非风格样本**
（工具/记忆/纪律），保持"是元夕"而不是"是助手"。

### 3.2 防遗忘：KL 锚定（建议里唯一值得试的新招）

```
Loss = CE(新数据) + λ · KL(当前模型 ‖ 冻结的 dpo2)
```
- λ 取 **0.02–0.05** 起步（建议里的 0.01–0.1 太宽，我们的风格偏移很灵敏）
- 参考模型就是**上一版 dpo2**，不是原始基座——我们要保的是"元亨的平衡点"，不是"通用模型"
- 成本：多一份前向，显存要够（A800 无压力）

### 3.3 超参（我们验证过的区间）

| 项 | 值 | 依据 |
|---|---|---|
| lr | **1.5e-4**（v11 用的就是这个，loss 降 70% 且没炸） | 5e-5 在我们这代数据上几乎不动 |
| epochs | **1**（669 条级小补丁用 2） | 我们所有正向收益都来自 1 epoch |
| 调度 | cosine + warmup 3% | 已是现状 |
| 梯度裁剪 | 1.0 | 已是现状 |
| LoRA | r=16 / α=32（要更大再试 64/128） | 34.9M 已够；**先别上大 rank** |
| DeepSpeed | **不用** | 它会存半空 adapter 的风险，我们不必要地承担 |

### 3.4 训练/推理格式一致性 —— 我们踩过，且已治理

- 我们的判据坑里有一条：**评测脚本漏传 system prompt**，导致"客服腔 4/25"的假结论（实际 0/25）。
- 现在**提示词只有一个来源**（`backend/target_prompts.py` 渲染 + 工作台可覆盖 22 块），
  评测/训练/生产都指它。**任何改提示词的实验，必须同时确认生产路径**。

### 3.5 当 SFT 反复失败 → DPO（已做过，且有效）

- dpo2 就是 DPO 产物：**45 → 49（配两条示例）**，群聊 27/28。
- 所以"升级到 DPO"不是待办，是**已验证的下一步首选**：在 dpo2 上用新的偏好对继续做，
  **而不是继续堆 SFT**。

## 四、执行顺序（照这个来，别跳步）

| 步 | 做什么 | 需要什么 | 成本 | 判据 |
|---|---|---|---|---|
| **0** | **已做**：核对 5 条陷阱，3 条证伪、1 条不适用、1 条待验 | 无 | 已完成 | 本文 §一 |
| **1** | **冒烟测试**：60 条 × 6 epoch 过拟合 | **GPU（A800 最好）** | ~10 分钟 | §二.2 三条判据 |
| **2** | 同批数据做 `use_cache` 前向对比 | GPU 或大内存 CPU | ~2 分钟 | `max\|Δlogits\|≈0` → 建议①不成立 |
| **3** | 若冒烟通过 → 正式：dpo2 上做**小补丁 SFT + KL 锚定**（λ 0.03） | GPU | ~15 分钟 | 56 题 ≥49 + 群聊 ≥27 + 闸门过 |
| **4** | 若 SFT 仍不稳 → **改走 DPO**（已验证路线） | GPU | ~10 分钟 | 同上 |
| **5** | 每版必须转 GGUF 实测（不能只看 loss） | 本地 CPU | ~3 分钟 | 56+28 两遍一致 |

### 明确不要做

- ❌ 不要再堆到 15k（v11 已证伪：44 < 49）
- ❌ 不要改 `use_cache`（无证据，且与梯度检查点冲突）
- ❌ 不要加 `bias="lora_only"` / `modules_to_save lm_head`（这个模型没有 lm_head）
- ❌ 不要用 DeepSpeed ZeRO-3 存 adapter
- ❌ 不要用"loss 13–15"当健康标尺
- ❌ 不要在**本地 8G 卡**上训（实测 3.5 分钟/步）
