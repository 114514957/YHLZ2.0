# 元亨改云端常驻、本地 LLM 封存（2026-11-18）

## 决策

老爹 2026-11-18 定：**维持云端 DeepSeek，本地 LLM 封存**。

## 事实核对

- `config/llm.local.json`：`provider=cloud`、`base_url=https://api.deepseek.com/v1/chat/completions`、`model=deepseek-chat`。
- `backend/llm_endpoint.py` 注释：1229/1231 定论「项目 LLM 直接上大模型，本地 llama 彻底下线，不做兜底」。
- 聊天一直走云端；本机 8081 之前仍在跑，只被 kg 抽取等本地模块用。

## 封存机制

- 开关：`config/local_llm_sealed.flag`（或 `YHLZ_LOCAL_LLM_SEALED=1`）。
- `tools/yhlz_launcher._spawn_llama()`：封存时直接返回，不再启动 8081。
- `ensure_stack()`：封存时跳过 llama 拉起。
- `tools/yhlz_watchdog._down_keys()`：封存时把 gemma 从必检项剔除，不会每 tick 重拉。
- `backend/gpu_window.py`：翻唱 GPU 窗口结束后不再 `_spawn_llama()`，标记 `llama="sealed"`。
- `backend/kg_v2._kg_llm_target()`：封存时抽取改走云端 `llm_endpoint`（有 key）；`YHLZ_KG_LLM=0` 仍可关。
- 本地模型文件、LoRA、GGUF **不删除**；封存只是运行时不启动。

## 验证

- 停 8081 后：`/turn` 云端 7.1s 正常回；`/health` llm=cloud（DeepSeek）。
- kg 抽取云端返回正常（老爹创建元亨/元亨喜欢可乐，带 evidence）。
- 看门狗运行 30s+，8081 保持 down、llama 进程 0。

## 回滚

删 `config/local_llm_sealed.flag`（或 unset `YHLZ_LOCAL_LLM_SEALED`），重启栈，launcher/看门狗会重新拉起本地 llama；模型文件都在。

## 影响

- 语言能力 = DeepSeek；人格/记忆仍本地（kg_v2、memstore、台账）。
- 依赖：云端网络、Key、费用；断网/欠费时聊天不可用（不再自动回落本地，符合 1229/1231 定论）。
- 隐私：聊天与 kg 抽取内容会发往 DeepSeek；敏感内容不要进聊天/抽取。
