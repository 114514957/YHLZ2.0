## 1. 目的与边界

### 1.1 目的

本作业用于冻结以下内容：

- 会话和 turn 的所有权；
- 实时输入、模型输出、TTS、播放、打断和恢复的事件契约；
- Provider、Agent、记忆、Avatar 与会话核心之间的边界；
- 验证、发布、回滚和变更审批规则。

冻结的对象是**外部可观察行为和不变量**，不是某个模型、线程实现或当前的临时代码。

### 1.2 不在本作业范围内

- 直接复制 NEKO 的完整实现；
- 一次性拆分微服务；
- 在协议未冻结前新增功能；
- 以文档替代对已知故障、安全问题和测试缺口的修复。

## 2. 基线事实

当前仓库包含多条入口和多套运行路径：

```text
文本/麦克风
  ├─ /chat → 对话/上下文 → LLM → TTS → 播放/Live2D
  ├─ /ws/stream → 流式 ASR/LLM/TTS
  └─ /agent/chat → AgentBrain → 工具 + SQLite 记忆
```

冻结前必须复核的已知风险：

1. `/ws` 处理链存在调用不存在的方法的记录；
2. WebUI 工具路径与后端工具路由不一致；
3. 旧记忆接口存在空实现，且与 Agent SQLite 并存；
4. 插件导入路径、SDK 参数、生命周期和声明文件不完全一致；
5. README、依赖、启动脚本、模型说明和实际代码存在漂移；
6. 对外绑定、通配 CORS 和文件工具需要重新确认认证与路径权限。

以上项目未关闭前，不得宣称“架构已冻结”。

## 3. 术语和目标状态

### 3.1 Session Kernel

每个会话唯一的状态与 turn 所有权组件，负责：

- `session_id`、`turn_id`、递增 `seq`；
- 状态转移、取消令牌、超时和恢复；
- 过期输出的丢弃；
- 向下游发布规范事件。

它不负责具体模型推理、音频设备、记忆存储或 Avatar 渲染。

### 3.2 目标状态机

```text
IDLE → LISTENING → THINKING → SPEAKING → DONE
                         └→ INTERRUPTED → RECOVERING
```

任何新增状态必须有 ADR、转移条件、超时策略和契约测试。

### 3.3 全双工的最低语义

- 输出播放期间仍可接收输入；
- 用户输入可以抢占当前输出；
- 被取消 turn 的 LLM/TTS chunk 不得提交到新 turn；
- 只有正式完成的 turn 才能写入历史和记忆；
- 正常结束与中断结束必须有不同的事件语义。

## 4. 作业流程

### 步骤 0：建立冻结工作区

1. 确认目标目录、当前分支、提交、Python 和依赖版本；
2. 保存 `git status`、`git log -1`、目录清单和配置模板校验值；
3. 严禁把 `.env`、API Key、模型权重和运行数据库纳入提交；
4. 生成一个只读基线标签或记录，便于回滚。

### 步骤 1：建立功能和入口清单

按“核心 / 可选 / 实验 / 废弃”分类，至少覆盖：

- HTTP、SSE、WebSocket 和 Demo 入口；
- ASR、VAD、LLM、TTS、播放和打断；
- Agent、工具、视觉、具身和主动行为；
- 记忆、Avatar、桌面端和外部服务。

每项记录唯一负责人、依赖、失败表现、是否进入 Golden Path。

### 步骤 2：编写并评审协议

冻结事件公共字段：

```text
protocol_version
session_id
turn_id
seq
kind
actor
timestamp
trace_id
payload
```

建议事件：`INPUT`、`STATE`、`TOKEN`、`TOOL_CALL`、`TTS_TEXT`、`AUDIO_CHUNK`、`AUDIO_DONE`、`INTERRUPT`、`ERROR`、`COMPLETE`。

协议必须明确：

- 字段是否必填、大小和编码；
- 序号是否严格递增；
- 重复事件是否幂等；
- 何时提交历史/记忆；
- 中断时是否发送 `AUDIO_DONE`；
- 客户端和 Provider 的能力协商与版本兼容。

使用 ADR 记录每个有长期影响的选择。

### 步骤 3：固定现状行为

在迁移前编写特征测试（characterization tests），至少覆盖：

1. 文本输入 → LLM 流式 → TTS → 播放；
2. 麦克风输入、静音、噪声和回声；
3. LLM 生成期间打断；
4. TTS 播放期间打断；
5. 工具调用成功、失败和超时；
6. WebSocket 断线、重连和服务重启；
7. 历史、记忆和隐私脱敏；
8. 两个会话并发时的相互隔离。

Mock 只用于快速单测；至少保留一条真实 Provider/音频设备的集成路径和长时间运行测试。

### 步骤 4：按绞杀式路径迁移

迁移顺序固定为：

1. 文本 Golden Path；
2. 本地 ASR + LLM + TTS；
3. WebSocket 全双工和打断；
4. Agent/工具；
5. 记忆、主动行为、视觉和 Avatar。

每次只切换一个入口。旧入口先作为适配器保留，经过对照、回放和回滚验证后才允许废弃。

### 步骤 5：执行冻结门禁

以下条件全部满足才可打冻结标签：

- 所有生产入口都通过 Session Kernel；
- 每个会话只有一个 turn 所有者；
- 中断、超时、重连和恢复均有确定语义；
- 契约测试、Golden Path、干净环境启动和长跑测试通过；
- P0/P1 安全与数据一致性问题关闭或有书面豁免；
- 文档、配置、依赖和启动方式与代码一致；
- 有可回滚版本和数据迁移/恢复说明。

### 步骤 6：冻结后的变更

冻结后任何下列变化都必须走 ADR + 评审 + 契约测试：

- 修改事件字段或状态转移；
- 新增入口或第二套状态存储；
- 改变中断、提交、重试和恢复语义；
- 变更隐私、权限、文件访问或插件执行边界。

模型、TTS Provider、UI 和内部实现可在不破坏契约的前提下独立迭代。

## 5. 故障与回滚

- Provider 超时：停止当前 turn，发布 `ERROR`，按能力降级，不重复提交历史；
- 用户打断：增加取消代际/令牌，停止播放并丢弃旧 chunk；
- 进程崩溃：重启后从未完成 turn 恢复为可重试或明确失败；
- 协议不兼容：拒绝协商并保留旧适配器，不静默解析未知字段；
- 迁移异常：切回上一个入口适配器和版本标签，保留事件/错误记录供复盘。

## 7. 参考原则

NEKO 可借鉴单点状态机、事件 fan-out、realtime/offline 同接口、抢占令牌和交付确认；不直接复制其 Provider、前端、记忆和生命周期实现。直接复用代码时必须保留许可证、NOTICE 和依赖声明。
