# V9 八万段语料目标修订

2026-10-11。用户提出首版至少8万段。当前工作口径调整为：制作至少80000段去重、来源可用、内容与行为审核后的训练记录，validation/test另留；不是下载80000条、epoch累计80000次或把多轮每句话拆成记录。

## 1. 依据与承诺范围

此前25000是工程初始预算，没有实验依据证明它比80000更优，也没有普遍的“80000保险线”。接受更充分的数据建设范围，是为了覆盖更多独立任务和条件，不是声称数量翻倍必然提升。

LIMA的65B/1000例和Tulu3的多任务完整后训练方案面向不同目标；二者都没有给Gemma E4B元亨PT一个通用条数阈值。质量、技能覆盖、去污染与未见评估不能被总条数替代。当前没有训练数据规模对照，不报告80k的预期成功率或训练时长。

## 2. 暂定分配

| 池 | 训练记录目标 | 工作重点 |
|---|---:|---|
| 核心黄金 | 4000 | 现有素材为主，保留人格/思想/关系；精品来源可追溯 |
| 说话及一般任务辅助 | 36000 | 多样的交流、解释、改写、创作、澄清、任务完成；不将通用助手话术全部照搬 |
| 工具和概念边界辅助 | 24000 | 条件/参数/schema/失败/澄清/不调用/开发授权边界，按真实注册表和独立声明模拟工具区分 |
| 上下文和多轮辅助 | 16000 | 原始对话连续性、指代/更正、多角色来源、聊天任务切换与记忆证据 |
| 合计 | 80000 | 主要用途互斥，变体属于同source/group，不能跨池重复加总 |

这些池配额是本轮规划拆分，可随实际独立来源、token分布和验证调整；不是经消融得到的最优配比。80000是合格训练集目标，不用低质/重复数据强行结账；补量困难要报告缺口。

5000段黄金建设目标保持：4000训练+500validation+500test。500黄金长块已在4000内，不因总量扩大而强迫所有上下文样本变20轮。总validation暂1500/test500，其中包含黄金部分，后续按场景组覆盖确认够不够，不因总量变大自动给出未经核查的分母。

## 3. 缺口与来源

原有3429候选单元是未去重/分组的源块+旧工具行，其中部分要留做评估，并不是已冻结训练数。若乐观假设全部可用且不留评估，相对80000账面差76571；这不能作为实际采集结算。黄金5000的账面缺1571仍是独立建设口径，不再额外叠加至总差额。

辅助训练目标由21000提高到76000，当前冻结合格数仍0。旧NaturalConv/COIG/Muice来源方案继续作为调查入口，但小型角色集不能按总量同比放大：先核允许用途、独立段数和clean子集，必要时补新的可用来源与自产不同场景。当前没有承诺某个来源已能提供指定万条。

工具24k主要解决已知选择/参数/概念范围，不能靠每个工具模板改数百个同义句凑数。外部function-call轨迹与YHLZ执行结果须区分，teacher不能凭空写真实执行；先保留真实协议/语义，后补语言变化。

## 4. 训练与人格保留

- 先做模板/labels/工具轨迹小试，再建立4k、20k、40k、80k的评估节点：可以是分层子集或checkpoint，并非自动顺序训练4遍，也不等于这些规模全都必须另租卡。
- 基础黄金不因扩到80k而失去作用。4000段在80k按记录仅5%，这只是算术；真实影响看有效assistant token/采样/训练顺序。需实测核心回放或适量重采样，不能把重复曝光计作新增样本；暂无最优权重。
- 验证辅助池是否重新带入客服腔、误派开发或概念扩大；表现恶化时定位来源并修样，不因还没训满80k就硬继续。
- 每版记录有效监督token、长块截断、工具schema、group划分和checkpoint；固定未见测试，不拿测试失败照抄补训后继续称独立通过。

## 5. token与预算

按每段平均200–400 assistant tokens估算，80k一遍约1600万–3200万有效输出tokens；按整段平均600–1600 tokens估算约4800万–1.28亿输入序列tokens。这里是平均长度假设乘法，不是PT模板实算；长块/工具schema/视听token可超出区间。只用于预留资源，正式数量、时长和GPU配置等真实渲染统计后再定。

多epoch增加训练暴露量，不增加独立数据；未运行新训练、下载大库或调用付费teacher。Gemma E4B PT已定案，自有核心无需整库推倒，当前重点仍是工具与概念适用边界。租卡后V8原loss/trainer_state/参数/sft.log优先回收不变。
