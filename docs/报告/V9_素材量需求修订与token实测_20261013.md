# V9 素材量需求修订与真实 token 实测

日期：2026-10-13。触发：老爹「现在首先确定素材量，8w 条肯定不够」。
本文只做两件事：**① 用真实 tokenizer 实测现有素材，把"条数"换成可核的语义量；② 据此提出修订后的分池需求与产能约束**。不声称已训练、不声称 8w 或任何数字已经足够/必然成功。

---

## 1. 口径修正：为什么"条数"不能当需求

"80000 段"本身没有定义一段有多长。实测显示同一"段"的监督量可以差 3 倍：

| 类型 | 实测监督 tokens/块 | 样本 |
|---|---:|---|
| 中短块（对话样本） | **244** | 1993 块实测均值 |
| 承认不确定（单轮短答） | 24 | 155 块 |
| 长块（>20 轮） | **730** | S01 首批 3 块 + 测试样本 2 块 |

**结论**：同样是"一段"，长块装的监督信号是中短块的 3 倍。所以需求应当写成 **assistant 监督 token 量 + 独立场景数**，条数是这两个量的导出值，不是目标本身。

**测量边界（重要）**：本轮 token 计数只统计自然语言正文（`### …问N/答N` 下的台词行）。工具轨迹里的 `<tool_call>` JSON 与工具返回 JSON 被当作协议载荷跳过——实测 T01 轨迹样张 10 条为 **2062 监督 tokens / 10 条 = 206/条（仅正文）**。真实训练时 tool_call 的 function JSON 与 tools schema 另需计入（旧 v8 记录：schema JSON 299572 tokens 另计），因此**工具池的条数→token 换算在正式冻结前必须用最终模板重算**，本文表 2.1 里工具池"600/块"是工作假设，不是实测。

现存量核对（`cache/v9_materials_preparation/20261013/token_measure.json`，自实现 BPE 近似实测，tokenizer = `models/gemma4-hf/gemma4-e4b-text/tokenizer.json`，262144 词表）：

| 池 | 块数 | 整块 tokens | assistant 监督 tokens | 监督/块 |
|---|---:|---:|---:|---:|
| 核心·对话样本 | 1993 | 531924 | 486785 | 244 |
| 核心·记忆v2 | 249 | 29334 | 21886 | 88 |
| 核心·诚实边界 | 180 | 20032 | 15305 | 85 |
| 核心·安全拒绝 | 120 | 7893 | 7893 | 66 |
| 核心·承认不确定 | 155 | 6979 | 3769 | 24 |
| 核心·真实对话 | 25 | 1342 | 1147 | 46 |
| 核心·优质样本 | 8 | 606 | 486 | 61 |
| 已改写·批次01 | 15 | 2850 | 2615 | 174 |
| 长块·S01首批 | 3 | 2446 | 2066 | 689 |
| 长块·测试样本两集 | 2 | 2016 | 1583 | 792 |
| **合计（已解析 2750 块）** | **2750** | **605422** | **543535** | **198** |

汉字→token 实测比：**约 0.90 token/汉字**（中英混排素材平均）。

对照 v8 装配产物（记录 2026-10-11）：`data/finetune/sft_persona_v8r4.jsonl` 4047 条、assistant 正文 **409039** tokens。**现有存量（0.54M）与 v8 装配量（0.41M）同量级——这就是现在手里真实的全部监督信号。**

## 2. 修订建议：8w 条不够，但"条数"不该是主目标

### 2.1 换算：8w 条在今天是什么量级

按现有各池实测密度外推 8w 条（核心 4000×250、说话 36000×400、工具 24000×600、上下文 16000×600）：

| 池 | 配额 | 假设监督/块 | 监督 tokens |
|---|---:|---:|---:|
| 核心黄金 | 4000 | 250 | 1.0M |
| 说话与一般任务 | 36000 | 400 | 14.4M |
| 工具与概念边界 | 24000 | 600 | 14.4M |
| 上下文与多轮 | 16000 | 600 | 9.6M |
| **合计** | **80000** | — | **39.4M** |

单遍 39.4M；3 遍 118M；5 遍 197M；10 遍 394M。

**判断**：39.4M 监督 token 对 4B 模型不算"多"，但**也不至于严重不足**——它的问题不在总量，而在这三条：

1. **分布严重偏轻**：核心黄金按 4000×250 只有 1.0M 监督 token（占 2.5%）。人格/哲学/关系/诚实这些"元亨之所以是元亨"的部分，监督量最薄。
2. **密度低**：中短块 244 tokens/块意味着大量"段落"其实是短问答对；靠这种块堆到 8w，等于把轮数和场景都摊薄。
3. **补量的天花板不在写不动，而在场景会写尽**：日常闲聊的独立场景是有限的，硬凑到 36000 段必然产生近重复与模板变体——这恰好违反既定原则（"同一句改写几十遍不算新增"）。**单纯加条数会自伤。**

### 2.2 修订后的需求（以监督 token 与场景覆盖为主，条数为导出值）

| 池 | 现冻结/可用 | 建议目标 | 主导约束 | 产能风险 |
|---|---:|---:|---|---|
| 核心黄金（人格/思想/关系/诚实） | 15 冻结；约 2750 块存量待审 | **8000–10000 段，≥4M 监督 token** | 质量上限由人审决定；长块化提升密度 | 低（自有素材+长块产线） |
| 说话与一般任务 | 0 | **18000–24000 段** | 许可（NaturalConv 非商业 / Muice NC / COIG 逐子集） | **高：许可不清则无法记数** |
| 工具与概念边界 | 0 | **16000–20000 条轨迹** | 真实 registry schema + 参数/条件组合独立性 | 中（可合成，但必须声明真实/模拟） |
| 上下文与多轮 | 长块 5 块 | **12000–15000 段，其中 >20 轮长块 ≥1500** | 长程对话来源稀缺 | 中高（长块单产慢） |
| **合计（训练）** | — | **54000–69000 段 / 40–50M 监督 token** | — | — |

另留 validation 1500 / test 500（按 source group 切，不跨边界泄漏）。

**关键判断三条：**

1. **长块要加权，不是等权。** 长块 730 tokens/块 是 3 倍密度，且是上下文池唯一能真正教"长程"的载体。500 长块目标偏低——建议提到 **≥1500 块**，这是四条线里唯一能同时提量提质、且不依赖外部许可的。
2. **工具池是唯一可以"合法堆量"的池。** 每个工具的参数/缺参/失败/不调用/权限边界都是独立场景，16000–20000 条有真实的信息量；但要守住"名称/参数/结果一致 + 模拟显式声明"。
3. **说话池的量取决于许可，不取决于我的产能。** NC 池（NaturalConv/Muice）若只用于非商业可隔离使用；否则这条 20000 段的池子必须另找可核来源，缺口要如实报，不拿未核许可的集填账。

### 2.3 与旧文件的关系

- `V9_八万段语料目标修订_20261011.md`（8w 目标）与 `V9_PT训练素材量与工具概念边界_20261011.md`（25000 初始预算 + 5M–10M 有效监督 token 预算）**均不推翻**，本文是第三次修订：条数不再是主口径，**监督 token 与独立场景数**成为主口径；80000 作为"段数下限"保留，真正要盯的是 ≥40M 监督 token 与长块 ≥1500。
- 8w 条若按现密度实现，就是 39.4M 监督 token，落在旧文件"5M–10M"预算之上、但没有质变；所以**"8w 不够"的准确含义是：靠中短块堆到 8w 只换来 40M 监督 token 且场景会重复，必须改成"长块加权 + 工具池堆量 + 说话池看许可"的结构**。

## 3. 顺带查出的存量数据质量问题（扩写选源必须避开）

本轮抽看源块时实测到两类问题，与盘点报告"689 块触发线索"一致：

1. **口癖越界**：对话-10（哲学）元亨答3 用了「理论上来说」——按作业单这是利贞专属口癖，元亨不得使用（门控 story/general 档对此是禁项）。
2. **整段自我复读**：对话-20（故事）元亨答1/2/3 是同一大段文字重复三遍（仅开头几个字不同）。这类块**不能直接进训练集**，也不能作为扩写母本——否则教出来的是复读。

处理建议：这类块在重写/扩写时**修掉并登记**，不静默保留；统计上它们属于"待修"而非"可用存量"。
