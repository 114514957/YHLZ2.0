# 翻唱工作流 v2（快速分离 + FP16 SVC + 双验收）

时间：2026-09-23 ｜ 台账：0466 ｜ 状态：**整首《洛天依-一花依世界》通过验收**

## 背景与根因

- 老爹判定整首"快速版"（无人声分离）"没一句人话"。
- 根因：SVC 的内容取自**混音**（器乐+人声）→ 内容单元全乱 → 废。对照实验：《传奇》51.5s **分离版**
  SVC 的 ASR 逐句全对（"只是因为在人群中多看了你一眼…"）。
- 旧分离器 BS-Roformer：整首 288s 要 **45 分钟以上**（且与 llama 抢 8GB 显存时退化到 12x 实时）。

## 现管线（4 步，全部真机实测）

| 步骤 | 工具 | 耗时（288s 整首） | 备注 |
| --- | --- | --- | --- |
| 1. 人声分离 | demucs `htdemucs`（GPU） | **~13s**（22x 实时） | `tools/wsl_fast_prep.sh` |
| 2. F0 提取 | SoulX rmvpe（GPU） | **~3s** | 同上脚本内 |
| 3. SVC | SoulX-Singer `cli.inference_svc` | **227s**（14 段，~11-14s/段） | 唱窗内跑；`--fp16` + 段间 `empty_cache()` |
| 4. 验收 | `verify_cover.py` + `cover_asr_check.py` | ~2-3 分钟 | 内容/音高/歌词三重 |

对比旧版：SVC 940s→227s；分离 45min+→13s；总时长 ~1 小时 → **~8 分钟**（含唱窗冷启/模型加载）。

## 关键改动

1. **分离器换 demucs**：`tools/wsl_fast_prep.sh`（新）；`tools/wsl_soulx_prep.sh` 变为调度器——
   默认 demucs，`SOULX_SEP_MODE=roformer` 回退 BS-Roformer 质量档。
2. **SVC 默认 raw 模式**（不 `--auto_shift`）：音高零偏移（median F0 ratio 1.0；auto 档会整体降 ~2-4 半音）。
3. **FP16 默认开**（`SOULX_FP16=0` 关）：速度/显存双收益。
4. **段间清缓存补丁**（WSL 侧，不入 git）：
   `~/soulx/SoulX-Singer/soulxsinger/models/soulxsinger_svc.py` 内 `Inferring segments (SVC)` 循环末尾
   加 `torch.cuda.empty_cache()`——不打补丁时后半程显存碎片化，单段从 13s 退化到 110s+。
5. **验收工具链**（新）：
   - `tools/verify_cover.py`：ContentVec-768L12 内容保真（≤6000 帧 DTW；长音频自动分块余弦）+
     rmvpe 音高比（median ratio / 八度错误率 / 在调占比）+ 基础 sanity（时长/削波/静音比）。
     标定：已知良好 ≈0.86，无关 ≈0.23。
   - `tools/cover_asr_check.py`：faster-whisper large-v3，歌词引导（`initial_prompt`），分块转写；
     输出 ASR 文本 + 与歌词/源人声的字符相似度。
   - 运行器：`tools/wsl_verify_cover.sh`。

## 三轨模式（干声/和声/伴奏替换混回，2026-09-23 晚）

老爹要求：**分离出干声（主唱）、和声、背景音乐 → 只把干声 AI 换成元亨的 → 三轨合拼**。

管线（`cover_job.py --3stem`）：

| 步骤 | 工具 | 耗时（288s 整首） |
| --- | --- | --- |
| ① 人声/伴奏 | demucs htdemucs | ~13s |
| ② 主唱/和声 | **MDX `UVR_MDXNET_KARA_2`**（audio-separator，作用于①的人声轨） | ~2-3min |
| ③ F0 | SoulX rmvpe | ~3s |
| ④ SVC（换元亨嗓，只换主唱） | SoulX-Singer FP16 | ~2min（本次 127s） |
| ⑤ 三轨混回 | `wsl_mix3.py`（主唱1.0/和声0.85/伴奏0.85，峰值限幅0.99） | 秒级 |
| 合计（含唱窗冷启） | | **247s** |

```bash
python tools/cover_job.py "音频素材/翻唱投入/某歌.mp3" --3stem --keep-vocal \
  [--lead-gain 1.0] [--backing-gain 0.85] [--bgm-gain 0.85]
```

- 产物命名带 **`_三轨_`** 标记；入库标签含 `三轨`；分轨留在 `cache/sing/stem3/{lead,backing,bgm}.wav`。
- 本次整首成品：`音频素材/翻唱产出/洛天依-一花依世界_Xiaoyi嗓_三轨_20260923-085200.wav`
  （入库 song_20260923085200；混音前峰值 1.604→限幅 0.99）。
- 验收：主唱内容 0.76 / 音高 ratio 1.0；混音成品前段歌词 ASR 仍逐句可读。
- 环境：`audio-separator 0.47` + `UVR_MDXNET_KARA_2.onnx`（Windows 梯子预取到 `~/soulx/sep_models/`）+ WSL 安装 ffmpeg；
  torch 钉 2.8.0 / torchvision 钉 0.23.0（audio-separator 安装会升级，需回钉）。
- 旧卡拉OK Roformer（becruily）**弃用**：35s 要 18 分钟，慢 30 倍以上。
- **0472 修正**：分轨第二段（主唱/和声）**改用 MDX（`UVR_MDXNET_KARA_2`）**——
  aufr33 会把**原唱同度叠唱留在"和声"轨**（同度占比 88%），只换主唱的成品里原唱仍然很响；
  MDX 把同度叠唱归主唱（同度 0.94）、三度才是真和声（三度 0.66），符合"只换干声、保留和声"。

## 使用方式

```bash
# 1) 一键翻唱（全流程唱窗：demucs 分离 + F0 + SVC），留存分离人声便于验收
python tools/cover_job.py "音频素材/翻唱投入/某歌.mp3" --fast-sep --keep-vocal

# 2) 验收（内容 + 音高）
wsl.exe -d Ubuntu-22.04 -- bash tools/wsl_verify_cover.sh <人声> <翻唱.wav> [--asr]

# 3) 歌词核对（whisper large-v3，歌词引导）
wsl.exe -d Ubuntu-22.04 -- bash -lc \
  'LD_LIBRARY_PATH=$HOME/soulx/venv/lib/python3.10/site-packages/nvidia/cublas/lib \
   $HOME/soulx/venv/bin/python /mnt/c/.../tools/cover_asr_check.py <翻唱.wav> \
   --lyrics <歌词.txt> --chunk 13 --no-context'
```

工作台（QQ/控制台）路径自动走新默认：分离=demucs、SVC=raw+fp16。
SVC 需要独占唱窗（GPU 互锁），聊天暂挂 ~5 分钟；分离/F0 可与聊天共存（demucs 只占显存十几秒）。

## 环境坑（WSL）

- hf-mirror 偶发 ReadTimeout：`faster-whisper-large-v3` 需 `tokenizer.json`/`vocabulary.json`；
  缺失时用 Windows 侧 curl（梯子）补齐到 HF 快照目录，或 `HF_HUB_DOWNLOAD_TIMEOUT=60` 重试。
- ctranslate2 运行需 CUDA 12 库：`LD_LIBRARY_PATH` 指向 venv 内 `site-packages/nvidia/*/lib`。
- demucs 权重默认走 huggingface.co（墙）：必须 `HF_ENDPOINT=https://hf-mirror.com`。
- SoulX 管线里 pydub 找不到 ffmpeg 只是 warning（mp3 由 libsndfile 解码），不影响。
