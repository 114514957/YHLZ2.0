# V9 素材格式 · 国标合规核验与整改方案

日期：2026-10-13。触发：老爹「你看一遍有关人工智能大模型训练的国标，还有优秀的内容，确定咱们的素材格式可靠可用」。

**先说结论（一句话）**：**格式本身可靠可用**——中间稿（.md）元数据齐、导出稿（JSONL）结构统一、且我们**手上已经有一份 18567 条的真实中文对话语料**（`corpus_qq.jsonl`，带 group/user/ts/tags）。**但"符合国标"这四个字现在不敢说**：GB/T 45654—2025 要求的**四类留痕**（来源抽样评估、4000 条抽检、个人信息同意/匿名化、安全标注规则）我们现在**一样都没有**。

## 2. 我们现在的格式（实测）

核验脚本：`tools/v9_gb_compliance_check.py`（只读），结果 `cache/v9_materials_preparation/20261013/gb_compliance_check.json`。

### 2.1 中间稿：`docs/素材/**.md`（11 个文件、2795 块）

实测元数据出现次数：

| 字段 | 出现次数 | 说明 |
|---|---:|---|
| emotion / length_tier / contract | 2794 | 几乎每块都有 |
| status | 2786 | keep/candidate/drop |
| subtype | 2537 | |
| category | 2300 | 哲学/日常/故事/技术/闲聊 |
| fiction | 1468 | 虚构标记（模型可见框架靠它） |
| source | 735 | 来源标注 |
| expansion_of / continuation_of | 32 | 派生关系（防切分泄漏用） |
| tool / simulation | 各 10 | 工具轨迹样张用 |

**判定：作为"中间稿 + 人审载体"，格式是稳的**——必需元数据零缺失，派生关系有登记（`expansion_of` 已经在用了）。

### 2.2 导出稿：`data/finetune/*.jsonl`

| 文件 | 记录数 | JSON 错误 | 顶层键 | 带 tools | **带安全标签** |
|---|---:|---:|---|---:|---:|
| `sft_persona_v8r4.jsonl` | 4047 | 0 | messages / source / tools | 626 | **0** |
| `tool_use_v8.jsonl` | 626 | 0 | messages / tools / source | 626 | **0** |
| `corpus_qq.jsonl` | **18567** | 0 | text / group / user / nick / ts / tags | 0 | **0** |

role 分布：`system 4673 / user 8288 / assistant 8624 / tool 902`。

**判定**：导出格式统一（messages+role，工具样本带 tools），**无一处 JSON 损坏**——训练器能直接吃。**但零安全标签**。

### 2.3 关键好消息

`corpus_qq.jsonl` 有 **18567 条真实中文对话**，且**自带 group / user / nick / ts / tags**——这正是国标要求的"可追溯"结构。**我们缺的不是数据，是标签与留痕。**

## 3. 逐条对照 GB/T 45654—2025（训练数据部分）

| # | 国标要求 | 我们现状 | 判定 |
|---|---|---|---|
| 1 | 采集**前**对拟采来源抽样评估，违法不良信息 >5% **不得采集** | 外部来源（NaturalConv/Muice/COIG/QQ 群）**无任何抽样评估记录** | ❌ 缺证据 |
| 2 | 采集**后**对每个来源抽样核验，>5% **不得用作训练数据** | 同上 | ❌ 缺证据 |
| 3 | 不得采集 robots 明确拒绝 / 个人已拒绝授权的数据 | 公网抓取（百科/维基/萌娘/Fandom）**未留 robots 记录**；QQ 群为自有群但**含他人发言** | ⚠️ 部分 |
| 4 | 用于训练前对**全部**训练数据过滤违法不良信息 | 门控 v1.0.1（禁项/纪律/防污染）+ 人工抽审；**无全量过滤报告** | ⚠️ 有机制、无留痕 |
| 5 | 过滤后**人工抽检 ≥4000 条、合格率 ≥96%** | **从未做过** | ❌ 缺证据 |
| 6 | 具备**训练数据知识产权管理策略和规则** | 有 `rights_scope_status` 字段与"逐本核权"约定；**无成文策略文件** | ⚠️ 部分 |
| 7 | 个人信息：使用前取得**对应个人同意** | QQ 群友发言属他人个人信息，**无同意记录** | ❌ 缺证据 |
| 8 | 敏感个人信息：取得**单独同意** | 同上 | ❌ 缺证据 |
| 9 | 标注规则：**功能性标注与安全性标注分别制定** | 有功能性规范（作业单 v1、门控说明 v1.0.1、写作规范 v1）；**无安全性标注规则** | ⚠️ 部分 |
| 10 | 安全性标注规则**宜覆盖附录 A 全部 31 种风险** | 现无 31 类风险映射 | ❌ 缺 |
| 11 | 标注**执行**与**审核**不得同一人 | 单人项目（老爹审 + 我产）——需在留痕里写明职责分离方式 | ⚠️ 需说明 |

| 13 | 输出合格率 ≥90%、拒答率 ≥95% | 属服务运营指标，**语料环节不判** | ➖ 本轮不判 |

**统计：❌ 缺证据 5 条、⚠️ 部分 5 条、➖ 不适用 3 条、✅ 0 条。**

## 5. 我的判断

1. **格式不用推翻。** 中间稿（.md）与导出稿（JSONL）都站得住；真正的短板是**标签与留痕**，不是格式。
2. **最该先补的是 P0-2 和 P0-1。** 来源登记册一建，5% 双评估就有地方落；31 类映射一有，安全标注才有规则可依。这两件是后面所有事的底座。
3. **`corpus_qq.jsonl` 是这次最大的意外收获**——18567 条真实中文对话，带 group/user/ts/tags，做匿名化+标注就能直接进"上下文与多轮"池。**建议优先做它**。
4. **一个必须说的边界**：本文不是法律意见，也不是合规结论。我核的是"我们有没有按国标该做的动作做"，答案是**没做，也还没留痕**；补上之后才能谈"符合"。
