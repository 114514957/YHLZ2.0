## 2. ❌ 硬问题：258 条"利贞当独立 assistant"（必须处理）

**样本实况**（`sft_persona_v8r4t_train.jsonl`，source=`lizhen:对话-862｜技术`）：

```
[system]    你是利贞——元亨的伙伴、靠谱的技术担当。稳重、博学、直接，话不多但到位……
[user]      元亨：利贞，我那张卡才跑两步就报显存不够，明明参数不大，这也太离谱了吧。
[assistant] 先给结论：报显存不足通常不是模型参数单独占满的，而是参数、梯度、优化器状态……
            第一，推理时权重本身占一份……第二……
```

**三重冲突（任何一条都足以判它不能进 V9）**：

1. **身份冲突**：0802 明确「利贞是家里那台接入了 DE 的主机，**不特指哪个智能体**」——而这批把利贞训练成**有 system 人设的独立助手**；
2. **声音反转**：**元亨在请教技术、利贞在答技术**——正好把两个人的位置调换了（与本次会话里 L01 批次的同款缺陷）；
3. **文体冲突**：答话是「先给结论／第一／第二」的**讲台腔**，正是 2026-10-11 作业单明令消除的写法。

**历史来源（不是新问题）**：台账 0564/0651 就记过"利贞 300 条独立 assistant 样本"，`V9_PT语料准备执行方案` §2 也写过「现装配器还生成独立利贞 assistant 样本；在元亨专用 V9 中应**单独控池**，不能混成身份混淆正例」——**规矩早就有，只是一直没执行**。

**处置（建议，待老爹点头）**：
- **A 案（最低风险，推荐先做）**：V9 装配时**排除**这 258 条（单独产物里留存，不删源）；
- **B 案**：把技术内容**改写成元亨自己讲**（元亨从"请教者"变回"有技术主见的人"），这样技术池不损失——但这是改写工作量，且要先过人物声音审查；
- **C 案**：保留但打标（**不推荐**——身份混淆正是要防的东西）。
