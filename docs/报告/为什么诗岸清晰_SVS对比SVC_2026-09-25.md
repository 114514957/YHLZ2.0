# 为什么"诗岸"听起来清晰？——SVS vs 我们 SVC 链路的技术拆解

时间：2026-09-25 ｜ 台账：0494 ｜ 性质：技术研究（非结论性定案）

## 一、结论先行

诗岸（Synthesizer V 声库）的清晰度与表现力，核心不是"换声换得好"，而是**技术路线不同**：

| | 诗岸 = SVS（歌声合成） | 我们（SoulX/DDSP）= SVC（歌声换声） |
| --- | --- | --- |
| 输入 | **音符 + 歌词（音素）** | **别人唱好的音频** |
| 音高 | 显式（MIDI） | 从音频提取（rmvpe） |
| 吐字 | 显式（歌词→音素） | 从音频推断（ContentVec） |
| 源瑕疵 | **不存在** | 如实继承/放大（分离残留、混响、和声、怒音） |

**"清晰"是 SVS 的结构性优势；SVC 的清晰度上限被"源录音"卡死。**

## 二、SVS 为什么清晰（拆解）

1. **音素显式**：歌词直接给出音素序列，吐字不靠"猜"。
   - SVC 靠 ContentVec 从源唱里推断内容——源唱有瑕疵（破音/气声/混响），内容就跟着漂（我们实测：和声 cos 0.4、门限吃字）。
2. **音高/节奏显式**：音符给精确 F0 与时长。
   - SVC 靠 rmvpe 提 F0：高音区抖动/八度错、和弦直接失效（实证：392Hz 以上崩坏、差帧 82%）。
3. **不为源瑕疵买单**：不吃分离误差、混响、叠唱、怒音、房间声。
   - 我们的链路每一步误差都会传导并放大：分离 → F0 → 换声 → 降噪 → 混音。
4. **声库数据与建模**：专业歌手数小时干净、音素均衡的录音；专为**歌唱**建模（颤音/气声/力度/张力可参数化）。
   - 加上人类"调教"（精修 pitch/表情/动态）——成品的一部分，SynthV 社区生态就是靠这个。
5. **声码器与规格**：现代 SynthV AI 声库用高质量神经声码器、更高采样率、干净训练域；
   - 我们的换声还要在 24k/44.1k、分离域、降噪域之间来回搬运误差。

## 三、我们的实证对照（本仓记录）

- DDSP：G4(392Hz) 以上崩（差帧 51-82%）；多声部乱唱（cos≈0.4）；-60dB 绝对门限吃字。
- SoulX SVC：392Hz+ 退化（差帧 11-17%）、高音区需降调；合唱/和声必须换 SoulX 或保留原声。
- 结论：这些坑都源于"源是真实录音"——而这正是 SVS 从结构上避免的。

## 四、可落地：我们也有一条 SVS 路

本仓 SoulX-Singer 除 SVC（`cli/inference_svc.py`）外，还有 **SVS 推理**（`cli/inference.py`，依赖 preprocess 的歌词/MIDI 转录）：

- 输入：**歌词**（我们有）+ **音符/F0**（可从原曲提取后再校正）+ **prompt**（元亨嗓）；
- 输出：元亨嗓"从零唱出"这首歌 → 不吃源唱瑕疵，吐字/清晰度预期上一个台阶（更接近诗岸式清晰）。
- 代价：需要"打谱"一步（歌词与旋律对齐/校正），表现力仍需人工调教。
