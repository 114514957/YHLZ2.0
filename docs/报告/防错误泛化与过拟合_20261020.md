# 防错误泛化与过拟合 · 工具轨迹重建 v9 · 2026-10-20

> 触发：老爹「这不行，需要预防错误的泛化和拟合」。
> 上一步把生成轨迹砍光后 tools 池只剩 8 条真实轨迹——**8 条必然背样例**（过拟合），
> 而 43 个工具里 35 个没见过（错误泛化）。本轮按协议重建。

## 1. 先量化问题

`v9_tool_schema_check.py` 审旧 `tool_use_v8.jsonl`：451 次调用、覆盖 **34/43（79.1%）**、
工具名全真、**0 非法参数、0 缺必填**——schema 干净，但**缺 9 个工具**，且全是**生成**未标记。

## 2. 重建协议（`tools/v9_tool_traces_synth.py`）

只从**真实注册表 43 项**出发，逐条标 `simulation: true`，施加六道防过拟合控制：

| 控制 | 做法 |
|---|---|
| **覆盖** | 每个工具 ≥1 正例；每工具上限 **10 条**（防单工具主导） |
| **场景** | normal / missing-required（缺参先问，不调）/ empty-result（查无直说）/ error（如实报错）/ no-call（不该调），正:负 ≈ 2:1 |
| **多样性** | 每场景 ≥3 种措辞；参数值取自占位池（**不写真实文件内容**，防记忆泄漏） |
| **近重复** | 5-gram Jaccard > 0.8 丢弃；**去重只比对话本体**（system 相同不算重复） |
| **留出** | **6 个工具完全不进训练**：`file_share`、`ledger_add/delete/update`、`qq_runbatch`、`qq_shutdown` → 测"没见过的工具会不会乱调/乱编参数" |
| **标记** | `simulation: true` / `generated: true` / `group_id=sim:<tool>:<scenario>` |

## 3. 产出（`data/finetune/tool_use_v9_synth.jsonl`）

## 4. 门与语料的变化

- 出集门：**`simulation: true` 的轨迹放行**（工具名仍须在白名单）；**未标记的旧 `tooluse` 继续隔离**（`generated-tool-trace`）；
- PT 语料：`load_tool_synth()` 接入 → **tools 池 = 168（160 合成 + 8 真实）**；
- 顺手修了一个真缺陷：**前缀近重去重对短样本误杀**（工具/对话类前 64 字常相同，160 条只活 9 条）→ 前缀去重只对 ≥400 字长文生效。

**base v12**：**11,861 篇 / 21,710,555 token / 14.83%**；四池 self_core 2026 / speaking 4647 / **tools 168** / context 5020。
