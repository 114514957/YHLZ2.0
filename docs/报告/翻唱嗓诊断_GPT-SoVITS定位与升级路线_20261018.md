# 翻唱嗓专项：GPT-SoVITS v5 能做什么、不能做什么
## ——「元亨语音包」＝翻唱嗓的口径更正与升级路线

- 时间：2026-10-18（承接同日《GPT-SoVITS-v5研究》）
- 触发：老爹更正——「元亨语音包」指的是**翻唱那条嗓**，不是 TTS 克隆
- 结论先行：**翻唱是 SVC，GPT-SoVITS 是 TTS；v5 不能换声、不能唱，不能替代 SoulX-Singer。** 翻唱现在不好听，主因在**后处理把音色往原唱方向推** + 零样本 SVC 上限 + 24 kHz 带宽，不在 TTS 引擎。
- 证据等级：**[实测]** 本机数字 ｜ **[代码]** 工作台/脚本 ｜ **[官方]** 上游文档 ｜ **[推算]** 待实测

## 0. 一页纸结论

1. **口径更正**：GPT-SoVITS 是「文本 → 语音」，没有 F0/时值条件，**唱不了，也换不了声**。拿它替 SoulX-Singer 做翻唱，是范式错配。
2. **v5 的正确位置**：不是翻唱引擎，是**「元亨本音」的制造机**——48 kHz 干净说话嗓 / 稳定微调 / 语料与 prompt 工厂。它属于路线里的 **P3**，不是第一步。
3. **现在最大的问题不是引擎，是后处理**：`清晰增强` 的实现是 `AI干声 + 0.65 × 原唱干声(>6 kHz)`——**主动把 65% 的原唱高频叠回去**；`柔化` 再去齿+饱和。两步叠加，实测「像原唱」从 **0.47 → 0.70**，「像元亨」从 **0.64 → 0.56**。
4. **第二大的问题是零样本 SVC 的上限**：训练式（DDSP 40 万步）相似度 **0.6021**，零样本 SoulX 只有 **0.4834**（+25% 相对），而且训练式推理是**秒级**，SoulX 是 **2–5 分钟/首**。RVC 线 2026-10-10 就定了，**至今没开工**。
5. **第三是带宽**：SoulX 输出 24 kHz，语料源头是 Edge 24 kHz，8 kHz 以上能量 AI 只有 **~1%**，原唱 **5.66%**。
6. **建议顺序**：P0 关掉两个注入做 A/B（今天）→ P1 用 BWE 替代「叠原唱高频」→ P2 训 RVC（已验证 +25%、秒级）→ P3 用 v5 重建 48 kHz 元亨本音 → P4 对「零原曲味」的歌上 SVS。

## 1. 前提纠正：TTS ≠ SVC

| | GPT-SoVITS（TTS） | SoulX-Singer（SVC） |
|---|---|---|
| 输入 | 文本 | **源唱干声**（音高/节奏/咬字都在里面） |
| 音色来源 | 参考音（prompt）+ 微调权重 | prompt 音色 + 目标 F0 |
| 能不能唱 | **不能**（无 F0/时值控制） | 能（保留源唱旋律） |
| 输出 | 说话 | 歌声 |
| 在翻唱链里的位置 | **没有位置**（除非做音色源/语料） | 主引擎 |

所以「用 v5 提升翻唱」这个命题，**只能在‘音色资产’层成立**，不能在‘换声引擎’层成立。

## 2. 现状：链路与参数（代码核实）

```text
源曲
 → demucs 分轨（lead / backing / bgm）
 → MDX 卡拉OK（干声/和声再分）
 → MSST anvuew 去混响（SDR 19.17）        lead_dry
 → F0（wsl_soulx_prep.sh，同时算 prompt F0）
 → SoulX-Singer SVC（fp16，n_steps=64，cfg=3 禁改，**输出 24 kHz**）
 → 清晰增强：AI + 0.65 × highpass(原唱干声, 6 kHz)
 → 柔化 DSP：轻压缩(-18 dB, 2.5:1) + 动态去齿(5k+) + 轻饱和 + 等响
 → 三轨混回：主唱 1.4 / 和声 0.8 / 伴奏 1.13
```

| 参数 | 值 | 出处 |
|---|---|---|
| SVC 步数 | 64（`SOULX_N_STEPS` 可覆盖） | `tools/wsl_soulx_svc.sh` |
| CFG | 3，**禁改**（v8 证明 >3 毁音色） | 同上注释 |
| 精度 | fp16（10× 快、省显存） | 同上 |
| 默认嗓 | `bright`（清亮嗓），prompt = `refs/design_bright/ref01.wav` **7.76 s / 24 kHz** | `sing_start(voice="bright")` |

## 4. 把「性能不好」拆成四件事

### 4.1 不像元亨（最主要）——两个注入点

1. **清晰增强**：`y = SVC + 0.65 × highpass(原唱, 6 kHz)`。这不是「增强清晰度」，这是**把原唱的音色特征按 65% 混进来**。原唱的高频里带着他自己的齿音、气息、声带特征。
2. **柔化**：`deess_mild` 在 5 kHz 以上做动态衰减——**刚叠进去的高频又被削掉一部分**；再加 tanh 饱和，把清亮嗓的锐度磨平。两道处理互相打架，净效果是「更闷 + 更像原唱」。

### 4.2 不清晰——带宽双重天花板

- 语料源头：Edge 合成 24 kHz（Nyquist 12 kHz），上采样到 44.1 kHz **不增加信息**；
- 引擎输出：SoulX SVC **24 kHz**；
- 结果：8k+ 只有 1%，靠「借原唱高频」补，越补越像原唱。

### 4.3 慢——零样本扩散逐段采样

SoulX 64 步、整首逐段，SVC 唱窗 2–5 分钟；训练式 SVC（DDSP/RVC）推理是**秒级**。

### 4.4 高音——降调绕过，不是根治

`pitch_shift=-2/-4` 整首降调，和声/伴奏/高频参照用 rubberband 同步降，能避免破音，但**牺牲了原曲的调性与听感**。

## 5. GPT-SoVITS v5 的真实位置

### 5.1 不能做的事（先把预期钉死）

| 想法 | 结论 |
|---|---|
| 用 v5 替掉 SoulX 做换声 | **不行**，TTS 不接受源唱 |
| 用 v5 直接「唱」一首歌 | **不行**，无 F0/时值条件 |
| 用 v5 的 48k vocoder 给 SoulX 的 24k 输出超分 | **不行**，vocoder 只吃它自己的 mel |
| 用 v5 解决「原曲音色泄漏」 | **不行**，泄漏发生在 SVC 的源唱输入侧 |

### 5.2 能做的事（三条，按价值排序）

**A. 造「元亨本音」——v5 微调一个 48 kHz、稳定的说话嗓**

- 先用高质量源定义音色（真人授权录音 / CosyVoice3 / Fish / IndexTTS2 / Qwen3 VoiceDesign），**不要再用 Edge**；
- 用这 1–2 h 干净 48 kHz 语料微调 v5（8 GB 走 LoRA，全参上云）；
- 产出：`元亨本音 v1`（S1+S2+参考音+评测分），既是 TTS 嗓，也是翻唱的**音色母版**。

**B. 当 RVC 的语料工厂**

- 用 A 的 v5 生成 1–2 h、48 kHz、音色一致的干声语料；
- 训 RVC（训练式 SVC）→ 翻唱引擎换成 RVC；
- 预期：相似度从 0.48 档升到 0.60+ 档，推理从分钟级降到秒级。
- 风险：说话语料训的 RVC，**高音/长音**仍需 A/B（0730 已标注）。

**C. 当 SVC 的 prompt 工厂**

- 用 v5 生成 20–30 s、48 kHz 的干净参考音，替换现在的 7.76 s / 24 kHz prompt；
- 这是**待验证假设**：prompt 带宽提升，SVC 输出的音色细节可能更好；但 SoulX 还要 prompt F0，说话 prompt 的音域窄，未必全面占优。

**D. 非歌唱部分**：念白、歌曲介绍、和声设计、口白。

### 5.3 一个必须说清的边界

v5 的「新 vocoder 压高频伪影」只作用于**它自己生成的 mel**。它的 48 kHz 输出不能拿来给 SoulX 的 24 kHz 结果做超分。**要做带宽修复，应该用 AP-BWE（GPT-SoVITS 仓库里就有 `tools/AP_BWE_main/24kto48k`）或 HQ-SVC/Seed-VC 的 44.1 kHz 输出**，而不是继续叠原唱高频。

## 6. 正确优先级

| 阶段 | 动作 | 工时 | 预期收益 | 风险 |
|---|---|---|---|---|
| **P0** | 出四个 A/B：raw / 只增强 / 只柔化 / 全链；先听「减原味」是否更好 | **半天** | 最大且免费：把「像原唱 0.70」拉回 0.5 档 | 可能觉得「不够亮」，需用 P1 补 |
| **P1** | 用 BWE（AP-BWE 24k→48k）替代「叠原唱 >6 kHz」 | 1 天 | 8k+ 从 1% → 3–5%，**且不引入原唱** | BWE 可能造出假高频，需盲测 |
| **P2** | 训 **RVC 元亨嗓 v1**（2 h 语料现成），接进 `sing_start` 做可选引擎 | 1–2 天 | 相似度 0.48 → 0.60+；整单从 5–11 min → 数十秒 | 8 GB 训练需排班；高音待验 |
| **P3** | 用 v5 重建 48 kHz「元亨本音」→ 重生成语料 → 重训 RVC / 换 prompt | 1 周 | 天花板从 12 kHz → 20 kHz+；摆脱 Edge 音色与版权 | 周期长，需试听定版 |
| **P4** | 对「零原曲味」的歌走 **SVS**（乐谱合成，SoulX SVS UI 已装） | 按歌 | 结构性去掉源唱痕迹 | 需要音准/时值标注，工作量大 |
| **P5** | 指标固化 + 盲测 | 持续 | 防止「越改越像原唱」复发 | — |

> 如果「性能」主要指**速度**：直接做 P2。训练式 SVC 推理秒级，这是唯一能数量级改善的路线。
> 如果主要指**像不像元亨**：先做 P0，再做 P1，P2 兜底。
> 如果主要指**清晰/亮**：P1 + P3。

## 8. 结论

- **翻唱的问题，换 GPT-SoVITS v5 治不了**：它是 TTS，不是 SVC；它连「唱」都不行。
- **真正该先做的是 P0**：把「清晰增强（叠 65% 原唱高频）」和「柔化（去齿+饱和）」关掉做 A/B。0789 已经把病因量化出来了，但「减原味」的 A/B **一直没做**。
- **第二该做的是 P2**：RVC 元亨嗓。训练式在 0731 已经赢过零样本 25%，而且快一个数量级；这条线因为等开工令停了两周。
- **v5 值得做，但它是 P3**：造一个 48 kHz、干净、可版本化的「元亨本音」，再去喂 RVC 和 SVC。**先有本音，再谈翻唱**——顺序反了，就会一直在 24 kHz 的合成音里打转。
