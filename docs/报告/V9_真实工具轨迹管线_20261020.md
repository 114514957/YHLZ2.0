# 真实工具轨迹管线 v1 · 2026-10-20

> 起因：tools 池 982 条**全是按 schema 生成的轨迹**（`tool_use_v*.jsonl`），不是元亨真实调用记录——这是我一直标着的缺口。
> 本轮把它变成**真实留痕**。

## 1. 管线

```
元亨一轮对话（daemon /turn）
   └─ ConversationSession.run_turn 结束
        └─ backend/tool_trace_log.py: log_turn()   ← 新增钩子
             └─ data/tool_traces/live.jsonl        （每次真实调用追加一行）
                  └─ tools/v9_tool_traces_build.py
                       └─ data/pd/v9_tool_traces_real.jsonl   （训练样本：user→tool_calls→tool_result→answer）
                            └─ v9_pt_corpus.py 的 tools 池（source=tooltrace:real，可区分生成/真实）
```

记录字段：`channel / user_text / tools[{name, arguments(脱敏截断), ok, error, output, readback,
elapsed_ms}] / iterations / answer / generated:false`。
隐私：参数里命中 token/secret/password/key 的键打码，参数与输出各截 600 字。

## 2. 首次留痕（已跑通）

## 3. 顺带修的服务问题

触发留痕测试时发现 daemon 的 500：**llama 8081 与 ollama 11434 都停了**，双轨（deepseek→ollama）
在 deepseek 波动时直接 `RuntimeError: dual-rail failed: ConnectError`，连日程任务都在 fail。
已拉起两个服务（8081 UP / 11434 UP），daemon 重启后 turn 恢复正常。
