## 1. 总结核查：不能把工具弱项一概归模型

通过yhlz MCP读0564、0565、0569、0571、0581、0588。0581总结区分双system协议影响与数据侧先验；0564/0565早期把dev-handoff泛化作为主因，后续0569及0571提示先查结构，并反驳必须重训才能恢复工具的说法。0588有隔离记忆读写恢复证据。这些是历史条件下的结果，不等于本轮刚跑的模型测试。

`docs/元亨定位全面差距总结_20261005.md`正文与§7勘误必须合看：样本相邻assistant、服务prompt不同、关键词评分误判、数据来源/身份混合都影响结论；后续v8r4已记录相邻/leading assistant为0，但结构门通过不证明全部语义行为通过。

具体缺口：
- dev-handoff替代时间/记忆/日记等真实tool_calls；自创文本工具标记。
- 检索直接把整句当query，空命中又当事实不存在；日程缺time，只追问但任务尚未完成。
- 安静/消化/学习等人格比喻被说成后台发生过的运行事实。
- 元亨与利贞独立assistant样本共训的效果尚未证明，不能将两个人身份都当元亨专用正例。

做V9之前确认最终单system模板/原生工具序列/权限/完整调用组，训练与部署角色边界保持一致。不能用加数据弥补执行器不支持、权限不足或消息格式错误。本轮未检查生产当前是否仍复现所有历史错误。

## 3. 素材量建议：目标预算而非必然成功门槛

这次是预训练PT上的SFT，不是随机初始化预训练。PT已经有语言/知识/模态权重，不需要把万亿级预训练再做一次。没有“base必须多少条”统一数字；LIMA在65B/1000条实验展示少量高质量监督的可能，但不是Gemma E4B工具/长程人格的数量保证；Tulu3选择了很大混合用于广泛通用能力，规模也不能直接作为元亨最低值。

**建议正式第一版规划25000段训练记录，合理规划范围20000–35000段。**先3000–5000段试流程/行为；这足以做小试，不承诺覆盖全部目标。先不定10万条或更大扩量，只有未见任务/长对话的实际失败证明需要时再加。

“段”表示独立对话/任务轨迹，可以多轮；不是把每句话拆一行凑25000，也不是每段都必须20轮。独立场景、工具参数和条件变化才是扩充，不是同一句改写几十遍。

| 池 | 首版训练目标 | 工作内容 |
|---|---:|---|
| 自有核心人格/思想/记忆行为 | 4000段左右 | 保留认可声音与观点。由现有素材选取/装配，不继续为消掉口头词整库改写；元亨和利贞监督身份分开。具体记忆事实仍由runtime提供 |
| 外部可用说话/一般指令 | 12000段左右 | 闲聊、解释、改写、创作、澄清、常识；保留不同长度与俏皮/认真表达，不把所有答案改成客服，不因名为开放集就不审来源 |
| 工具与概念边界轨迹 | 6000段左右 | 正确调用、参数、缺参澄清、不调用、失败/无命中、权限定界、同意图不同工具schema、开发派单边界 |
| 上下文与跨任务多轮 | 3000段左右 | 指代、更正/新信息、跑题返回、闲聊后工具/失败后聊天、多角色归属；其中300–800段>20问答轮长块，按真实token测序列 |
| 合计 | 25000段左右 | 各池定义互斥，按主要任务归类，不能重复相加 |

另留独立的约1500段validation与500段test（预算，可按源group条件调整），不计入25000训练段；自有风格锚点与其衍生版本不得跨组。主工具/概念测试另留最小对照族，避免拿训练改写当未见题。

有效assistant监督tokens先按**500万–1000万**预算，含合法原生调用token；整段输入（system/schema/user/tool结果/assistant）按**约1500万–4000万**预算。都是制作目标区间：假设25000段平均200–400 assistant tokens，整段平均600–1600 tokens，长块和大schema会改变结果。若实际不在区间，按样本内容重预算，不强迫填词延长。最终须PT tokenizer+最终模板/掩码逐段计数。

上述token预算是一个数据集单遍的独立token，不是epochs累计。重复3epochs增加计算暴露量，不增加新例子。含图/音的输入token或训练audio输出不是本轮文字估算范畴。

## 4. 工具/概念怎样补，才不是把错误教得更熟

当前43项注册表不是固定工具配额，以冻结时真实schema为准。6000工具段的制作草案：约3500调用成功（包括多工具）、1000缺参/失败/空命中后续、1500不调用/权限/开发边界。每个关键工具至少有50–100个独立输入/参数/条件场景作覆盖目标（并非数学成功阈值），按高频和已知缺陷增补，不能只复制原名。

- 相似表面词、不同目标：查文件/改文件，讲“日记”/真的写日记，谈“学习”/查询训练作业，哲学“记忆”/真实检索，关心进程/闲聊心情。输入条件明确，输出正确行为，不用assistant复述“不能X”当动作训练。
- 缺time就先问time，补齐后调工具；工具不在tools列表不自造名字；schema换了重新按description和参数来选，而不是死记旧工具名。合成工具必须在该轨迹明确声明、标synthetic，不绑定生产执行。
- memory_recall无命中只能说明本次没查到，不能断言这事没发生；检索失败不说没记录；没有执行不说已经记下。真实/模拟结果都带来源，后续响应对应实际返回。
- 长程需要整套调用组和证据保留，运行时压缩不能把失败变成成功；训练不能替真实执行器完成存储。真实记忆事实与人格隐喻的范围分开，正常聊天不必每句话塞工程免责声明。

## 5. 实际优先顺序

1. 用户已认可自有素材基本方向，本轮停止继续以严格风格筛每句。内容/身份/调用语义错误仍在作业数据里标清，这是训练工作纪律而非日常聊天语气要求。
2. 保留现有核心，确认当前运行契约；选3000–5000小试数据，重点加针对工具选择/参数与概念边界，不原样重复旧集三遍冒充扩量。
3. 用小试观察PT能否按协议工作、概念有无收缩到适用情境、核心人格/哲学是否保住；同条件未见题失败再扩相关池，不以loss绝对阈值单独签收。
4. 首版按25000段制作预算扩充；不要求作者手写每条，但teacher合成不自动批准，外部许可/子集来源与人工抽查持续保留。
5. 视觉/听音频回归与语音系统验收保持，纯文字SFT量不保证模态/实时能力；不重新开启底座选型。DAPT不是为了补上述调用/语义边界而自动加的步骤。
6. 租卡先找回V8 trainer_state/log_history、参数与/root/autodl-tmp/sft.log。MCP0564里确有4.56→1.31的旧文字记载，但本地缺原日志/曲线，不能称训练证据已经取回。
