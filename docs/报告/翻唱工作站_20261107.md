# 翻唱工作站（2026-11-07）

> 触发：老爹「翻唱工作站，把工作流的 UI 弄上」。
> 位置：`http://127.0.0.1:8321/cover`（元亨工作台顶栏「翻唱」/ 翻唱面板「打开翻唱工作站」进入）。
> 原则：后端只加静态路由，工作流仍走 `tools/cover_produce.py`（S1–S7），不复制业务逻辑。

## 一、页面结构

```
┌ 顶栏：←工作台 · 翻唱工作站 · 状态/计时 · 明暗 ─────────────┐
│ 左：1 选歌（拖拽/点选）  2 设定（嗓/柔化）  开始翻唱         │
│     链路：S1 规范化 → S2 Kim → S3 MDX → S4 Seed-VC          │
│           → S5 柔化 e → S6 三轨混回 → S7 归档入库          │
│ 右：运行（当前阶段 + 计时 + 进度条 + 实时日志）              │
│     试听/对比（原曲 vs 成品，双播放器）                      │
│ 下：成品库（/songs 过滤翻唱，试听 + 时间/来源）              │
└──────────────────────────────────────────────────────────────┘
```

- 上传：`POST /sing/upload?name=`（原始字节）→ 返回 `path`。
- 启动：`POST /sing {target, voice, presets}`；GPU 互锁被占时直接显示后端错误。
- 进度：轮询 `GET /sing/status`（2.5 s），阶段从 `step` + `log` 里 S2/S3/S4-S6 标记推断；进度条按 420 s 估算，完成置 100%。
- 成品：完成后从 `/songs` 找到对应条目，播放走 `GET /songs/audio?id=`；原曲用本地 `URL.createObjectURL`，可 A/B。
- 成品库：`/songs` 过滤 `source~cover | tag=翻唱 | title含翻唱`，最近 30 条。

## 三、边界

- 一次只跑一个任务（后端 `_sing_lock` + GPU 互锁），重复点击会被后端拒绝。
- 唱窗期间生产 LLM 会暂停；跑完由 `close_window()` 拉回（11-06 已修为只认 8081）。
- 页面只读 `/songs` 与 `/sing/status`，不直接读盘；成品落盘仍由 `cover_produce` 负责。
