# 播客拉取换路子：RSS → 音频 → 本地 ASR · 2026-10-21

> 老爹：「我没找到导出，尝试其他方法拉取」。
> 换了三条路，最后走通的是 **播客 RSS 拿音频、本地 faster-whisper 转写**——不需要任何导出功能。

## 1. 试过但走不通的路

| 路 | 结果 |
|---|---|
| 小宇宙/公众号导出 | 你没找到入口，我也没有 API |
| Bilibili 字幕 | 能搜到视频，但 `player/v2` 返回 **空字幕列表**（CC 字幕要登录/UP 主上传） |
| YouTube 转写 | `RequestBlocked`——代理 IP 被 YouTube 挡了 |
| HF 中文播客转写 | 搜不到 |

## 2. 走通的路：RSS + 本地 ASR

```
播客 RSS（iTunes 搜到的 feed）
  → 下载 mp3（47–63 MB/集）
  → faster-whisper small（int8 CPU，自带 ffmpeg/PyAV）
  → 中文转写（1333 段 / 18,368 字 / 779 秒 ≈ 13 分钟）
```

**实测（十字路口·对谈 Treg）**：
> 嗨 我是Cody 本周十字路口的嘉宾是Jason和史天心 Jason是Trig 这个公司的创始人… Trig是在Cloud Code和Codex的工具的open router…

- 中文识别**可用**，但有三类噪声：**无标点**、专有名词音译错（Claude Code → "Cloud Code"、Treg → "Trig"）、无说话人分离；
- 适合当**技术内容/上下文**，不适合教口吻（所以进 `context` 池，不进 SFT）。

## 4. 工程细节（踩过的坑）

1. **`NO_PROXY` 里的 `[::1]`** 会让 huggingface_hub 报 `Invalid port: ':1]'` → 起进程前清掉；
2. **HF 缓存写 `models/` 报 os error 5**（Windows 权限/符号链接）→ 改 `cache/hf` + `HF_HUB_DISABLE_SYMLINKS=1`、`HF_HUB_DISABLE_XET=1`；
3. 模型走 `hf-mirror.com` 镜像（`HF_ENDPOINT`）；
4. 脚本支持**追加模式**（按 content_hash 去重），可一集一集补。

## 6. 这条路的成本与上限

| 项 | 数 |
|---|---|
| 单集时长 | ~60 分钟音频 |
| 转写耗时 | **~13–20 分钟/集**（CPU int8，small） |
| 磁盘 | 每集 mp3 50–80 MB + 转写 JSON |
| 质量 | 中文可用、无标点、专名易错 |

**结论**：能拉，但**慢**。要成规模（50 集+），建议：
1. 换 GPU 跑 faster-whisper（或 funasr paraformer-zh，中文更准）；
2. 或者你给中文转写（最省）；
3. 云 ASR API（阿里/讯飞，便宜且带标点）。
