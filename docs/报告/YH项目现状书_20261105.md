## 6. 本轮新发现：环境层的坑（不是项目代码）

> 这条单独拎出来，因为它会让「体检」本身说谎。

在本机（利贞的 shell）里跑的每个子进程，`NO_PROXY` 都会被注入成
`localhost,127.0.0.1,::1,.maas.aliyuncs.com,deepseek.com,[::1]`。
httpx 0.28.1 解析 `[::1]` 直接抛 `InvalidURL`，**所有 httpx 请求全灭**。

实测（A/B）：

| 条件 | 结果 |
|---|---|
| NO_PROXY 带 `[::1]` | `下载失败: InvalidURL` |
| NO_PROXY 去掉 `[::1]` | `已下载… 成功` |
| `backend.test_target_access` 直接跑 | 1 FAIL（InvalidURL） |
| 同上，进程内先 `sanitize_proxy_env()` | **51 项全绿** |
| `backend.test_llm_stream` 直接跑 | 1 ERROR（`invalid literal for int(): ':1]'`） |

结论：**项目测试没坏，是环境注入了非法值**。launcher 给 daemon 做了 `sanitize_proxy_env`，
所以线上 daemon 不受影响（它确实能调 httpx 打 8081，见 2.4）。
但凡是手动跑的工具、测试、脚本，都会被这个坑误伤——以后报「某能力崩了」之前，先排除这一条。
