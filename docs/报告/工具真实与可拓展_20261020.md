## 2. 落地：真实 + 可拓展

### 2.1 注册表快照（可拓展的基础）

新增 `tools/v9_tool_registry.py`，以 `setup_scheduler_capabilities().export_openai_tools()` 为唯一真源：

- `--snapshot`：导出 JSON 快照（43 项、带 sha16、必填参数、属性列表）
  → `data/tool_registry/snapshot_20261020_02655794e8f890a7.json` + `snapshot_latest.json`
- `--check <轨迹文件>`：校验工具名是否 **100% ⊂ 白名单**（假名即 FAIL）
- `--drift`：快照 vs 当前注册表 → 新增/删除/参数变化（后端加工具后，这里点名"训练数据要跟上"）

实测：43 项、sha16 `02655794e8f890a7`、v6 **FAIL**（15 假名）、v8 **PASS**、真实轨迹 **PASS**、漂移 **无**。

### 2.2 训练侧：生成轨迹默认不进

- `v9_pt_corpus.py`：`TOOL_FILES` 默认空 → **生成轨迹不进 PT**；只有显式 `YHLZ_ALLOW_GENERATED_TOOLS=1` 才收 v8，**v6 永远不收**（假名）。
- `v9_out_gate.py` 新增两条判据：
  - **`fake-tool:*`**：行内工具名不在快照白名单 → 隔离；
  - **`generated-tool-trace`**：`source=tooluse`（生成）→ 隔离；`--allow-generated-tools` 才能放行。
- 门默认加载 `data/tool_registry/snapshot_latest.json` 作为白名单。

## 4. 可拓展性怎么用

新增工具时只改后端注册表，然后：
```bash
python tools/v9_tool_registry.py --snapshot   # 出新快照
python tools/v9_tool_registry.py --drift      # 看训练数据要不要跟上
python tools/v9_tool_registry.py --check data/finetune/tool_use_v8.jsonl
```
训练数据里的工具名永远以快照为准；真轨迹由 `backend/tool_trace_log.py` 自动累积。
