## 1. 复审结论

- 此前遗漏了明确未经过指令SFT的 Baichuan-Omni-1d5-Base。它是符合“base起点+视听说架构”的真实候选，不能再把局部检索未命中当作候选不存在。
- Gemini/Gemma、Qwen、MiniCPM、百川的参数名与部署版本不能混用。量化语言主干、量化完整模型、是否关闭语音生成，是三个不同条件。
- 候选资格最清楚的两条路线：Gemma E4B PT作为视听认知核心，继续使用声音模块的系统路线；百川Omni Base作为原生视听说的研究路线。两者都没有完成本轮8GB部署与V9训练验收，不能定冠军。
- 用户从预训练base开始的要求不撤销；“语音链路端到端”不擅自解释为已同意外接TTS，也不擅自解释为所有模块必须同一套权重。两种架构分别列出，实际交互验收不能互相冒名。
- 原计划是租卡训练并回本机部署；“本地能训练”是需要另外核实的能力，不能把所有候选都按8GB全参训练过滤掉。

## 2. 证据怎么分级

| 级别 | 能证明什么 | 不能证明什么 |
|---|---|---|
| E1：官方权重/阶段说明/配置 | checkpoint存在，PT或SFT阶段被明确声明，架构有对应输入输出模块 | 元亨人格质量、中文哲学实用能力、本机能跑 |
| E2：官方推理/训练代码 | 实际接口、投影器/声码器依赖、loss或训练入口存在 | 示例已在本机通过；训练某一个模态不代表全部模态受支持 |
| E3：上游公布资源/量化方法 | 在上游声明条件下的资源结果，或代码实现的量化路径 | 8GB Windows机器的实际延迟；一切CPU分担配置都可行 |
| E4：本机加载并产出完整结果 | 指定revision/精度/输入/模块开关下可用 | 尚未跑的上下文和交互压力情境 |
| E5：自有题组与多轮盲评 | 当前条件下哲学、主见、陪伴、身份、诚实与记忆/工具行为 | 所有任务或其他底座天然优劣 |

本轮主要完成E1/E2并核对E3；本机只做硬件/源码只读检查，没有候选E4或E5。Gemma现役视觉/哲学表现来自用户体验与既有部署文档，不能冒充PT的新实测。排行榜自报成绩不可跨PT/IT和不同提示词当成人格排名。

### 百川需要进一步核的事项

1. 官方明确未经过指令SFT，解决的是训练起点资格；官方首页的成品模型成绩不能自动归给Base。
2. Base配置已有音频生成相关模块，不能由此保证未经V9训练已能遵守复杂聊天/工具指令。
3. Fine-tuning章节尚未提供完整操作方案，当前Gemma脚本不可只改base路径；需确认forward损失、特殊tokens、processor、PEFT目标、语音code监督和waveform decoder。
4. 原版约11B完整权重。按全部11B均4bit的理想计算仅权重约5.5GB（十进制）；这没有计量化元数据、未量化层、外部声码器、KV、视听激活和系统开销，不是8GB实测或承诺。
5. 模型卡标Apache，但正文同时提社区许可/商业条件，不能沿用卡面标签宣称全用途放行；本项目个人研究和未来发布需分别核实际条款。

- 只读硬件快照：RTX4060 Laptop，总8,188MiB、当时已用4,627MiB；物理内存约15.80GiB、当时空闲约2.93GiB；i7-13700H，Windows家庭版。不把瞬时占用当静态上限，没有停止服务。
- 本地b10991 `conversion/qwenvl.py` 的Qwen25OmniModel过滤器只处理visual/audio_tower，使用thinker_config；现有该转换路径不能证明Talker和语音波形输出被保留。
- 当前项目训练入口是Gemma专用模型类/语言层LoRA正则，build_example只处理文字messages；没有为新Omni语音code监督准备数据/损失。base与Omni的训练接口迁移应独立计划。
- 本地Gemma IT/QAT的mmproj与速度记录是历史部署证据，当前base候选未下载/转换，不保证PT使用旧投影器/adapter即可正常。
- CPU分担也需要系统RAM和带宽，不能在只看显存时忽略16GB内存；当前无本机Omni的短输入、长输入或流式时延测量。

## 6. 暂定名单与验证顺序

**不宣布最终底座。**

1. 对现役Gemma记录同一组文字、看图、听音频输出和系统设置，作为保留能力基线；客服腔成因不用重新验证。
2. Gemma E4B PT与百川Omni Base进入正式候选池。它们满足的语音输出路线不同，分别记录，用户目标不被偷换。
3. 对百川先确认微调forward与特殊token掩码可行，再做短音频+一张图的完整加载/语音输出预检；精度、哪些模块在CPU/GPU、外部声码器、内存峰值、首次声音延迟必须一起记录。只出文字不能签收S2S。
4. 不先完整训练再发现部署不通。8GB预检未通过，保留结果并评估可否调整模块位置/精度；不直接逼用户换硬件或删除视觉。
5. 公平判断base候选必须用同一批经认可素材的小试结果，裸base对话差不能当作SFT后人格必差。只做base候选评估，不恢复旧IT/base成因四臂对照。
6. 验收分开看：中文哲学的理解/反例/修正、主见与关系、多轮记忆/工具证据、视觉听音频、语音忠实度/声线/情绪、实时打断/恢复。不得以总榜高分抵消身份/诚实错误，或用语音流畅度替代认知质量。
7. 旧V8的trainer_state、loss、参数和/root/autodl-tmp/sft.log继续先回收；本次调研不消耗云卡、不声称已拉回证据。
