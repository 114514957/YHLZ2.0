## 2. 审计器本身先做自检（否则"全绿"没意义）

故意注入三种错，看它抓不抓：

| 注入 | 审计器反应 |
|---|---|
| 把 `answer_check` 改错（520→521） | 独立重算 520 → **标签不一致** ✅ |
| 把正文结论改错（"那答案是 99999"） | 正文结论 99999 vs 重算 520 → **不一致** ✅ |
| 把算式改错（"70×8=561"） | `expr_check` 抓出 `70×8=561` ✅ |

**三种全抓到**，审计器的"PASS"才有可信度。

## 4. 审计过程中发现的另外两个问题（已修）

1. **答案重复 81 条**（`dup-answer`）——不同题目给出**同一句答案**（logic/table 为主），
   属于过拟合隐患（模型会背句子）。已给两个生成器加**答案级去重**（`seen_ans`），
   并把 multihop 的数值范围扩大到 11–89 / 2–37、量词多样（条/份/个）：
   - 去重后 `dup-answer = 0`；multihop 曾掉到 40 条，扩范围后恢复 **120**。
2. **`cotdeep` 没进同意映射**——400 条在出集门被当成 `consent-pending` 隔离。
   已补 `CONSENT_BY_DIM["cotdeep"] = "n/a"`，重跑 enrich 后归零。
