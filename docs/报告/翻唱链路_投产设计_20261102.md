# 翻唱链路投产设计（2026-11-02）

> 目标：把 10-22 验收过的那条链（Kim RoFormer → MDX 卡拉OK → Seed-VC → 柔化 e → 三轨混回）
> 变成**不依赖 WSL、可自动运行**的投产链路，产出与验收版逐样本一致。
> 依据：台账 0935（验收配方）、1053/1055（复刻与跑偏）、1058（WSL 系统级坏）。

---

## 一、现状与证据（全部实测）

| 环节 | 结论 | 证据 |
|---|---|---|
| Kim RoFormer（人声/伴奏） | **逐样本一致** | 伴奏 vs 验收版 bgm `corr = 1.0000`；人声 vs 验收版(主唱+和声) `corr = 0.9987` |
| MDX 卡拉OK（主唱/和声） | **一致（audio-separator 原版）** | vocals vs 验收 lead `corr = 0.9988`（RMS 同为 −25.1 dB）；instrumental vs 验收 backing `corr = 0.9997`（−19.4 dB） |
| MDX 卡拉OK（自写 onnxruntime 版） | **不一致，弃用** | 自写版 vs 验收：主唱 `0.28`、和声 `0.89` → 细节口径（compensate/归一化/通道语义）没对齐 |
| Seed-VC 44k / 柔化 e / 混音 1.0-1.5-0.7 | 已复刻 | 20261101-234252_黑夜梦想家_1022复刻，老爹验收通过 |
| WSL | **系统级坏** | `vmcompute` 停止，`wsl.exe` 在我方 shell / MCP cmd / daemon 全部 `E_ACCESSDENIED`；只有交互式（双击）能跑 |

结论：**链路已可逐样本复刻，且不依赖 WSL**（Kim 用 MSST，MDX 用 audio-separator + onnxruntime）。

---

## 二、投产链路（设计）

```
S1 输入规范化   ffmpeg → 44.1k / stereo / wav（原文件不动）
S2 人声分离     MSST Kim RoFormer  (cache/msst/kim.ckpt)          → vocals / instrumental(bgm)
S3 卡拉OK拆分   audio-separator UVR_MDXNET_KARA_2.onnx            → lead(主唱) / backing(和声)
S4 音色转换     Seed-VC 44k（30 步 / cfg 0.7 / f0 / fp16 / bright）→ AI 主唱
S5 柔化         cover_v3_dsp.py --preset e
S6 三轨混回     wsl_mix3.py  主唱 1.0 / 和声 1.5 / 伴奏 0.7（peak 上限 0.99）
S7 归档         音频素材/翻唱产出/<时间戳>_<歌名>/ + 说明.txt + 歌曲库登记
```

**入口**：`tools/cover_produce.py <音频>` —— 统一入口，内部按 S1→S7 串起来，自带唱窗开合。

**分层与职责**
- `tools/svc_kim_split.py`：S2（MSST Kim，自带唱窗）
- `tools/svc_mdx_karaoke.py`：S3 —— **改为调用 audio-separator**（自写实现保留为实验，不投产）
- `tools/svc_karaoke_split.py`：becruily 分轨（备用/对照，不投产）
- `tools/cover_rebuild.py`：给定三轨做 S4→S6（可用 `--svc-wav` 复用）
- `tools/cover_seedvc.py`：历史入口，保留（WSL 优先 + demucs 兜底）

## 三、降级与可见性

| 情况 | 行为 | 必须记录 |
|---|---|---|
| Kim/MDX 原生可用（常态） | 走 S2/S3 原生 | `sep = native-kim+mdx` |
| audio-separator 不可用 | 退 becruily 分轨 | `sep = native-kim+becruily`，日志标注 |
| 原生链全崩 | 退 demucs 两轨（无和声） | `sep = demucs-2stem ⚠ 降级` |
| WSL 可用（交互式） | 可走老命令 `wsl_msst_chain.sh` | `sep = wsl-kim+mdx` |

**原则**：降级必须写进任务日志与产出说明，不允许静默（10-30 那次就是静默降级）。

## 四、资源与耗时（实测）

| 步骤 | 202s 歌曲耗时 | 显存 |
|---|---|---|
| S2 Kim | 52.6 s | 峰值约 7.1 GB（需唱窗） |
| S3 MDX（audio-separator，CPU 回退） | 77 s（分离总时长） | 0（CPU） |
| S4 Seed-VC | 约 2–3 min | 约 6.5 GB（需唱窗） |
| S5+S6 | 约 1 min | 0 |

整首约 **6–7 分钟**；唱窗期间聊天暂停（沿用 `backend/gpu_window`）。

## 五、验收判据（先写死）

1. **分轨一致性**：Kim 伴奏 vs 验收 bgm `corr ≥ 0.999`；MDX vocals vs 验收 lead `corr ≥ 0.99`。
2. **成品指标**（同一首歌与验收版比）：RMS 差 ≤ 1 dB；`8k+` 差 ≤ 0.2 个百分点；立体声宽度差 ≤ 0.05；无削波。
3. **听感**：老爹确认"是 10-22 那个效果"。
4. **可重复**：同一条命令重跑，指标波动 ≤ 0.1 dB。

## 六、风险与待办

- **依赖变更风险**：为跑 audio-separator，`venv-gsv5` 升了 `protobuf 6.31.1`、`numpy 2.5.4`，新增 `onnx / onnx2torch / torchvision(CPU)`。
  → 必须回归：Seed-VC 推理、GPT-SoVITS、demucs、librosa 相关脚本；出问题按台账回滚（protobuf 3.19.6 / numpy 原版本）。
- **onnxruntime GPU 与 torch CUDA 版本不一致**（ort 需 CUDA 13）→ MDX 目前走 CPU（77 s，可接受）；要提速再看是否换 ort 版本。
- 工作台接线：`console_server.sing_start` 目前走 `cover_seedvc.py`，需改为调用新入口并回传 `sep`。
- 待办：正式入口脚本 + 端到端验收（新歌一首）+ 工作台切换 + 回归测试。
