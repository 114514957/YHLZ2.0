## 2. 架构变化说明

### 2.1 变更前

```
voice A ──▶ _prompt_cache (全局单值) ──▶ 下一次加载直接覆盖
```

- `self._prompt_cache` 是单个对象, 由 `QWEN3_TTS_REF_AUDIO` 环境变量决定, `load()` 时提取一次。
- 多声音只能"最后一次加载", 先加载的声音被无声覆盖, 无法共存。

### 2.2 变更后

```
_voice_caches: Dict[str, Cache]
{
  "voice_a": { "prompt": <voice_clone_prompt>, "embedding": <x-vector>, "metadata": {...} },
  "voice_b": { "prompt": <voice_clone_prompt>, "embedding": <x-vector>, "metadata": {...} }
}
```

- 每个 `voice_id` 独立缓存条目, 结构为 `{prompt, embedding, metadata}`:
  - `prompt`: `create_voice_clone_prompt()` 返回值 (合成时传入 `generate_voice_clone`);
  - `embedding`: x-vector 说话人向量 (模型返回对象暴露 `x_vector` 字段时优先, 否则等于 prompt);
  - `metadata`: `{voice_id, ref_audio, x_vector_only_mode, created_at}`。
- `synthesize(text, voice="default", rate="+0%", voice_id=None, **kwargs)` 新增可选参数 `voice_id`:
  - `voice_id=None` → 沿用 `voice` 参数 (默认 `"default"`), **旧调用 `tts.synthesize(text)` 行为不变**;
  - `voice_id` 显式传入时优先于 `voice`;
  - 指定 voice 无缓存 → 日志告警 + 回退默认 voice; 默认也无 → 返回兜底静音 (与旧行为一致, 永不静默失败)。
- `stream_synthesize_text` 同步透传 `voice_id`。
- `load()` 预热逻辑保留: 默认参考音频写入 `DEFAULT_VOICE_ID` 缓存, 已有缓存则跳过。

### 2.3 新增缓存管理接口

| 接口 | 签名 | 说明 |
|---|---|---|
| `load_voice_cache` | `(voice_id="default", ref_audio=None, x_vector_only_mode=True) -> dict \| None` | 提取指定 voice 的说话人特征并写入缓存 (核心入口) |
| `get_voice_cache` | `(voice_id="default") -> dict \| None` | 读取缓存条目 |
| `clear_voice_cache` | `(voice_id=None) -> int` | 清空单个 / 全部, 返回清理数量 |
| `get_voice_cache_stats` | `() -> dict` | 缓存统计: count / voice_ids / has_default |
| `_prompt_cache` (只读属性) | — | 旧属性兼容别名, 返回默认 voice 的 prompt |

### 2.4 约束遵守情况

- ✔ 不 import / 不依赖任何未来模块 (`voice_identity`), 纯底层能力;
- ✔ 未创建 `backend/voice_identity/` 目录, 未实现 Voice Profile / Permission / Voice Registry;
- ✔ `unload()` 时清空全部 voice 缓存并释放显存;
- ✔ 命名风格与现有代码一致 (snake_case 方法 + 中文日志注释)。

## 4. 潜在风险

| # | 风险 | 等级 | 说明与缓解 |
|---|---|---|---|
| R1 | prompt cache 持久化未验证 | 高 | 多声音提取仍需逐次调用 `create_voice_clone_prompt` (3-10s/次), 跨进程无法复用。属 M0 遗留, 与集成审计 R6 一致; M0.1 只修"可共存", 持久化留待后续 spike |
| R2 | 多缓存显存占用 | 中 | 每个 prompt 均为模型内 tensor, 大量 voice_id 会累积显存/内存。当前无容量上限, 由上层 (未来 VIS cache_manager) 负责预算管理; 现有 `clear_voice_cache()` 已提供清理手段 |
| R3 | 未知 voice_id 静默回退 | 低 | 回退默认 voice 会发出告警日志并产出默认声音, 可能被误认为"声音生效"。设计符合"永不静默失败"原则 (有日志), 上层接入时需显式校验 |
| R4 | `voice` 参数语义漂移 | 低 | 旧代码 `voice` 参数被忽略; 现映射为 voice_id 查找。`synthesize(text, voice="edge音色ID")` 类调用会落空回退默认 — 与原行为一致 (原也被忽略), 但新增一条告警日志 |
| R5 | 测试使用 FakeModel | 低 | 单测不触达真实模型 API 细节 (`create_voice_clone_prompt` 返回结构、`embedding` 字段)。真机验证需在 M2 适配器联调阶段执行 |

---

## 5. 结论

M0.1 目标达成: 单实例缓存升级为多 voice_id 缓存 (`Dict[str, Cache]`), 旧接口 `tts.synthesize(text)` 完全兼容, 新增 `voice_id` 可选参数与 4 个缓存管理接口, 14 项单测全部通过 (含"多声音 A/B/A 交替调用不覆盖"核心用例)。本阶段未触碰 Voice Identity 层, 符合阶段边界。

*不进行下一阶段修改。*
