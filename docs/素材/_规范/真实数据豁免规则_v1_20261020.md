# 真实数据豁免规则 v1（2026-10-20）

> 触发：老爹「定豁免规则」。
> 问题：`真实对话样本.md` 是 QQ 实录、**原样保留不得润色**，但它有 40 处不合格——其中 31 处是格式（括号/星号/列表），9 处是元亨自己的客服腔。
> **本规则要解决的是：既不逼着把真实记录改脏，又不把旧毛病喂回模型。**

---

## 1. 一句话原则

**豁免"形态"，不豁免"内容"。**

真实记录长什么样就长什么样（括号、星号、列表、分号），那是**记录形态**；
但**元亨说了什么**必须仍然是我们要她说的——那是**内容**。

---

## 2. 标记方式（块元数据里写，四行缺一不可）

```markdown
## real-qq-4｜小寻虚拟主播交流群
- raw: true
- raw_source: qq_小寻虚拟主播交流群(1094579571)
- raw_captured: 2026-10-05
- polish: forbidden
```

| 字段 | 含义 | 缺失后果 |
|---|---|---|
| `raw: true` | 声明这是原始记录 | 缺 → **按普通块全量审**（不豁免） |
| `raw_source` | 原始出处（群号/平台/时间） | 缺 → 不豁免 |
| `raw_captured` | 采集日期 | 缺 → 不豁免 |
| `polish: forbidden` | 明示禁止润色 | 缺 → 不豁免 |

---

## 3. 豁免范围（逐项列死）

| 检查项 | raw 块 | 理由 |
|---|---|---|
| **括号动作**（（笑）（沉默）） | ✅ **豁免** | QQ 原文自带（图）（链接）（动作） |
| **星号** | ✅ **豁免** | Markdown 残留是原始形态 |
| **列表行**（1. 2. -） | ✅ **豁免** | 原文列举 |
| **分号 / 冒号** | ✅ **豁免**（本就是 WARN） | 书面表达 |
| **风格六条**（句长/留白/称呼） | ✅ **豁免** | 真人打字本来就散，不套模板 |
| **禁词**（我这边 / 我接 / 我认 / 稳了 / 别指望） | ❌ **不豁免** | 这是老爹点名要治的病 |
| **客服腔**（为您 / 建议您 / 我可以帮） | ❌ **不豁免** | 同上 |
| **模板腔 / 报告腔 / 应答模板** | ❌ **不豁免** | 同上 |
| **身份**（元亨在答位、大肥鱼禁言、发言人白名单） | ❌ **不豁免** | 硬要求 |
| **元数据齐全**（emotion/length_tier/contract） | ❌ **不豁免** | 装配必需 |

---

## 4. ⭐ 关键：真实记录里的元亨 = **改造前的旧元亨**

实测 `真实对话样本.md` 31 块：

| 类别 | 处数 | 归属 |
|---|---:|---|
| 格式类（括号/星号/列表） | 31 | 记录形态 → 豁免 |
| **内容类（我这边 5 / 我可以帮你 3 / 收到。1）** | **9** | **全部在元亨嘴里** |
| 非元亨（老爹/陌生人）台词命中 | **0** | — |

这 9 处是**旧版元亨真的那么说话的记录**。**照原样进 SFT，等于把旧毛病固化。**

所以对命中的**元亨轮**，二选一：

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 剔除该轮**（默认） | 保留前一轮老爹提问，该块降为"纯输入样本" | 当前做 SFT 阶段 |
| **B. 标负样本** | 加 `negative: true`，保留原话，供后续 DPO 当 rejected | 做 DPO 阶段 |

**不许既不处理也不标注地原样进 SFT。**

---

## 5. 额度（防止真实数据淹没规范数据）

| 约束 | 上限 |
|---|---|
| `raw: true` 块在**全部训练数据**中的占比 | **≤ 10%** |
| 单一 `raw_source` 的占比 | **≤ 5%** |
| 单块 `raw` 正文长度 | **≤ 800 字**（超长截断或拆块，避免一段灌满上下文） |

超出额度时，按"来源多样性优先"保留，而不是按时间先后。

---

## 6. 门禁实现（`v9_story_gate.py`）

读到 `raw: true` 后：

1. **格式类检查跳过**，计入 `raw_skipped` 计数（不记 FAIL）；
2. **内容类检查照做**（禁词/客服腔/模板腔/报告腔/应答模板）；
3. 输出块名后加 **`[RAW]`** 标记，报告里单列 `RAW-SKIP` 统计；
4. 缺 `raw_source` / `raw_captured` / `polish` 任一项 → **不豁免**，按普通块审。

---

## 7. 审计留痕（每块必须能回溯）

| 要留的 | 写在哪 |
|---|---|
| 原始出处（群号/平台） | `raw_source` |
| 采集时间 | `raw_captured` |
| 禁止润色声明 | `polish: forbidden` |
| 元亨轮是否被剔除 | `dropped_turns: <轮号>` |
| 是否作负样本 | `negative: true` |
| 人工确认人 | `reviewer: <代号>`（审核后填） |

**执行与审核分离**：agent 产出 + 标注，老爹/利贞审核并填 `reviewer`。

## 8. 与既有规范的关系

| 文档 | 关系 |
|---|---|
| `知识产权与来源策略_v1_20261013.md` | 真实数据属 **L1（自有）/ L2（已获同意）**，但 D-1 群成员同意仍未决，**出处必须留痕** |
| `素材格式标准_v1_20261013.md` | 本文是其**例外条款**：raw 块免形态检查，不免内容检查 |

| `安全标注规则_v1_20261013.md` | raw 块照常做宪章扫描（真实对话也可能含风险表述） |

## 9. 自检清单（每块 raw 数据贴入前）

- [ ] 四行标记齐了吗？（raw / raw_source / raw_captured / polish）
- [ ] 格式是原样吗？（不许为了让门禁过而删括号/星号）
- [ ] 元亨轮有没有命中禁词/客服腔？（命中就剔除或标负样本）
- [ ] 有没有把"元亨说的"和"老爹说的"搞混？（实测非元亨台词 0 命中，别自己制造）
- [ ] 占比是否在 ≤10% / 单源 ≤5% 内？
- [ ] 群成员同意（D-1）有结论了吗？没有就先只留档、不进训练集
