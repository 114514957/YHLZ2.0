# V9 素材格式标准 v1（2026-10-13）

> 目的：把"我们现在的素材长什么样"固化成**可校验的格式标准**，并把它与**国标与数标委要求的留痕**衔接起来。
> 依据：① 现有素材实测（`tools/v9_gb_compliance_check.py`）；② GB/T 45654—2025 训练数据条款（见 [核验报告](V9_素材格式国标合规核验_20261013.md)）；③ 数标委 TC609 WG5《高质量数据集 格式要求》等草案的**方向**（该草案原文未取到，本文不逐条引用）。
> 状态：**试行版**，随素材线推进迭代；字段增删需更新本文件与校验脚本。

---

## 0. 一句话

素材走**三层**：**内部稿（.md，人审载体）→ 候选稿（.md，过门控）→ 训练稿（.jsonl，进训练器）**。
**每层都必须能追溯到上一层的哪一块**；三层各自的字段在下文固化。

---

## 1. 第 1 层：内部稿（`docs/素材/**.md`）

### 1.1 结构

```
## <块 ID>｜<分类·短名>
- <元数据键>: <值>            （每块必填，见 §1.2）
### <发言人>问<N>
<台词>
### <发言人>答<N>
<台词>
```

铁律：
1. **轮号在该块内从 1 连续递增**（问与答共用一个序列），不跳号、不重号；
2. 发言人只能取白名单：`老爹 / 元亨 / 利贞 / 陌生人 / 朋友 / 群友`（**大肥鱼只能被提及，不得有台词**）；
3. 块 ID 全局唯一（跨批次不重号）。

### 1.2 元数据字段（分层：必填 / 条件必填 / 合规留痕）

| 字段 | 层级 | 取值 | 说明 |
|---|---|---|---|
| `category` | **必填** | 日常/哲学/故事/技术/闲聊/工具/记忆 | 主要用途分类 |
| `subtype` | **必填** | 短描述 | |
| `status` | **必填** | `keep` / `candidate` / `drop` | **只有老爹认可的才是 keep** |
| `emotion` | **必填** | happy/calm/sad/surprised/neutral… | |
| `length_tier` | **必填** | short/medium/long | |
| `contract` | **必填** | `VOICE_ANCHOR` / `TOOL_EVIDENCE` / … | 该块承担的训练职责 |
| `fiction` | **条件必填** | true/false | **凡虚构必填**；且虚构框架必须**在模型可见输入里生效**，不能只写元数据 |
| `source` | 条件必填 | 来源标识 | 非原创必填 |
| `expansion_of` / `continuation_of` / `adapted_from` | 条件必填 | 源块 ID | 派生关系**必须登记**（防切分泄漏） |
| `tool` / `simulation` | 条件必填 | 工具名 / true\|false | 工具类必填；**模拟必须标 true** |
| `group_id` | **合规留痕** | 分组 ID | 同源/同族样本同组，切分时整组走 |
| `source_id` | **合规留痕** | 来源内定位（章/行/URL） | 精确到段，不只到书名 |
| `rights_scope_status` | **合规留痕** | `pending` / `cleared` / `nc_only` / `public_domain` | 未核 = pending |
| `review_status` | **合规留痕** | `draft` / `gated` / `user_approved` | 人审状态 |
| `consent_status` | **合规留痕** | `own` / `consented` / `anonymized` / `n/a` | **他人发言必填** |
| `content_hash` | **合规留痕** | sha256 前 16 位 | 批准时的内容指纹 |
| `annotator_exec` / `annotator_review` | **合规留痕** | 代号 | **执行与审核不得同一人**（单人项目写清分离方式） |
| `safety_labels` | **合规留痕** | 风险类目列表（见 §4） | 无风险写 `none` |

> **现状差距（必须知道）**：上表前 7 项（必填/条件必填）**已在实际素材中普遍使用**；后 8 项（合规留痕）**目前一项都没落**——这是核验报告里 ❌/⚠️ 的直接原因。

### 1.3 标点与文体硬规则（与门控一致）

- 对话区**不得出现**分号 `；`、冒号 `：`、圆括号、星号；
- 破折号每块 ≤1；短句为主、勤断；
- 元亨不得使用「理论上来说」（利贞专属）；
- **工具协议载荷轮**（整轮纯 JSON 或 `<tool_call>…</tool_call>`）不受禁符限制，但不参与复读扫描。

## 2. 第 2 层：门控与候选（`.gate.txt`）

- 每份候选稿**必须**跑 `python tools/v9_story_gate.py --profile story|general <文件>`；
- 门控 **FAIL=0** 才进人审；WARN 需在交付说明里逐条解释；
- 报告落盘 `<文件>.gate.txt`（可加 `--json`）；
- **门控只保证下限**：像不像元亨、人味、IP 实质相似、人物声音有没有串——**归人审**。
  （2026-10-13 教训：L01 批次机械全绿、门控 PASS 27/30，但人审发现**人物声音整体错位 56 处**。故新增 `tools/v9_l01_voice_mix.py` 作人审前预筛。）

## 3. 第 3 层：训练稿（`data/finetune/*.jsonl`）

### 3.1 记录格式（现行，实测统一）

```json
{"messages": [{"role": "system|user|assistant|tool", "content": "..."}],
 "source": "<来源标识>",
 "tools":  [ ... ]        // 仅工具样本带
}
```

实测：`sft_persona_v8r4.jsonl` 4047 条、`tool_use_v8.jsonl` 626 条，**JSON 错误 0**，role 分布 system 4673 / user 8288 / assistant 8624 / tool 902。

### 3.2 训练稿**必须**补的字段（当前缺失）

| 字段 | 为什么 |
|---|---|
| `source_id` / `group_id` | 切分与溯源（现在 `source` 太粗：只到 golden/memory/scene） |
| `content_hash` | 记录批准时的内容指纹，防"审过之后又改" |
| `safety_labels` | 国标要求的安全标注（见 §4） |
| `consent_status` | 个人信息合规（QQ 语料必填） |
| `annotator_exec` / `annotator_review` | 执行/审核分离留痕 |
| `seq_len` / `supervised_tokens` | 便于长度与监督量核算 |

### 3.3 切分规则

- **按 `group_id` 成组切分**，同源/同族/改写变体**不得跨 train/val/test**；
- validation 1500 / test 500（预算，按场景族覆盖调整）；
- 近重复检测在切分后仍要跑一遍，防泄漏。

## 4. 安全标注（国标要求，当前为零）

- 需**分别**制定**功能性标注**规则（已有：作业单 v1、门控说明 v1.0.1、写作规范 v1）与**安全性标注**规则（**待建**）；
- 安全性标注**宜覆盖 GB/T 45654 附录 A 全部 31 种风险**（清单见 `tools/v9_gb_compliance_check.py` 的 `SAFETY_RISK_31`）；
- 标注**执行**与**审核**不得同一人；
- 落库位置：素材元数据 `safety_labels` + 训练稿同名 JSONL 字段。

## 5. 校验（标准要能被机器查）

| 层级 | 校验手段 | 现状 |
|---|---|---|
| 第 1 层 | 门控（形态/禁项/纪律/防污染）+ CRUD `stats` | ✅ 已有 |
| 第 2 层 | 门控报告落盘 + 人审 | ✅ 已有 |
| 第 3 层 | **schema 校验脚本**（字段齐备、JSON 合法、group 不跨切分） | ❌ **待建** |
| 合规留痕 | `tools/v9_gb_compliance_check.py` | ⚠️ 只做体检，不阻止不合格数据出集 |

**下一步**：把第 3 层校验做成出集前的硬门（`finetune_assemble.py` 之后强制跑），不合格不出集。

---

## 6. 与国标的关系（说清楚，不越界）

本标准**高于**我们现在的实践、**低于**国标要求。落实国标还需要：

1. 素材来源登记册（采集前/后 5% 双评估留痕）；
2. 人工抽检 ≥4000 条、合格率 ≥96% 的留痕；
3. 个人信息同意/匿名化路径；
4. 31 类安全标注规则与双签留痕。

这四项的整改方案见 [国标合规核验报告 §4](V9_素材格式国标合规核验_20261013.md)。
