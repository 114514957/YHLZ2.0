# 安全标注规则 v1 · 2026-10-13

> 依据：GB/T 45654—2025 附录 A 的 31 种安全风险（**要求"宜覆盖全部"**），以及"功能性标注与安全性标注**分别**制定规则""标注执行与审核不得同一人"。
> 本文件是**安全性标注**规则（功能性标注见：作业单 v1、[门控说明 v1.0.1](门控说明_v1.0_20261012.md)、[素材格式标准 v1](素材格式标准_v1.md)、[训练参数标准 v1](训练参数标准_v1.md)）。
> 用途：每条素材在**人审通过时**必须同步打安全标签；未打标签的素材**不得出集**。

## 1. 三档处置（先定档，再落标签）

| 档 | 名称 | 含义 | 处置 |
|---|---|---|---|
| **A 档** | 无条件禁止 | 出现即整块作废，不修不救 | **drop + 记原因** |
| **B 档** | 有条件保留 | 取决于上下文与框架（虚构/讨论/群聊转述） | **留 + 标注条件**，或改写后重标 |
| **C 档** | 仅登记 | 无害但需知情（涉及未成年、医疗、金融等敏感语域） | **留 + 打标签** |

### 2.2 老爹裁定（2026-10-13，三条界线的正式口径）

> 原话：「1，给你的这些没有强烈性暗示，2，认可，ai对人类需要永远保持热诚，耐心，偶尔的调侃是可接收的，3，按照道德规范约束，按照宪章约束」

| 条 | 对应类目 | **正式口径** |
|---|---|---|
| **1** | **S25 性暗示** | **我们经手的素材不存在强烈性暗示**（老爹确认）。→ 处置：**只对"露骨"（S11 淫秽色情口径）判 A**；含蓄玩笑、成人向调侃**B 档保留**，不做额外收紧。**这条与我们既有素材的实际情况一致**（现有素材本就没有越线内容）。另：宪章运行时 `porn` 正则（`色情\|淫秽\|性行为\|露骨`）仍对**记忆写入**是硬拒——**规则边界不要混：素材侧按本节，运行时按宪章。** |
| **2** | **S26 自伤自杀 / 情绪回应** | **完全认可**，并加一条正向要求：**"AI 对人类需要永远保持热诚、耐心；偶尔的调侃是可接受的。"** → 处置：① 情绪低落场景**必须教"热诚与耐心"的回应**（接住情绪、不敷衍、不模板化安慰）；② **偶尔的调侃可接受，且是元亨的正当语域**（不能因为"对方情绪低落"就把元亨写成唯唯诺诺的客服）；③ **方法/鼓励/美化一律 A 档**，不变。 |
| **3** | **S16 侮辱诽谤 / S17 侵犯隐私** | **按道德规范约束，按宪章约束。** → 具体落法（对齐 `backend/embodied/companion/constitution/`）： |

**第 3 条的宪章依据**（本轮实读代码）：

- **四大原则**：`identity_first`（身份优先）／`safety_first`（安全优先）／`governed_growth`（成长受治）／`partner_principle`（伙伴原则：**AI 是伙伴，不是替代者**）；
- **治理优先级**（低不得覆盖高）：`identity → safety → constitution → growth → intelligence → expression` → **表达自由永远排在最后**；
- **`partner_principle` 直接约束 S16**：伙伴关系意味着**对人保持热诚与耐心**（承接第 2 条），**辱骂、贬损、非人化表达与该原则冲突**；
- **`target_constitution.py` 五类运行时红线**：`identity_override`／`mission_override`／`memory_destroy`／`harm_illegal`／`porn`——**素材侧 S16/S17 的判定必须与之同向，不得教出"绕过身份守护、清空记忆、伤害他人"的表达**。

**据此的三条落法**：
1. **对着真人**：辱骂／造谣／贬损／开盒／人肉 → **A 档**（与 `harm_illegal` 同向）；
2. **虚构角色互怼**：保留，但**不得出现对人的非人化贬损**（如把人比作垃圾／牲口）——理由是 `partner_principle` 不容；
3. **玩笑与调侃**：**保留**（第 2 条明确"偶尔的调侃可接受"），界线是**"怼里有在意"**（元亨既有基线），不是"怼到贬低"。

### 2.1 广告与引流（不属于 31 类，但必须处理）

`广告营销` 不是国标 31 类之一，但**是我们语料里最高频的噪声**（本次 4000 抽样：含链接 20 条、诈骗黑产 3 条）。处置：

- 群内推广链接、拉群二维码、课程报名、返利话术 → **剔除**（不进集）；
- **技术讨论里贴的论文/文档链接**（如 arxiv）→ **保留，但要把 URL 去掉**（避免教模型发链接）；
- 判定记录进 `safety_labels` 的 `ad_removed` 标记。

## 3. 标注落在哪（字段）

**素材层（.md 元数据）**：

```
- safety_labels: none | S##[,S##] | ad_removed
- safety_review: <审核人代号>
- consent_status: own | consented | anonymized | n/a
```

**训练层（.jsonl）**：同名 JSON 字段 + `annotator_exec` / `annotator_review`。

规则：
1. `safety_labels: none` 表示**已看过且无风险**，不是"没看"；没看过的不许写 none；
2. **凡命中 B 档**，必须在 `subtype` 或 `review_status` 里写明保留理由（例：`虚构框架内冲突`）；
3. **执行与审核分离**：单人项目（老爹审 + 我产）在留痕里写清"产出＝agent，审核＝老爹"，不假装是两个人。
