**口径（写死，不再讨论）**：
1. **模型家族与尺寸锁定 Gemma-4 **E4B****——不换更大的（12B/27B 及以上一律不考虑）；
2. **训练侧用与部署同源的 QAT 未量化基座**（`q4_0-unquantized`），训完导 LoRA → 挂到 `q4_0` GGUF 上；**训练与部署必须同源**，否则 LoRA 挂载口径不一致；
3. **部署量化档位锁定 `q4_0`**，不因为"想更好"就换 Q8/Q5——那会改显存与推理速度，属另一次决策；
4. 若将来确实要动基座，**必须单独立项并说明理由**，不在素材线里顺手改。

| 文件 | 整段 p50/p90/p99/max | 监督 p50/p90/max | **超 2048 的记录** | 被截监督 token | **监督 token 合计/遍** |

**结论**：
- **2048 的截断风险在当前数据上几乎不存在**（就 1 条）——因为我们的块**太短**（整段 p50 仅 206 token，监督 p50 仅 **63** token）；

- **V9 目标 8 万条 / 40–50M 监督 token** ⇒ 是 v8 的 **约 90–110 倍**。**数据规模变了一个数量级，参数不能照抄**。

## 4. V9 参数标准（建议值 + 理由 + 出厂线）

| 参数 | **V9 标准** | 理由 | 上一轮 |
|---|---|---|---|
| 基座 | 冻结同一份 QAT 未量化权重，**记录 SHA256** | LoRA 必须与部署同源，否则挂载口径不一致 | 同 |
| LoRA r / α | **维持 16 / 32**（不因为数据变多就放大） | 数据变多应体现在**更多独立场景**，不是更大容量；r 加大更易过拟合小核心 | 16 / 32 |
| target / 精度 | 维持 7 投影 + 语言塔；**bf16** | 多模态塔必须保住 | 同 |
| **序列长度** | **2048 → 4096** | 长块目标：L01 实测 692 监督 token/块，S01 为 689/792；整段接近或超过 2048 ⇒ 2048 必然截长块。**必须实测每批 p99 再定档** | 2048 |
| batch / 累积 | 视显存：`4×4` → **`2×8` 或 `1×16`**，**有效 batch 保持 16** | 序列翻倍后显存吃紧，动 batch 不动有效 batch | 4×4 |
| 学习率 | SFT **2e-4 起步，但必须用 2e-5 / 1e-4 / 2e-4 三档小试定档** | 数据量 ×90 后 2e-4 未经验证；**不许拿"上一轮用过"当依据** | 2e-4 |
| 调度 / warmup | **cosine**，`warmup_ratio=0.03`，**显式指定**（不再吃默认值） | 数据量大时 cosine 比默认 linear 更稳；显式写死便于复现 | 默认 linear |
| 梯度 | **`max_grad_norm=1.0`**（显式） | 长块 + 大 lr 的爆炸风险 | 未设（默认 1.0） |
| epoch | **2–3 + 早停**（看 `eval_loss`，patience 2，`load_best_model_at_end=True`） | v8 用 3；数据变大后过拟合风险上升，用早停兜 | 3，无早停 |
| eval / save | `eval_steps=100`、`save_steps=100`、`save_total_limit=2`，**评测集固定未见** | 同上 | 同 |
| seed | **20260913**（沿用，便于与 v8 对照） | 复现性 | 同 |
| DPO | **默认不做**（SKIP_DPO=1）；要做则 `lr=1e-5, β=0.05, 1 epoch`，且**必须单独看工具回归** | v6/v8 的既定策略 | 同 |
| 混合配比 | 核心锚点（golden+voice_anchor 类）**监督 token 占比 ≥15%**；scene 类**降到 ≤30%** | v8r4 里 scene 占 48.9% 但**监督 p50 仅 63 token**——"条数多、监督少"，会把训练信号稀释成闲聊 | scene 48.9% |
| 长块 | 长块**单列一组**，超长样本**不得静默截断**：要么 seq 够、要么显式记录截断位置与损失量 | 门控与训练必须同一口径 | 无此规则 |

## 4.1 样本权重（老爹 2026-10-13：「核心样本高权重，一般样本与教学样本低权重」）

**问题**：8 万条里核心锚点只占个位数百分比，等权训练会被辅助数据稀释——**光靠条数配比解决不了，必须按样本加权**。
**现状**：导出数据里**原无 weight 字段，训练脚本也不支持**（实测 `sft_train.py` 无 weight/loss 相关代码）。本轮已把字段补上，**但未打补丁前它只是留痕，不生效**。

### 权重分级（已落进导出数据）

| 权重 | 覆盖 | 理由 |
|---:|---|---|
| **1.0** | golden、refusal、honesty、real | **核心锚点**——"她是谁、她守什么底线"由这些决定 |
| **0.6** | memory、uncertain | 次核心——行为规范，但不是人格核心 |
| **0.3** | scene、story、tools、lizhen、extra | **一般与教学**——教说话、教做事，不该压过人格 |

实测分布（v8r4t 4047 条）：**1.0 → 400 条（9.9%）｜0.6 → 743 条（18.4%）｜0.3 → 2904 条（71.8%）**。

### 训练侧消费方式（补丁，待实施）

`sft_train.py` 的 `build_example()` 目前返回 `{input_ids, attention_mask, labels}`。要按样本加权，**最小改法**：

```python
# 1) build_example 里带出权重
w = float(rec.get("weight", 1.0))
return {"input_ids": ids, "attention_mask": [1] * len(ids), "labels": labels,
        "weight": w}

# 2) 自定义 collator：把 weight 收成张量
class WeightedCollator(DataCollatorForSeq2Seq):
    def __call__(self, features):
        ws = torch.tensor([f.pop("weight", 1.0) for f in features], dtype=torch.float)
        batch = super().__call__(features)
        batch["weight"] = ws
        return batch

# 3) 子类化 Trainer，按样本加权 CE（等价于加权 NLL）
class WeightedTrainer(Trainer):
    def compute_loss(self, model, inputs, return_outputs=False, **kw):
        ws = inputs.pop("weight", None)
        out = model(**inputs)
        logits = out.logits
        labels = inputs["labels"]
        shift_logits = logits[..., :-1, :].contiguous()
        shift_labels = labels[..., 1:].contiguous()
        loss_fct = torch.nn.CrossEntropyLoss(reduction="none", ignore_index=-100)
        flat = loss_fct(shift_logits.view(-1, shift_logits.size(-1)),
                        shift_labels.view(-1))
        if ws is not None:
            tok_w = ws.unsqueeze(1).expand(-1, shift_labels.size(1)).reshape(-1)
            mask = (shift_labels.view(-1) != -100).float()
            denom = (tok_w * mask).sum().clamp_min(1.0)
            loss = (flat * tok_w * mask).sum() / denom
        else:
            loss = flat.mean()
        return (loss, out) if return_outputs else loss
```

**注意三点**：① 旧数据无 `weight` 时按 1.0 处理（向后兼容）；② 权重是**乘在 loss 上**，不影响 token 计费与显存；③ **DPO 段是否加权另说**——DPO 的偏好对本来就来自高分样本，暂不加权。
