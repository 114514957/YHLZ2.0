## 3. 为什么看样有用、什么情况下没用

LIMA研究在其65B/1000条高质量样本实验中展示了学习回答格式/风格的可能，不能据此承诺Gemma E4B PT只用1000条就达标。Self-Instruct通过生成后过滤构建监督数据，支持“生成只是候选”的做法；论文不证明这些过滤能识别元亨的幽默品味。

对本项目的推论：IT teacher可以作加工工具，但其成稿仍可能模板化，标签本身不决定最终训练声线。最终审核后的assistant目标、混合素材分布、训练条件与运行时提示都会影响结果，不能保证永不回到客服腔。当前两版被退回就是不应让生成者自行签收风格的本地证据。

看样有用的条件：每次把反馈落实到准确编号/具体句式/情境；只有用户认可范围可做teacher锚点，未表态不默认通过；负例说明为什么不合适；再看新情境/长对话验证可迁移性。不只是收藏几个好句或问“像真人吗”。

## 4. 生成和筛选约束（待样张验证，不代表已执行）

1. 锚点按情境匹配：普通接话、俏皮、安静、认真、失败分别给相应范围，不能拿同三句反复套所有问题。
2. 每个新情境可先产少量不同写法，保持原内容/关系/事实；候选里出现完整解题、机械包袱或幻想经历时重写，不靠换几个词压长度。
3. 核对信息点/身份/诚实/工具结果，再由用户或已校准人工判断风格。自动词表仅线索，teacher自评不能代替用户审阅；“更全面更礼貌”不是目标评分。
4. 每个批准块保存源ID、内容哈希、许可/模拟或实录标记；未审和退回稿不进入正式SFT，素材池加料时同样审核assistant回答。
5. 用从未用于生成锚点的自有情境检验效果，覆盖单轮、多轮、分歧/纠错、工具失败、群聊与视听一致。不把当作风格示例的源片段又当独立未见测试。
6. 如果新情境仍反复回到客服口吻，降低/停止该批合成扩量，保留人工修订和真实认可样本；不把失败批次多训练几轮当解决方案。本轮不调用付费teacher或声称pilot通过。

## 5. 当前成果边界与来源
