# YHLZ Voice Identity System M0.5 Audit Report

> 版本: M0.5
> 生成日期: 2026-08-03
> 阶段目标: 统一 Emotion → Voice Style → TTS Adapter 接口
> 范围: VoiceStyle 数据结构 + Emotion 系统输出 VoiceStyle + 三适配器接收 VoiceStyle; 未改动 main.py 端点 / TTSManager / WebUI

---

## 1. 背景与问题

### 1.1 现状缺陷 (Emotion → TTS 接口不统一)

| 问题 | 表现 |
|---|---|
| Emotion 默认关闭 | `config.emotion_enabled = false`, 情绪→音色映射未生效 |
| Emotion 输出引擎专属 | `resolve_voice_for_emotion()` 直接返回 Edge-TTS 音色字符串 (`zh-CN-XiaoyiNeural`), 无法跨 Qwen3 / GPT-SoVITS 复用 |
| 不同 TTS 处理方式不同 | Qwen3 用 `rate` 字符串 (`+10%`), GPT-SoVITS 用 `speed_factor` 数值 (`1.1`), Edge 用音色 ID — 三套参数语义割裂 |
| Emotion 逻辑泄漏到端点层 | `main.py` 的 `/synthesize`、`/synthesize/stream`、`/chat` 三处直接调用 `resolve_voice_for_emotion`, 情绪分类逻辑散落在请求处理层 |

### 1.2 M0.5 决策

建立统一 `VoiceStyle` 数据结构作为 Emotion 系统与 TTS Adapter 之间的契约:

```
Emotion 系统 (emotion_classifier.py)
    ↓ 输出 VoiceStyle (emotion + speed + pitch + energy 数值字段)
TTS Adapter (qwen3 / gpt-sovits / edge)
    ↓ 翻译数值字段为引擎私有参数 (rate / speed_factor / ...)
具体 TTS 引擎 (Qwen3TTSEngine / GradioClient / EdgeTTSEngine)
```

**核心约束**: 禁止 emotion 分类逻辑进入具体 TTS 引擎实现 — 适配器只消费 VoiceStyle 的数值字段, 不依赖 `emotion` 标签做决策。

## 3. VoiceStyle 数据结构

### 3.1 字段定义 (对齐任务要求示例)

```python
@dataclass
class VoiceStyle:
    emotion: str = "neutral"   # 情绪标签 (metadata, 适配器不应依赖此字段做分类)
    speed: float = 1.0         # 语速倍率 (1.0 = 正常, >1 加速, <1 减速)
    pitch: float = 0.0         # 音调偏移 (半音, 0 = 正常, 正数升调, 负数降调)
    energy: float = 1.0        # 能量/强度倍率 (1.0 = 正常, >1 增强, <1 减弱)
```

任务要求示例对照:
```json
{"emotion": "happy", "speed": 1.1, "pitch": 3, "energy": 1.2}
```
→ `VoiceStyle(emotion="happy", speed=1.1, pitch=3, energy=1.2).to_dict()` 完全匹配。

### 3.2 情绪 → VoiceStyle 映射表 (EMOTION_STYLE_MAP)

| 情绪 | speed | pitch | energy | 语义 |
|---|---|---|---|---|
| happy | 1.1 | +3.0 | 1.2 | 加速 / 升调 / 增强 |
| calm | 0.95 | 0.0 | 0.9 | 略慢 / 平调 / 减弱 |
| sad | 0.9 | -2.0 | 0.8 | 慢 / 降调 / 减弱 |
| angry | 1.05 | +2.0 | 1.3 | 略快 / 升调 / 强增强 |
| neutral | 1.0 | 0.0 | 1.0 | 中性 |

此映射表是 Emotion 系统的唯一真相源 — 适配器禁止重新实现此映射。

### 3.3 工具函数

| 函数 | 用途 |
|---|---|
| `get_style_for_emotion(emotion) -> VoiceStyle` | 情绪名 → VoiceStyle (未知回退 neutral) |
| `speed_to_rate(speed: float) -> str` | 语速倍率 → rate 字符串 (1.1 → "+10%", 0.9 → "-10%"); 引擎私有转换集中在此模块 |
| `VoiceStyle.from_dict(d)` | dict → VoiceStyle (缺失字段回填默认) |
| `VoiceStyle.merge(override)` | 字段级 merge (override 非默认值覆盖 self) |

旧函数保留向后兼容:
- `resolve_voice_for_emotion(text, base_voice, ...) -> str` (输出 Edge 音色字符串, 仍可用)

### 4.2 TTS Adapter 接收 VoiceStyle

`BaseVoiceEngineAdapter.generate()` 统一签名 (M0.5):

```python
def generate(
    self,
    text: str,
    voice_id: Optional[str] = None,
    voice_style: Optional[VoiceStyle] = None,  # M0.5 新增
    **params,
) -> Tuple[np.ndarray, int]:
```

各适配器翻译策略:

| 适配器 | voice_style.speed | voice_style.pitch | voice_style.energy | emotion 标签 |
|---|---|---|---|---|
| Qwen3TTSAdapter | → `rate` 字符串 (`speed_to_rate`) | 忽略 (debug 日志) | 忽略 (debug 日志) | 不消费 |
| GPTSovitsAdapter | → `speed_factor` 数值 | 忽略 (debug 日志) | 忽略 (debug 日志) | 不消费 |
| EdgeTTSAdapter | (预留, 签名对齐) | — | — | — |

### 4.3 禁止 emotion 逻辑进入具体 TTS (验证)

**约束**: 适配器源码不得导入 `emotion_classifier`, 不得调用 `classify_emotion`, 不得基于 `voice_style.emotion` 字段做条件分支。

**实现**: 适配器只引用 `voice_style.speed` (Qwen3 还引用 `voice_style.pitch` / `voice_style.energy` 做 debug 日志判断), 从不引用 `voice_style.emotion` 做决策。

**测试验证** (TestNoEmotionLogicInAdapters):
- `qwen3_adapter.py` 源码不含 `emotion_classifier` / `classify_emotion` / `resolve_voice_for_emotion` / `emotion_to_voice_style`
- `gpt_sovits_adapter.py` 同上
- `qwen3_adapter.py` 不含 `voice_style.emotion ==` 条件判断

## 6. 潜在风险

| # | 风险 | 等级 | 说明与缓解 |
|---|---|---|---|
| R1 | Qwen3 底层 `synthesize` 接受 `rate` 但当前实现未实际使用 (model.generate_voice_clone 不传 rate) | 低 | 适配器层翻译正确 (speed→rate), 底层引擎未消费是 Qwen3-TTS-0.6B-Base 模型限制; 未来模型升级或换 faster-qwen3-tts 时 rate 生效, 适配器无需改动 |
| R2 | pitch / energy 字段当前无引擎支持, 全部静默忽略 | 低 | 设计预留: 字段已进入 VoiceStyle 契约, 未来引擎支持时只需在适配器翻译层补充, Emotion 系统和上层无需改动 |
| R3 | main.py 端点层仍调用旧 `resolve_voice_for_emotion` (Edge 音色字符串路径) | 中 | M0.5 聚焦接口统一 (adapter 层), 未改动端点层; 端点层接入 VoiceStyle 路径留待后续 milestone (需同步改 /synthesize / /synthesize/stream / /chat 三处)。当前两路径并存, 互不干扰 |
| R4 | EMOTION_STYLE_MAP 的数值 (speed/pitch/energy) 是经验值, 未经听感调优 | 低 | M0.5 完成接口贯通; 数值调优属产品化阶段 (M4), 可通过修改映射表或 WebUI 暴露 |
| R5 | `voice_style.emotion` 字段当前无适配器消费 (纯 metadata) | 低 | 设计意图: 未来引擎原生支持情绪标签时 (如 Edge-TTS 的 emotion 模式), 适配器可补充消费; 当前保证 emotion 逻辑不泄漏进引擎 |
| R6 | GPT-SoVITS `voice_style` 覆盖 `params["speed_factor"]` (统一接口优先于私有参数) | 低 | 测试 `test_explicit_speed_factor_overridden_by_voice_style` 验证此行为; 符合"统一接口为权威"原则 |

## 9. 结论

M0.5 目标达成:

1. **VoiceStyle 数据结构建立**: `backend/tts/voice_style.py` 定义 dataclass (emotion/speed/pitch/energy) + EMOTION_STYLE_MAP + 工具函数, 对齐任务要求示例;
2. **Emotion 系统输出 VoiceStyle**: `emotion_classifier.py` 新增 `text_to_voice_style()` / `emotion_to_voice_style()`, 文本/情绪 → VoiceStyle; 旧函数保留兼容;
3. **TTS Adapter 接收 VoiceStyle**: `BaseVoiceEngineAdapter.generate()` 统一加 `voice_style` 参数; Qwen3 (speed→rate) / GPT-SoVITS (speed→speed_factor) / Edge (签名对齐) 三适配器接收;
4. **禁止 emotion 逻辑进入具体 TTS**: 适配器只消费 VoiceStyle 数值字段, emotion 标签不参与决策; 源码静态检查 + 测试验证;
5. **验收通过**: Qwen3 + GPT-SoVITS 均可接收同一 VoiceStyle 对象并正确翻译为引擎私有参数 (TestUnifiedVoiceStyleAcceptance);
6. **测试覆盖**: 43 项 M0.5 新测试全部通过, M0.1/M0.2/M0.3/M0.4 共 71 项回归零破坏; **总计 114 项零回归**。

端点层 (main.py) 接入 VoiceStyle 路径留待后续 milestone; 当前 adapter 层管道已贯通, Emotion → VoiceStyle → TTS 接口统一完成。

*不进行下一阶段修改。*
