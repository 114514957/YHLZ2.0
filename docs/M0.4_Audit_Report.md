## 1. 背景与决策

### 1.1 双源真相风险 (集成审计 R3)

| 来源 | 描述 |

| 白皮书 10.1 | 提出新增 `backend/data/character.yaml` 作为角色绑定文件, 含 `voice_id` / `live2d_model` / `voice_style` |

- **取消** `character.yaml` 路线 (禁止创建该文件);
- **扩展** `personality.json` 顶层增加 `voice_identity` 字段;
- 字段结构遵循任务要求示例:

```json
{
  "name": "xxx",
  "personality": {},
  "voice_identity": {
    "voice_id": "default",
    "engine": "qwen3"
  }
}
```

- **硬约束**: 旧 `personality.json` (无 `voice_identity`) 必须正常运行, 不报错、不写盘篡改。

## 3. 架构变化说明

### 3.1 角色载体单源化 (Single Source Of Truth)

```
变更前 (双源风险):
  personality.json  ← 人格 (context_manager.py 读, /personality 端点读写)
  character.yaml    ← 白皮书设想的角色绑定 (voice_id / live2d / voice_style)
  → WebUI 改人格时, voice 绑定不同步

变更后 (单源):
  personality.json  ← 人格 + voice_identity (统一角色载体)
  {name, role, traits, ..., voice_identity: {voice_id, engine}}
  → context_manager.py 唯一读写入口, /personality + /personality/voice-identity 端点同源
```

### 3.2 voice_identity 字段结构

```json
{
  "voice_identity": {
    "voice_id": "default",   // 声音身份 ID (M0.1 多声音缓存键 / 未来 VIS voice_id)
    "engine": "qwen3"        // 引擎名 (qwen3 / gpt-sovits / edge)
  }
}
```

- 与 M0.1 `Qwen3TTSEngine._voice_caches` 的 `voice_id` 键语义对齐 (可作为缓存查找键);
- 与 M0.2 `create_tts_adapter(engine)` 的 `engine` 参数语义对齐 (决定走哪个适配器);
- 字段最小化: 当前阶段只承载"角色用哪个声音、哪个引擎"两个决策, 未来 VIS 落地后 `voice_id` 即可指向 VoiceProfile 的 UUID。

### 3.3 兼容性策略 (三层防御)

| 层 | 触发条件 | 行为 |
|---|---|---|
| L1 加载兼容 | 旧 json 无 `voice_identity` 字段 | 内存回填 `DEFAULT_VOICE_IDENTITY`, **不写盘** (保留用户原文件不变) |
| L1 加载兼容 | `voice_identity` 非 dict (null/字符串等) | 同上, 视为缺失 |
| L2 字段级补全 | `voice_identity` 是 dict 但缺 `voice_id` 或 `engine` | 缺失字段回填默认, 保留已有用户值 |
| L3 更新校验 | `update_voice_identity(voice_id="")` 传空字符串 | `_update_personality` 内部 `not vi.get("voice_id")` 触发回填默认, 防误清空 |

### 3.4 字段级 merge (避免整对象覆盖)

`_update_personality(voice_identity={...})` 不走默认 `dict.update`, 而是单独处理:

```python
new_vi = dict(cfg.get("voice_identity", DEFAULT_VOICE_IDENTITY))  # 复制当前
new_vi.update(kwargs.pop("voice_identity"))                        # 字段级 merge
# 校验回填
if not new_vi.get("voice_id"): new_vi["voice_id"] = default
if not new_vi.get("engine"):   new_vi["engine"]   = default
cfg["voice_identity"] = new_vi
```

用户只传 `{"voice_id": "v2"}` 时, `engine` 保留原值, 不会被 None 覆盖。

### 3.5 REST 端点

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/personality` | 获取完整性格配置 (含 `voice_identity`); 修复原 `config.dict()` bug |
| POST | `/personality` | 字段级更新 (含 `voice_identity` 可选字段, 走 merge 路径) |
| POST | `/personality/reset` | 重置为默认 (含 `voice_identity` 重置) |
| **GET** | **`/personality/voice-identity`** | **M0.4 新增**: 仅获取 `voice_identity` 子对象 |
| **POST** | **`/personality/voice-identity`** | **M0.4 新增**: 字段级更新 (`voice_id` / `engine` 任选, None=不修改) |

Pydantic 模型:

```python
class VoiceIdentityUpdate(BaseModel):
    voice_id: Optional[str] = None
    engine: Optional[str] = None
```

## 5. 潜在风险

| # | 风险 | 等级 | 说明与缓解 |
|---|---|---|---|
| R1 | `voice_identity.voice_id` 当前只是字符串, 无 UUID 强约束 | 低 | M0.4 阶段 voice_id="default" 是 M0.1 多声音缓存的合法键; 未来 VIS 落地后, profile.py 的 `validate()` 会强制 UUID 校验, 此处只承载引用, 不做格式强约束 |
| R2 | 字段级 merge 仅对 `voice_identity` 生效, 其他嵌套字段 (如 catchphrases) 仍是整对象覆盖 | 低 | 与原 `_update_personality` 行为一致, 不扩大改动范围; 未来若新增 live2d_model 等嵌套字段可复用同模式 |
| R3 | `GET /personality` 顺手修复了 `config.dict()` bug | 低 | 该 bug 是预存缺陷 (dict 无 .dict() 方法), 端点原会抛 AttributeError; M0.4 修改该端点时一并修复为直接返回 dict, FastAPI 自动 JSON 序列化。无行为回归 (本来就坏) |
| R4 | 端点 smoke test 使用 MagicMock 替换重量级模块 | 低 | 无法验证真实引擎加载下的端点行为; 但路由注册 + Pydantic 模型 + 接口一致性已验证, 真机端到端联调留待 M2/M4 |
| R5 | 兼容性回填仅在内存, 不写盘 | 低 | 设计意图: 不污染用户原文件; 副作用是若用户从不主动更新 voice_identity, 旧 json 永远没有该字段 — 但读取路径始终返回完整 dict, 不影响下游消费 |
| R6 | Pydantic V2 对 `.dict()` 的弃用警告 | 低 | 端点代码沿用项目现有风格 (PersonalityUpdate.dict(exclude_none=True)); 全项目统一迁移 `model_dump()` 不在 M0.4 范围 |

## 8. 结论

M0.4 目标达成:

1. **角色载体单源化**: personality.json 扩展 voice_identity 字段, 取消 character.yaml 路线 (未创建该文件);
2. **向后兼容**: 旧 personality.json (无 voice_identity) 经三层防御 (L1 加载兼容 / L2 字段级补全 / L3 更新校验) 正常运行, 不写盘篡改用户原文件;
3. **REST 端点**: `/personality/voice-identity` GET/POST 上线, PersonalityUpdate 加 voice_identity 字段, 顺手修复 `GET /personality` 的 `config.dict()` 预存 bug;
4. **测试覆盖**: 29 项 M0.4 新测试 (20 兼容性 + 9 端点 smoke) 全部通过, M0.1/M0.2/M0.3 共 42 项回归零破坏;
5. **白皮书修订**: 10.1 / 14 附录 的 character.yaml 路线正式取消, personality.json 单源扩展为权威实现。

Voice Identity Manager (backend/voice_identity/) 仍未创建, 留待 M1 落地; TTS 引擎层 / WebUI / 直播系统零改动。

*不进行下一阶段修改。*
