## 先说结论

不是再换一份更长的人格提示词，也不是直接再训一次。先让评测能分清“说对了、工具调了、真的写入了、权限守住了”，修复运行时错误分流，再用现有本地 Gemma 与 v8 适配器复验。人格/工具收口验收通过后，接回记忆与数字人长程任务。六段开发、四个验收门；每段可连续推进，但不能跳过前置验收后宣布成功。

用户范围：本任务完成后，将 LLM 接入之前长程任务，跑通所有链路，**排除已冻结的语音对话链路**。文字输入是非语音验收入口，不改动现有 ASR、麦克风、TTS、扬声器、蓝牙、全双工及原生音频路径。

### 为什么还不能直接宣布跑通

1. 旧评测把每题工具策略覆盖成统一白名单，改变了真实私聊/群聊权限与意图分流。旧成绩只作历史基线。
2. 只记录调用工具名称，无法区别执行失败、审批拒绝、写入成功和模型嘴上说成功。
3. r02仍出现“我的存在是自己造出来的”；r06群聊把提问者当创造者；t02用文本`[[dev: diary_write]]`代替原生工具；t16拒绝讲笑话却因未调工具获得旧规则通过。
4. p06/t14有关键词误判可能，不能为了加关键词破坏自然风格。r05语义确实改进，但旧评分两次都通过，不应写成旧分数FAIL→PASS。
5. 提示词先宣传完整工具，后按回合裁剪工具；能力描述和实际可用能力可能不一致。
6. dev文本标记的下游分流需要真正的请求授权，不能把模型输出标签当任意任务执行许可。
7. 新建沙箱记忆服务会绕过默认LLM hook装配；不显式接钩子，所谓真模型记忆测试可能实际没用模型。

### 训练判断

台账0580的“训练不足”是待验证假设，不是单凭一次答错就能下的诊断。0581也要求先排除提示/模板/评测并重复验证。0582存档的v8参数是历史运行配置，不是新训练的自动处方；其中loss来自监控采样，缺原始trainer_state.json。采样从1.24到1.31有回升，不能据此称严格单调，也不能用下降loss证明工具能力合格。

本轮不启动训练、不更换适配器。只有固定模型、固定模板、清楚权限、未见改写题至少三次重复后仍稳定失败，才产出训练建议。建议包必须包括失败轨迹、正负对照、同义改写隔离集、实际副作用验证、assistant-only标签/截断检查。若未来训练，必须回传trainer_state.json、all_results.json及训练日志；不只打包adapter。

## 三、六段任务与四道验收门

### R1：让验收可信（当前立即做）

**目的**：补齐测量工具，先避免假通过。

**改动位置**：tools/persona_regression.py、独立的评测支持模块与backend/test_persona_*；保留tools/persona_bank.py旧38题不改分母。

**子任务**：
1. 运行ID唯一化，记录prompt源码hash、工具schema指纹、模型/适配器证据和模式；不覆盖同日同版本报告。
2. 默认生产策略与沙箱白名单取交集，绝不扩大公共权限。另设显式diagnostic诊断模式；诊断得分不能作为生产验收。
3. 记录工具名、执行ok、受限错误状态；不把完整参数/私有记忆/结果原文暴露到普通接口。
4. 独立语义核对清单覆盖创造者关系、公共身份、诚实、图片实际有无、创作响应；自动规则只能发现确定性问题，未评/缺证据标review，不能假装自动语义裁判。
5. 区分原生第一次成功、纠正后成功、尝试失败、效果未核验。没有readback证据的写调用不得算效果通过。
6. 为后续live补齐可写路径/数据库/网络隔离清单。只读私有文件也不能任模型遍历；最终live必须有明确允许路径和目的地址。

**验收**：旧38题仍可复算；群聊不获得memory_save；失败调用不算执行成功；缺结果不算成功；同版本多次运行不会覆盖；离线无网络/进程/生产写。产物包含单测日志、字段说明和未覆盖安全项。R1本身不代表已具备live放行资格。

**失败处理**：保留旧结果文件；修测试/隔离，不以强制曝光工具获得高分。

**改动位置**：backend/target_entry.py、target_prompts.py、prompt_structure.py、target_dev_bridge.py、target_daemon.py及专门测试；只动文字路径，音频相关分支保持原样。

## 四、8GB显存的运行约束

- 只复用已有本地LLM；不加载第二个裁判LLM，不在离线回归导入torch/transformers，不自动开训练。
- 推理并发建议初始1（属于开发目标；需要检查服务现有调度并实测，不假称已全局实现）；后台提炼可让步给前台，积压保留到下一次空闲。
- 长记忆靠分层存储和检索，不把历史全塞入上下文。检索预算、提炼长度和批次数可观测，超预算降级需标注。
- CPU向量检索只在显式启用且已备好依赖时测试，不因索引缺1临时下载大模型。先保障FTS/关键词可用。
- 45秒是现有后台请求默认超时，不是交互体验目标。区分排队、检索、prefill、生成、工具IO和写盘耗时再优化。

## 五、开发纪律与执行入口

1. 台账是唯一事实源：历史检索走MCP；每个有意义成果追加记录号。文档/JSON是台账引用的执行快照，不成为第二事实源。
2. 本仓库已有大量未提交改动。改之前核对当前文件，精确增量编辑；不把别人的改动计入本次成果。
3. 默认生产库只读；测试使用临时库和合成身份。不公开工具原始参数、记忆文本或密钥；仅记录必要状态、指纹。
4. `tools/persona_regression.py`现有live/answers/dump/version/base-url/expect-lora/only/limit/out/save-answers参数已存在；本文其他设计不表示CLI已实现。新增参数以本轮实现与测试为准。
5. 可用离线基线命令（在项目根目录，输出另设新目录，避免覆盖证据）：

```powershell
$env:YHLZ_TRAINING_ACTIVE='1'
$env:YHLZ_FINETUNE_ACTIVE='1'
$env:PYTHONUTF8='1'
.\.venv\Scripts\python.exe -B tools/memory_offline_regression.py --output artifacts/persona_longrun_20261003/regression_next
```

以上保护仅作用调用进程，不能从该进程health判断全机训练状态。live阶段要明确选择测试资源策略；不全局删除生产保护变量。
