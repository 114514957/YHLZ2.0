# 台账CRUD最小可行维修方案

> 最终交付更新（2026-10-04）：当前执行限制解除后，YHLZ MCP读取、追加及再次读回全部成功；本批方案已合并归档到台账0604。正文中的“待登记/404阻断”描述此前过程，以本条为最新交付状态。未修改业务代码、模型或代理配置，自动审批404未做长期修复。桌面最终副本已同步。

日期：2026-10-04。结论先说：**台账程序本身不复杂。复杂的是外层审批、代理和执行环境。** 本方案把两层彻底分开，后续不再为一个增删查改程序引入模型判断、复杂任务队列或多级验收。

## 1. 只保留一条真实链路

```text
调用方
  → MCP ledger_list / ledger_get / ledger_search / ledger_add / ledger_update / ledger_delete
  → Capability Registry
  → backend.ledger_store
  → docs/上下文台账.md + 索引 + 自动备份
  → 返回结果
```

`ledger_store`是唯一业务实现；`tools/ledger_cli.py`和`tools/yhlz_mcp_server.py`都调用它。以后只修这条链路，不复制第二份台账逻辑。

自动审批属于调用前的控制层：

```text
自动审批失败 = 调用没有开始
台账写入失败 = 调用已经开始但业务失败
台账写入成功 = 返回记录号并可读回
```

三者不能混成“台账坏了”。

## 2. 当前已经能用的最简单路径

根据已读台账0603，其他代理验证了CLI与MCP共享`ledger_store`且CLI可用。它证明存储层可工作，不代表本任务可以绕过审批。本任务仍遵守用户提供的AGENTS要求：台账检索及登记使用MCP。操作保持简单：

- 查最近记录：`ledger_list`
- 按关键词查：`ledger_search`，只用1～3个关键词
- 读单条：`ledger_get(no)`
- 追加：`ledger_add(title, body)`
- 修改：`ledger_update(no, title/append/body)`
- 删除：保留现有删除策略，必须先读回确认目标编号

CLI保留为既有维护工具，与MCP复用同一存储层；不能在某项操作被审批阻断后自动改走CLI。另一代理执行成功属于其执行条件，不能代替本任务的审批。无论哪个获准入口，写入都要读回确认。

## 3. 审批404只做四项维修

不改`ledger_store`，不改台账格式，不增加模型，不给台账工具接“智能回退”。只查：

1. 自动审批请求到底选了哪个模型：错误显示`gpt-5.6-luna`，当前主配置是`gpt-6.1-sol`，两者角色不同。
2. CC Switch当前提供方和模型映射是否把审批角色发到了不可用分组。
3. 审批模型能否处理当前`/responses`请求；普通聊天可用不能证明审批请求可用。
4. 审批服务恢复后，MCP是否能连续完成读和写。

修复顺序固定为：

```text
记录配置 → 找到审批角色 → 修正角色/提供方映射 → 重启或刷新代理
→ MCP读 → MCP追加真实维修记录 → MCP读回
```

不要先修改MCP代码。除非能证明MCP服务自己把模型名改错，否则改业务层没有意义。

## 4. 最小验收：三次操作就够

### A：读

连续三次启动MCP客户端，读取最新列表和一条已知记录。要求返回记录号、标题和正文，不出现审批404。

### B：写

追加一条明确的维修记录，返回自动编号。不得手填编号，不得直接编辑台账文件。

### C：读回

用`ledger_get(自动编号)`和关键词搜索读回同一条。标题、正文摘要、编号一致，才算成功。

如果A成功、B失败，说明写权限或审批链问题；如果B返回成功但C失败，说明回执/索引问题；如果A、B、C都没有启动，说明仍是审批层问题。

## 5. 长期规则

- 本任务继续使用MCP。审批层不可用时保留待登记正文和具体错误，不自动切换CLI、直写文件或换工具执行被阻断动作。
- 不让LLM参与编号、正文改写、权限判断或成功判断。
- 不把台账写入放进记忆队列、复盘队列或数字人推理闸门。
- 每次新增台账记录随附对应git提交，但只提交本次相关文件，不提交整棵脏工作树。
- 只记录必要诊断字段，不写API key、token和完整私密请求。
- 删除操作先`get`确认编号，删除后再次`get`确认不存在；如果项目策略不允许删除，返回明确拒绝。

## 6. 这次问题的直接结论

目前没有必要做“给MCP ledger_add加复杂直写回退”的大改造。0603及本轮成功的MCP读取表明项目能力与存储层并非整体不可用；应聚焦自动审批模型/代理映射。CLI是已有维护入口，不是对审批失败的自动绕行。

本方案不改变YHLZ对话、记忆、QQ和Gemma链路，也不要求训练。它只解决台账CRUD和外层审批的边界问题。
