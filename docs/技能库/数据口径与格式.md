# 数据口径与格式（统一术语·v1，ledger 0182）

> 元亨、老爹、各工具回话用同一套词汇与数字口径。凡数字必说明指哪个库/哪个文件。

## 一、概念唯一化
| 词 | 唯一含义 | 位置 |
|---|---|---|
| 白名单群/黑名单群 | 捕获范围（现白名单 3 群：855372167/931057213/681195563；黑名单含 175966141） | config/qqwatch.json |
| **候选** | 待云端抽取的消息行（≥25字/链接/代码/信任源） | cache/qqwatch/all.jsonl |
| **原文留痕** | 低价值消息原文（非候选、不抽不库，仅留痕） | cache/qqwatch/_skip.jsonl |
| 游标 | 已抽取候选行数 | cache/qqwatch/state.json |
| **知识** | 抽取沉淀的唯一去处=知识库条目（不再用"L2 knowledge/长期记忆 knowledge"说法） | data/yuanheng_kb.db |
| 记忆 | 人格/经历/与老爹关系（与知识彻底分离） | cache/memstore/memstore.db |
| 导出产物 | QCE 全量历史 JSON（群原文全集副本） | ~/.qq-chat-exporter/exports/group_<群>_<时间戳>.json |

## 二、格式
- 候选行 JSONL：`{ts, group_id, user_id, nickname, text, candidate, tags}`（ts=消息秒）
- 知识条目：`{id: kb_xxx, category: tech|method|..., summary≤400字, detail≤2000字, source: qq:g<群>:t<ts>, created}`
- 原文=QQ 消息文本去占位（[图:..]等）+去 @/回复框后入候选判断；_skip 保留含占位原文

## 三、口径规则
1. 说"候选 N 条"=all.jsonl 行数；"待处理"=行数−游标
2. 说"知识 N 条"=kb_items active 计数（用 kb_stats）
3. 不再引用已废弃口径：L2 knowledge 条目、"127 条 knowledge"（历史值已迁移）
4. 导出群历史=qq.export 返回 {exported_msgs（导出文件消息数）, candidates_added（新增候选）, deduped（被去重）}
5. 重复导出不会重复加候选（fingerprint=(群,人,文本归一) 去重）
6. "聊天原文"=all.jsonl+_skip.jsonl 全集（白名单群全量留痕）+导出 JSON 副本；不要用文件大小判断格式（jsonl 是 UTF-8 文本，file_read 可读）
