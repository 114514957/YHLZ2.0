### 一个必须记下的坑

同一问题的另一个 harness（system prompt 只写"必须调 see_now、不要猜"）返回了**空答案**，但工具调用成功、图片也进去了。加上"看过一次就够，不要重复调用"之后立刻正常。

判断：**模型可能在同一轮反复调 `see_now`**，循环收敛时把答案挤掉。这不是 P2 的 bug，是 P3 节流要解决的事——**单轮最多一次**必须做，否则真机上会出现"调了工具却没回答"。已写在计划的 P3 里，提为必做。

### 抓到一个真 bug：region 抓屏直接失败

带 `--region` 时 ffmpeg 报：

```
Impossible to convert between the formats supported by the filter 'graph -1 input from stream 0:0'
[vf#0:0] Error reinitializing filters!  -40 (Function not implemented)
```

原因：Windows 的 `gdigrab` 输出 bgra，而上游只生成 `scale=…`；区域模式还会走 gdigrab 的
`-offset_x/-offset_y/-video_size`，格式协商就断了。

修法（改在 `tools/see_now_bridge.mjs`，不动上游包）：自己拼 ffmpeg 参数，`-vf` 前补 `format=bgra`：

```
ffmpeg -f gdigrab -framerate 12 [-offset_x X -offset_y Y -video_size WxH] -i desktop \
       -vf "format=bgra,scale=798:450:flags=area" -f rawvideo -pix_fmt rgb24 -
```

改完两种模式都通：

| 模式 | 帧 | 留帧 | token | png |
|---|---:|---:|---:|---|
| 全屏 2s | 22 | 1 | 222 | 370 KB |
| region(0,0,900,700) 2s | 22 | 1 | 222 | 235 KB |

### 验收结论

| 维度 | 结论 |

## P4+ · 读字：不需要外部 OCR（四条路实测）

老爹问「字读取能不能用别的工具」。先在**不装任何东西**的前提下把四条路量了一遍，
同一块屏幕、同一个问题（"把最显眼那行字念出来"）：

| 路径 | 读到的字 | prompt tokens | 结论 |
|---|---|---:|---|
| A 全屏 `low` 拼图 | 「今晚吃什么」 | 213 | ❌ **编的**（屏幕上没这句） |
| B `region=700×400` 走拼图（放大到 798×462） | 「五、现在怎么用」 | 213 | ✅ 对 |
| C 原生裁剪 700×400（不缩放） | 「五、现在怎么用」 | 163 | ✅ 对，更省 |
| D 原生裁剪 420×240 | 「五、现在怎么用」 | **127** | ✅ 对，最省 |

> A 那一行的"今晚吃什么"是决定性的：**同一屏、同一问，全屏拼图会把字编出来**。
> 所以"读字失败"不是模型不认字，是 798×462 里根本没留下笔画。

### 结论：框小一点 + 原生像素，比装 OCR 更好

- 零新依赖、零安装；
- token 反而更少（127 < 222）——小图本身就便宜；
- 坐标就是屏幕像素，和 `region` 同一套。

### 于是加了 `raw` 模式（已上线）

- `tools/see_now_bridge.mjs --raw --region x,y,w,h`：**一帧、原生像素、不缩放不拼图**；
- `backend/see_now.py`：`capture(raw=True)`、`capability_result` 认 `raw`；
- 工具 schema 换成 typed（`SeeNowArgs`）：`seconds` 是 integer、`quality` 是枚举、`raw` 是 **boolean**，
  模型不用再猜字符串；
- 描述里写死：「要读具体文字：传 region 框住那块 + raw=true」。

实测（走 capability，真模型）：

```
summary: 屏幕原图裁剪：420x240 原生像素（不缩放，读字用）。
model  : 五、现在怎么用        prompt_tokens: 124
png    : 56,733 bytes
```

### 要不要真 OCR？（暂不）

只有在这些情况才值得装：

- 要**整页文档/长表格**（一屏一屏框太慢）；
- 要**坐标**（点某个按钮、取控件位置）；
- 要多语言混排或竖排。

候选（都要装东西）：
1. Windows 自带 `Windows.Media.Ocr`（需 `winsdk`，无额外模型，中英支持好）；
2. RapidOCR（`onnxruntime` 已装，只差 `rapidocr_onnxruntime` 包 + ~15MB 模型）。

现在的判断：**先不装**。`region + raw` 已经把"读一行字"解决了，等真遇到整页再上 OCR。

### 尝试替代：切片 + 多图（成了一半）
既然 420×240 能读准，那就把正文切成 4 块一起发：

| 项 | 值 |
|---|---|
| 切片 | 4 × 560×320（正文四象限） |
| 图片部分 token | 393（含问题与系统提示） |
| 读到的内容 | 「三种情况：1. 文件/长表… 2. 坐标… 3. 多语言… 候选：Windows 自带 Windows.Media」——**确实是屏幕上的字**（我的文档正文），不是编的 |
| 问题 | 后半段**退化复读**（一长串 "..."）：max_tokens=400 + 开放式问法，模型从"念字"滑成"继续写" |

**结论**：不装 OCR 也能读整页，但**问法必须硬**——比如"每块只念前 3 行，念完停"，否则它会开始续写。
OCR 仍然值得在"要坐标 / 整页结构化 / 多语言"时再上，等网络或离线包。

### 现在的使用建议（三步）

- 问「我在干什么 / 界面怎么不对」→ 默认全屏、low，够用且便宜（222 token）；
- 问「上面写了什么字」→ 传 `region` 框住那块 + `raw=true`（原生像素，实测 124 token 读准）；
- 她答得含糊时，别追着问，直接圈区域再看一次。

代码全部就绪，但**开关默认是关的**。要真正让元亨用上：

1. `YH\.env` 加一行 `YHLZ_SEE_NOW=1`（想调整力度再加 `YHLZ_SEE_NOW_GAP=20`）；
2. 重启元亨（daemon 读 .env 与注册表都在启动时）；
3. 在 QQ/工作台里说一句「看我屏幕」——她应该调用 `see_now`、看到图、然后描述。

默认 off 的理由：整屏会看到 QQ、密码框、私聊；开着等于常驻一个能看屏幕的能力。爹点头再开。

## 追加：系统自带 OCR（老爹点的那条路）

老爹提醒「手机、电脑的图片处理里都能读字」。对——Windows 自带 `Windows.Media.Ocr`
（照片/截图工具的「提取文字」就是它）。这条路**不需要模型、不联网**，只要一个 Python 绑定。

### 装了什么

```
pip download winsdk -i https://pypi.tuna.tsinghua.edu.cn/simple   → 12.0 MB，秒下
pip install winsdk-1.0.0b10-cp312-cp312-win_amd64.whl              → 成功
```

关键：之前 `rapidocr` 卡在 PyPI 直连；**换清华镜像就好了**——不是包大，是通道慢。

### 实现（`backend/ocr.py`）

- 引擎：`OcrEngine.try_create_from_user_profile_languages()`，本机识别语言 `zh-Hans-CN`；
- **不走 StorageFile**：受限进程里 `StorageFile.get_file_from_path_async` 报
  `E_ACCESSDENIED`；改成把 PNG 字节写进 `InMemoryRandomAccessStream` 再交给 `BitmapDecoder`；
- 中文逐字空格清理（`clean()`），英文/数字空格保留；
- `read_screen(region=None)`：ffmpeg 抓一张**原生分辨率**图 → OCR；`region` 只读一块。

### 实测

| 项 | 值 |
|---|---|
| 图 | 2560×1600 原生（不缩放） |
| 行数 | 98~100 行 |
| 耗时 | 767~807 ms（截图 + OCR） |
| 图片 token | **0**（输出是文字） |
| 语言 | zh-Hans-CN |

读出来的东西是真的屏幕内容（侧栏「LZ / YH / 外围学习」、正文「四、要继续推进的话…」都在）。

### 质量（和手机「提取文字」一个水平）

- 正文大字：准；
- 小字/艺术字会错：「deepseek」→「deepseel」、「新会话」→「新会讠舌」、「应用 编辑」→「旧应用编辑」。

所以分工很清楚：

| 要什么 | 用哪个 |
|---|---|
| **字**（报错、标题、代码、段落） | `screen_text`（系统 OCR，ms 级、零图片 token） |
| **布局/颜色/在干什么** | `see_now`（看图） |
| 整页但 OCR 装不上时的兜底 | 切片 + 多图（393 token，需硬问法） |

### 已注册成能力

`screen.text`（工具名 `screen_text`）：参数 `region`（可选）、`limit`（默认 120 行）；
`YHLZ_SEE_NOW=1` 时与 `see_now` 一起注册，**现在 47 个工具**。实测
`execute_openai_async("screen_text", {})` → ok=True，100 行，767ms。

daemon 已重启，能力已上线。
