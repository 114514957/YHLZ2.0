# 外围学习技术评估：哪些能进元亨新架构

日期：2026-10-21 · 输入：`docs/研究/` 六份报告 + 本机体检
结论：**真正值得立刻用的是 4 个“微结构” + 3 个“接线”**；上游的大系统、记忆算法、外部记忆服务都不应直接搬。

## 0. 一句话结论

> YHLZ 不缺子系统，缺的是**关键路径上的微结构**（前缀稳定、文本平滑、延迟闸门、轮次完整性）和**已有机制的接线**（stance/provenance、双路径召回、outbox/游标）。
> 外围报告里 23 万行的 CX-O、7k 行的 lianlian、MemOS/Honcho 都不是答案；它们是“边界样本”。

## 2. 立刻可用的四项（P0.5，1-2 天）

### 2.1 前缀稳定 + cache 预热

- 现状：`target_orchestrator.py:345-347` 把每轮变化的 `early_context[:1500]` 放进 `system[0]`；`PromptFrame` 每轮重排 → 前缀断，KV 白扔。
- 做法：
  1. `PromptFrame` 拆 `render_static()`（人格/规则/工具纪律，逐字稳定）与 `render_dynamic()`（early_context）。
  2. 只把 static 放 `system[0]`；dynamic 作为**第二条 system** 放在 history 之后、current user 之前，位置固定。
  3. 启动时用同一段 static 前缀发一次 `max_tokens=1` 预热；不预热等于白改。
- 验收：第二轮起 prefill token 只剩动态块+本轮话；`voice_trace` 首 token P50 下降；persona regression 不退化。

### 2.2 文本平滑 + 延迟闸门

- `TextSmoother(window_ms=30, char_threshold=2, max_chunk=40)` 插在文本流与 speech generator 之间；首句用更激进阈值。
- `tools/voice_latency_gate.py`：同一组 10 句 × 6 轮，输出 P50/P95/P99，超阈值退出 1；第一版只打印，第二版卡阈值。
- 验收：TTS 请求数下降 ≥30%，首包延迟不退化；P95<800ms（先建基线再定）。

### 2.3 轮次完整性 + 代理免疫

- 打断时补 assistant 占位或 `interrupted=True` 过滤半轮；确保不出现连续 user。
- 纯本机客户端显式 `trust_env=False` + `proxy=None`；`test_proxy_env.py` 补两条断言：NO_PROXY 必须含 127.0.0.1/::1；本地请求 <100ms。

## 3. 记忆：不要换算法，先接线

本机审计（只读）硬数据：

- L2 710 / active 176；importance **139/176 全是 8**；stance 空 **134/176（76%）**；access_count >0 = **0**；causal_edges = **0**；shadow 86 条 top-1 从未变。
- 日记 66 条，**49 条【自主时刻】**，召回时与事实同前缀注入。
- 14 个链路问题里 **8 个是“机制在、线没接”**：stance 不写/不读、主轨不跑 adjudicate、L1 摘要从未产出、社区摘要全空、early_context 按顺序砍尾（kb/profile 最先被砍）、vec scope 硬编码等。

**结论**：不要装 MemOS/Honcho，不要改乘性公式；先做：

1. 主写入轨写 `stance`，消费侧（注入/日记）读它；自产内容标 opinion/speculation，不冒充 fact。
2. 自动注入严格（persona/reflection/recent），工具召回才混合（BM25+向量+RRF）；把 `contextual_recall` 的四路混用拆开。
3. 后台整理加 outbox + cursor + 幂等 job；不要 fire-and-forget。
4. importance 加 10/8-9/6-7/5/1-4 档位锚点，先把 8 分饱和打散；不要动排序公式。
5. L1 摘要/社区摘要/early_context 截断三处先修，否则后面调排序没有意义。

## 4. 借形不借体

- **CX-O 的契约/测试/评测**：三层契约（schema 48 / interface_stub 24 / config_template 13）+ 246 个后端测试 + EvalKit（memory/latency/quality）；这是 P1 API 拆层最值得借的组织方式。
- **NEKO 的管理闭环**：outbox + events + cursors + 幂等 handler；evidence 双时钟、persona protected；只借机制，不搬 293KB facts.py。
- **MemOS**：L1 traces / L2 policies / L3 world model + Skills；本地 SQLite+FTS5+vector 与 YHLZ 同栈；可借“policies/Skills”两层概念，不装服务。
- **memU**：MemoryService 不做 LLM，判断留给 agent；对 YHLZ 的后台 LLM 成本有参考。
- **Honcho**：`(observer, observed)` 双视角；想法有价值，AGPL 只能读不能抄。

## 5. 明确不采纳

1. **CX-O 五服务/230k 行平台、梦境引擎、Tuner、四维动机整套**：体量与维护成本失控；YHLZ 已有 drives/reflection，不需要再叠一套。
2. **lianlian 的半双工/音频栈**：YHLZ 有真 AEC、barge_in、echo_cancellation，退化会变差；只借延迟与失败语义。
3. **外部记忆服务替换 YHLZ 记忆**：MemOS/Honcho/memU 是“给 agent 的工具记忆”；元亨需要的是角色记忆，YHLZ 现有 L1/L2/L3 更深。两者可共存，不能混为一谈。
4. **乘性记忆公式/场景权重先上**：P1-6 已修正——当前信号饱和，套公式会降低相关性；先接线、再分带。
5. **无 LICENSE 的代码**：lianlian/CX-O 都没有 LICENSE，只能借机制，不能复制代码。
6. **把文档当验收**：这几份报告里的性能数字多来自上游作者，不是本机复现；必须本机 A/B 后再写进验收。

## 6. 与体检 P0/P1 的合并顺序

- **P0 先止血**（监督权/GPU/仓库/秘密/日志）——不完成，P0.5 的测量会被重启污染。
- **P0.5 推理微结构**（1-2 天）：前缀稳定+预热、文本平滑、延迟闸门、轮次完整性、代理免疫。
- **P1 记忆接线 + API 拆层**（1 周）：stance、双路径、outbox/cursor、importance 锚点、L1/社区/early_context；同时按 CX-O 的契约/测试方式拆 API。
- **P2**：证据双时钟、RRF、MemOS 式 policies/Skills、双视角。

## 7. 风险与验证

- 前缀改动会改变记忆块位置：必须跑 `persona_regression` + 记忆宣称守卫，确认人格不漂。
- 文本平滑可能让“边说边出”顿一下：现场听感 + 首包延迟双验收。
- 记忆接线会改变注入内容：先 shadow 对比，不直接覆盖生产；stance 只做门控权重，不改相关性排序。
- 上游数字不可横比：本机只认自己的 TTFT/P95/TTS 请求数/召回评测。
