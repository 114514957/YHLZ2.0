## 1. DSH 插件

### 1.1 `SAOS-3624/dsh-video-storyboard` ★148 · MIT · 2026-10-26 建，10-29 还在推

**做什么**：把一段视频压成**一张宫格图（384 token 封顶）+ 一份带时间码的文本清单**，让模型"看过"视频，而不是逐帧抽图把 token 撑爆。

四个工具：

| 工具 | 作用 |
|---|---|
| `video_probe` | 只读容器头（时长/分辨率/帧率/有无音轨/是否已分析），**不花图片 token** |
| `video_storyboard` | 出宫格图 + 文本清单（每格起止时间、台词、切了几刀） |
| `video_zoom` | 只看某一段（更小时间窗、更密格） |
| `video_locate` | 纯文本：一句话 → 时间码 |

- 依赖：**ffmpeg/ffprobe 必须**；yt-dlp 可选（贴 B 站/YouTube 链接才要）；ASR 可选（没有就没有台词）。
- 参数很细：`cells`（格数，不给就按 motion/字每秒/响度推）、`pick=sharp|mid|thumb`（取帧策略）、`burn`（烧格号）、`scanGap`、`minGap`、`detail=low|med|high`（每格台词预算 60/120/400 字）、`sheets`（长片切几张）。
- 输出形如：`<storyboard path="film.png" grid="3x3" … audio events(7)… fast cuts: 00:42.80-01:04.80 (22 shots)>`。

**对我们的价值：高。** 元亨已经有 B 站工具链（`bili_find/watch/status/notes/read`）。这个插件补的正是"看"这一环，而且它的取舍（一张图 + 时间码 + 按需 zoom）和我们在 prompt 预算上的结论同源：**信息密度优先，token 封顶**。

### 1.2 `wonderandyou/dsh-qwen-paint` ★30 · MIT（原版）

**做什么**：DSH 插件（host + client 两半），注册一个 `draw_image` 工具——说一句"画一只雪地里的柴犬"，本机 ComfyUI 用 **Qwen-Image 2.1** 出图，落盘并把绝对路径回给助手内联显示。**全程 127.0.0.1，不出网、不需要 API Key**。

- host 半：注册工具、**空闲 5 分钟自动关停 ComfyUI**、只读状态端点。
- client 半：工具行里自绘图片卡片、composer 下方显示 ComfyUI 在线状态。
- 依赖：ComfyUI 在 `127.0.0.1:8188` + **三个模型共约 13.3 GB**（UNET int8 / CLIP qwen3vl_8b_w4a8 / VAE bf16）。
- 安装脚本：`setup.mjs --check/--verify`，模型走 **ModelScope 官方直连**并逐个 **SHA256 校验**（不过就删）；ComfyUI 本体因官方不公布哈希，默认**不自动下**。
- N 卡开箱即用；**A 卡走 ROCm**（AMD 官方 Windows wheels，锁 ROCm 7.2.1，README 明确"别升 10.0，HIP 7.15 会破坏权重"）。

### 1.3 `yanfei0725/dsh-qwen-paint` ★24 · MIT（朋友的 AMD 适配 / 优化版，v0.17.13）

在 0.1.1 的 ROCm 基础上做了不少工程：

- **代码层网络边界**：`lib/net-guard.js` 强制 `comfyUrl`/`hipfireUrl` 只能是回环，**配成外网地址直接拒绝启动**；所有出站走 `guardedFetch`，强制 `redirect: 'error'`。另有 `allowRemoteComfy`（默认 false）供局域网显式 opt-in。
- **OOM 自动回退**：显存不足时 VAE 解码切分块重试一次。
- **串行抽卡**（`serialBatch=auto`，默认 <16GB 显存判定）：一次只提交一张 latent；明确说"串行**不卸载**主模型，否则每张都要重载 13.5GB"。
- **生成后自动放大**（`upscaleAfter`，与 `upscale_image` 共用同一节点图）。
- **记忆联动雏形**：每次成功出图追加 JSONL 到 `.qwen-paint-memory.jsonl`，提供 `/api/qwen-paint/health|capabilities|presets|memory/recent|memory/preference`（仅本机）。
- 权限披露按 DSH STORE 口径写清：`files=write`、`network=默认仅 127.0.0.1（代码强制）`、`commands=restricted`、`credentials=none`，并列 6 条已知风险。

**对我们的价值：中，且有硬门槛。** 13.3 GB 模型 + ComfyUI；我们 4060 8GB 属于它的"危险区"（作者自己在 `<16GB` 就默认串行）。但**它的工程做法值得抄**：网络边界用代码强制而不是靠文档、OOM 回退、串行不卸载模型、以及那份"权限与已知风险"披露格式。

### 1.4 `wall1234567/dsh-rofm` ★8 · MIT（DSH 长期记忆插件）

**这是这批里和我们记忆线最直接相关的一个。**

- **纯 Host 插件**：3 个工具（`memory_judge` / `memory_recall` / `memory_image`）+ 2 个 system-prompt section（回忆块 / 记忆评分任务）+ 3 个事件监听器；**无 client、无命令、无定时器、无子进程**。
- **归档是确定性的、不调模型**：每个模型步骤前（`agent/pre-step`，防止一轮内工具输出撑爆上下文）用 DSH 的 `tokenMeter` 算占用，超过 `triggerPercent`（默认 60%）就把最早的一段对话切进 `memory/` 文件夹。
- **评分由会话模型自己给**：α（重要性）、β（信任/使用规则）、关键词，通过 `memory_judge` 工具在它自己的回合里打分；**未评分的记忆不参与回忆**。
- **回忆 = 关键词命中 + α + 代数衰减概率**；回忆块注入在**系统提示词区块**（v1.1 形态；作者试过 v1.2 挪到"最早历史消息"，已回退）。
- 重启后按 **v2 快照**恢复；`memory_image` 按关键词/记忆 id/文件名找归档图片，块里只给**文件路径**，模型用 `read_image` 读（不重传附件）。
- 引擎 `engine/` **零依赖、不 import 任何 DSH 包**，可脱离 DSH 单独跑；配置在插件目录 `config.json`，改完热加载。
- 原名 `dsh-memory-recall`，0.3.0 起改名 `dsh-rofm`（避开 npm 同名包）。

**对我们的价值：高。** 它的 α/β + 衰减 + "未评分不召回" 和我们筹划的 `stance`/`belief` 加权是同一个问题的两种解；而且它是 **DSH 原生**的，装上去就能和元亨的 YHLZ 记忆并存做对照实验。

## 2. 数字生命型系统（同赛道）

### 2.1 `Mieksido/surfcore` ★211 · MIT（SnowLuma 闭源）· 2026-10-26 建

**这是这批里最该细看的一个——它和 YHLZ 是同一件事的另一种做法。**

> "它不是'把大模型接进 QQ'的机器人框架，而是**给模型一个身份、一套会遗忘的记忆、一份作息、两只手（QQ / B站）和一个能坐在你桌面上的分身**。"

双进程架构：

- **一条腿在 DSH 里**：`surfcore` 插件——设置窗口、B 站生物钟、记忆卡维护、桌宠接口；
- **一条腿是独立进程**：`src/bridge.js`——QQ 收发、会话映射、控制台、安全闸门。

四项能力（它的自我描述）：

1. **在 QQ 里当一个群友**：自己判断要不要看、要不要说、说几条、引用谁；说完能判断"这段可以结束了"，带着"下次怎么接"潜水。
2. **在 B 站当一个用户**：有作息、偏好、每日额度；看视频会打分、评论、回帖、发动态。
3. **记得住也忘得掉**：一份会衰减的记忆卡（进提示词）+ 一份永不遗忘的全量卡（只存档）。
4. **会主动找你**：从近期记忆里提炼"我想弄明白/想做点什么"，安静时段主动分享或索取。

工程细节（README 里全是踩过的坑，很实在）：

- 目标 **DSH 0.2.1-rc.2+**（rc.3 能装、功能未完整回归）、Windows 绑定（沙箱 ACL / SnowLuma / 启动脚本）;
- 安装顺序不能反：**先 `npm install` 再 `install_bundle`**，否则激活时报 `Cannot find module '@deepseek-ai/schemastery'`；junction 安装时模块从**仓库真实路径**解析，所以仓库根必须有 `node_modules`；
- **必须从仓库根目录装**：插件里有 19 处 `../../../src/xxx.js`，只装 `plugins/surfcore` 会去 `D:\src\...` 找；
- 装完 **F5 刷新**或重启 DSH，否则设置里看不到（客户端模块图是页面加载时的快照）；
- 不含任何真实数据：角色卡脱敏、记忆卡空壳、群号/QQ 号/B站 mid 全占位。

配套仓库：`surfvoicelocal` / `surfvoicecloud` / `surfpet`。

**对我们的意义**：它把"数字生命"做成了 **DSH 插件 + 独立桥接进程**，而 YHLZ 是**自建 daemon**。两条路的差别值得逐条对照：插件化省掉了进程管理，但把生命周期交给了 DSH；自建 daemon 自由，但要自己维护启动/守护（我们刚为这个修过启动入口）。

它的 `surfpet`（桌宠）也提示：桌宠可以是独立仓库，不必和主链路耦合。

### 2.2 `PurrPod/purrcat` ★85 · MIT · Python + Electron

> "An Agent foundation designed around **information theory**… **The model decides capability; information decides direction.**"

- 关注"信息如何进入系统、执行中如何流动、哪些值得长期保留"；hybrid memory、UI 插件架构、编排信息流。
- 安装：`curl … install.sh | bash` / PowerShell 一行装，源码克隆到 `~/purrcat`；`purrcat desktop start`；API 端口默认 8000（可用 `PURRCAT_API_PORT` 固定）。
- 文档站 `purrpod.github.io`；只有源码安装，没有打包安装器；Windows 流程测试最充分。
- **不是 DSH 插件**，是独立 Agent 基座。

**价值：概念层。** "信息决定方向"和我们在记忆上做的"来源/可信度决定注入"是一路；但它的代码是独立 Python 栈，不能直接进 DSH。

### 2.3 `sola1039/HAST-SEC` ★444 · **非商用许可** · 武汉光影流明

**价值：方向参考。** "语言 + 动作"的具身演示，和我们 Live2D 桌宠同题；但许可非商用、且不含训练链，不能作为产品基础。

## 4. 横向判断

### 4.1 三个"能装"的，优先级怎么排

| 插件 | 前置 | 我们这台机器 | 建议 |
|---|---|---|---|
| **dsh-rofm** | 无（零依赖） | ✅ 可装 | **先试这个**：和记忆线直接相关，装上就能对照 α/β+衰减 与我们的 stance/belief |
| **dsh-video-storyboard** | ffmpeg（+可选 yt-dlp/ASR） | ✅ 可装（ffmpeg 要先确认） | **第二个**：给元亨补"看视频"，和现有 bili 工具天然互补 |
| **dsh-qwen-paint** | ComfyUI + 13.3GB 模型 | ⚠️ 8GB 显存危险区 | 先别装；想试就走优化版的串行模式，且要接受"可能静默出错、必须人眼看图" |

### 4.2 surfcore 是最值得做"对照研究"的

它和我们解决同一组问题（身份/记忆衰减/QQ 行为/B站/桌宠），但选择了 **DSH 插件化** 而不是自建 daemon。值得逐条对照的三点：

1. **记忆双卡**：衰减卡进提示词 + 全量卡只存档。我们的 L2 是单库 + status 状态机（active/downgraded/archive），没有"永不遗忘的档案"这一层。
2. **QQ 群友行为**：它把"要不要说、说几条、引用谁"交给模型自己判断，并显式建模"这段可以结束了/下次怎么接"。我们的 QQ 桥接更偏"工具化"。
3. **B 站作息与额度**：它把"用户行为"做成有作息、有额度的角色，而不是"有任务才动"。

### 4.3 风险与许可

- **surfcore**：SnowLuma 是**第三方专有运行时，不随仓库分发**——要用得自己去官方 Releases 拿。MIT 只覆盖它自己的代码。
- **HAST-SEC**：**非商用许可**（`hast-sec-noncommercial-0.1`），只能学习研究。
- **music-learning**：**AGPL-3.0**，并入闭源项目会传染。
- **qwen-paint**：README 明确 **Qwen-Image 模型禁止商用**。
- **ds-h-rofm / video-storyboard / qwen-paint**：MIT，可放心读与改。

## 5. 如果只做一件事

**先装 `dsh-rofm` 跑一周，用它的 α/β + 衰减与元亨现有的记忆做对照。**

理由：它是这批里唯一"装上去就能直接回答我们一直在纠结的问题"的东西——记忆该不该衰减、评分该由谁给、召回该不该有概率。而且它零依赖、零风险、随时可卸。
