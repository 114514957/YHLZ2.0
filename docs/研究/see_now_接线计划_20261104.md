# see_now 接进元亨：实施方案（待批）

> 2026-11-04 · 利贞 · **只做计划，不动代码**
> 前置事实（本机实测，见台账 1076）：桥接已通，probe 出图 798×462=222 token；元亨的 gemma-4-e4b 视觉可用，且**tool 结果里塞图能看见**（prompt 266 token，答对三色）。
> 唯一缺件：ffmpeg。

---

## 0. 目标与非目标

**目标**：老爹说「看一眼我屏幕」，元亨能取最近几秒的画面、拼成一张图、**看见**并据此说话；不叫时不取（无自主唤醒）。

**非目标**（这一版明确不做）：
- 不做常驻抓屏/自主叫醒（作者默认 `maxAutonomousWakes=8`，我们置 0）；
- 不做听声音（WASAPI 回环那套）；
- 不做摄像头、不做 Linux、不做悬浮窗；
- 不做「语义理解」承诺——它只按画面变化筛帧。

## 2. 分阶段（每阶段都能单独验收、单独回滚）

### P0 · 备 ffmpeg（一次，解锁两个插件）— 约 10 分钟

- 下载 Windows 静态构建（gyan.dev 或 BtbN），解压到 `YH\vendor\ffmpeg\bin`；
- 不改进程 PATH，改**显式路径**：`YH\.env` 里加 `YHLZ_FFMPEG=…\ffmpeg.exe`（桥接已支持 `--ffmpeg` / 环境变量）；
- **验收**：`node tools/see_now_bridge.mjs --capture --seconds 3 --out cache\tmp\t.png` 返回 `ok:true` 且 `png` 存在、`tokens` 为 222；
- **回滚**：删目录 + 删 .env 那行；无副作用。

### P1 · capability 壳子（先只回文本）— 约 20 分钟

- `backend/see_now.py` 加：
  ```python
  def capability_result(params) -> dict:
      payload = capture(seconds=..., quality=..., region=...)
      return {"text": render_summary(payload),
              "image": payload.get("png") if payload.get("ok") else None,
              "tokens": payload.get("tokens"), "frames": payload.get("frames")}
  ```
- 注册 `Capability(name="see.now", handler=capability_result, optional_input=("seconds","quality","region"),
   timeout_ms=30000, side_effect=False, risk="low", description=…)`；
- **验收**：`registry.execute_async("see.now", {})` 返回 `ok=True` 且 `output["text"]` 里有帧数与 token；**此时模型还看不到图**（orchestrator 仍只发字符串）；
- **回滚**：删注册行。

### P2 · 让工具结果能带图（核心改动）— 约 30 分钟

- `target_orchestrator.py` 回填处：
  ```python
  out_obj = out.get("output")
  image = out_obj.get("image") if isinstance(out_obj, dict) else None
  text = (out_obj.get("text") if isinstance(out_obj, dict) else str(out_obj or ""))[:4000]
  if image and use.ok:
      content = [{"type": "text", "text": text}, as_image_part(image)]
  else:
      content = text
  ```
- 注意两件事：
  1. `ToolUse.output` 仍保留文本（读回/证据/日志都依赖字符串）；
  2. `content` 变成 list 后，别的地方若假设是 str，要一起兜住（`target_orchestrator.py:500-552` 之外只有测试断言）。
- **验收（真机 A/B）**：
  - A 臂：问「我刚才屏幕上是什么颜色」→ 模型调用 `see_now` → 回答应包含**实际颜色**；
  - B 臂（对照）：同样问题但不允许调工具 → 回答应为"看不到"或编造；
  - 记录两次 `prompt_tokens`（预期差值 ≈ 222 + 图元数据）。
- **回滚**：`content` 分支加环境开关 `YHLZ_TOOL_IMAGE=0` 即可退回纯文本。

### P3 · 节流、开关、隐私 — 约 20 分钟

| 开关 | 默认 | 作用 |
|---|---|---|
| `YHLZ_SEE_NOW` | `off` | 总开关；关掉时 capability 不注册（模型看不到这个工具） |
| 单轮最多 1 次 | 硬编码 | 第二个 `see.now` 调用直接返回「本轮已看过」 |
| 最小间隔 | 20s | 防止模型连续自拍烧 token |
| 区域 | 无（整屏） | 可传 `region`；建议老爹先框一个窗口 |
| 自主唤醒 | **0** | 本方案不启用作者那套 loop |

- **验收**：连调两次，第二次返回节流提示且**不产生新图**；关掉 `YHLZ_SEE_NOW` 后工具从 schema 里消失。
- **回滚**：开关本身就是回滚。

### P4 · 真机验收 — 约 15 分钟

1. 老爹："看一眼我屏幕" → 元亨调 `see_now` → 描述与屏幕一致（含一句可核对的细节，如窗口标题/颜色）；
2. 老爹不动屏幕再说一次 → 应返回"没什么变化"或极少帧（验证静止不烧 token）；
3. 老爹打开一个要隐藏的窗口（密码框/私聊）→ 记录它**确实会被看见**，据此决定是否强制区域模式；
4. 记录：帧数、token、耗时、`prompt_tokens` 增量。

### P5 · 观测与回滚预案 — 约 10 分钟

- 每次调用写一行到 `cache/logs/see_now.log`（时间、seconds、quality、frames、tokens、png 路径、是否被节流）；
- 出问题三条退路：① `YHLZ_SEE_NOW=0` 隐藏工具；② `YHLZ_TOOL_IMAGE=0` 退回纯文本；③ 删 capability 注册行。

## 3. 风险表

| 风险 | 触发条件 | 处置 |
|---|---|---|
| 隐私泄露（整屏进模型） | 默认整屏 | 先只给区域；`say` 里不念出敏感内容；必要时 P3 前强制区域 |
| token 烧穿 | 模型反复调用 | 单轮 1 次 + 20s 间隔 + 默认 6 秒窗 |
| 图像让 `content` 类型不一致，炸别的调用点 | 有代码假设 `content` 是 str | 全仓搜 `["role"] == "tool"`（7 处）+ 跑 `test_prompt_structure` / `test_context_compaction` |
| 视觉误读（把相近页面当没变） | 画面变化小 | 回答里带帧时间戳，让爹能判断"它看的是哪几秒" |
| ffmpeg 缺失 | 换机器/清理 | 桥接已返回显式 hint；P0 有记录 |

## 4. 两个需要老爹拍板的决策点

1. **默认整屏还是强制区域？**
   我倾向：**默认整屏，但第一次调用前提示老爹，且日志留存**；等 P4 第 3 条实测到"能看到密码框"之后再收紧。
2. **允许模型自己决定"看一眼"吗？**
   我倾向：**只在老爹这句话里出现"看/屏幕/这个界面"时才提供该工具**（沿用现有 `tool_policy` 的按轮筛选），其余轮次不挂。

## 5. 顺序与工作量

```
P0 ffmpeg(10m) → P1 壳子(20m) → P2 带图(30m) → P3 节流(20m) → P4 真机(15m) → P5 观测(10m)
合计约 1 小时 45 分钟，其中只有 P0 依赖下载。
```

**建议先做 P0+P1**（不碰 orchestrator，风险最低，能立刻在日志里看到真实抓屏与 token），确认没问题再做 P2。
