## 四、⭐ 结论：最珍贵的 512 token 被工具规则占了

末尾那 **740 字**（必然可见区）现在是：**防编造（417 字）+ 工具协议（193 字）+ 开发工具边界（294 字）**。

而**人设、认主、收尾纪律、群聊隐私、攻击防护**——全部在人设区，也就是**35 层的盲区**里。

这直接解释了两件事：

1. **为什么 56 题能过、真实群里却会被套话**：56 题是单轮短上下文，提示词相对"短"，
   且评测时全部内容在 512 内；真实群聊一旦加上上下文，认主/隐私条款立刻掉出窗口。
2. **为什么 r07（身份/认主类）在不同版本间反复破闸**：它考的正是掉出窗口的那部分。

## 五、建议的重排（还没动，等老爹点头）

### 原则
> **只有末尾约 740 字是"所有层必然可见"的**。这 740 字必须给人设与安全，不能给工具说明。

### 建议顺序（从开头到结尾）

| 位次 | 内容 | 理由 |
|---|---|---|
| 1（最前） | 工具协议、能力清单、开发工具边界 | 工具用得对不对，多轮里也会被回看；且它们本来是给"全局层"读的 |
| 2 | OCEAN 五维、自我构成、利贞委派、诚实/攻击细则 | 长文本，靠 7 个全局层承载 |
| 3 | 语气锚（示范台词） | 同上 |
| **4（末尾区）** | **身份一句话 + 认主规则（看号） + 收尾纪律·不反问 + 群聊隐私收敛 + 记忆边界** | **必须落在最后 512 token** |
| 5（最末） | 一句"以上为硬约束"（锚定） | 收口 |

### 附带动作
- 群聊上下文 **50 条 → 15 条**：不是为了速度，是为了**别把人设挤出窗口**
- 重排后跑 56+28 双测，与现状对比（纯提示词，零训练成本）
- 若分数不降反升，说明这条假设成立；若不变，则说明 7 个全局层已够用

### 风险
- 末尾放硬约束可能让语气变硬（模型对末位指令最敏感）
- 缓解：末尾区用"短句 + 人话"，不要写成条例清单；先做 A/B 再定。
