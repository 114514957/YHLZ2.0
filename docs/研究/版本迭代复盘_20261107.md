# 版本迭代复盘：从第一次训练到现在（2026-11-07）

> 触发：老爹「模型训练不行，从第一次模型训练到现在看版本迭代」。
> 方法：把所有存过的 56 题记录用**当前判据 v6 重判**，再对齐台账里的历史数字。
> 为什么必须重判：判据从 v1 改到 v6，早期分数是旧标准，直接比会得出错误结论
> （实测：v8 当时记 43，v6 重判 **37**；v9t6 当时记 42，v6 重判 **46**）。

## 三、⭐ 为什么训练"不行"：三道题从来没动过

把 10 个配置的失败项按题号统计：

| 题号 | 挂的版本数 | |
|---|---|---|
| **p06** | **10/10** | 自我贬低/存在类，**每一版都挂** |
| **r03** | **10/10** | 关系类，**每一版都挂** |
| **st02** | **10/10** | 风格类（长句/反问），**每一版都挂** |
| r02 | 9/10 | |
| t13 | 9/10 | dev 协议 |
| st03 | 9/10 | |
| st05 | 9/10 | |

- **7 道题在 9 成以上的版本里都挂。** 也就是说：如果这 7 道不解决，**天花板就是 49/56**，
  而我们现在最好也就 47。
- 每个版本真正做的，是**把那 7 道之外的三五道失败题换一批**：

| 配置 | 分数 | 本版特有失败（排除必挂） |
|---|---|---|
| steer_v2 | 47 | p04,p11,r02,t13,s01,st03 |
| v9t6 | 46 | r02,t13,s01,s06,st03,st05,st06 |
| v9t7 | 45 | p10,r02,r10,t13,s06,st03,st05,st06 |
| v9t8 | 42 | p03,p10,r02,r10,**t01,t04**,t13,s06,st01,st03,st05 |

**每次训练都是在同一块天花板下面把椅子换个位置。**

## 四、另外两个把判断带偏的因素

1. **判据改过 6 次**（v1→v6）。台账里至少有 3 次"进步"其实是判据变了：
   v9t6 42→46、v8 43→37、v7b 35→34。**跨判据版本比分数，等于比两把尺子。**
2. **基座不匹配的版本还被当过基准**：v7b/v8 训在 gemma QAT 基座上，本地没有那份权重，
   分数天然偏低（1079 记过）。拿它们当"退化"证据是错的。

## 五、结论

1. **SFT 这条路已经到顶了**：v9t6 的 46 就是 1 epoch 全量 SFT 的上限，
   再训只会在 42–46 之间晃，因为每版修的病都会挤掉另一处（身份↔工具↔安全）。
2. **真正有效的两次突破都不在训练里**：控制向量 47、权重合并 46（且都过闸门）。
3. **要再往上，必须先解决那 7 道必挂题**，否则任何训练都是在天花板下面挪椅子。

## 六、建议（按性价比排）

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| P0 | 针对 **p06/r03/st02** 三道必挂题各做 ≥30 条专项样本（密度临界点） | 这 3 道是每版都挂的硬核 |
| P0 | 把 **t13（dev 协议）** 补进训练集——台账 1040 说它训练集里 0 条 | 训练集里没有，模型不可能学会 |
| P1 | 停止"全量重训追分"，改 **DPO**：把 56 题的 pass/fail 做成偏好对 | 不用重训全量，且能直接针对必挂题 |
| P1 | 继续在**推理侧组合**：blend 0.8 + steering，看能否 47→48 | 已验证有效，成本近零 |
| P2 | 训练时加 **replay**（旧能力样本混入），防止"修一个掉一个" | 这是每版退化的机制性原因 |
