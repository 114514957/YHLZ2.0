## 1. 一句话结论

八个项目里，**只有一个现在就该装**（dsh-video-storyboard），**一个等 GPU**（IndexTTS2 studio），**三个只读**（surfcore / Seekmemory / PurrCat），**两个弃**（surf-core、dsh-orb-cordis），**一个延后到换卡**（dsh-qwen-paint）。

理由不是功能好坏，是**依赖与权限边界**：能用现有栈跑的才装，需要新开一套运行时或拿桌面权限的，只读。

## 3. P0 详情：dsh-video-storyboard

### 为什么是它

元亨有 `bili_find / bili_watch / bili_status / bili_notes / bili_read`，但没有"看"的能力——只能拿文字。这个插件把视频压成 **一张 9–16 格图 + 带时间码的文本清单（384 token 封顶）**，需要细节时再 `video_zoom` 局部放大。取舍和我们自己的 prompt 预算结论同源：**信息密度优先，token 封顶**。

### 四个工具（报告写成两个，已纠正）

| 工具 | 作用 |
|---|---|
| `video_probe` | 只读容器头（时长/分辨率/帧率/有无音轨/是否已分析），**不花图片 token** |
| `video_storyboard` | 出宫格图 + 文本清单（每格起止时间、台词、切了几刀） |
| `video_zoom` | 只看某一段（更小时间窗、更密格） |
| `video_locate` | 纯文本：一句话 → 时间码 |

### 前置（本机现状）

```
ffmpeg   : 不在 PATH   ← 必须先补
ffprobe  : 不在 PATH
yt-dlp   : 不在 PATH   ← 只在贴 B站/YouTube 链接时需要，可不装
ASR      : 可选，不装就没台词列；也可直接给 SRT/JSON
```

### 安装步骤（等批准后执行）

```cmd
winget install Gyan.FFmpeg          :: 或官方压缩包解压后加 PATH
git clone https://github.com/SAOS-3624/dsh-video-storyboard.git
cd dsh-video-storyboard
node --test                          :: 需要 ffmpeg 在 PATH
node scripts/install-dev.mjs         :: 装进 DSH profile
:: 完全退出 DSH 再打开（host 插件在启动时装配，F5 不够——今天 dsh-music 已实测）
```

### 验收

1. `node bin/storyboard.mjs <片子> --cells 9 --text` 出图 + 清单；
2. 会话里让元亨"看"一段 90 秒的片子，问"第 3 分钟/第 42 秒发生了什么"；
3. `video_zoom` 对快切段复读，确认格号能对上时间码；
4. 记录：一图多少 token（应为 384 量级）、一集 5 分钟要几张图。

### 回滚

把 profile 里 `dsh-video-storyboard` 的 dependency/bundle 行删掉、删 junction、重启 DSH（和 dsh-music 一样的卸载方式）。

### 风险

- ASR 若走公网，视频内容会离开本机 → **默认不配 ASR**，或用本地；
- 快切素材时间戳会漂；音乐段落会让 ASR 产生似是而非的字幕；
- v0.1，manifest 字段与参数可能变。

## 4. P1 详情：IndexTTS2 两件

### 选型

先 **studio**（低显存、单句、可操作），跑稳之后再考虑 **longform-workbench**（多轨时间轴）。理由：长篇的核心难题是**时间轴累积误差**，而时间轴必须先有一个稳定的单句基线。

### 上游基线（非 fork 锁定，来自 IndexTTS2 上游资料）

| 类别 | 值 |
|---|---|
| Python | 3.10（`>=3.10,<3.12`） |
| Torch | cu128 wheel 通道 |
| Gradio | 5.45.0（webui extra） |
| DeepSpeed | 0.17.1（可选加速） |
| 音频 | librosa 0.10.2.post1、descript-audiotools 0.7.2、ffmpeg-python 0.2.0 |
| 中文 | jieba 0.42.1、cn2an 0.5.22 |

### 与现有能力去重（重要）

我们已经有三套声音链路：**Qwen3-TTS / edge-tts / GPT-SoVITS + Seed-VC**。IndexTTS2 的增量价值只在两点：**音色与情绪解耦**、**显式时长控制**。所以 P1 的验收标准应该是"这两点比现有链路强多少"，不是"能不能出声"。

### 8GB 显存的做法

1. 单句 + `--fp16` 起，记录峰值；
2. 逐项加 `--accel`、`--torch_compile`，每次只加一项，记峰值与首包时延；
3. 长文先切段（30s 一档），批量并发固定 1；
4. 任何 OOM 都要留下"GPU 型号 + 驱动 + torch + flags + 模型哈希"四元组，便于回滚。

### 前置

GPU 空闲（LLM 调整完成）、Python 3.10 独立 venv、模型权重（数 GB，需 SHA256 自存）。

## 5. 只读项：要带走的结论

### surfcore（真的那个）

和 YHLZ 同题异构：**DSH 插件 + 独立 bridge 进程**（我们是自建 daemon）。三处值得对照：

| 维度 | surfcore | YHLZ | 要判断的 |
|---|---|---|---|
| 记忆 | 衰减卡进提示词 + 全量卡只存档 | 单库 + active/downgraded/archive 状态机 | 要不要加"永不遗忘的档案层" |
| QQ | 群友式：要不要说、说几条、引用谁、说到哪停 | 偏工具化桥接 | 她的"发言决策"现在是模型自发还是我们在调度 |
| B站 | 有作息、偏好、每日额度 | 有任务才动 | 要不要给"用户身份"而不只是"任务执行" |

### Seekmemory

只取一个问题：**每条记忆是否必须带来源/时间/主体/可撤回**。我们 L1/L2 现在有 status 但没有"来源字段"，这条可以单独立项。

### PurrCat

只取分层：UI 插件 / DAG 编排 / 容器工具 / 混合记忆 / 技能沉淀。与我们 L1-L3 的对应关系值得画一张对照表，不接代码。
