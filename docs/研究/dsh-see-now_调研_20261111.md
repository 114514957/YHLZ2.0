## 1. 它对付的是什么

想让 AI 陪你看屏幕，直觉做法「定时截全屏」有两个死结：

| 做法 | 后果 |
|---|---|
| 每 2 秒截一张全屏 | 一分钟 30 张重复图，token 直接烧穿 |
| 每 30 秒截一张 | 中间全丢，AI 只会说「看起来你在用电脑」 |

它的翻转：**先判断这一帧值不值得看，再决定传不传**。每帧打 0–255 的「变化分」（64×36 网格 HSV 加权差，约 0.2ms），只有「画面突然换了一张」或「一直在动、攒够了量」才留；留下来的几帧拼进同一张图，摊薄固定成本。

同样 30 秒操作，别人烧 30 张图，这里常常 2~3 张。

## 2. 机制：两道筛子

### 2.1 打分刻度（0–255，作者实测）

| 内容 | 分数 |
|---|---|
| 静止桌面 | **0.00** |
| 光标在静止画面上移动 | **0.7** |
| 两张色调接近的照片切换 | 16~18 |
| 滚网页 / 切窗口 | 30~42 |
| 两张完全不同的照片切换 | 46~63 |

`cutAbs:12` 就卡在这里：照片切换抓得住，光标和微小抖动碰不到。
（0.1.4 起打分加了**亮度归一 + 黑边补偿**，默认开、可关。）

### 2.2 ① 切点：分数跳得又高又孤立

```
score ≥ cutAbs(12)                 // 绝对地板
score > 2.5 × max(1, 前后帧)        // 尖峰
mc ≥ cutSpikeMcAbs(20)             // 尖峰也要有运动补偿覆盖
距上一刀 ≥ 0.4 秒                   // 不应期
```

三条补充出口（换机位、强台阶、相似构图）之外，还有一套**背景守卫**：最近 6 帧里没怎么动的格子算稳定背景；若这帧只改掉一部分（`bg < 100`）、变化格数 ≤ 600、且没盖满画面高度（`mcSpanY < 0.85`），判**前景运动**（手、勺子、产品）不切。

高分候选（`score ≥ 60`）**再等 0.5 秒做未来帧确认**：拿最近 24 帧的参考背景，看被改掉的部分有没有回来。手离开、画面回到旧背景就不切；真换镜头在新场景稳定下来仍切。

> 这套守卫是拿**真实带货直播**调出来的（大手/产品盖住外圈），不是实验室推的。作者在 CHANGELOG 里记了每次误判和补丁。这是我最信它的一部分。

### 2.3 ② 积分：分不高但一直有

```
need = 4 分 × fps × 3 秒          // fps 默认 12 → 144
每帧累加自己的分，累够就录、清零
```

为什么两个都要：**尖峰是相对的**，低分区也会成立（实测缓慢放大某帧 s=13.6、邻居只有 1.1/1.3，尖峰判据完全放行）；只有地板也不行，一镜到底每帧 4 分永远不「跳」。

> **0.2.3 修了这里一个真 bug**：`need` 原来写死 `4×12×3`，但积分累的是**绝对差**（与 fps 无关）。8fps 时阈值偏高、30fps 时积分帧直接归零——同一段素材实测 8/12/15/24/30fps 积分和是 5093/5092/5090/5090/5090，几乎不变，而旧阈值从 96 涨到 360。改成按 `INTEGRAL_BASE_FPS` 算，三处按帧标的窗口也按 fps 折算（`timeNormalizeFrames`）。**但 0.2.3 没发到 npm**，见 §7。

## 3. 成本口径（这段最值得抄）

token 按宿主 42px patch 网格算：`rows×(cols+1)+2`。

| 档位 | 画布（画面 + 音轨条） | 每张 token |
|---|---|---|
| `low`（默认） | 798×450 + 12px = **798×462** | **222** |
| `standard` | 1050×600 + 30px | 392 |
| `high` | 1260×720 + 36px | 560 |
| `ultra` | 1596×900 + 24px | 860 |

**① 宽度故意对齐 42，不对齐 16:9。** 800 会 pad 到 812 = 19.3 格，白算一整列；798 正好 19 列，面积只少 0.25%，每张省 11~24 token。整条链路唯一**零代价**的降本点。（0.0.10 那一版从 254 降到 222 就是这条。）

**② 音轨条不额外花钱。** token 按 42px 一行算，是阶梯函数：450 高占 11 行、上界 462，底下空着 12px 照收 11 行的钱。条就长这 12px 里，加不加同价。

> 一张图塞 4 帧还是 8 帧**价格一样**。「多留一帧几乎免费、漏掉一帧才贵」——这条成本结构决定了它所有设计取舍。

### 3.1 看久了会变贵——而且原因不在它（新增，重要）

**每张 222 token 只是编码成本。真正吃钱的是累积。**

图在会话历史里是一段 base64：一张 798×450 的 PNG 约 130KB，base64 后约 **173KB**。

DSH 的「图片省略」机制：**单个请求里保留的 base64 图片总量超过 `maxRequestImageBytes`（默认 20MiB）时，把最老的图片永久替换成「附件路径」占位文字，然后重试。**

关键词是**永久**——它改的是**会话历史本身**。历史一改，前缀缓存从被改的位置往后全部对不上：**每省略一张老图，那一段上下文就重新计费一次。**（社区实测：图片从第 43 万 token 处开始出现，每省略一张，后面 14 万 token 重算。）

换算：20 MiB ÷ 173 KB ≈ **120 张**。`dense` 档 110 秒出 6 张（社区实测），一小时约 200 张 → **半小时出头撞线**；默认节奏 15~40 秒一张，也在 1 小时上下。

**插件拦不住它**（省略发生在宿主发请求之前，插件只看得到自己交付的那张）。能做的只有三条：

- **长会话分段**：陪看一两小时后开新会话，比让老图被反复省略便宜得多；
- **别一直挂 `dense`**；
- 静止画面本来就不出图，那段是真免费。

> 作者自己的结论：真要根治得在宿主侧让省略**从最前面开始**（连同更早历史一起截），而不是在历史中间挖洞。这不在插件范围里。
>
> **这条对我们比 flops 数字重要**——它决定了「能不能一直挂着」的答案是不能。

## 4. 能力面（0.2.x）

### 4.1 工具

| 参数 | 说明 |
|---|---|
| `action` | `watch`（阻塞取图）/ `peek` / `start` / `stop` / `status` / `window` / `region` / **`help`** |
| `region` | 只看一块 `"x,y,w,h"` 或 `"off"`；`action:"region"` 拖框选 |
| `say` | **唯一**能进悬浮窗、能被念出来的通道 |
| `quality` | 四档，改它重启采集 ~0.6s |
| `pace` | `calm`(20分/30s) / `normal`(12分/15s，默认) / `dense`(7分/8s) |
| `scene` | 逐场景：一图一画面铺满，粘性 |
| `seconds` / `minFrames` | 阻塞上限（默认 300，封顶 860）/ 少于 N 帧别给 |
| `source` / `path` / `realtime` | 屏幕 / 摄像头 / 视频文件 |
| `tier`（0.1.3 起） | 模型可改档位，但契约里不教它 |

**`action:"help"` 是 0.1.3 的工程决定**：工具契约从 **9187 字符砍到 6803（-25.9%）**——description 是每轮请求都要重发的常驻文案，所以「为什么 / 多少 token / 实测数字」搬进手册现取，契约里只留「什么时候调、默认值多少」。**这个取舍对我们自己的工具设计直接可用。**

### 4.2 `/seenow` 斜杠命令（0.2.1 新增）

| 命令 | 行为 |
|---|---|
| `/seenow` | 开窗（幂等）→ 起采集 → 把常驻循环绑到**发命令的这个会话** → 通知模型「眼睛开了」 |
| `/seenow off` / `status` / `show` / `hide` | 停 / 查 / 显示 / 最小化到托盘 |

命令**不提交用户消息、不额外开一轮**——宿主侧直接执行，只投一句话给模型。没有 `commands` 服务时自动跳过注册，工具照常可用。

### 4.3 新增的配置面（`~/.dsh/see-now.json`）

| 字段 | 默认 | 作用 |
|---|---|---|
| `maxAutonomousWakes` | 8 | 连续这么多次自动叫醒没人理 → 收工（窗开着时≈实际陪看时长） |
| `idleStopMin` | 3 | 没开窗时，用户这么久没说话 → 收工 |
| `defaultPace` | `normal` | 还多了 `game-economic` |
| `fps` | 12 | 采集与打分共用；不一致会让积分阈值和密度窗整体偏 |
| `timeNormalizeFrames` | `true` | 三处按帧窗口按 `帧数/12×fps` 折算，12fps 时逐位不变 |
| `tierMode` | `density` | `weight` = 按变化分切面积（省 28~45% token，但覆盖时长变长、出图变慢） |
| `tierCurve` | `docx` | `perceptual`（按人眼瞬时记忆定标，一格 3s~0.3s）/ `custom` |
| `tierMap` / `tierStyle` | `standard` | 第 i 档映射到哪一档 |
| `changeLog` | `false` | 交付时附「这期间屏幕怎么动的」，每张 +约 100 token |
| `maxCrop` | `0`（未发布） | 一格都不裁；老行为 `0.3`（能多装 8.9% 帧，但每格少 10~23% 画面） |
| `speechPacing` | `true` | 下一轮按上一句时长排 |

`changeLog` 值得单说：出图队列只留最新一张（「宁可丢老画面，不给模型看十几秒前的事」），这在**陪看视频**时对，但**配合操作电脑时不够**——点完一下、或者上一轮思考的十几秒里屏幕变了什么，回来只剩一张「现在」。打开后每张图（含被挤掉的）留一行摘要：`27.4s · 分 35 · ⚡切场景 · 中右 51%`。

### 4.4 本地视频回放控制（0.2.0）

`pause` / `resume` / `seek` / `configure`——本机视频能暂停能跳，不用等播完。

## 5. 平台（这条改得最多）

| 平台 | 屏幕引擎 | 要额外做的 |
|---|---|---|
| Windows | `ddagrab`，不行退 `gdigrab`（自动探测） | 无 |
| macOS | `avfoundation` | 系统设置 → 隐私与安全性 → **屏幕录制** 勾上跑 DSH 的 App |
| **Linux** | **`portal`**：xdg-desktop-portal ScreenCast → PipeWire → gst | `python3-gi` + GStreamer 基础插件 + `pipewiresrc`；首次弹一次选屏框（之后用 restore_token） |

**Linux 怎么抓**（0.2.0 新增）：Wayland 下 ffmpeg 没有正路（`x11grab` 抓的是 XWayland 根窗口、`kmsgrab` 要 root），所以走 portal：

```
portal 握手（一次授权，restore_token 存 ~/.dsh/see-now/portal-token.json）
  → PipeWire 节点（GNOME 上还要 OpenPipeWireRemote 拿 fd）
  → gst：pipewiresrc → videorate → videoconvert → [videocrop] → videoscale → rgb24
```

Mutter/KWin 只在有 damage 时发帧，所以加了 `keepalive-time=250`（桌面不动时每 250ms 重发最后一帧）。

**Linux 也能听声音了**（0.2.1）：抓 PulseAudio/PipeWire 的 monitor 源（`ffmpeg -f pulse -i <默认输出>.monitor`，`pactl` 找默认输出），只要 `numpy` + `ffmpeg`，**不需要 pyaudiowpatch**。

**悬浮窗**（Tk）在 0.1.4 之前 macOS/Linux 上**必崩**（`ctypes.windll`，issue #40），现在能起：非 Windows 默认走 `frost`（静态磨砂，不抓屏、CPU≈0），`live`（实时玻璃）在 Wayland 拿不到窗口背后像素会整窗发黑。

## 9. 本机能不能跑（2026-11-11 21:22 复核）

| 项 | 结论 | 依据 |
|---|---|---|
| 装没装 | **没装** | `desktop` profile 的 bundles 无 dsh-see-now；`node_modules/dsh-see-now` 不存在 |
| ffmpeg | **没有** | PATH 无；`~/.dsh/tools/ffmpeg/bin/ffmpeg.exe` 不存在 |
| 声音配置 | **一套没配** | `~/.dsh` 下无 `voice.json` / `tts.json` / `asr.json` / `see-now.json` |
| 平台 | Win 满足 | 走 `ddagrab`，自动退 `gdigrab` |
| Node | 满足 | 本机 24.21.0，要求 ≥20 |
| DSH 版本 | 待核 | runtime.json 记 `0.2.1-rc.2`；台账 1022 当时记 `0.2.1-rc.3`。插件只要 `dsh-tools ≥ 0.1.0-rc.7` |

## 10. 对我们的价值

判据是「补哪一环 + 前置成本 + 边界是否诚实」，不是功能多少。

### 用法

1. **利贞看老爹的屏幕**。老爹说「这界面怎么不对」，现在我得让他描述；装上我直接看。静止几乎不出图，一操作就出帧——「调试式旁观」正是它的强项。
2. **元亨的实时视听**。她已有 B 站工具链（离线「看」靠 storyboard），这是**实时**那一半。`say` 进悬浮窗并被念出来，接上本机 TTS 就是视觉 + 听觉 + 出声一条闭环。0.2.1 的**进程分声源**还解决了「AI 听见自己的 TTS」这个老毛病。
3. **方法论**（不用装就能拿）：
   - 42px patch 网格反推画布尺寸（§3）
   - 阶梯函数把附加信息塞进免费余量（音轨条）
   - 工具契约瘦身 25.9%（`help` 现取，§4.1）
   - `changeLog` 这种「摘要替代原图」的思路
   - 省略机制与前缀缓存的成本模型（§3.1）——**这条对元亨自己的长上下文设计同样成立**

### 担心

1. **它会自己叫醒模型**：`maxAutonomousWakes` 8、`idleStopMin` 3 分钟。挂上之后是主动打扰的，不是纯被动工具。日常挂要先把 `defaultPace` 改 `calm`。
2. **常驻抓屏 0.28~0.45 核**。老爹这台同时跑模型和 TTS，要不要常驻得算。
3. **隐私**：看的是整屏——QQ、密码框、私聊都进帧。区域模式能收窄，但收窄后 token 反而更贵（帧不再缩小，low 档 2 帧约 345 token）。
4. **长会话成本不是线性的**（§3.1）：1 小时左右撞 20MiB 省略线，之后每省一张都在重算前缀。**这不是插件的锅，但用的人必须知道。**
