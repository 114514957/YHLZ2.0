## 0. 一句话

**给 DSH 的实时视觉插件：把屏幕（或摄像头 / 视频文件）变成一串按变化量筛过的画面，几帧拼进同一张图交给模型。静止画面几乎不花 token。**

## 1. 它对付的是什么

想让 AI 陪你看屏幕，直觉做法「定时截全屏」有两个死结：

| 做法 | 后果 |
|---|---|
| 每 2 秒截一张全屏 | 一分钟 30 张重复图，token 直接烧穿 |
| 每 30 秒截一张 | 中间发生了什么全丢，AI 只会说「看起来你在用电脑」 |

它的翻转：**先判断这一帧值不值得看，再决定传不传**。

- 每帧打一个 0–255 的「变化分」（64×36 网格上的 HSV 三通道加权差，约 0.2ms）
- 只有「画面突然换了一张」或「一直在动、攒够了量」才留下来
- 留下来的几帧**拼进同一张图**，把一张图的固定成本摊到 4~8 帧上

结果：同样 30 秒操作，别人烧 30 张图，这里常常 2~3 张。

## 2. 机制：两道筛子 + 一个装箱

### 2.1 打分（`src/cuts.js`）

64×36 网格，HSV 三通道加权差，输出 0–255。作者给的刻度（同一套代码实测）：

| 内容 | 分数 |
|---|---|
| 静止桌面 | **0.00**（屏幕采集近似无损） |
| 光标在静止画面上移动 | **0.7** |
| 两张色调接近的照片切换 | 16~18 |
| 滚网页 / 切窗口 | 30~42 |
| 两张完全不同的照片切换 | 46~63 |

默认门槛 `cutAbs:12` 的位置就是这么定的：**照片切换抓得住，光标和微小抖动碰不到**。

### 2.2 留帧两条判据，缺一不可

**① 切点** —— 分数跳得又高又孤立

```
score ≥ cutAbs(12)                 // 绝对地板
score > 2.5 × max(1, 前后帧)        // 尖峰
mc ≥ cutSpikeMcAbs(20)             // 尖峰也要有运动补偿覆盖
距上一刀 ≥ 0.4 秒                   // 不应期
```

外加三条补充出口（相机 / 机位 / 压缩场景），以及一套**背景守卫**：拿最近 6 帧算「稳定背景」，如果这一帧只改掉一部分稳定背景（`bg < 100`）、变化格数不多（`≤ 600`）、变化区域没盖满画面高度（`mcSpanY < 0.85`），就判**前景运动**（手、勺子、产品），不切。真换镜头会把稳定背景整片换掉，或至少盖满高度。

高分候选（`score ≥ 60`）还会**等 0.5 秒做一次未来帧确认**：用最近 24 帧的参考背景，看候选帧改掉的部分有没有回来。手离开、画面回到旧背景就不切；真换镜头在新场景里稳定下来，仍然切。

**② 积分** —— 分不高但一直有，攒够才录一帧

```
need = 4 分 × 12fps × 3 秒 = 144      // 固定绝对阈值，不跟着画面涨
每帧累加自己的分，累够就录、清零
```

为什么两个都要：**尖峰是相对的**，低分区也会成立（作者实测缓慢放大时某帧 s=13.6、邻居只有 1.1/1.3，尖峰判据完全放行）；反过来只有地板也不行，一镜到底每帧 4 分，永远不会「跳」。

### 2.3 出图（`pack.js` + `sheet.js`）

DP 装箱把大小不一的格子铺满画布（档位决定格子边长 1/k），合成 PNG 并烧帧号。逐场景模式走 `strategy:'single'`，一帧铺满，避免场景一密格子缩成 1/4、1/9、中间全灰条。

## 3. 成本口径（这段最值得抄）

token 按宿主 42px 的 patch 网格算：`rows × (cols+1) + 2`。

| 档位 | 画布（画面 + 音轨条） | 每张 token |
|---|---|---|
| `low`（默认） | 798×450 + 12px = **798×462** | **222** |
| `standard` | 1050×600 + 30px | 392 |
| `high` | 1260×720 + 36px | 560 |
| `ultra` | 1596×900 + 24px | 860 |

两个反直觉但算得很细的结论：

**① 宽度故意不对齐 16:9，对齐 42。** 800 会被 pad 到 812 = 19.3 格，白算一整列；798 正好 19 列，面积只少 **0.25%**，每张省 11~24 token。这是整条链路里唯一**零代价**的降本点。

**② 音轨条不额外花钱。** token 按 42px 一行算，是阶梯函数：450 高占 11 行、上界 462 —— 底下空着 12px 也照样收 11 行的钱。所以条就长在这 12px 里，「加条」和「不加条」同价。其余档位同理（600 余 30、720 余 36、900 余 24）。

> 一张图塞 4 帧还是 8 帧，**价格一样**。所以「多留一帧」几乎免费，「漏掉一帧」才贵——这个成本结构决定了它几乎所有设计取舍。

## 4. 能力面

### 4.1 工具参数（`see_now`）

| 参数 | 说明 |
|---|---|
| `action` | `watch`（阻塞取图，默认）/ `peek` / `start` / `stop` / `status` / `window` / `region` |
| `region` | 只看一块 `"x,y,w,h"`（屏幕物理像素）或 `"off"`；`action:"region"` 可拖框选，不用手量 |
| `say` | **唯一**能进悬浮窗、能被念出来的通道（普通回复只进小窗的对话记录） |
| `quality` | 四档；改它重启采集约 0.6s，并立刻返回当前帧 |
| `pace` | `calm` / `normal`（默认）/ `dense` |
| `scene` | `true` = 逐场景模式，一图一画面铺满，粘性到 `scene:false` |
| `seconds` | `watch` 阻塞上限（默认 300，封顶 860），攒够就提前返回 |
| `minFrames` | 少于这么多帧的图别给我（省 token） |
| `source` / `path` / `realtime` | 屏幕 / 摄像头 / 回放视频文件 |

### 4.2 三档节奏

| 档 | 换画面门槛 | 最多多久叫醒一次 | 适合 |
|---|---|---|---|
| `calm` | 20 分 | 30 秒 | 日常挂着，只想知道「大场面变了没」 |
| **`normal`** | 12 分 | 15 秒 | 滚网页、切窗口不会每下都留帧 |
| `dense` | 7 分 | 8 秒 | 幻灯片、逐帧播报 —— 贵，别常开 |

0.1.1 加了 `speechPacing`：下一轮叫醒按上一句的估计时长排（中文约 5 字/秒，±20%），有 3 秒地板；不再是从叫醒那一刻起算的固定间隔。

### 4.3 悬浮窗 + 声音

- **悬浮窗**是 Python Tk 的玻璃窗，AI 的话在气泡里出现并被念出来。不内置 TTS 引擎，只 dynamic import 你指的适配器；改 `voice.json` 下一句就生效（每次调用前比对配置指纹）。
- **听声音**抓 WASAPI 回环（「电脑正在放什么」，不是麦克风）+ 转写，台词按时间码挂到图上，图底长音轨条。

实测延迟链（作者本机）：静音判定 350ms + 写盘扫盘约 55ms + 转写 100–180ms ≈ **0.6 秒**。长句说满 1.8 秒先转一版，整句落盘后覆盖（首版字幕 3.30s → **2.08s**）。

> **还有一段不归 ASR 管**：一张图覆盖 15 秒，第 3 秒说的话要等第 15 秒出图才随图交付，平均 7.5 秒。要跟得上画面就压 `maxWaitSec` 或 `pace:"dense"`，代价是 token 按比例涨。

## 5. 工程侧

```
capture.js   唯一 spawn ffmpeg 的地方，一根 rawvideo 管道
binaries.js  找 ffmpeg（DSH 桌面版不进 PATH，所以不能写裸命令）
cuts.js      逐帧变化分（64×36 HSV 网格）
pipeline.js  唯一有状态的地方：帧 → 打分 → 切点/积分 → 留帧 → 档位 → pack → 出图
tiers.js     档位（格子边长 1/k）与策略
pack.js      DP 装箱
sheet.js     合成 PNG（烧帧号、留缝）
runner.js    采集管线 + 阻塞取图 + 节奏
listen.js    听声音：扫 wav → 转写 → 台词缓冲 → 挂到图上
loop.js      常驻循环：有新图就唤醒模型
index.js     工具注册与路由
```

- **181 条测试**（README 口径），`test/` 下 33 个文件。
- `debug/` 有个调试窗：左边每一帧的分数条（留下的带缩略图和格号），右边正在拼的 sheet 按真实像素位置摆、新帧落格会亮、重排会滑。**不进 npm 包、不进插件**，从外面驱动同一条流水线。
- **包本身不依赖 DSH**：`exports` 有 15 个子路径（`capture` / `pipeline` / `pack` / `png` / `tokens` / `chat` …），能当普通 Node 库用。
- 插件形态：`cordis.patch.yml` 一行 insert + `dsh.plugin.json`（inject `sessionController` / `tools` / `attachments`）。peer 依赖可选。

### 实测开销（作者机器：i9-12900HX / 4060 / 2560×1600）

| 源 | 首帧 | CPU |
|---|---|---|
| `ddagrab`（桌面复制 API） | 370ms | **0.28 核** |
| `gdigrab`（GDI 抓屏） | 310ms | 0.45 核 |
| OBS 虚拟摄像头 | 575ms | 0.13 核 |

## 6. 本机能不能跑（逐项核过）

| 项 | 实测结论 | 依据 |
|---|---|---|
| 装没装 | **没装** | `desktop` profile 的 `dsh.profile.bundles` 是 base / web-app / chat-wallpaper / experimental-auto-review / startup-secret / global-prompt / agent-md / dsh-music |
| ffmpeg | **没有** | PATH 无 `ffmpeg.exe`；`~/.dsh/tools/ffmpeg/bin` 与 `~/.dsh/bin` 目录都不存在；`AppData\Local\Programs\DeepSeek Harness` 递归无 `ffmpeg*.exe`；`PROJECT` 下四层内也无 |
| 声音配置 | **一套没配** | `~/.dsh` 下无 `voice.json` / `tts.json` / `asr.json` / `see-now.json` |
| 平台 | Win 满足 | 走 `ddagrab`，不行自动退 `gdigrab` |
| Node | 满足 | 本机 24.21.0，要求 ≥20 |

**门槛只有一个：ffmpeg。** 全链路所有画面都从 ffmpeg 一根管道来，找不到就直接不工作。

> 顺带：台账 1046 的结论是「只有一个现在该装 —— `dsh-video-storyboard`」。那个**也卡在同一个 ffmpeg 上**（它要 ffmpeg/ffprobe），现在同样没装。所以**备一次 ffmpeg 同时解锁两个插件**，这是当前性价比最高的一个前置动作。

**另外记一笔环境坑（跟本插件无关，但会拦住所有联网调研）**：环境变量把 `http_proxy`/`https_proxy` 指到 `127.0.0.1:7897`，**那个端口没起**（代理客户端没运行）。本轮 `web_fetch`、`yhlz web_fetch`（报 InvalidURL）、`curl`（schannel `SEC_E_NO_CREDENTIALS`）、`Invoke-RestMethod` 全废在这里；TCP 直连是通的。可用绕法：node 里清空四个 proxy 变量 + `NODE_USE_ENV_PROXY`，设 `NO_PROXY=*`，再 `fetch`。已在台账 1073 记过。

## 7. 限制（作者自己列的 + 我认的）

- **只认「画面变了」，不认「语义变了」**：同一句话的两个排版版本算变化；两段内容不同但长得很像的页面可能算没变。
- **没有跨帧去重**（除了一道粗筛），不保证每帧都有新信息。
- **前景守卫有边界**：外圈也被前景盖住、或 `bg ≥ 220` 时挡不住；反过来，真正切到「外圈固定、主体只在中部变」的近景可能被误挡。
- **参考背景会被长期前景污染**：24 帧里前景占多数时模型会漂。
- **区域模式只看前台像素**：被遮挡 / 最小化窗口抓不到；锁屏、UAC 安全桌面时会退成纯色底板。
- **只支持主屏**（负坐标表达不了）。
- **Linux 没接**（要补 `x11grab` / PipeWire，现在直接报错，不假装能用）。
- **听声音只有 Windows**（WASAPI 回环）；mac 要 BlackHole 之类，这一版没做。
- **它听得见自己**：TTS 念台词时音箱出声会被回环收回去，靠 `quiet-until.json` 在落盘前丢弃。

## 8. 对我们的价值

**判据是「补的是哪一环 + 前置成本 + 边界是否诚实」，不是功能多少。**

### 三个真实用法

1. **利贞看老爹的屏幕**（最直接）。老爹说「这个界面怎么不对」，现在我得让他描述；装上之后我直接看。这类「调试式旁观」正是它的强项：静止就几乎不出图，一操作就出帧。
2. **元亨的实时视听**。她已有 B 站工具链（离线「看」靠 storyboard），这个是**实时**那一半；再和本机 TTS 主链路接上，`say` 进悬浮窗并被念出来 —— 视觉 + 听觉 + 出声，这是一条完整的感官回路。
3. **方法论**。§3 那套「按 42px patch 网格反推画布尺寸 + 用阶梯函数把附加信息塞进免费余量」的做法，跟我们在 prompt 预算上的结论同源，可以直接搬到元亨自己的图/视频管线里。**这部分不用装插件也能拿。**

### 三条我担心的

1. **它会自己叫醒模型**。`maxAutonomousWakes` 默认 8、`idleStopMin` 默认 3 分钟 —— 挂上之后是会主动打扰的，不是纯被动工具。日常挂着得先调 `defaultPace: "calm"`。
2. **常驻抓屏 0.28~0.45 核**。老爹这台要同时跑模型和 TTS，要不要常驻得算一下。
3. **隐私边界**。它看的是整屏：QQ、密码框、私聊都会进帧。区域模式能收窄，但收窄之后 token 反而更贵（帧不再被缩小，low 档 2 帧约 345 token）。
