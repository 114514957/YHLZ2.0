## 2. W1 · 动态阈值

### 目标

不再用"0.42 一刀切"，改成**按本次结果分布算**，并给下限保护。

### 参数（借 A_memorix，调成我们的尺度）

| 参数 | A_memorix | 我们（建议） | 理由 |
|---|---|---|---|
| 方法 | adaptive（percentile/std/gap 综合） | **relative**（0983 公式）为主，`percentile` 可选做 A/B | relative 已经对着我们的分布标过 |
| 相对公式 | — | `thr = max(top1 - 0.08, mean + 1σ)`，再 `max(thr, 0.50)` | 0983 D4 |
| 夹逼 | min 0.29 / max 0.95 | **0.29 ~ 0.95**（照抄） | 我们的 cos 尺度也落在这个区间 |
| 最少保留 | `min_results = 4` | **4**（照抄） | 防止分布平坦时全被砍掉 |
| 上限 | — | `k ≤ 8`（0983 D4） | 与现有 top 参数一致 |

### 改动

```python
# backend/vector_memory.py —— 新增一个纯函数，两处调用点共用
def pick_threshold(scores: list[float], top1: float, *,
                   method: str = "relative",
                   lo: float = 0.29, hi: float = 0.95,
                   min_results: int = 4) -> float:
    ...
```

调用点：`semantic_any`（:231）与 `semantic_l2`（:416）→ 改成先取候选（不要提前 `continue`），再统一 `pick_threshold()` 过滤。

### 验收

| 指标 | 通过线 |
|---|---|
| 命中条数分布（16 条真实查询） | 从 2–179 收敛到 **p50 ∈ [4,12]**、最大 ≤ 20 |
| 40 条标注集 recall@5 | **不低于**固定阈值的基线（先量基线再改） |
| 单次额外耗时 | < 1 ms（纯排序统计） |

### 回滚

`YHLZ_VEC_THRESHOLD=fixed` → 走旧路径（0.42/0.35）。

## 3. W2 · 加权 RRF 融合

### 现状

`contextual_recall` 四路候选**分数口径不一**（余弦 vs 常量 0.45），rerank 摘掉后只剩"字面 + 常量"，实际顺序≈插入顺序（0983 第 7 条）。A_memorix 用**加权 RRF** 解决同一问题（`_fuse_ranked_lists_weighted_rrf`）。

### 目标

`score(d) = Σ_i w_i / (k + rank_i(d))`，`k=60`、默认 `w = [1.0(向量), 1.0(字面/FTS)]`；同一 id 多路上榜只累加一次每路。

```python
# backend/rank_fusion.py（新增）
def rrf(lists: list[list[str]], weights: list[float] | None = None,
        k: int = 60) -> list[tuple[str, float]]:
    ...
```

落点：`backend/target_memory.py` 的 `contextual_recall` 组装处——把四路候选先各自排序成 id 列表，再 `rrf()` 合并，最后按 W1 的阈值截断。

### 验收

| 指标 | 通过线 |
|---|---|
| 确定性 | 同一 query 连跑两次，顺序完全一致 |
| 40 条标注 recall@5 | 相对"向量 only"与"字面 only" **各 +10pp**（0983 D8 门槛）才允许把默认开关从 off 改成 auto |
| 常量分清除 | 代码里不再出现 `0.45` 这类占位分 |

### 回滚

`YHLZ_RRF=off` → 退回按各路分数直接拼接（旧行为）。

## 4. W3 · 时间维度

### 借什么

A_memorix 的 `time/hybrid` 模式：**必须给 `time_start` 或 `time_end`，否则报错**——"不再静默按未命中处理"。

### 目标

`memory.recall` 能力加两个可选参数 `time_start` / `time_end`（ISO 日期或 `YYYY-MM-DD`）：

- 给了任一端 → 先按 `COALESCE(valid_at, created_at)` 过滤，再排序；
- 格式不合法 → **返回参数错误**（不静默返回空）——这条直接抄。

### 落点

- `backend/target_scheduler_tools.py` 的 `memory.recall` capability（`input_model` 加两个字段）；
- `backend/target_memory.py` 的 `recall`/`semantic_l2` 加 `time_range` 形参，SQL 里加 `AND ts BETWEEN ? AND ?`；
- 相对时间（"上周"）暂不做解析，只收显式日期；要自然语言时间再加解析器（MaiBot 有 `time_parser.py`，我们没抄）。

### 验收

| 指标 | 通过线 |
|---|---|
| 10 个"上周/上个月说了什么"类问题 | 带时间过滤后 top3 命中 ≥ 6/10 |
| 非法时间输入 | 返回 `invalid arguments`，**不返回空列表** |
| 无时间参数 | 行为与现在完全一致（回归） |

### 回滚

`YHLZ_RECALL_TIME=off` → 参数被忽略（并提示不支持）。

## 5. W4 · 生命周期强度

### 借什么

A_memorix `RelationLifecyclePolicy` 的数值与滞回思路：

```
half_life 24h · freeze 0.1 · revive 0.15 · access_alpha 0.05
access_cooldown 3600s · reinforce/weaken_alpha 0.5
```

### 我们的调整

| 参数 | A_memorix | 我们（建议） | 理由 |
|---|---|---|---|
| 半衰期 | 24 h | **7 天**（env 可调） | 我们对话密度远低于 Q 群，24h 太狠 |
| 冻结/复活 | 0.1 / 0.15 | 照抄 | 滞回防抖是纯收益 |
| 访问加成 | 0.05 / 1h 冷却 | 照抄 | |
| 衰减对象 | 关系边 | **l2_items 条目** | 我们没建图 |

### 改动

```sql
ALTER TABLE l2_items ADD COLUMN strength REAL NOT NULL DEFAULT 1.0;
ALTER TABLE l2_items ADD COLUMN last_access_at REAL NOT NULL DEFAULT 0;
```

- 召回命中 → `strength += 0.05`（1h 冷却内不重复加），写 `last_access_at`；
- `memory_save` 新条目 `strength=1.0`；裁决 `downgrade` → `weaken_alpha=0.5`；
- 读路径按半衰期算 `retention = strength * 0.5 ** (Δt / half_life)`；`retention < 0.1` 标 frozen（**只降权，不删**），`> 0.15` 复活。

### 验收

| 指标 | 通过线 |
|---|---|
| 30 天未访问条目 | retention ≈ 0.05（7 天半衰期 → 4 个半衰期） |
| 高频访问条目 | retention 稳定 > 0.5 |
| 排序影响 | frozen 条目从 top5 掉出，但**仍可被关键词召回** |
| 迁移 | 旧库 ALTER 后默认 1.0，行为不变（回归） |

### 回滚

`YHLZ_L2_STRENGTH=off` → 读路径忽略 strength（列还在，不删除）。
