# Gemma-4 独有性质清单（对训练、提示词、量化的影响）

> 2026-11-14 · 利贞
> 方法：**直接读 `config.json`、`model.safetensors` 张量头、生产 GGUF 元数据、`modeling_gemma4.py`**，
> 不采信二手说法。每条都给「值 + 出处 + 对我们的后果」。

---

## 0. 先说结论

外部那段建议的**总前提是对的**——"Gemma 4 结构独特，照抄 Llama 的 LoRA 配方会失灵"。
**但它点名的三个具体机制，在本 checkpoint 上全都不成立**（我上次已逐条验证）。
真正的独特机制是下面七条，其中 **第 ② 条是我们目前最大的隐形天花板**。

| # | 独有性质 | 值 | 对我们的后果 | 级别 |
|---|---|---|---|---|
| ① | **logit softcap** | `final_logit_softcapping = 30.0` | 压缩 logit 差异；q4 量化噪声 × softcap 可能把风格差异一起压掉 | 中 |
| ② | **混合注意力（滑窗+全局）** | 42 层 = **35 滑窗(512) + 7 全局**，图案 `SSSSSG` | **提示词 2724 token = 窗口 5.3 倍**，35 层只看得到**最后 512 token** | ⭐ 最高 |
| ③ | **逐层嵌入 PLE** | `embed_tokens_per_layer` [262144, **10752**] = **2.82B（35.3%）** | LoRA 只覆盖 49.3% 参数，**PLE 全冻** | 中 |
| ④ | **KV 跨层共享** | `num_kv_shared_layers = 18` | 省显存；k_proj 只 0.064B | 低 |
| ⑤ | **比例式部分 RoPE，双基** | `partial_rotary_factor 0.25`、`rope_type=proportional`、θ=1e6(全局)/1e4(滑窗) | 长上下文外推行为特殊；别再套 Llama 的 rope 调参经验 | 低 |
| ⑥ | **tied embedding / 无 lm_head** | 全模型**唯一 bias 在 audio_tower** | `modules_to_save=["lm_head"]`、`bias="lora_only"` 均为空操作 | 已排除 |
| ⑦ | **多模态塔** | vision 2.09% + audio 3.81%，线性层是 `ClippableLinear` | 用 `target_modules="all-linear"` 会**误伤音视频塔** | 已规避 |

---

## ① logit softcap = 30.0（训练/推理都带，已核对）

- **【代码】HF**：`text_config.final_logit_softcapping = 30.0`
- **【代码】GGUF**：`gemma4.final_logit_softcapping = 30.0` ✅ 转换时没丢
- 机制：`logits = tanh(logits/30) × 30`，把极大值压平。
- **后果**：
  1. 训练与推理一致（都带），**所以不是"训练白训"的原因**。
  2. 但它**压缩头部差异**：模型越自信的地方越被压平，配合 **q4_0 量化**的 logit 噪声，
     细微的风格差异可能被一起吃掉。
- **可验证的便宜实验**：同一个 adapter，跑 **q4_0 与 q8_0/f16** 两版 GGUF，对比 56 题分数。
  若 q8 明显更高 → 说明我们一直在"量化噪声 + softcap"下评测风格，之前所有版本的分数都低估了真实风格强度。

---

## ② ⭐ 混合注意力：**35 层只有 512 窗口，7 层全可见**

- **【代码】HF `layer_types`**：42 层，`sliding_attention` 与 `full_attention` 交替图案
- **【代码】GGUF `gemma4.attention.sliding_window_pattern`**：`SSSSSG` 重复（S=滑窗 512，G=全局）
  - 层数 **42**｜滑窗层 **35**｜全局层 **7**｜`sliding_window = 512`
- **【实测】我们的提示词**：

| | 字数 | ≈token | 是 512 的几倍 |
|---|---|---|---|
| 私聊系统提示 | 4086 | **2724** | **5.3×** |
| 群聊系统提示 | 4260 | **2840** | **5.5×** |

### 后果（这是重点）

在 **35/42 的层里，每个位置只能看到自己前面 512 个 token**。
而我们的提示词把**人设、纪律、关系口径放在开头** —— 对滑窗层来说，这些内容
**在序列后半段完全不可见**，只有 7 个全局层能看见全貌。

这就解释了几个一直没想通的现象：

| 现象 | 解释 |
|---|---|
| 长上下文/多轮后"人设变淡"、规矩被忘 | 35 层看不见开头的人设 |
| 群聊上下文加到 50 条后表现更差 | 每条都在把人设往更远处推，同时挤占可见窗口 |
| v11 里"记忆分层"题（r04）崩 | 记忆/人设条款位置太靠前 |
| 同样的提示词，短对话里守得住，长对话里守不住 | 序列短时全部落在 512 内；一长就露馅 |

### 立刻能做的（零训练成本）

1. **把最关键的条款搬到提示词末尾**（紧贴用户轮之前）：收尾纪律、禁反问、记忆边界。
   滑窗层必然看得到"最后 512 token"。
2. **压缩总长度**：群聊上下文 50 条 → 15 条以内（这条以前是为速度，现在是为**可见性**）。
3. **改完直接用 56+28 复测**，对比改动前后分数——这是纯提示词实验，不需要训练。

> 这一条的性价比远高于再训一版：**同样的权重，只要把话说在它看得见的地方。**

## ③ PLE：35.3% 的参数，我们一个都没训

- **【代码】`embed_tokens_per_layer.weight` shape = [262144, 10752]** → **2.819B 参数（35.25%）**
- 每层还有 `per_layer_input_gate` [256, 2560] + `per_layer_projection` [2560, 256] +
  `post_per_layer_input_norm`，以及全局 `per_layer_model_projection` [10752, 2560]
- **参数占比实测**：

| 模块 | 占比 | LoRA |
|---|---|---|
| **PLE（逐层嵌入）** | **35.25%** | ❌ 冻结 |
| mlp gate/up/down | 41.31% | ✅ |
| embed_tokens（主词表） | 8.39% | ❌ |
| attn q/k/v/o | 8.02% | ✅ |
| audio+vision 塔 | 5.90% | ❌ |
| **合计 LoRA 覆盖** | **49.34%** | — |

- **后果**：这是 Gemma-3n/4 系列放"知识/身份"的大仓库，我们完全没动。
  风格 LoRA 只在 MLP+attention 上转，可能是"能学语气、学不进更深的东西"的原因之一。
- **风险**：PLE 是**输入侧**的大表，训它容易过拟合/破坏通用能力，且显存与步时会涨。
  **建议先不碰**，等冒烟测试与单变量对照做完再评估。

---

## ④ KV 共享 18 层 / ⑤ 比例式部分 RoPE

- `num_kv_shared_layers = 18`：18 层共用 KV，省显存 → 长上下文成本比"42 层全 KV"低。
- RoPE：`partial_rotary_factor=0.25`（只转 1/4 维度）、`rope_type='proportional'`、
  双基 `θ=1e6`（全局）/ `θ=1e4`（滑窗）、`rope.dimension_count 512 / swa 256`。
- **后果**：**不要照搬 Llama 的 rope scaling 经验**；外推长度靠这几组参数共同决定，
  改了要么不动、要么必须用 GGUF 实测。

## ⑥⑦ 已排除项（外部建议点错的地方）

| 外部说法 | 实测 |
|---|---|
| LoRA 挂不上（`Gemma4ClippableLinear` 不是 nn.Linear） | 该类只在 **audio/vision 塔**；`Gemma4TextMLP` 是 **nn.Linear**。我们 34.88M 参数正常 |
| 必须训 `lm_head.bias` | 全模型**只有 1 个 bias** 且在 `audio_tower.output_proj`；**无 lm_head**（tied） |
| `use_cache=False` 毁注意力 | 源码仅 2 处标准 `past_key_values` 分支，无特殊路径 |

## 那"一长段"里到底哪部分是真的？

| 它的说法 | 判定 |
|---|---|
| "Gemma 4 有独特结构，Llama 配方会失灵" | ✅ **对**，但理由不是它说的那些 |
| "用 `all-linear` 会撞上音视频塔" | ✅ 对（我们确实该 exclude vision/audio） |
| "用 `.linear` 后缀指内部层" | ❌ 对本 checkpoint 无必要（文本塔就是 nn.Linear） |
| "必须训 lm_head bias" | ❌ 无 lm_head |
| "`use_cache=False` 致命" | ❌ 无证据 |
| "检查可训练参数数量" | ✅ **做法对**（我们是 34.88M，属正常） |
| "先做 50–100 条过拟合冒烟测试" | ✅ **最该做的一条**（我们从没做过） |
