# L1 摘要排空 · 2026-10-22

> 一句话：**56 条该压没压的对话，两条频道各一堆；根因不是"记账没做"，是"没人跑"。** 现在给了它一条可空闲时自己跑通的路，并且不跟对话抢缓存。

---

## 1. 实测：积压是真的

扫 `cache/memstore/*.l1*.json`：

| 频道 | 窗口内轮次 | pending（未摘要） | 已有摘要 |
|---|---|---|---|
| `qq_p2258…` | 5 | **31** | 空 |
| `console` | 5 | **25** | 空 |
| `private` | 5 | 0 | 空 |
| （旧主库文件） | 5 | 0 | 22 字，version 1790681249 |

**合计 56 条从未被压缩。** 按 `process_summary` 的设计（成功落盘才确认），这 56 条一条都没丢——原文都在 `pending` 里，可以补压。

## 2. 根因有两层

**第一层：模型没开。**
`YHLZ_MEMORY_LLM_MODE` 默认 `disabled` → `build_memory_hooks` 返回 `DeferredMemoryHooks`，它的 `compress()` **直接抛异常**。于是每次 `process_summary()` 都失败、`_summary_error` 记一笔，pending 原样保留。这是**安全的设计**（不确认不删），代价是永远不前进。

**第二层：就算开了，也不该在回合末尾压。**
`target_entry.py` 在每轮结束后 `kick()`。本地模型只有一个 llama slot，摘要请求会把对话的前缀缓存挤掉——我们昨天量过：**前缀断一次 +3.7 秒**。等于"为了省记忆，让下一句话变慢"。

## 3. 做法

### 3.1 只开 L1 压缩（`YHLZ_MEMORY_SUMMARY_MODE=local`）

新增独立的开关，不复用 `YHLZ_MEMORY_LLM_MODE`：

- `YHLZ_MEMORY_SUMMARY_MODE=local` → 构建真的 `MemoryLLMService`，但用 `SummaryOnlyHooks` 包一层：
  - `compress()` → 走本地模型；
  - `candidates()` → 永远返回 `[]`（不做每轮的候选抽取）；
  - `adjudicate()` → 抛 `MemoryWorkDeferred`（不裁决）。
- 训练/微调标记仍然一票否决。
- 完整模式（候选+裁决）仍需 `YHLZ_MEMORY_LLM_MODE=local`，保持原样。

> 理由：老爹 2026-10-22 说模型是本地部署的，消耗不是约束。那就把"摘要"这一块单独打开——它只花时间，不动每轮的对话链路。

### 3.2 空闲闸门（`idle_gate` + `min_idle_s=90`）

`MemorySummaryScheduler` 新增两个参数：

- `idle_gate()` 返回"距上一轮多少秒"；
- 小于 `min_idle_s` 就**不跑**，计 `deferred_idle`，并 `arm()` 一个一次性回调，90 秒后再 kick。

调度器自己**仍然不持有定时器**（`background_idle_timer: False` 不变），`arm()` 借的是调用者的事件循环。这样它既不会在对话里插队，也不会永远等不到机会。

`target_entry` 在回合结束时把 `_last_turn_ts` 设为当前时间，于是：

```
回合结束 → kick() → idle=0 → 推迟 + arm(90s)
        → 90 秒无对话 → 再 kick → 跑 4 批摘要（每批 ≤32 条）
```

失败仍按原逻辑指数退避（最长 300 秒），pending 不丢。

## 4. 验证

**测试**（全过）：

- 调度器 + 策略 **30 项**（新增：空闲闸门推迟并 arm、没给 gate 时保持旧行为、summary-only 只放行 compress）；
- 相关回归 **64 项**（`target_entry` / `persona_text_boundary` / `prompt_structure`）；
- 记忆耐力/生命周期/资源策略 **61 项**。

**离线排空演练**（`research/drain_l1_sim.py`，在**副本**上跑，真文件没动）：

```
scope=qq_p2258 before= 31 after=  0  summary='要点0: 重新自检；要点1: [[voice]]好，重新走一遍…' ver=1 calls=1
scope=console  before= 25 after=  0  summary='要点0: （计划表到点）你的例行计划：午间自主回顾…'   ver=1 calls=1
TOTAL pending 56 -> 0
```

31 条一次就压完了（`summary_batch_size` 默认 32）。说明**补压路径是通的**，只差模型在跑。

## 5. 上线与回滚

- `.env` 已加：`YHLZ_MEMORY_SUMMARY_MODE=local`（一行 + 注释）。**需要重启 daemon 才生效。**
- 回滚：删掉这一行，重启即可回到"只记账不压缩"。
- 现在 8081（llama）和 8321（daemon）都没起，所以积压**还没动**——这是预期，不是失败。

## 6. 一个环境坑（已确认）

本机 `NO_PROXY` 里有 `[::1]`，httpx 会抛 `InvalidURL: Invalid port: ':1]'`。launcher 会替子进程清洗（ledger 0815），但**手跑脚本要先 `set NO_PROXY=`**。我第一次验证时就栽在这儿，记一笔。

## 7. 还没做的

- **启动即排空**：现在要"某个频道被用一次 + 空闲 90 秒"才会压。如果某频道长期不用，积压会一直躺着。要不要在启动后 5 分钟做一次全频道排空，等老爹定。
- **摘要质量**：Gemma 压出来的要点好不好，要等真跑一轮才知道；离线演练用的是桩，只证明管道通。
