# NapCat 唤起失败：根因与修复

> 2026-10-29 · 利贞
> 现象（工作台）：`唤起失败：RuntimeError: 普通 CMD 启动请求失败，请检查本地启动环境，napcat唤起错误`
> 结论：**目录重排留下的一个路径少算了一层**，已修；从我的环境里能启动到 NapCat 引导进程，但登录/3001 那一步必须由你在工作台点（原因见 §4）。

---

## 1. 根因

调用链：

```
工作台按钮
  → backend/napcat_launcher.launch_napcat()
    → cmd /d /c tools\napcat_start_user.cmd        （非管理员、新控制台）
      → start "YHLZ QQ" /D "<napcat 工作目录>" cmd /k napcat_single_login.cmd
        → NapCatWinBootMain.exe QQ.exe hook.dll
  ← proc.wait(10s)：退出码非 0 就抛 RuntimeError
```

`tools/napcat_start_user.cmd` 原来是这么算工作目录的：

```cmd
if not defined YHLZ_EXTERNAL_DIR set "YHLZ_EXTERNAL_DIR=%~dp0..\.."
set "YHLZ_NAPCAT_CWD=%YHLZ_EXTERNAL_DIR%\qqwatch"
```

- 重排**前**：`%~dp0` = `…\PROJECT\YHLZ\tools\` → `..\..` = `…\PROJECT` → `…\PROJECT\qqwatch` ✅
- 重排**后**：`%~dp0` = `…\PROJECT\YHLZ\YH\tools\` → `..\..` = `…\YHLZ` → `…\YHLZ\qqwatch` ❌ **不存在**

实测：

```
> if exist "C:\Users\ACE_WAN——PROJECT\YHLZ\qqwatch" …   → missing
> qqwatch\shell\NapCatWinBootMain.exe                    → OK（真实位置在 PROJECT\qqwatch\shell）
```

`start /D` 指向一个不存在的目录会失败，`exit /b %errorlevel%` 带出非 0，于是 Python 侧在 10 秒等待后抛了那句通用错误——**错误信息里看不出是路径问题**，这就是它难查的原因。

## 2. 修复

### 2.1 `tools/napcat_start_user.cmd`

不再依赖 `..\..` 的层数，改成：

```cmd
rem 1) 优先用 launcher 一定会传进来的 YHLZ_NAPCAT_SHELL（权威位置）
if defined YHLZ_NAPCAT_SHELL for %%I in ("%YHLZ_NAPCAT_SHELL%") do set "YHLZ_NAPCAT_CWD=%%~dpI"
rem 2) 没有就三级回退（tools → YH → YHLZ → PROJECT）
if not defined YHLZ_NAPCAT_CWD set "YHLZ_NAPCAT_CWD=%~dp0..\..\..\qqwatch"
rem 3) 规范化 + 去尾斜杠 + 不存在就 exit /b 3（给出可区分的退出码）
for %%I in ("%YHLZ_NAPCAT_CWD%") do set "YHLZ_NAPCAT_CWD=%%~fI"
if defined YHLZ_NAPCAT_CWD if "%YHLZ_NAPCAT_CWD:~-1%"=="\" set "YHLZ_NAPCAT_CWD=%YHLZ_NAPCAT_CWD:~0,-1%"
if not exist "%YHLZ_NAPCAT_CWD%" exit /b 3
```

另外加了**诊断模式**（只打印、不启动）：`set YHLZ_NAPCAT_PROBE=1` 之后跑这个 cmd，会输出

```
cwd=…\qqwatch
entry=…\tools\napcat_single_login.cmd
shell=…\qqwatch\shell
```

### 2.2 `backend/napcat_launcher.py`

错误信息带上退出码和 napcat 目录，下一次一眼能看出是哪一类失败：

```python
code = proc.wait(timeout=10)
if code:
    raise RuntimeError(
        f"普通 CMD 启动请求失败（exit={code}），请检查本地启动环境"
        f"（napcat 目录：{env.get('YHLZ_NAPCAT_SHELL', '未设置')}）")
```

### 2.3 排查过、确认无关的点

- `qqwatch\shell\config\webui.json` 的 `autoLoginAccount` 已经是 `3655185302`（= `BOT_UIN`），所以不会触发写配置（那一步在工作区外，会 EPERM）。
- `C:\Program Files\Tencent\QQNT\QQ.exe` 存在。
- 全仓库再没有别处用 `%~dp0..\..` 算外部目录（`findstr` 只命中本文件）。

## 7. 第二轮：常规终端入口 + 一个编码坑

老爹指出关键约束：**登录必须在常规终端里**，工作台/后台拉起的窗口不算。于是把方案改成"给一个双击入口"，而不是继续在工作台里挣扎。

### 7.1 新增 `YH\启动NapCat.cmd`

- 自检 shell / QQ.exe / uin / 工作目录，全部打印在窗口里并写 `cache\logs\napcat_console.log`；
- 支持 `YHLZ_NAPCAT_PROBE=1`：只打印路径、不启动；
- 目录缺失 `exit /b 3`、QQ 缺失 `exit /b 2`、NapCat 自身失败带退出码；
- 结尾 `pause`，窗口不会一闪而过。

### 7.2 抓到一个编码坑（那行莫名其妙的错误就是它）

第一版这个 .cmd 是 **UTF-8**、开头 `chcp 65001`。实测运行时 stderr 冒出一行：

```
The system cannot find the path specified.
```

用 `@echo on` 定位，发现它来自一行**注释**：

```
C:\...\YH>�志：cache\logs\napcat_console.log
The system cannot find the path specified.
```

原因：cmd 用**控制台 ANSI 代码页**（这台是 936/GBK）解析 .bat 文件。UTF-8 中文的字节在 GBK 下会被错位组合，某个尾字节"吃掉"了换行，导致下一行的 `rem` 被上一行吞掉、再下一行**当命令执行**。

修改：**整个文件改成 GBK(cp936) 编码，第 3 行 `chcp 936`**。实测：

```
stdout: [1/2] 记录环境... / [probe] 只检查路径，不启动。
stderr:（空）
```

按 GBK 解码核对过，中文正常。

> 教训：这个仓库自己的 `YH_boot.bat` 注释里早就写了 "All text below is ASCII on purpose (Chinese in a GBK-parsed bat breaks)"——我这次犯了同一个错。

### 7.3 工作台不再"假成功"

原来只要 `start` 返回 0，工作台就报"已唤起"，但窗口里的 NapCat 可能根本没注入。现在 `launch_napcat()` 在 `start` 成功后**再验证**：

```python
if not _napcat_booting(timeout_s=12):   # 轮询 tasklist 里的 NapCatWinBootMain.exe
    raise RuntimeError("启动窗口已发出，但 12 秒内没看到 NapCat 进程——工作台拉起的窗口"
                       f"不算常规终端，登录会失败。请双击 {manual} 手动登录。")
```

拉起成功时返回 `note: "NapCat 引导进程已出现；登录请在弹出的窗口里完成"`。

### 7.4 生效范围

| 改动 | 何时生效 |
|---|---|
| `启动NapCat.cmd`（新文件） | **立即**，双击就用 |
| `tools/napcat_start_user.cmd`（路径修复） | **立即**（每次唤起都会重新调用它） |
| `backend/napcat_launcher.py`（错误指向 + 进程校验） | **需要 daemon 重启**（当前 8321 在跑，pid 3428；我没重启，避免训练期间把它弄挂） |

### 8.1 依据

- `qqwatch\shell\launcher.bat`：非管理员时会 `powershell -Command "Start-Process … -Verb runAs"` **自动提权重启**——这就是"终端改为管理员模式"；

### 8.2 改回什么

`backend/napcat_launcher.py` 重写为走 `launcher-user.bat <uin>`：

```python
proc = subprocess.Popen(
    [COMSPEC, "/d", "/c", f'call "{launcher}" {uin}'],
    cwd=str(QQWATCH_SHELL), env=env, close_fds=True,
    creationflags=CREATE_NEW_CONSOLE)
```

  - 已在线（3001 可连）就直接返回"无需重复启动"，不再拉第二个实例；
  - 拉起后等 `YHLZ_NAPCAT_WAIT`（默认 20s）看 3001，返回值里带 `online`，**不再假报成功**；
  - 仍然拒绝以管理员身份运行（`is_elevated()` → PermissionError），也不把密码带进子进程。
- `console_server.py` 的 `napcat_login / qq_switch` 分支恢复原状，只把 launcher 的 `note` 透传给工作台。

## 9. 第三轮：黑窗只打 argv[0] 就停 —— 工作台改用「把入口递给你」

### 9.1 截图说明什么

工作台拉起的黑窗标题是 `YHLZ QQ - "...\tools\napcat_single_login.cmd"`，内容只有一行：

```
argv[0]:C:\Users\ACE_WAN
```

对照 09-06 那次**成功**的日志（`qqwatch\shell\napcat.out.log`），同一行后面本应继续：

```
config_current_version:9.9.31-49919
load from:...\QQNT.dll
NapCat Shell App Loading...
[NapCat] [Core] Version: 4.18.19
WebUi: http://127.0.0.1:6099/webui?token=…
二维码已保存到 …\cache\qrcode.png
```

所以这次是**在加载配置前就停住**了；`qrcode.png` 的时间戳仍是 22:56（你手动登录那次），没被更新。

### 9.2 查过但**不成立**的两个假设

1. **cwd 不对**：`napcat_start_user.cmd` 用 `/D` 把工作目录设成 `qqwatch`（父目录），而 NapCat 的相对路径按 `cwd` 解析。理论上成立，但你 22:56 手动成功那次用的也是同一套（cwd 同样是 `qqwatch`）——所以**不是它**。（仍给 `napcat_single_login.cmd` 加了 `cd /d "%S%"` 兜底。）
2. **启动链在低完整性上下文**：我先看到 `cache\logs\launcher.log` 带 `Mandatory Label\Low Mandatory Level`，以为 daemon 是 Low、注入被 UIPI 挡住。进一步 `icacls cache` 发现 **`cache` 目录本身带 Low 完整性策略（OI)(CI)(NW）**——里面任何文件都会被打上 Low 标签，**与写入者无关**。所以这条证据无效，撤回。

### 9.3 结论：工作台拉起的窗口就不是"常规终端"

沿用你 22:52 的判断：登录必须在常规终端。工作台无论用哪个脚本、哪个 cwd，拉起的都是 daemon 的子进程，实测都没有二维码。

所以工作台这一块改成**不再假装唤起**：

- 3001 在听 → "NapCat 已在线，无需重复启动"；
- 否则先清掉卡住的 `NapCatWinBootMain.exe` / 没注入的 `QQ.exe`（等同旧 `KillQQ.bat`），再尝试拉 `launcher-user.bat`（cwd=shell）；
- 等 `YHLZ_NAPCAT_WAIT`（默认 20s）后若 3001 仍未监听 → **自动打开资源管理器并选中 `launcher-user.bat`**，提示"双击它用常规终端登录"。

另外 `_napcat_procs_alive()` 从"看进程名"改成"看 3001 端口"——原来 `NapCatWinBootMain.exe` 卡住也会被当成"已运行"，把重启按钮永久挡死（截图那一刻就是这个状态：窗口挂着、面板显示离线）。

### 9.4 验证

- `python -m unittest backend.test_napcat_launcher -q` → **9 tests OK**；
- daemon 连续重启两次（launcher 的 `ensure_stack` 自动把它拉回来，见 `cache/logs/launcher.log` 的 `spawn daemon: requested`）；
- `POST /control {"action":"napcat_login"}` → `{"ok": true, "note": "已尝试拉起；若窗口里没有二维码，请在已打开的文件夹里双击 launcher-user.bat 用常规终端登录（元亨号）"}`，同时 `explorer.exe` 打开并选中了该文件。
