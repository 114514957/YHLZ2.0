# 《深海灯志 Beta v0.1》评估 · 2026-10-22

> 对象：`Downloads\深海灯志-Beta-v0.1-beta.zip`（24 个文件，解压 90 KB）
> 结论先说：**这是我见过的最干净的"陪伴型 DSH 覆盖包"**——它把"每轮上下文不涨"当成第一性约束，为此主动砍掉了工具、语音、看图。值得抄的是它的**预算纪律**和**摘要覆盖区间的记账方式**；不值得抄的是它没有工具面（YHLZ 的业务需要工具）。

---

## 1. 它是什么

不是安装器，是**覆盖包**：先装好 DeepSeek Harness（DSH），把文件夹放进去，跑向导填两个 QQ 号，就把 DSH 变成"只跟一个人说话的 QQ 陪伴 AI"。

```
bot.mjs              QQ 消息 → 组装上下文 → DSH headless → 回消息
lib/memory.mjs       三层记忆：原文 / 摘要 / 检索索引
lib/context.mjs      每轮组装，硬预算 800 字
lib/search.mjs       零依赖 BM25（中文二字滑窗 + 停用词）
lib/channel.mjs      OneBot 11 正向 WS（自带重连、echo 配对）
lib/format.mjs       去 Markdown / 拆 2~3 个气泡 / 拟人延迟
profile/             DSH 人设 + 模型（deepseek-flash, reasoningEffort low）
profile-省token.yml  50+ 个 DSH 插件 id 的禁用清单
setup/start/check.ps1 向导 / 启动 / 七项只读诊断
```

技术选择很克制：**零第三方依赖**（WebSocket 用 Node 22 内置，检索自己写 BM25），安装只依赖 DSH 自带的 node。

## 2. 记忆设计（这是它的核心卖点）

### 2.1 三层，职责清楚

| 层 | 文件 | 规则 |
|---|---|---|
| 原文 | `data/chat.jsonl` | 只追加，不删不改，每条 `{t, role, text}` |
| 摘要 | `data/memory/YYYY-MM-DD.md` | 满 30 条压一次，或次日首次启动补压；3–5 条要点，每条 ≤60 字 |
| 索引 | `data/index.json` | 摘要切段；删了自动重建 |

**最妙的一处**：每份摘要文件第一行是覆盖区间

```
<!-- 覆盖：#31-#60 2026-10-22 19:20 ~ 2026-10-22 23:41 -->
```

README 里叫"可重建"，实际效果是三条：**幂等**（重启不会重复压）、**可审计**（哪份摘要覆盖哪段原文一目了然）、**可手工修复**（文件头丢了按顺序兜底）。

> 对照 YHLZ：我们的 L1 摘要**没有**这个区间记账，所以才会出现"31/9/190 积压"这类问题——不知道压到哪了。

### 2.2 每轮只带 800 字，三块各有配额

| 块 | 配额 | 超预算时 |
|---|---|---|
| 最近 6 轮原文 | ~300 字（用户每条 ≤200、AI ≤120，从旧往新丢） | 最后让 |
| 最近三天摘要 | ~300 字（新的优先） | 中间让 |
| 关键词命中的旧摘要 | ≤3 段，~200 字（只查 14 天内） | **最先让** |

`context.mjs` 里是真的有"让位代码"：先算 recent 的预算（`budget*0.6`），再依次扣减，第三块拿剩下的。**不是系数摆设。**

### 2.3 检索：BM25 + 中文二字滑窗，明确不做向量

它自己写了理由：*"向量检索要额外模型和显存，跟'装完即用'冲突；几百到几千段用本地 BM25 够用。"*

这和我们这两天的结论**方向一致但取值相反**：我们算出 bge-small 单条 19 ms、407 条暴力扫 0.2 ms，成本其实可以接受；但它的场景是"别人电脑上的零依赖安装"，用不了 100 MB 的模型。**两个结论不矛盾，是约束不同。**

## 3. 人设与边界（这部分写得好）

三份文档分工明确：

- `profile/cordis.patch.yml`：给模型看的人设——语气（短、先听再说、不用 Markdown）、脾气（被冷落会嘟囔、不记仇）、陪伴方式（拆小任务、夸具体、难受时先接住人）、**危机处理**（自伤 → 让他找信任的人、打 12356/120，"你不是医生，别装能治"）。
- `AGENTS.md`：给模型看的"你住的地方"——`data/` 有什么、三个标记怎么用、**记忆的真实边界**（"你不是什么都记得，忘了就说记不清，别编"）。
- `红线.md`：给人和 AI 一起看——能自己做 / 先问再做 / 绝对不碰（隐私、外传文件、删别人文件、提"谁把你放这的"）。

> 它把"**会忘什么**"直接写进人设，这是防幻觉最便宜的一招。YHLZ 的 `MEMORY_CLAIM_GUARD` 是**程序侧**禁言，它是**人设侧**认账，两个层次。

## 4. 省 token：一份可直接用的 DSH 插件禁用清单

`profile-省token.yml` 按类别列了 50+ 个 `id`，直接对应 DSH 0.2 内置插件：

- 命令执行：`tool-bash` / `tool-pwsh` / `*-persistent` / `bash-sandbox` / `pwsh-sandbox` / `shell-env` / `tool-terminal`
- 文件：`tool-fs` / `tool-fs-search` / `tool-str-replace-editor`
- 联网：`tool-web` / `web-fetch` / `web-fetch-http` / `web-search-deepseek|exa|perplexity`
- 子代理/工作流：`tool-subagent*` / `subagent-*` / `tool-workflow` / `workflow-*` / `tool-ralph` / `tool-cordis` / `tool-lsp`
- 会话/作业：`tool-session-query` / `tool-jobs` / `jobs-local`
- 技能：`tool-skill` / `skill-*`
- 计划/展示：`tool-todo` / `tool-goal` / `goal-round-driver` / `plan-mode` / `tool-present` / `tool-workspace-dependencies`
- MCP：`mcp-client` / `mcp-resources`

并**明确列出保留项**：`agent-loop`、`agent-instructions`、`agent-default-model`、`system-prompt`、`session-*`、`compaction-*`、`tool-call-timeout-policy`、`tool-ask-user`。

> 对我们直接有用：这份清单是**按依赖关系分过组**的，比我们自己从 capability 名猜要准。它同时证明了"关工具真的能省几千 token"——和我们在 YHLZ 上量到的 4,108 token（45 工具）是同一个现象。

## 5. 它自己定的验收标准（值得抄）

六条里有三条是**我们缺的**：

1. **接入**：没接触过的人 30 分钟内装完并收到第一条回复（必须真人试）。
2. **记忆**：次日重启后能准确复述前一天至少三个具体事项，不混淆。
3. **可诊断**：人为造三类故障（3001 不通 / config 缺字段 / 额度耗尽），诊断脚本都给出明确定位。
4. **零密钥**：全包 `sk-[A-Za-z0-9]{20,}` 扫描无命中。
5. **体积不涨**：常驻注入 ≤800 字，**跑满两周后仍是这个数**。
6. **断网不崩**：模型失败时回一句人话并记日志，不吐堆栈给用户。

> 第 5 条正是我们这两天的主题（token 预算），它用"跑满两周后仍是这个数"来验收，比"平均 800"严格得多。

## 6. 我不建议 YHLZ 照抄的地方

1. **零工具**。它的取舍成立是因为它只陪聊；YHLZ 要查台账、读文件、写日记，工具面是业务本身。
2. **BM25 二字滑窗**。对"换说法"（不吃香菜 ↔ 别推荐香菜）无效——这正是我们想用向量补的洞。它承认这个限制，我们不该退回去。
3. **没有 provenance 分级**。它把所有摘要等同看待，"他说过"和"我猜的"在摘要里长得一样。YHLZ 的 `stance` 虽然没接通，但方向是对的。
4. **单人单号**。没有并发、多群、多用户的路由——YHLZ 的 QQ bridge 这块比它复杂得多。

---

## 7. 一处值得问老爹的细节

`能力清单.md` 里写：

> **跨月记忆**：分层档案 + 事件卡 + 出处标注……本机那套「回声」就是完整版，但**每轮常驻约 29,000 字**。

29,000 字和我们 YHLZ 现在的 prompt 量级（中位 ~24k 字符，含工具 30k+）几乎吻合。作者显然知道另一套更大的本机系统，而且就是按"字/轮"来衡量的。

**如果这套包不是老爹自己做的，那"回声"是谁、跟我们什么关系，值得问一句。**

---

## 8. 结论

**它是一份"减法做对了"的样本**：砍掉工具、砍掉语音、砍掉向量，换来了"每轮 ≤800 字、跑多久都不涨"的可承诺性。

对 YHLZ 的三条直接借用（按性价比）：

1. **摘要文件头记录覆盖区间**（`<!-- 覆盖：#a-#b 起止 -->`）——修我们 L1 积压/重复压的根子。
2. **每轮注入体积作为验收指标**（且要求"跑满 N 天不涨"）——比"平均 token"严格，能防回归。
3. **省 token 的插件 id 清单**——DSH profile 侧直接可用，或用来对照我们 45 工具的成本结构。
