## 1. 先用人话解释现在做到哪里

过去的问题不是“把模型换成端到端就能解决”。有两条不完整的链：

- 原会话链：认识你，有人格和记忆，能向 Gemma 发音频，但实时播放和持续输入没有统一归属。
- Target 语音链：有麦克风、打断、Kernel、Qwen 和播放，但 daemon 实际仍可能装上只懂文本的 reasoner；分段 TTS 也未启用。

本轮将它们接在同一条可选主链中：

```text
持续麦克风采集 → 原有 DSP/VAD/扬声器安全门
               → 内存 WAV（不先等 ASR 文本）
               → 同一个 Target Kernel / turn / generation
               → 原 ConversationSession（保留人格、记忆）
               → Gemma E4B input_audio → 内容 delta
               → 有界文本分段 → 同一个常驻 Qwen（Xiaoyi 克隆）
               → PCM → 同一个播放端 callback

HTTP 音频文件 / data URI ────────────────┘
后台转写：由 daemon 长寿命 loop 托管，前台开始时让路
```

**这仍然是“原生音频理解 + 文本桥接 TTS”的工程链路，不是单模型 speech-to-speech。** 目前麦克风音频按 VAD 片段提交，仍然需要等片段结束；不能把它说成模型逐帧实时听入。

## 2. 本轮六段任务与交付

### 第1段：把音频接到真正能处理音频的会话

- service 改用 `SessionAudioReasoner`，复用原会话的人格、历史、记忆与安全策略。
- 开启 Target 服务内部的 segmented TTS；外层总开关仍默认关闭。
- 显式音频允许空文本，不需要伪造唤醒词；不会改变旧麦克风文本唤醒状态。
- 带音频却没有 `generate_audio` 的 reasoner 明确失败，不再静默当文本回答。
- 原生快通道默认不带 tools，避免工具策略将正文扣到整轮结束；提示词明确禁止假装已查询/执行。
- `YHLZ_TARGET_VOICE_TOOLS=1` 可恢复工具策略，但可能重新引入整轮等待，不作为低延迟默认。
- 注入的音频流工厂显式禁用跨模型 fallback，避免不同能力的模型偷偷接手。

### 第2段：接通持续麦克风的原生音频入口

- 新增 `NativeAudioIngress`，复用原来的 MediaAdapter、VAD、segment、generation 与取消结构。
- `YHLZ_TARGET_NATIVE_CAPTURE=1` 时不构造 Sherpa ASR，音频直接转为 16k/mono/16bit WAV data URI。
- PCM 只在内存，不落录音；历史/episode 只写短哈希引用，不存长段 base64。
- 输入有采样率、通道、空数据、NaN/Inf、奇数 PCM、长度边界校验。
- 修复默认 100 帧上限对 20ms 采集可能造成的约2秒截句：本入口改为 VAD 结束提交，最长30秒/1500帧保护，最短120ms。
- 30秒是保护上限，不是每轮都等待30秒。VAD 一旦确认结束即提交；达到上限会强制切片，超长独白的语义拼接尚未实现。
- 这是显式进入的活跃会话，不使用文本唤醒词。默认不开启，防止用户未准备好就持续收音。

### 第3段：分段合成与播放重叠

沿用台账0533经过验证的步长，不在没有真机证据时随意压到极小：

| 项目 | 当前配置/行为 | 解释 |
|---|---|---|
| 首段文本 | 最少8、目标14、最多20字符 | 尽早说出有语义的短句 |
| 后续文本 | 15～45字符 | 减少碎句和重复合成启动开销 |
| 无标点等待 | 350ms | 到条件后尽快提交 |
| 硬年龄 | 600ms | 低速 delta 也不能无限等 |
| 分段检查 | 20ms tick | 即使没有新 delta 也能触发期限 |
| PCM重打包 | 20ms | 与文本字符步长不是同一个单位 |
| 包装层PCM队列 | 15帧，约300ms | **不是整条链总缓存** |
| 文本段队列 | 8段 | 有界，不无限堆积 |
| 原播放初缓冲 | 300ms | 本轮没凭空调小 |
| 原播放最大队列时长 | 配置5000ms，另受block数限制 | 尚不能宣称总待播≤500ms |

真实 Session + 真实 Target chain + 分段适配器 + 假模型/假播放的联合测试，使用“后半句必须等待首段已到播放端才产生”的同步约束，验证不是整答后播放。也新增了从连续合成音频帧起步的联合测试。

### 第4段：打断、回退与资源归属

- 已经提交到 Target 之后失败，不自动回旧链重答，避免说两遍或两个播放端争设备。
- startup timeout 会取消启动并等待清理；清理未确认则拒绝继续，不声称设备已释放。
- HTTP 取消仅允许中止该请求所属 turn；迟到取消不会打掉新轮。
- 新音频段等待旧请求取消清理，关闭入口会取消正在处理的音频。
- 服务 shutdown 多调用者共用一个清理任务；监控任务不递归互等。
- 语音 service 入口保留现有 GPU chat interlock，SVC 占用时拒绝新轮；这不代表已完成“常驻模型与唱歌模型换入换出”的显存联调。
- QQ/public 不启动本地扬声器。

### 第5段：记忆回填和后台任务

- 转写任务不再依靠短命 `asyncio.run`；daemon supervisor 持有，容量4、最长60秒、状态记录最多64项。
- 播放前台存在时新转写等待；新前台到来会取消正在运行的转写。
- **当前被抢占转写不自动重试**，会记 cancelled，不能保证每句用户语音都有文本回填。
- 取消客户端请求不等于服务端GPU已停，仍需真机测尾延迟。
- 每条语音记忆有独立 `voice_id`；逆序完成时按身份回填，不再覆盖最近另一轮。
- L1 保存/重载保留有效的 voice_id；淘汰出短期窗口的条目不强写别的记录。
- 普通 console 会话的 text/audio `run_turn` 增加同一 asyncio 锁，避免并发交错写历史。它可能产生可测的排队时间，不是抢占文本轮的调度器，也不是全系统所有后台任务的统一资源锁。

### 第6段：非阻塞接口、延迟证据和复跑工具

新增 localhost-only 控制接口；拒绝非loopback、非console、非JSON与跨站 Origin；请求体上限3MiB：

| 接口 | 行为 |
|---|---|
| POST `/voice/start` | 显式准备同一个服务；冷启动可能等待，不能当快速submit |
| POST `/voice/submit` | 已ready时返回202 + job_id；不等待整轮说完，不隐式起第二个服务 |
| GET `/voice/jobs/{job_id}` | 查queued/running/completed/failed/cancel_requested/cancelled |
| POST `/voice/cancel` | 请求取消指定job，真正清理结束才进入cancelled |

- job 最多2个活跃、保存最近64条；输入录音不进入job状态；结果包含业务回答文本，仅内存保留。
- 这不是两人并发说话或FIFO播放队列：所有job/麦克风共用同一Kernel，新轮仍按现有supersede规则打断旧轮。
- `cancel_requested` 不是“已经静音”；停止证据失败会是failed。
- 原 `/turn` 同步接口保留兼容；新接口未强行替换现有UI，也没有声称UI已经使用job API。
- 接口是本机信任边界，不是互联网鉴权服务；daemon继续只绑定loopback，不应暴露公网。

每轮最多32个内容无关事件，以 `perf_counter` 高精度时钟记录。保存目录：
`C:\Users\ACE_WAN——PROJECT\YHLZ\artifacts\voice_turn_traces`
最多保留500个本工具命名的UUID JSON，仅轮转这些文件，不删除其他用户文件。

关键事件依次包括：request_received、turn_accepted、session_start、session_queue_enter/exit、llm_request_start、llm_first_content、first_segment_ready、first_tts_submit、first_pcm_produced/received、playback_callback_first_nonzero、llm_done、session_done、request_finished。

- `llm_request_start` 在流式请求函数调用边界，不是底层网络抓包时刻；包含HTTP客户端准备等开销。
- `llm_done` 与 `session_done` 分开，避免将会话后处理混成模型生成耗时。
- `playback_callback_first_nonzero` 必须真的在输出callback拷入非零样本才记录，enqueue不算。
- **未记录真实人声结束、DAC输出或耳朵听到的时刻。** `speech_end_measured=false`、`acoustic_output_measured=false` 保留。
- `/voice/start`和VAD等待不包含在单轮request计时中；不能用request→callback冒充人声结束→声学首声。
