**日期**：2026-09-27  
**适用项目**：`C:\Users\ACE_WAN——PROJECT\YHLZ`  
**当前前提**：Phase 0 埋点骨架已完成，但真实基线尚未完成；当前默认 `/voice` 仍是旧 Live 链，Target 链尚未接入工作台。  
**本设计的目标**：先把现有 Target 架构真正接成一条可运行的语音对话链，再在不破坏旧链的前提下实现“边听、边想、边说、可插话”的全双工流式效果。

## 0. 先把“端到端”说清楚

本项目里“端到端”有两个含义，不能混为一谈。

### A. 本阶段必须完成：工程链路端到端

```text
麦克风 PCM
→ MediaAdapter / VAD
→ StreamingASRBridge
→ Sherpa final
→ SessionKernel 开启唯一 turn
→ ConversationSession / LLM 流式输出
→ TargetVoiceChain 句子切分
→ TTS 音频 chunk
→ SoundDevicePlaybackPort
→ 用户听到声音
```

这叫**工程链路端到端打通**。它不要求现在训练一个新的语音大模型，但必须让一帧音频最终能产生一段可取消的声音，并且所有事件都属于同一个 `session_id / turn_id / generation`。

### B. 本阶段只做接口和实验：语音到语音 Provider

```text
麦克风 PCM
→ AudioDirectProvider
→ 增量文本/音频事件
→ SessionKernel / 工具 / 记忆策略
→ Playback
```

这才是通常所说的“纯音频端到端”或 speech-to-speech。它必须作为可插拔 Provider 做 A/B，不能直接绕过 `SessionKernel`、记忆、工具和取消机制，也不能未经批准上传云端音频。

**本阶段决策：先完成 A，再接 B 的接口；不训练，不立即把 B 设为默认主链。**

## 1. 本阶段的最终用户效果

不是追求“模型名字看起来端到端”，而是让用户得到下面的体验：

1. 麦克风常驻，不需要每轮点开始。
2. 用户开口后，界面约 200–400ms 内显示正在听和 partial。
3. 用户说完后，final 只提交一次。
4. LLM 还没有生成完整答案时，第一句已经开始合成和播放。
5. 播放时用户可以自然插话。
6. 一旦确认插话，旧回答停止，旧 LLM/TTS 输出被丢弃。
7. 新问题可以立即形成新 turn。
8. 外放时不把自己的声音当成用户插话；如果 AEC 不可靠，明确降级为 B 模式或要求耳机。

### 目标指标

这些是阶段性工程目标，不是没有真机数据前的硬承诺：

| 指标 | 目标方向 | 说明 |
|---|---:|---|
| `speech_start → asr_final` | p50 ≤ 700ms | 不能通过截断用户语句来换数字 |
| `asr_final → llm_first_delta` | p50 ≤ 1200ms | 记录模型排队和首 token |
| `llm_first_delta → tts_first_chunk` | p50 ≤ 500ms | 必须区分模型首字和 TTS 首包 |
| `tts_first_chunk → playback_started` | p50 ≤ 300ms | 记录真实声卡开始播放 |
| `barge_in_detected → playback_stopped` | p50 ≤ 300ms | 必须以播放端确认停止为准 |
| 连续 20 轮 | 0 次幽灵音频 | 旧 turn 不得继续出声 |

## 2. 现有架构如何接，不再新建第二个状态核心

当前仓库已经有足够的核心组件：

| 现有模块 | Phase 1 职责 | 不允许做的事 |
|---|---|---|
| `backend/media_adapter.py` | 持续采集、处理、VAD 边界、播放参考 | 不保存业务对话历史 |
| `backend/streaming_asr_bridge.py` | PCM 分帧送 ASR，发 partial/final，处理取消 | partial 不得提交 LLM |
| `backend/session_kernel.py` | 唯一的 session/turn/generation/cancel 所有者 | 不再创建第二套 turn 状态 |
| `backend/target_chain.py` | transcript → reasoner/LLM → TTS → playback | 不负责设备采集生命周期 |
| `backend/target_runtime.py` | Media、ASR、Chain 的启动/停止/故障降级 | 不持有第二份会话历史 |
| `backend/target_playback.py` | 持久播放流、队列、停止确认、播放事件 | 不做模型推理 |
| `ConversationSession` | 历史、人格、记忆、LLM | 不直接操作麦克风或声卡 |
| `console_server.py` | HTTP/SSE 兼容适配器 | 不再扩张成新的总协调器 |

### 允许新增的文件

可以新增一个**无状态或薄适配器**：

```text
backend/target_workbench_adapter.py
```

它只做：

```text
HTTP/SSE 请求
→ 调用 TargetVoiceRuntime / TargetVoiceChain
→ 将 RuntimeEvent 转成工作台事件
```

它不能持有：

- 第二份 `generation`；
- 第二份活动 turn；
- 第二份播放队列；
- 第二份对话历史。

`SessionKernel` 仍然是唯一真相。

## 3. 目标总架构：输入、推理、输出同时运行

```text
                         ┌────────────────────────────┐
                         │      SessionKernel          │
                         │ session / turn / generation│
                         │ cancel / stale-event drop  │
                         └─────────────┬──────────────┘
                                       │
        ┌──────────────────────────────┼─────────────────────────────┐
        │                              │                             │
        ▼                              ▼                             ▼
┌───────────────┐              ┌───────────────┐             ┌───────────────┐
│ Capture Loop  │              │ Reasoning     │             │ Playback Loop │
│ MediaAdapter  │              │ LLM stream    │             │ TargetPlayback│
│ VAD + AEC ref │              │ sentence buf  │             │ persistent    │
└──────┬────────┘              └──────┬────────┘             └──────┬────────┘
       │                              │                             │
       ▼                              ▼                             ▼
┌───────────────┐              ┌───────────────┐             ┌───────────────┐
│ ASR Bridge    │──final──────▶│ TargetChain   │──PCM───────▶│ SoundDevice   │
│ partial only  │              │ TTS provider  │             │ start/stop ack │
└───────────────┘              └───────────────┘             └───────────────┘
       │                              │                             │
       └────────────── events / trace / cancellation ──────────────┘
```

三个循环必须并发存在：

1. **Capture Loop**：不能因为 LLM 或 TTS 忙就停止收音。
2. **Reasoning Loop**：收到 final 后立即启动，不等待完整音频回答。
3. **Playback Loop**：收到第一段可播放 PCM 就开始，不等待完整答案。

这就是“全双工”的工程基础。

但需要区分两种模式：

- **B 模式：可插话全双工**：输入和输出设备同时打开，用户可以打断系统。第一阶段目标。
- **C 模式：真正重叠说话**：系统播放时仍识别用户全部内容，并在没有明显停顿的情况下保持双方重叠。必须有可信 AEC/参考信号/回声验证，不能仅凭 RMS 阈值宣称完成。

Phase 1 先通过 B 模式，C 模式只做能力验证。

## 4. Turn 与事件协议

### 4.1 每个事件必须带的字段

```json
{
  "session_id": "s-xxx",
  "turn_id": "turn-xxx",
  "generation": 12,
  "trace_id": "trace-xxx",
  "event": "asr_final",
  "ts_mono_ms": 123456.7,
  "payload": {}
}
```

规则：

```text
generation 不是当前值：丢弃
turn_id 不是当前 turn：不能出声、不能写记忆、不能调用工具
partial：只显示，不能提交正式回答
final：同一 segment 只能提交一次
```

### 4.2 状态机

```text
READY
  → LISTENING
  → CAPTURING
  → FINALIZING_ASR
  → THINKING
  → SPEAKING
  → LISTENING
```

插话路径：

```text
SPEAKING
  → VAD 确认有效用户语音
  → SessionKernel.abort_active_turn("barge_in")
  → generation + 1
  → 取消 LLM
  → 取消 TTS
  → 清空播放队列
  → wait_stopped() 确认声卡停止
  → 新 turn 进入 CAPTURING
```

这里必须使用仓库真实 API：当前播放实现实际有 `wait_stopped(timeout_s)`，不能在设计里继续写不存在的 `stop_and_wait()`。

### 4.3 推荐事件表

| 层 | 事件 | 产生位置 | 用途 |
|---|---|---|---|
| 输入 | `capture_start` | MediaAdapter 开始取帧 | 请求级观测 |
| 输入 | `speech_start` | VAD 首次确认人声 | 真正测说话延迟 |
| 输入 | `first_partial` | ASR 首个 partial | UI 和输入首包 |
| 输入 | `speech_end` | VAD 结束 | 端点观测 |
| ASR | `asr_final` | Bridge final 回调 | 唯一正式提交点 |
| 会话 | `turn_opened` | `SessionKernel.begin_turn` | turn 关联 |
| LLM | `llm_start` | TargetVoiceChain 提交文本 | 推理延迟 |
| LLM | `llm_first_delta` | 首个非空 delta | 首字延迟 |
| TTS | `tts_start` | TTS provider 开始 | TTS 排队 |
| TTS | `tts_first_chunk` | 第一段 PCM | TTS 首包 |
| 播放 | `playback_started` | 声卡 callback 首次送有效帧 | 用户真正开始听到 |
| 插话 | `barge_in_detected` | VAD + 回声门控确认 | 取消起点 |
| 取消 | `cancel_requested` | Kernel 开始 abort | 取消耗时 |
| 播放 | `playback_stopped` | `wait_stopped()` 返回真 | 取消终点 |
| 会话 | `turn_closed` | Kernel 完成/中断 | 统计和回归 |

第一批 Phase 0 的 trace 必须先完成逐轮隔离，否则这些事件不能直接用于统计。

## 5. 分阶段开发顺序

### Phase 1A：先把文字到声音的 Target 链跑通

**目的**：先排除麦克风和 AEC 干扰，验证 `SessionKernel → TargetVoiceChain → TTS → Playback`。

做法：

1. 用固定 transcript 注入 TargetVoiceChain。
2. 验证一次 `begin_turn()`。
3. 验证 LLM delta 能切成句子。
4. 验证第一句能产生 TTS PCM。
5. 验证 `TargetPlayback` 能开始和结束。
6. 验证取消时旧音频不再出声。

验收：

```text
固定文字 20 轮；0 次重复提交；0 次旧音频串入新 turn；
取消 10 次；每次都能看到 playback_stopped 或明确失败原因。
```

不通过时不要接麦克风。

### Phase 1B：把 MediaAdapter → ASR → TargetChain 接通

**目的**：把真实音频送入 Target 链，但仍保持耳机模式。

接线：

```text
TargetVoiceRuntime.start()
→ MediaAdapter 持续回调 ProcessedAudioFrame
→ StreamingASRBridge.accept_frame(frame)
→ VAD 开始时 open_stream()
→ partial 只发 UI
→ VAD 结束时 finish_stream()
→ final 只调用一次 TargetVoiceChain.submit()
```

必须关闭或绕过旧 `/voice` 中：

- SenseVoice 正式二次提交；
- `_transcribe_audio_turn()` 二次转写；
- partial 触发 LLM；
- 旧 `_StreamingSpeaker` 与 TargetPlayback 同时播放。

验收：

```text
耳机模式 10 句短句 + 10 句长句；
每句最多一个 final、一个正式 turn、一个回答播放。
```

### Phase 1C：接入工作台，但默认仍保留旧链

新增请求参数：

```json
{
  "pipeline": "target",
  "continuous": true,
  "audio_route": "headset"
}
```

路由原则：

```text
pipeline=legacy：继续走旧 /voice
pipeline=target：通过薄 adapter 调 TargetVoiceRuntime
```

不要直接删除旧分支，先让工作台可以切换。

SSE 只负责转发：

```text
state
partial
final
assistant_delta
tts_started
playback_started
barge_in
playback_stopped
turn_done
error
```

SSE 不得自行决定取消真相，取消由 Kernel 和 Runtime 事件决定。

### Phase 1D：耳机模式插话

这一步才开始做“像 NEURO”。

插话处理顺序必须固定：

```text
1. Capture Loop 继续取麦克风帧
2. VAD 发现有效人声
3. 确认不是纯静音/短噪声
4. 标记 barge_in_detected
5. Kernel abort_active_turn()
6. LLM cancellation handle.cancel()
7. TTS cancellation handle.cancel()
8. Playback 清队列并 stop
9. wait_stopped() 返回
10. 创建新 turn
```

不要让 UI、ASR、TTS 各自维护一个 stop 标志。

验收：

```text
长回答播放中插话 10 次；
旧回答不能在新 turn 后继续出声；
barge_in_detected → playback_stopped 给出 p50/p95；
取消失败要记录具体组件，不准静默吞掉。
```

### Phase 1E：外放与 AEC

耳机模式通过以后才做。

当前 `SoundDevicePlaybackPort.playback_rms()` 只能作为粗粒度播放活动参考，不能等同于 AEC。要实现可靠外放全双工，需要：

1. 保存真实播放 PCM 的 render reference ring buffer；
2. 用相同采样率、频道、时间基准送入 AEC；
3. 记录 reference 是否连续、是否丢帧、设备延迟是多少；
4. 对“只有播放没有用户说话”和“播放中用户说话”分别测试；
5. AEC 不可验证时，`SessionKernel` 降级到 B 模式或要求耳机。

不能通过简单提高 RMS 阈值假装解决回声。AEC 主要是 CPU/设备同步问题，不是显存问题。

### Phase 1F：接入真正 AudioDirect Provider

在 A–E 通过之后，定义统一 Provider 接口：

```python
class AudioDirectProvider:
    def start(self, session_id: str) -> None: ...
    async def send_audio_frame(self, frame, lease) -> None: ...
    async def finish_input(self, lease) -> None: ...
    def events(self): ...  # partial/final/text/audio/status
    def cancel(self, lease, reason: str) -> None: ...
    def wait_stopped(self, timeout_s: float) -> bool: ...
    def close(self) -> None: ...
```

Provider 事件必须能映射成：

```text
TEXT_PARTIAL
TEXT_FINAL
AUDIO_FIRST_CHUNK
AUDIO_CHUNK
DONE
CANCELLED
ERROR
```

准入条件：

- 真正接受分帧 PCM，而不是录完 WAV 一次性上传；
- 能增量输出文本或音频；
- 能取消并确认停止；
- 能带 `turn_id/generation`；
- 失败可回退到混合链；
- 不绕过工具/记忆策略；
- 同一固定样本上不劣于混合链的稳定性。

如果现有 `audio-direct` 只是“录音结束后一次性调用”，它不算全双工 Provider，只能算离线 A/B。

5. ASR、LLM、TTS、Playback 各自注入一次失败。
6. 设备断开后能回到可恢复状态。

## 8. 失败时如何降级

| 故障 | 降级策略 |
|---|---|
| Sherpa 无 final | SenseVoice 只做一次 fallback，不与 Sherpa 正式链并行 |
| LLM 首 token 超时 | 回到 listening，保留文本错误事件，不播半截音频 |
| TTS 首包失败 | 文本仍通过 SSE 展示，回到 listening |
| Playback 停止超时 | 标记核心故障，停止接受新音频，等待 idle 后重启播放设备 |
| AEC reference 丢失 | 从 C 模式降级到 B 模式/耳机要求 |
| AudioDirect Provider 失败 | 当前 turn 失败后回退混合链，不重复写记忆 |
| 旧 generation 事件到达 | 丢弃并递增 stale counter，不得出声 |

## 9. 是否需要训练

**现在不需要。**

先证明瓶颈是：

- 端点等待；
- ASR final；
- LLM 首 delta；
- TTS 首包；
- 播放缓冲；
- 取消与队列；
- AEC/设备同步。

只有当链路稳定、延迟已经可接受，但出现下面问题时，才考虑训练或微调：

- 专有名词持续识别错误；
- 特定口音导致 final 失败；
- 人格和说话风格不稳定；
- AudioDirect Provider 的语音语义能力明显不够。

训练不能替代状态机、取消机制和全双工音频参考。

```text
→ TargetVoiceChain
```

保持耳机模式，关闭旧链的正式二次转写。

### 第 4 步：增加 `pipeline=target`

默认仍为旧链，只在明确指定时走 Target。工作台能切换，出现问题可以立即回退。

### 第 5 步：做耳机可插话

先得到稳定 B 模式，再谈外放和 C 模式。

### 第 6 步：最后接 AudioDirect Provider

用同一套 turn、事件、trace、取消和验收标准做 A/B。谁更稳定，谁才有资格成为默认链。

---

## 11. 本轮完成定义

本阶段只有全部满足以下条件，才叫“端到端打通”：

- 一帧真实音频可以进入 Target 链并产生声音；
- 每轮只有一个 final、一个正式 turn、一个可关联的回答；
- LLM/TTS/Playback 是流式的，不等完整回答；
- 播放开始和停止有真实设备事件；
- 插话可以取消旧 generation；
- 旧音频不会串到新 turn；
- 耳机模式连续 20 轮稳定；
- 外放模式只有在 AEC reference 可验证时才宣称全双工；
- AudioDirect Provider 可以失败回退；
- 所有结论都有 JSONL 和 p50/p95 数据支持。

**一句话：先把现有 Target 架构变成一条真正可运行、可取消、可测量的端到端主链；再把它升级为耳机模式的全双工可插话；最后才验证外放 AEC 和纯音频端到端 Provider。**
