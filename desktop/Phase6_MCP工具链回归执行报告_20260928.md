### 3.2 真实 `ledger_search` 调用

测试：`test_ledger_search_real_call`

实际调用：

```json
{
  "query": "麦克风",
  "limit": 2

```

检查点：

- 返回不是 `isError`；

- 返回内容包含 `ledger:` 记录标识；
- 返回内容包含查询关键词。

这只证明 MCP 的检索调用链可用，不代表本报告已经修改台账。

### 3.3 核心工具连续调用

测试：`test_core_tools_can_be_called_twice_after_discovery`

在同一个 MCP 连接内先完成工具发现，再连续两轮调用：

```text
system_time
ledger_search(query=全双工, limit=1)
memory_recall(query=扬声器, limit=1)
```

共返回 6 个结果，全部满足：

- `isError=false`；
- 返回文本非空。

这覆盖了“只在第一次调用时正常，后续请求失效”的常见连接生命周期问题。

### 3.4 非法参数与连接恢复

测试：`test_invalid_arguments_and_connection_recovery`

覆盖以下输入：

```json
{"query": ""}
{"query": "xxxxxxxx...", "长度": 81}
{"query": "MCP", "limit": 0}
{"query": "MCP", "limit": -1}
{"query": "MCP", "limit": 501}
```

检查点：

- 每个非法请求都返回 `isError=true`；
- 错误文本包含 `invalid arguments`；
- 非法请求之后，同一连接调用 `system_time` 仍然成功；
- 没有因为一次参数错误而关闭整个 MCP 连接。

这里保留了生产代码的参数边界，不通过放宽校验来换取测试通过。

### 3.5 能力注册异常隔离

测试：`test_failed_capability_does_not_block_healthy_capability`

测试注册一个主动抛出 `RuntimeError` 的 handler，再注册一个返回 `healthy` 的 handler。

结果：

- 异常 handler 返回 `ok=false` 和错误信息；
- 健康 handler 仍返回 `ok=true` 和 `healthy`；
- 异常没有污染后续能力执行。

这验证了能力注册层的局部失败隔离。

### 3.6 原始 stdio JSON-RPC

测试：`test_raw_stdio_is_newline_delimited_json_rpc`

绕过高级 MCP 客户端，直接向 server 的 stdin 写入换行分隔 JSON-RPC：

1. `initialize`；
2. `notifications/initialized`；
3. `tools/list`；
4. `tools/call(system_time)`。

检查点：

- 每个有响应的消息都包含 `jsonrpc: "2.0"`；
- 返回消息 id 与请求 id 对应；
- `tools/list` 返回核心工具；
- `tools/call` 返回非错误结果；
- stdout 每行都能被 JSON 解析。

### 3.7 干净关闭与重启

测试：`test_server_can_restart_after_clean_disconnect`

测试启动服务、完成一轮原始 stdio 调用、关闭 stdin、等待进程退出，然后重复整套流程。

结果：

- 第一次 server 进程退出码为 0；
- 第二次 server 进程退出码为 0；
- 两次都能完成 `initialize`、`tools/list` 和 `system_time`；
- 测试结束后显式关闭 stdout/stderr，未再出现此前的 `ResourceWarning`。

## 6. 下一阶段执行顺序

MCP 回归通过后，按以下顺序推进，不跨阶段宣称完成：

### Phase 7：DeepSeek MCP 客户端持续回归

目标：让实际工作 Agent 使用与本地测试相同的 `initialize`、`tools/list`、`tools/call` 协议路径。

验收最小集：

- DeepSeek 客户端能发现工具；
- 连续调用 `ledger_search`、`memory_recall`、`system_time`；
- 非法参数后连接仍可用；
- 客户端能处理 server 正常退出和重启。

### Phase 8：固定文本播放

先不接麦克风，固定 transcript 走：

```text
固定文本
  -> SessionKernel
  -> TargetVoiceChain
  -> TTS
  -> Playback
```

验收：冷启动、暖机、长句、取消、旧 generation 音频隔离。

### Phase 9：播放停止证据

取消请求不能直接等同于“已经停止播放”。需要记录至少一种真实 stop evidence：

- 播放后端确认停止；
- 输出流停止回调；
- 播放 generation 结束事件；
- 设备级播放状态变为 stopped。

### Phase 10：蓝牙耳机路由

主通道仍是扬声器，但先用耳机模式完成稳定的插话和播放停止链路。蓝牙需要单独记录：设备 id、采样率、输入输出端点、连接/断开、路由切换和实际出声确认。

### Phase 11：ASR 与插话

规则：

- partial 只更新 UI，不创建业务 turn；
- final 只提交一次；
- 过期 generation 的 partial/final 丢弃；
- 插话必须同时具备请求返回和播放停止证据；
- 不用 RMS、VAD 或 ducking 冒充 AEC。

### Phase 12：扬声器 AEC 真机验证与全双工验收

扬声器全双工只有在真实 AEC 证据存在时才放行。耳机模式通过不代表外放模式通过；外放模式需要单独的回声、误触发、双讲和插话数据。
